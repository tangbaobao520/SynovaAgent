## Q0: 定位 — 项目拼图 + 文件审计

### a) 项目拼图
Synova 控制塔的 DSH Web GUI 已通过 synova-dashboards 插件在右侧栏展示三仪表盘。
本任务把 DSH Web GUI 封装为 macOS 桌面壳（方案 A：壳 + 本地 dsh web 服务，零侵入），
让创始人不用开浏览器即可使用控制塔。属于 CTO 控制塔工具资产，非产品代码（src/ L1-L5 归编码 session）。

### b) 文件审计
- `dsh/plugins/synova-dashboards/` — 已有右栏仪表盘插件（Host+Client 双半），本任务不修改
- `dsh/desktop/` — 新建：main.cjs（Electron 主进程）+ start.sh（LaunchServices 启动）+ verify.sh（自检）+ package.json
- `electron/` `electron-renderer/` — 产品桌面端遗留（Phase 4.1），**不碰**（那是产品功能，非控制塔工具）

### c) 决策
桌面壳 = 纯展示层，零侵入 DSH 与插件系统。Electron 壳指向 127.0.0.1:3080，
端口探测复用已有实例 / spawn dsh web 双分支。技术栈沿用仓库已有 electron ^33.4.11。

## Q1: 调研 — 业界最佳实践 / 决策链 / memory 历史教训

- 壳方案（Electron + 本地服务）是 DSH 这类本地 HTTP 服务 GUI 化的标准做法（类比 VSCode 远程、Jupyter Desktop）
- 铁律 11/24/31：降级信号传播——端口探测失败走显式提示而非静默
- 铁律 0-2 接线验收：交付物含 verify.sh 自检（数据路由 + client 包 + 单实例 + 二进制）
- memory 教训：2026-08-16 实测 Electron 从 DSH/VSCode 终端 spawn 会 SIGTRAP（VSCode coalition 继承），
  必须走 LaunchServices（open）启动——已固化进 start.sh 与 README
