## Q1: 调研 — 根因 + 历史教训
根因（bash 语言语义）：`case` 的 pattern 在 **parse-time** 解析，`|` 是 alternation 语法；变量展开发生在 **runtime**，展开结果里的 `|` 只是字面字符，不重新参与语法解析。`[[ $x =~ $re ]]` 的 RHS 在 runtime 展开后按正则解析，`|` 作为 alternation 生效——这是正确工具。审计实测 bash 3.2/5.x 一致，我已独立复现（变量展开不匹配 vs 字面 alternation MATCH）。
历史教训：M1（fail-open 静默失效）第三次同型——"检查未执行==检查通过"。验收只查 exit 0 不查行为正确（P1-3）= M2 声称 vs 事实的变体。我"分步改 CI 留中间态"的旧账再次证实：门禁改动必须行为级验证。
参考：bash 手册（case pattern parse-time vs variable expansion runtime）+ K3 审计物理复现 + 第一性原理（门禁必须 fail-closed 且行为可测）。
