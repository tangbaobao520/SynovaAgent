## Q1: 调研 — 业界最佳实践 / decision 参考系
- **第一性原理**：门禁的价值 = 每次都跑。**没有 runner 的测试不是测试，是文档。**
  「PR 绿」若不含某支测试，绿就是假象——这正是创始人「让绿变真」的诉求。
- **Anthropic 工程基线**：CI 只应因**代码缺陷**红，不应因**数据漂移**红（脆性测试 = 噪音 = 门禁被绕过）。
  → 冒烟组断言不变量，具体数值留给密封夹具组（测试分层：密封夹具 vs live 冒烟）。
- **memory 历史教训**：M3（机制建成未接线，本项目 4 次接线失败）/ M1（fail-open 静默失效）——
  故新增段必须 **fail-closed**（glob 零命中 → 报红，不静默跳过）；M2（声称 vs 事实）——
  判据全部给命令 + 原始输出，不给「已接线」式声称。
- **参考**：Anthropic 工程基线（先量、可验证）+ 第一性原理 → 结论：
  **接线用 glob（新增测试自动纳入）**；**既有清单零改动（纯新增 diff 可审计）**；**存量红当场修，不靠排除清单**。

## Q3: 验收 — 入口 → 交互 → 结果
入口：git push PR → GitHub Actions job `Control Tower Gate Tests (ubuntu-latest|windows-latest)`
处理：job 内 `run` 段先跑既有显式清单，再跑新增 glob 段（`tests/project/*.test.sh` 逐支 bash 执行）
结果：① 该 job 日志出现 `── tests/project/gen-project-board.test.sh` / `── tests/project/pr-queue-scan.test.sh`
　　　② 两支全绿 → job 绿；任一红 → `::error title=<测试名>` 注解 + job 红
　　　③ glob 零命中（目录被删/改名）→ 显式报红（fail-closed，不静默跳过）
