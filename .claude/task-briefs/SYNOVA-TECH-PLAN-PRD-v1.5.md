# Synova PRD v1.5 — 技术实施方案

> **基于**: SYNOVA-PRD-交互设计-20260620.html v1.6（§17-19 新增）
> **方法论**: 垂直切片思维 + Loop Engineering v3.2
> **原则**: 一个切片 = 一个用户可见行为变化 = 一个 commit

---

## 〇、与现有代码的关系

PRD 定义了三栏布局 + GA 工作流——这不是"重写"，是**在现有系统上加交互层**。已有的诊断管线、哨兵系统、专家推理全部复用。

```
PRD 新概念        → 现有模块（改动量）
─────────────────────────────────────
工作区            → SessionStore 扩展（+2字段）
判断卡片          → AgentMemoryStore 扩展（+1 subtype）
行动项            → 新模块（~200行）
三栏布局          → 新 HTML 页面（~800行）
叙事生成器        → 新 pipeline 模块（~300行）
老板信箱          → 新 service 模块（~200行）
推送消息          → 飞书 connector 扩展（~100行）
知识问答入口      → qa-router.ts 已有，加 UI 暴露
```

## 二、Slice 1: 三栏布局骨架

**用户价值**: 打开页面看到的不再是聊天框——是"我的企业当前有哪些问题"。

**改动文件**:
- 新建 `src/routes/workspace.ts` — 三栏布局 HTML 页面
- 新建 `src/routes/workspaces-api.ts` — 工作区 CRUD API

**具体实现**:

```
GET /workspace → 三栏 HTML 页面

左栏 (240px):
  ┌──────────────┐
  │ [+ 新建工作区] │
  │              │
  │ 🔴 工作区1    │  ← 从 SessionStore 读取
  │ 🟡 工作区2    │
  │ ✅ 工作区3    │
  │              │
  │ 📋 长期遗留   │
  └──────────────┘

中栏:
  ┌──────────────────────────────┐
  │ 主题: XXX · 主导: 财务顾问    │
  ├──────────────────────────────┤
  │ 对话区（复用现有 chat 逻辑）   │
  ├──────────────────────────────┤
  │ 当前目标 + 进度条 + 输入框     │
  └──────────────────────────────┘

右栏 (280px):
  ┌──────────────┐
  │ 🎯 目标跟踪   │
  │ 📍 增长卡点   │
  │ 📋 长期遗留   │
  └──────────────┘
```

**API**:
```
GET  /api/workspaces              → 返回工作区列表
POST /api/workspaces              → 创建工作区
GET  /api/workspaces/:id          → 工作区详情（含对话历史）
PUT  /api/workspaces/:id/status   → 更新状态
```

**数据源**: SessionStore 扩展 `workspaceType` `status` `priority` 字段。

**验收**: 浏览器打开 → 三栏布局 → 左栏显示工作区列表（可为空）→ 中栏显示对话区 → 右栏显示空状态。

**预估**: ~600 行 HTML/CSS + ~150 行 API。3-4 小时。

## 三、Slice 2: 工作区生命周期

**用户价值**: 诊断结论不再是"看完就扔的文本"——变成一个可以跟踪状态的工作区。

**改动文件**:
- `src/routes/workspaces-api.ts`（扩展）
- `src/store/session-store.ts`（加字段）
- `src/agent/sentinel-service.ts`（关联工作区）

**状态机**:

```
待审阅 → 分析中 → 方案已确认 → 执行中 → 已解决
                  ↘ 无法推进 → 📋 长期遗留 → (复活条件满足) → 待审阅
```

**具体实现**:

1. SessionStore 加 3 个字段：`workspaceType`（diagnostic/manual）`status`（pending/analyzing/confirmed/executing/resolved/shelved）`priority`（critical/high/medium/low）

2. 工作区 API 支持状态流转

3. 诊断完成后自动创建工作区（在 `diagnosis-upload-v2.ts` 和 `conversation-engine.ts` 的完成回调中调用）

**验收**: 上传诊断 → 完成后左栏自动出现新工作区 → 点击进入 → 状态"待审阅"。

**预估**: ~200 行。2-3 小时。

## 四、Slice 3: Agent 结构化回复

**用户价值**: Agent 说的不是"一段文字"——是"根因+建议+置信度+行动按钮"。人能直接采纳或讨论。

**改动文件**:
- 新建 `src/pipeline/narrative-generator.ts`
- `src/routes/chat.ts`（前端渲染结构化卡片）

**Agent 回复格式**:

```json
{
  "type": "judgment_card",
  "root_cause": "客户A采购系统迁移导致的临时异常",
  "suggestion": "暂缓催收，下月复查",
  "confidence": 0.78,
  "experts": ["财务顾问"],
  "actions": [
    {"label": "采纳此方案", "action": "confirm"},
    {"label": "继续讨论", "action": "discuss"}
  ]
}
```

**前端渲染**: Agent 消息不再用纯文本 div——渲染为卡片组件。含专家标注、置信度进度条、操作按钮。

**验收**: 对话中 Agent 回复显示为卡片 → 点击"采纳"→ 状态变为"已确认"。

**预估**: ~300 行 TS + ~200 行 HTML/CSS。4-5 小时。

## 五、Slice 4: GA 初步诊断入口

**用户价值**: 黄学松能独立完成一个新客户的完整诊断流程——从填写八维框架到拿到报告。

**改动文件**:
- 新建 `src/routes/ga-diagnosis.html`（GA 诊断页面）
- 扩展 `src/routes/diagnosis-upload-v2.ts`（关联 GA 上下文）

**页面结构**:

```
┌────────────────────────────────────────────┐
│  Synova GA · 新客户诊断                     │
├────────────────────────────────────────────┤
│  第一步：8 维度初诊框架（表单）               │
│  第二步：上传补充材料（财务/组织/访谈）        │
│  第三步：GA 个人判断（文本框）                │
│  [开始诊断]                                  │
├────────────────────────────────────────────┤
│  诊断完成后：8 位专家报告卡片                 │
│  综合报告 → [逐条审阅] [生成交付版]           │
└────────────────────────────────────────────┘
```

**数据流**: GA 表单 → `POST /api/diagnosis/upload`（已有）→ 8 专家并行 → 综合报告 → HTML 展示。

**验收**: 黄学松打开 GA 诊断页 → 填写母婴客户数据 → 点击开始 → 看到 8 位专家报告。

**预估**: ~400 行 HTML + 复用已有 API。3-4 小时。

## 六、Slice 5: 老板信箱

**用户价值**: 企业主不需要打开系统——每周收到一封 Synova 写的邮件，告诉老板"这周发生了什么变化"。

**改动文件**:
- 新建 `src/services/boss-mailbox.ts`
- 扩展 `src/cron/scheduler.ts`（注册每周任务）

**邮件内容结构**:

```
主题: Synova 周报 · 某母婴品牌 · 2026年第27周

一、本周关键信号
  🔴 现金流预警（连续3周恶化）
  🟡 人员流失（2人离职）

二、正在执行的方案进展
  ✅ 缩短付款周期 — 回款周期 59天→37天
  🟡 建立客户健康评分 — 模型已搭建，等待数据录入

三、需要你关注的事
  · 现金流紧张和人员扩张密切相关——建议查看关联分析
  · 上次确认的方案 C 已搁置 60 天，是否需要重新评估？
```

**实现**: 
1. 每周一 9:00 Cron 触发
2. 从 AgentMemoryStore + SentinelRunner 获取本周信号
3. 从 SessionStore 获取方案执行进展
4. LLM 生成邮件文本
5. 通过飞书 Bot 或 SMTP 发送

**验收**: 手动触发 → 生成邮件 → 内容包含信号+方案进展+建议。

**预估**: ~200 行。3-4 小时。

## 七、Slice 6: 知识问答全局入口

**用户价值**: 企业内任何人在任何界面都可以向 Synova 提问。权限自动过滤。

**改动文件**:
- `src/l1/qa-router.ts`（已有）→ 加前端 UI 暴露
- 新建搜索入口组件（嵌入三栏布局顶部）

**实现**:
1. 三栏布局顶部加搜索栏
2. 输入问题 → `POST /api/knowledge/search`（已有）→ 权限过滤 → 返回答案
3. 答案包含：直接回答 + 数据来源 + Agent 判断（可选）
4. 一键"创建为工作区"——将问答上下文注入新工作区

**验收**: 搜索栏输入"上个月客户流失率"→ Agent 返回答案+来源+可选操作。

**预估**: ~200 行。2-3 小时。

## 十一、v1.6 新增切片（3 个）

### Slice 7: 部门负责人独立协作空间（§17）

**用户价值**: 市场负责人能自己在 Synova 里和 Agent 讨论定价策略，不干扰老板的全局视图。

**改动文件**:
- `src/routes/workspaces-api.ts` — 扩展：部门工作区 CRUD
- `src/routes/department-workspace.html` — 部门负责人独立界面（简化三栏）
- `src/middleware/rbac.ts` — 三级权限过滤（owner/manager/employee）

**权限矩阵**:
| 角色 | 可见 | 操作 |
|------|------|------|
| 部门负责人 | 本部门工作区 | 自由讨论+确认方案 |
| 老板 | 所有部门摘要 | 只读 |
| 对接人 | 所有部门完整内容 | 只读+协调冲突 |

**数据流**: GA 确认方案 → Agent 建议创建子工作区 → 部门负责人收到通知 → 独立工作区讨论 → 方案汇入全局。

**预估**: ~300 行。Phase 1。

---

### Slice 8: 企业事实层（§18）

**用户价值**: Agent 3 月说"你们用 KPI"，6 月不会忘。事实版本化管理，老板问"上次什么时候改的制度"能追溯。

**改动文件**:
- `src/l4/agent-memory-store.ts` — 新增 `type=enterprise_fact` + 版本链字段
- `src/l3/expert-registry.ts` — System Prompt 顶部自动注入当前事实摘要

**AgentMemoryStore 新增字段**:
```
category, value, version, superseded_by, change_reason, changed_by, effective_from
```

**注入机制**: 每次对话/诊断的 System Prompt 顶部追加：
```
## 企业事实（硬约束——你必须基于以下事实推理）
- 收入确认: 按里程碑确认（2026-Q1 董事会决议）
- 考核制度: KPI + OKR 混合体系（2026-02 HR改革方案）
- 组织架构: 事业部制，3个事业部（2026-01 生效）
```

**验收**: 创建事实 → 新对话 → Agent 回答基于事实 → 更新事实（superseded_by）→ Agent 使用新版本。

**预估**: ~250 行。Phase 1。

---

### Slice 9: 诊断节奏控制（§19）

**用户价值**: Agent 不会在数据不足时乱给建议。只有 3 个月财务数据 → 只说趋势，不说"你应该融资多少"。

**改动文件**:
- `expert/*/STAGE_LOGIC.md` — 已有按规模调整。扩展：按数据充分度控制建议力度
- `src/l3/expert-dispatcher.ts` — 调度前检查数据充分度 → 选择建议级别

**建议三级**:
| 级别 | 条件 | 输出 |
|------|------|------|
| 方向性判断 | 仅有 8 维初诊 | "有三个可能方向，需要验证 X/Y/Z" |
| 分析+假设 | 有行业数据+基本客户数据 | 给结论+置信度+"需验证的假设"清单 |
| 完整方案 | 全量数据+竞品+调研 | 具体行动+时间线+风险预案 |

**实现**: STAGE_LOGIC.md 已有规模→工具映射。加一列 `data_sufficiency → recommendation_level` 即可。不写新代码，改配置文件。

**预估**: ~100 行（配置文件）。Phase 1。
