## 项目身份（每次重读）

- SynovaAgent = 组织数字孪生诊断 + 持续增长导航系统。
  诊断是手段，目的是增长。
  核心问题：这家企业的增长卡在哪里？现在该做什么？
- Agent，不是 ChatBot。驻扎企业，持续观测，主动发现，自动诊断，给出行动建议，跟踪执行。
- 五层架构：L1(交互)→L2(编排)→L3(洞察)→L4(本体)→L5(存储)，只能向下依赖相邻层。
- 8 位专家: strategy / org / finance / tech / marketing / action / business_model / knowledge
- 完整数据流:
  原始数据 → 本体层(电子病历) → 7维度×25测量器 → 证据池 → 专家ReAct推理 → 诊断报告

## Q1: 调研 — 这件事以前怎么做的？

### a) 业界最佳实践
- Anthropic Outcomes grade-and-revise loop: writer→grader→revise 闭环
- Claude Code skills marketplace: 4200+ skills, PM-skills 68+ 成熟
- DeepEval GEval: LLM-as-judge 六维评分体系
- RAGAS: 知识检索质量持续评估

### b) 顶级团队怎么做
- Anthropic: 先建文件索引→增量热加载→联邦进化独立进程→原子写入→FDE审核门禁
- 不会一次性工程化所有进化机制。Phase 1 先做自动沉淀+手动审核，Phase 2 做自动校准

### c) 我们犯过的错
- memory/feedback_iron-rules-collaboration.md: 铁律0-2 测试先行+接线验收——新代码必须有测试
- 铁律4 交付不完整——写完代码没接线。知识注入器必须接到 ExpertFileLoader

## Q2: 范围 — 最简方案是什么？

MVP: pkb-lifecycle.ts 增加 autoSediment() 方法（诊断完成后自动沉淀新知识）+ 从 pm-skills curl 导入 10 个最相关的 skill 文件并适配 Synova SKILL-SPEC 格式

不做: 自动 Skill 草稿生成、阈值自动校准（需要 n≥30 数据积累）、完整 FDE 审核 UI

## Q3: 验收 — 做完后用户能看到什么？

入口: 诊断完成后 ExpertDispatcher 调用 autoSediment()
处理: 提取 findings 中 confidence≥0.7 的规律→写入 PKB（status=proposed, confidence=0.6）
结果: FDE 工作台看到待审核的 PKB 条目 + 新导入的 10 个 Skill 可用
