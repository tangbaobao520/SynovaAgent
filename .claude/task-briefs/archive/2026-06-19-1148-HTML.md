## 项目身份（每次重读）

- SynovaAgent = 组织数字孪生诊断 + 持续增长导航系统。
  诊断是手段，目的是增长。
  核心问题：这家企业的增长卡在哪里？现在该做什么？
- Agent，不是 ChatBot。驻扎企业，持续观测，主动发现，自动诊断，给出行动建议，跟踪执行。
- 五层架构：L1(交互)→L2(编排)→L3(洞察)→L4(本体)→L5(存储)，只能向下依赖相邻层。
- 8 位专家: strategy / org / finance / tech / marketing / action / business_model / knowledge
- 完整数据流:
  原始数据 → 本体层(电子病历) → 7维度×25测量器 → 证据池 → 专家ReAct推理 → 诊断报告

## Q1: 调研 — 这件事以前怎么做的？

### a) 业界最佳实践
- McKinsey金字塔备忘录: 1页纸=Governing Thought + 3 Key Messages + 证据
- BCG/贝恩报告: 数据可视化(柱状图/雷达图)+ 标注数据来源 + 行动路线图
- Anthropic Outcomes: writer输出→grader评估→结构化报告

### b) 顶级团队怎么做
- 先写静态HTML模板(不依赖后端) → 验证视觉效果 → 再接入数据绑定
- 一个模板对应OUTPUT_SPEC的7个强制字段

### c) 我们犯过的错
- mvp-server.js时代报告8KB硬编码HTML，CSS内联，结构不呼应诊断逻辑
- 根因: 模板和诊断规范分离。这次OUTPUT_SPEC先写完，模板直接对齐
