## 项目身份（每次重读）

- SynovaAgent = 组织数字孪生诊断 + 持续增长导航系统。
  诊断是手段，目的是增长。
  核心问题：这家企业的增长卡在哪里？现在该做什么？
- Agent，不是 ChatBot。驻扎企业，持续观测，主动发现，自动诊断，给出行动建议，跟踪执行。
- 五层架构：L1(交互)→L2(编排)→L3(洞察)→L4(本体)→L5(存储)，只能向下依赖相邻层。
- 8 位专家: strategy / org / finance / tech / marketing / action / business_model / knowledge
- 完整数据流:
  原始数据 → 本体层(电子病历) → 7维度×25测量器 → 证据池 → 专家ReAct推理 → 诊断报告

## Q1: 调研 — 这件事以前怎么做的？

### a) 业界最佳实践
- **Notion AI**: Agent 回复结构化——文本块 / 标题块 / 操作块分离。
  用户可内联确认/建议。卡片自包含，action 不弹窗。
- **Claude for Work**: Tool use 卡片——结构化 UI，展开/折叠，输入/输出分区。
  置信度用颜色编码（绿/黄/红三色）。
- **ChatGPT**: Browse/Code Interpreter 卡片——内联渲染，带进度条。
- **设计模式**: Card 组件 = Header(title+tags) + Body(root_cause+suggestion) + Footer(confidence+actions)
  ⚠️ actions 必须在卡片内、不弹窗——减少交互步骤。
- **已知库**: 本项目用纯 HTML/CSS/JS 内联渲染（无框架依赖），
  遵循现有 `.card-finding` / `.card-proposal` 模式。

### b) 顶级团队怎么做
1. **先定义数据契约** — JudgmentCard 接口（root_cause, suggestion, confidence, experts, actions）
2. **后端分离** — 格式化逻辑独立于渲染（pipeline/judgment-card.ts）
3. **前后端通过 SSE event type 通信** — 新增 `judgment_card` SSE 事件类型
4. **渐进实现** — 先静态卡片（只读），再加交互按钮（confirm/discuss），最后持久化
5. **复用现有设施** — 已有 SSE 管线、chat.ts 事件处理、finding-card CSS 模式

### c) 我们犯过的错
1. **4 次接线失败**（铁律 4+5）— 组件通过单元测试但从未被生产代码调用。
   预防: 完成时 `grep -rn "addJudgmentCard" src/` — 零结果 = 未接线。
2. **流式过度工程化**（2026-06-07）— LineBuffer/FrameRateLimiter/StreamChunker 三层嵌套。
   Slice 3 不涉及流式，但提醒：简单 buffer + 60fps flush 即可，不要引入中间件。
3. **`as any` 零容忍**（铁律 38，47 次历史）— 本次 2 处已清零。
4. **静默降级**（铁律 11）— catch 块必须 log + degraded。卡片渲染失败不能崩溃整个聊天页。

3. `src/routes/diagnosis.ts` (MODIFY, ~20 行) — SSE 回调中 emit judgment_card 事件

**明确定义 NOT doing**:
- ❌ 不修改 conversation-engine.ts（PRD 明确不改动）
- ❌ 不修改 expert-dispatcher.ts（L3，不改动）
- ❌ 不做复杂置信度可视化——简单颜色条即可（绿≥70% / 黄≥40% / 红<40%）
- ❌ 不做多步骤操作流——只有 confirm/discuss 两个按钮
- ❌ 不做判断卡片的持久化存储（confirm 状态仅前端内存，不写 DB）
- ❌ 不做卡片动画/过渡效果
- ❌ 不做移动端适配

**MVP 边界**: 用户对话 → Agent 回复 → 前端渲染为卡片 → 用户点"采纳"→ 卡片状态变为"已确认"。
**后续迭代**: 卡片持久化、通知系统、方案跟踪、多专家卡片。

## Q3: 验收 — 做完后用户能看到什么？

**入口**: Web 对话界面 `/chat` → 输入组织问题 → 发送 → SSE 流式诊断
**处理**: diagnosis.ts SSE 回调 → 检测 expert_hypothesis 事件 → judgment-card.ts 格式化为卡片 → SSE emit `judgment_card` → chat.ts handleSSEEvent → addJudgmentCard() 渲染
**结果**: 聊天区显示结构化判断卡片（替代纯文本 div），包含：
  - 根因 (root_cause)
  - 建议 (suggestion)
  - 置信度进度条（颜色编码）
  - 专家标签
  - [采纳此方案] [继续讨论] 按钮
**点击"采纳"**: 卡片边框变绿 + 显示"✅ 已采纳" + 按钮消失
**点击"继续讨论"**: 输入框预填追问文本
