## Q1: 调研 — 这件事以前怎么做的？

### a) 业界最佳实践
单一数据源 (Single Source of Truth): Palantir Foundry 的 Ontology SDK → 所有类型定义在一个地方。双数据源必然导致不一致。
Backward-compatible migration: 保留旧路径 + feature flag → 新路径灰度 → 旧路径删除。不建并行系统。

### b) Anthropic 团队怎么做
删除优先于新建。发现双数据源 → 立即取消一个。不留"两个都留着吧以后再说"的妥协。保留旧系统为权威数据源，新系统降级为文档或直接删除。

### c) 我们犯过的错
Batch 1-4 跳过了 Q0b 文件审计 → 不知道旧系统仍活跃 → 建了新模块但没关旧模块 → 15 个双数据源。根因: Q0 在 PreToolUse 强制执行，但之前版本不在，被系统性跳过。
