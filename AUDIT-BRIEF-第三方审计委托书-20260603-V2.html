请验证: 子类是否正确继承基类 + retryable 语义是否正确 (Timeout→true, Auth→false)。

5.3 流式工具调用循环

文件: src/agent/conversation-engine.ts streamWithToolLoop()
承诺: 每条用户消息只调一次 LLM (chat() 带 tools)，不再 stream()+chat() 双调。
请验证: 代码路径确认只有 provider.chat() 调用，无 provider.stream() 调用。
测试: tests/stream-tool-loop.test.ts (6 tests)

5.4 ToolRegistry 多模式分发

文件: src/agent/tools.ts
承诺: execute() 支持 local/connector/http/remote-agent 四种模式。
请验证: switch 分支覆盖率 + connector 模式是否正确委托给 ConnectorRegistry。
注意: remote-agent 分支标记为"尚未实现"——这是已知限制，非缺陷。

5.5 Connector/Extension/Expert 三大注册中心

文件: src/connectors/registry.ts, src/extensions/registry.ts, src/expert-platform/*.ts
承诺: 完整接口 + 注册中心 + 生命周期管理。
请验证: 类型完整性 + 无循环依赖 + 全局单例正确性。
已知限制: 飞书/NemoClaw Connector 仍为 stub 实现（接口完整，无真实 API 调用）。

5.6 空 catch 块清零

承诺: 所有 catch 块必须有 log/stderr/注释三者之一。
验证命令: grep -rn "} catch {" synova-agent/src/ | grep -v "log\." | grep -v "stderr" | grep -v "benign" | grep -v "nosec"
预期: 只返回 hot-loop SSE JSON.parse catch (已标记 benign) 和 finally 清理 catch。
