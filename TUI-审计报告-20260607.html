三、渲染与闪烁问题（核心差距）

CodeWhale 渲染流程
  1. 帧率限制: time_until_next_draw() 判断是否允许立即绘制
  2. DEC 2026 同步更新: BeginSynchronizedUpdate → 渲染 → EndSynchronizedUpdate
  3. 差分渲染: ratatui 只写入与上一帧不同的单元格
  4. 完全重绘: 仅在 resize / 焦点恢复时；跟踪 draws_since_last_full_repaint
  5. 菜单预预留: Composer 面板锁定到最坏高度，防止菜单过滤时聊天区域跳动（Windows Terminal 问题）
// 120 FPS normal / 30 FPS low-dynamic
if let Some(delay) = frame_rate_limiter.time_until_next_draw(now) {
    return Delay(delay);
}
// DEC 2026 atomic frame commit
execute!(stdout, BeginSynchronizedUpdate)?;
terminal.draw(|f| render(f, app))?; // diff-only
execute!(stdout, EndSynchronizedUpdate)?;
Synova 渲染流程
  1. 无帧率限制: 每次 setState 立即触发 React reconcile
  2. 无同步更新: 中间状态直接输出到终端
  3. 全量 re-render: ink 重新计算整个虚拟 DOM 树
  4. 全量输出: ink reconciler 将完整帧写入 stdout
  5. 无预预留: 布局随状态变化实时调整
// 每 100ms 触发全局重渲染
const timer = setInterval(() => {
  setStreamingText(prev => prev + batch); // → 全局 reconcile
}, 100);
// 无 BEGIN/END SYNC → 中间帧可见
// 无差异更新 → 全量输出到终端

6.1 中文输入混乱根因

// ❌ 问题方案: useStdin + data 事件
stdin.on('data', (data: Buffer) => {
  const str = data.toString(); // Windows IME 可能发多次：
  // 第1次: "n" → setText("n")
  // 第2次: "i" → setText("ni")
  // 第3次: "hao" → setText("nihao")
  // 第4次: "你好" → insertAtGrapheme → 混乱！
});

// ✅ 修复方案: useInput (ink 内置，已处理 IME)
useInput((input, key) => {
  if (input) {
    setText(t => t + input); // input 是 IME 提交的最终字符
  }
});

总结

核心诊断

Synova TUI v2 的根本问题不是代码质量问题，而是 ink 3.x 框架本身的架构限制：

  1. React reconciler 全量重渲染 — 这是 React 的设计哲学，但终端输出每秒数百帧会导致用户可见闪烁
  2. 无差分渲染 — CodeWhale 的 ratatui 只输出变化的单元格，ink 每次都输出完整终端帧
  3. 无真实光标 — ink 是抽象层，无法控制终端底层光标显示

在这些限制下，通过降低渲染频率和消除不必要的重渲染，可以显著改善体验。

理想状态下，应重新评估框架选择：升级到 ink v5、迁移到 blessed、或考虑 Rust ratatui。
