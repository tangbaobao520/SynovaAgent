## 1. 用一句话说清楚

Synova 是一个**驻扎在企业里的 AI 诊断师**：它观察企业的数据（财务/客户/人才/技术……），发现异常，请多位"专家"（AI 角色）各自分析，最后给你一份报告：**这家企业增长卡在哪里、现在该做什么**——并且持续跟踪执行。

## 2. 数据怎么流（一条线）

```
原始数据 → 电子病历（本体层：企业知识图谱）
        → 25 个测量器算出指标
        → 按需（GA 诊断）或定时（Sentinel 哨兵）触发
        → 证据池 → 信号聚合 → 交叉关联 + 严重度升级
        → 按需激活问题域专家推理（交叉验证）+ host 主持整合
        → 综合诊断报告 / 工单 → 你（创始人）收到
```

## 3. 五层架构（人话）

| 层 | 名字 | 干什么 | 例子 |
|---|---|---|---|
| L1 | 交互 | 别人怎么碰它 | API / 终端 / 对话 |
| L2 | 编排 | 大脑：决定先做什么后做什么 | 对话引擎、诊断启动器 |
| L3 | 洞察 | 推理 + 洞察 | 问题域专家 / 哨兵 / 专家平台 |
| L4 | 本体 | 企业知识图谱：谁是谁、什么影响什么 | 图桥、实体解析 |
| L5 | 存储 | 数据库 | SQLite |

**规则**：每层只能和上下相邻层说话（防止依赖乱成一团，pre-commit 有脚本检查）。

## 4. 三个关键词（读文档时必备）

- **测量器（compute）**：纯数学计算，不碰数据库。例：毛利率、现金流覆盖率
- **哨兵（Sentinel）**：可独立告警的最小子领域。例："现金流预警"——一个哨兵管几个测量器
- **专家（Expert）**：按「问题域」分工的 AI 推理角色，**按需激活**（不是全部同时跑，省成本）。五个问题域：**资金效率 / 客户增长 / 组织能力 / 技术底座 / 竞争战略**。它们解读信号、给判断、交叉验证——回答「意味着什么、该怎么办」。
- **主持（host）**：**唯一主 agent**，常驻，统筹诊断、按需激活专家、整合结论，面向你回答「增长卡在哪、现在做什么」。

> 三层分工（谁干什么，别混淆）：
> - **计算层**（测量器/哨兵）：确定性计算，不跑 LLM——回答「数据偏离了什么」（低成本、可核查）
> - **推理层**（问题域专家）：LLM 推理，按需激活——回答「意味着什么、该怎么办」（中成本）
> - **主持层**（host）：唯一主 agent——回答「增长卡在哪、现在做什么」（常驻）
>
> 注意：`资金循环 / 客户循环 / 人才循环` 是**资源循环（cycle）**，是计算层因果骨架的名字，**不是专家名**——专家名不再含 cycle。

## 5. 扩展方式：加文件，不改代码

- 新增专家 = 声明式配置（prompt / tools / 输出结构 / 激活策略），改文件不改代码
- 新增哨兵 = 新建目录 + 配置 → 自动发现
- 新增技能 = 新建目录 + SKILL.md → 自动加载

> 这是从 Novis 时代"文件优先"决策（2026-06-15）继承来的核心哲学：**能文件化的必须文件化**。

## 6. 工程治理（谁保证质量）

- **铁律门禁**：pre-commit 13 组硬阻断（类型安全 / 测试 / 秘密扫描 / 接线 / 架构边界 / 任务认领……）——"硬阻断 100% 有效，软机制 0% 有效"
- **控制塔流程**：任务启动（task brief）→ 写前检查 → 写后验证 → 提交阻断 → 推送阻断
- **多 Agent 协作**：开发线（Codex / DSH / Claude Code）+ 审计线（Kimi K3）——分工见 `docs/synova/coordination/`

## 7. 历史演变（为什么长这样）

- **ClawOrg**（2026-03~05）：跑在 OpenClaw 上，管理 AI Agent 团队协作
- **Novis**（05-23~06-05）：转向"组织诊断"，引擎独立（engine-core）
- **Synova**（06-03 至今）：独立 API 进程 + 本体图 + 哨兵 + 专家体系，诊断对象 = 人 + Agent 混合组织
