## 0. 本文回答什么

**答案**：

> **① 能力面达成 ＋ ② 每个能力域真的接线 ＋ ③ 穿过真实入口验证过，且至少一个客户真的用它做出过决定。**

## 1. 产品完成的定义

### 1.1 三个条件（同时成立才算完成）

| 条件 | 内容 | 由谁保证 | 当前状态 |
|---|---|---|---|
| **A · 能力面** | 29 条线的**关键能力**都被实现 | 各线验收点 | 交付度 **16.8%**（125 点 / passed 21 / verified 12） |
| **B · 接线段** | 每个能力域 `wired = true` | **前提清单第 2 项（不变量机制）** | **9 处已确认断线**（§2.3） |
| **C · 验证段** | `testedThroughEntry = true` ＋ **至少一次客户侧验证** | **前提清单第 3 项（验证基建）** | **e2e 不在 CI**；**零客户验证** |

> **注意 B 与 C 都由「前提清单」保证** —— 这不是巧合，而是结构性的：**那 3 项是判定线是否达成的手段，不是被判定对象**（§2.2）。

### 1.2 每个能力域的「五态」（取代百分比）

| 态 | 含义 | 判定方式 |
|---|---|---|
| **缺** | `implemented = false` | 无实现 |
| **写了没接** | `implemented = true, wired = false` | **不变量**（不是 grep） |
| **接了跑不通** | `wired = true, live = false` | 冒烟启动 |
| **能跑未验证** | `live = true, testedThroughEntry = false` | e2e 状态 |
| **健康** | `live = true && testedThroughEntry = true` | 二者皆真 |

**共同报告方式**：`N 个健康 / M 个写了没接 / K 个缺` —— **离散计数，不是百分比**。

### 1.3 为什么「线全绿 ≠ 完成」——三个理由

**理由 1：有 12 项工作不属于任何一条线。**
即 T-D1~T-D12（§2.3）。它们是「已有线里的断线」，不是「线的缺失」——**线全绿也不会让它们消失**。

**理由 2：11 项 DSH 对照缺口虽已归线，但需要主动补验收点**（§2.1）。
它们不会自动出现在现有 163 个验收点里。

**理由 3（最根本）：线只能回答「有没有这个能力」，回答不了「这个能力真的能用吗」。**
以**线 7（持续监测）**为例：`done_definition` 是"装好后系统自动按周/月/季监测"——但 **e2e 不在 CI**，所以"自动监测"**无法自动验证**。**线 7 即使标 100%，也可能实际是"写了没接"。**

## 4. 三层的验收方式**各不相同**（最容易做错的地方）

| 层 | 验收方式 | ❌ 不合格 | ✅ 合格 |
|---|---|---|---|
| **能力线** | **穿真实入口的集成用例**（**禁止 grep 命中**） | "表已创建" | "跑一次真实哨兵，断言新增一行且 value 非空" |
| **前提清单** | **反向验证**（证明"不做会怎样"） | "支持 HTTP_PROXY 环境变量" | "只允许代理出网的环境跑真实调用成功，**且直连会失败**" |
| **线外工作项** | **三问自查**（见下） | "函数已被调用" | "注入 3 期历史后跑哨兵，断言 finding 含 trend 且方向正确" |

### 4.1 每个工作项完成时的「三问自查」

1. **谁调用它？**（给出**调用点行号**，不接受"应该会被调用"）
2. **有没有一条测试穿过真实实现？**（不是 fake provider 顶替）
3. **如果它明天被删掉，什么会坏？**（答不出来 = 没接线）

**三问答不出来，就不算完成。**

> **这三问来自本轮的实证**：已确认 9 处"写了没接上"（§2.3 的 12 项占了大部分），**没有一项能被"grep 命中"型验收发现**。

## 5. 边界：不做什么

| 禁做 | 理由 |
|---|---|
| ❌ **重开"要不要换 DSH 内核"的战略论证** | 决策已于 2026-08-20 定稿（A 形态）且在执行 |

| ❌ **在入场券②满足前建立任何 DSH 代码依赖** | 守卫 G1（`grep -rn "@deepseek-ai" src/ packages/` 零命中）**今日物理成立，务必守住** |
| ❌ **把哨兵挂到 DSH 的调度上（`ctx.jobs`）** | 实测 `dsh-schedule` 是**会话内提醒**（冷会话收不到通知、不做外部推送、不支持 cron 表达式），全谱**无 `dsh-cron`** |
| ❌ **用 grep 命中作为"完成"的验收标准** | 已发生 9 次"grep 通过但没接线"；**门禁组 4「接线完整性」失效即此因**（4a 只查"符号被引用"、4b 只查 3 个入口文件） |
| ❌ **把"29 条线全绿"当作"产品被验证"** | 线没有"被验证"维度（26 线里唯一带效果的是 6-3「命中 1 个老板没想到的盲区」） |
| ❌ **用 DSH 的界面当客户交付物** | 会露出工作区/文件树/终端 → **攻击定价**（"不能被认成软件"） |
| ❌ **把测量值塞进记忆表（`agent_memory`）** | 记忆是**定性知识**，时序是**定量数值**；混放会污染两者 → 要独立一层 |
