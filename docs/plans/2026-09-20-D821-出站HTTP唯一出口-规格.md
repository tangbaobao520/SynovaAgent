## 1. 冻结契约全文（队长冻结 v1 — API 名与语义一个字不动）

模块 `src/providers/http-exit.ts` = **全仓库唯一**读代理环境变量的文件。

### 1.1 env 名（两种大小写都支持）

`http_proxy`/`HTTP_PROXY`、`https_proxy`/`HTTPS_PROXY`、`all_proxy`/`ALL_PROXY`、`no_proxy`/`NO_PROXY`

### 1.2 解析顺序（对齐 DSH `dsh-http-proxy/lib/index.js:237`）

目标 scheme 自己的变量 → `ALL_PROXY` →（**仅 https**）回退 `HTTP_PROXY`。

### 1.3 env 读取时机

**调用时读取**，不在模块加载时缓存（运行时可改、可测）——这是相对 `NODE_USE_ENV_PROXY` 的实质改进（队长实测：后者在 v22.22.0 需进程启动前设定）。

### 1.4 loopback 恒绕过

`127.0.0.0/8` **整段**（127.0.0.2 也算）、`::1`、`localhost`、`*.localhost`、`::ffff:127.*`。

### 1.5 `NO_PROXY` 语义

逗号分隔；支持 `host`、`host:port`、`.suffix`/`*.suffix`、**IPv4 CIDR**（改写 DSH：DSH 不做 CIDR）、`*`；大小写不敏感。

### 1.6 不可用值 → 降级不阻断启动

`socks:`/`socks4:`/`socks4a:`/`socks5:`/`socks5h:` → `kind='socks'`；URL 畸形 → `kind='invalid'`；
二者 `degraded=true` + `log.warn` 一次 + 出站**直连**。

### 1.7 代理不可达（请求期）→ 禁止静默直连回退

抛 `OutboundHttpError{code:'PROXY_UNREACHABLE', phase:'connect', retryable:true, degraded:true}` + `log.warn`。

### 1.8 凭据纪律

代理 URL 内 `user:pass` → `Proxy-Authorization: Basic`，**永不**进日志 / `getProxyStatus()`；请求头 / 体**永不**进日志。

### 1.9 不做重试

出口**不做重试**（归 `src/services/retry.ts` 与调用方）；只做错误分类。

### 1.10 响应为真 `Response`

node `IncomingMessage` → `Readable.toWeb`，status/headers/流式 body 全真，尊重 `init.signal`。

### 1.11 零新依赖

只用 `node:http` / `node:https` / `node:tls` / `node:net` / `node:stream` + 全局 `Response`。

### 1.12 传输要求

- https 目标走 http 代理 → `CONNECT` 隧道（`http.request({method:'CONNECT'})` → `tls.connect({socket})` → `https.request({agent:false, createConnection:()=>tlsSocket})`）
- http 目标走代理 → 绝对 URI 请求（path = 完整 URL + Host 头）

### 1.13 导出 API（**冻结**，一个字都不能改）

```ts

export interface ProxyStatus { configured: boolean; active: boolean; kind: ProxyKind; variables: string[]; degraded: boolean; reason?: string; loopbackBypass: true; }
```

## 5. 降级 / 错误分类表

### 5.1 配置期（解析，不抛错、不阻断启动）

| env 值形态 | `kind` | `configured` | `active` | `degraded` | 出站 | 日志 |
|---|---|---|---|---|---|---|
| 未设置任何代理 env | `none` | false | false | false | 直连 | — |
| `http://p:8080` | `http` | true | true（非 loopback 非 bypass 目标） | false | 走代理 | — |
| `https://p:8443` | `https` | true | true | false | 走代理（TLS 到代理） | — |
| `socks5://p:1080`（含 `socks:`/`socks4:`/`socks4a:`/`socks5h:`） | `socks` | true | false | **true** | **直连** | `log.warn` 一次 |
| `ht!tp://p` / `p:8080`（URL 畸形或 scheme 非 http/https/socks） | `invalid` | true | false | **true** | **直连** | `log.warn` 一次 |
| 代理已配置，但目标是 loopback | **`none`** | true | false | false | 直连（恒绕过） | — |
| 代理已配置，但目标命中 `NO_PROXY` | **`none`** | true | false | false | 直连 | — |

> **`kind` 语义（队长 2026-09-20 裁决，规则一句话）**：`kind` = **本次实际生效 / 被记录的代理机制**。
> - loopback / `NO_PROXY` → 代理**不参与** → `kind='none'`（不用配置类型）。
>   理由：只读 `kind` 的消费方（如 D862 的健康暴露）会把 loopback 流量误报成"代理生效"；
>   `'none'` 让 `useProxy`/`kind` 这对字段自洽。**注意**：`getProxyStatus()` 的语义**不变** ——
>   它回答全局"配置了什么 / 是否 active"，其 `kind` 仍是配置的代理类型（`ProxyStatus` 无 `useProxy` 字段）。
> - 配置了但**不可用**（socks / 畸形）→ `kind='socks'|'invalid'` + `degraded=true`（保留"不可用来源"归因）。
> - 正常走代理 → `kind='http'|'https'` + `useProxy=true`。
>
> `variables` 只含**变量名**（如 `['http_proxy']`），**永不含值**。
> 降级值不参与 fallback：`HTTPS_PROXY=socks5://x` + `ALL_PROXY=http://y` → 仍 `kind='socks'` 直连（对齐 DSH `resolveScheme` 的"rejected 即保持直连"）。

### 5.2 请求期（`OutboundHttpError`）

| # | 触发 | `code` | `phase` | `retryable` | `degraded` | 附带 |
|---|---|---|---|---|---|---|
| 1 | `url` 无法解析为 http/https URL | `INVALID_URL` | `request` | false | 决策的 degraded | — |
| 2 | 连代理失败（ECONNREFUSED / ENOTFOUND / 超时 / reset） | `PROXY_UNREACHABLE` | `connect` | **true** | **true** | `log.warn`（含 proxyKind，不含值） |
| 3 | CONNECT 非 200，或隧道建立后 socket 提前关闭 / TLS 握手失败 | `PROXY_TUNNEL_FAILED` | `tunnel` | **true** | **true** | `log.warn` |
| 4 | 直连上游失败（ECONNREFUSED / ENOTFOUND / reset） | `UPSTREAM_UNREACHABLE` | `connect` | false | 决策的 degraded | `log.warn` |
| 5 | 有代理时数据面连接失败 | `UPSTREAM_UNREACHABLE` | `connect` | false | 决策的 degraded | `log.warn` |
| 6 | socket 超时（连接/传输） | `UPSTREAM_TIMEOUT` | `response` | **true** | 决策的 degraded | `log.warn` |
| 7 | `init.signal` 主动 abort | **不包装**（原样传播） | — | — | — | 尊重调用方 abort 语义（冻结枚举无 ABORTED 码） |

**禁止静默直连回退（冻结语义 1.7）**：任何"代理已选中（`useProxy=true`）"的路径，失败一律**抛错**，**绝不**在 catch 里改走直连。降级直连只允许发生在 **5.1 的配置期判定**（socks / invalid），且必须 `degraded=true` + `log.warn`。

### 5.3 与 `src/services/retry.ts` 的分工

出口 `retryable` 只是**分类标记**；实际重试由调用方 / `retry.ts` 决定。出口自身**零重试**（冻结语义 1.9）。

## 5.4 实现期实测发现（4 条，均已在冻结前修复 — 原始输出见自验记录）

| # | 发现 | 性质 | 处置 |
|---|---|---|---|
| 1 | `lookup` 只回**标量**，违反 Node happy-eyeballs 的 `options.all === true` 约定 → `localhost` / `*.localhost` / `[::1]` 直连即 `ERR_INVALID_IP_ADDRESS` | **实现缺陷**（与自身契约"本机目标不过 DNS"矛盾；`src/` 里成片 `http://localhost:${port}` 调用点会成片踩中） | 按 `options.all` 返回 `[{address, family}]`，否则标量；新增 6 条回归用例 |
| 2 | 隧道内层请求写了 `agent: false` → Node 22 实测**仍做 DNS 解析**（`getaddrinfo ENOTFOUND`），`createConnection` 退化为不被使用 | **实现缺陷**（`CONNECT` 隧道拿不到内层请求） | 去掉 `agent: false`，由 `createConnection` 接管隧道 socket；`node -e` 复现脚本留存（见自验记录） |

| 4 | 隧道 TLS 曾按"Node 默认"不写 `rejectUnauthorized` → 自签内网证书场景校验失败 | 契约取舍 | **按队长裁决硬编码 `rejectUnauthorized: true`**（安全默认）；企业内网 MITM CA 由 `NODE_EXTRA_CA_CERTS`/`tls.setDefaultCACertificates` 注入默认信任库解决，与 true 兼容。**不为测试放宽**，测试也不用 `NODE_TLS_REJECT_UNAUTHORIZED` |

### 5.4.1 本机物理约束（决定测试夹具设计，不得"改成能过"）

```
$ node -e "…bind(127.0.0.1) 后连 127.0.0.2…"
bind=127.0.0.1 -> 127.0.0.2:      TIMEOUT → ERR ECONNRESET ~5007ms
bind=127.0.0.1 -> 127.13.7.254:   TIMEOUT → ERR ECONNRESET ~5008ms
bind=127.0.0.2:                   EADDRNOTAVAIL（Linux 可绑）
bind=127.0.0.1 -> localhost:      OK 7ms
```

**macOS 不为 `127/8` 建别名** → "127.0.0.2 必须绕过代理"**无法靠"连上去"证明**，
只能靠路由证据（假代理命中计数 = 0 + 失败归属直连）。因此单测对 `127.0.0.2`/`127.13.7.254`
断言"假代理 0 命中"，不把它写成 live-connect 断言；**该地址在本机不可建连这一事实显式写进用例注释**，
Win 实机回归时同样适用（`127/8` 可达性问题属平台差异，不得据本机结论外推）。
