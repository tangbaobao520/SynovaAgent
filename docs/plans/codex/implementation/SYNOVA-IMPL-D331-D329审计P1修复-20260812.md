### 3.2 修复模式

**pre-push tag-祖先校验**:

```bash
# D331 (L4-1): 版本 tag 必须是 HEAD 祖先（防孤儿 tag/锚点断裂）
TAG_FAIL=""
for t in $(git tag -l 'V[0-9]*.[0-9]*.[0-9]*'); do
  if ! git merge-base --is-ancestor "$t" HEAD 2>/dev/null; then
    TAG_FAIL="${TAG_FAIL}  $t 不是 HEAD 祖先（孤儿 tag）\n"
  fi
done
LATEST_VER=$(grep -oE '^## V[0-9]+\.[0-9]+\.[0-9]+' "$ROOT/.codex/control-tower/VERSION.md" | head -1 | awk '{print $2}')
if [ -n "$LATEST_VER" ] && ! git merge-base --is-ancestor "$LATEST_VER" HEAD 2>/dev/null; then
  TAG_FAIL="${TAG_FAIL}  $LATEST_VER 缺失或非祖先\n"
fi
[ -n "$TAG_FAIL" ] && hard_check "D331: 版本 tag 锚点断裂" "$TAG_FAIL"
```

**check-bypass-log.sh（对账核心）**:

```bash
# 对比 origin..HEAD 提交与 bypass.log 的 HASH 条目；新提交缺失 → exit 1
MISSING=""
for h in $(git log origin/feat/prompt-architecture..HEAD --format=%H 2>/dev/null); do
  if ! grep -q "$h" "$ROOT/.claude/bypass.log" 2>/dev/null; then
    MISSING="${MISSING}  $h\n"
  fi
done
[ -n "$MISSING" ] && { echo "❌ bypass.log 缺以下提交记录:"; printf "$MISSING"; exit 1; }
```

> 说明：f685fa0 等历史提交可豁免（一次性补记或标注），对账从 D331 起的新提交强制执行；post-commit hook 在提交后立即校验本提交是否有记录，缺失即告警（防 amend 重提交再次漏记）。

**synova-commit guard 调用（替换 L367）**:

```bash
PYBIN=""
for _c in python3 python py; do
  if command -v "$_c" >/dev/null 2>&1 && "$_c" -c "import sys" >/dev/null 2>&1; then PYBIN="$_c"; break; fi
done
if [ -n "$PYBIN" ]; then
  GUARD_OUT=$("$PYBIN" "$STAGING_GUARD" --session-id "$SESSION_ID" --staged $STAGED_LIST 2>&1)
  GUARD_RC=$?
  if [ "$GUARD_RC" != 0 ]; then
    GUARD_STATUS=$(echo "$GUARD_OUT" | "$PYBIN" -c "import json,sys; print(json.load(sys.stdin).get('status','degraded'))" 2>/dev/null || echo degraded)
  else
    GUARD_STATUS="degraded"   # 执行失败 → degraded 显式提示，不静默
  fi
else
  GUARD_STATUS="degraded"
  echo -e "${YELLOW}⚠ staging-guard 跳过: python 不可用或损坏（fail-open 显式提示）${RESET}"
fi
```

> 注意：`GUARD_RC != 0` 时 guard 输出可能是 JSON（block 用 exit 1）——需区分"block（JSON status=block）"与"崩溃（非 JSON）"。实现时：`GUARD_RC != 0` 且输出可解析为 JSON 且 status=block → 按 block 处理；否则 → degraded 提示。

**--session 生产接线**: synova-commit 与 staging_guard 调 resolver 时传 `--session "$SESSION_ID"`；dev doc §5 增加 grep 断言：`rg -n "resolve-commit-brief.sh.*--session" scripts/` 命中 ≥1 生产调用点。
