# D332: 控制塔并行协调补丁

> 一句话问题: 2026-08-12 D330/D331 并行执行时共享暂存区拉锯（D331 re-add 抢占 → D330 被 D328 一致性门禁拒绝 → 循环）。根因三层：git index 是 worktree 级单例（物理）、控制塔用门禁仲裁替代物理隔离（设计）、依赖任务被并行派发（流程）。D307（worktree 隔离）是根治；本任务落 CT-10~13 软加固，让并行减害、竞争可观测、被拒有指引。

## 2. 代码审计——现状 (2026-08-12 实测)

### 2.1 缺陷 A (P0): staging-guard 被拒报错无指引 → 拉锯循环

[staging_guard.py](D:\novis-backup-20260526\Novis\synova-agent\scripts\control-tower\staging_guard.py) 拒绝时只输出 `foreign_files`（文件 + owner），**不输出**：活跃 session 列表、文件归属 brief 的 D#、下一步建议（等待/协调/串行）——被拒 session 不知道该怎么办，只能重试 → 与对方 re-add 拉锯。实测 2026-08-12 事件：D330 unstage → D331 re-add → D330 再被拒，循环。

### 2.2 缺陷 B (P0): attach.py 不 register session → 防护数据缺一半

[attach.py](D:\novis-backup-20260526\Novis\synova-agent\scripts\control-tower\attach.py) SessionStart 只写 `current-brief.<sid>`（D329），**不 register session-registry**——register 只在 synova-commit（提交时）。实测 registry：D330 从未登记（只有 D331/D331-test/prompt-architecture），staging-guard 不知道 D330 存在。

### 2.3 缺陷 C (P1): wait_manager 无暂存区竞争场景

[wait_manager.py](D:\novis-backup-20260526\Novis\synova-agent\scripts\control-tower\wait_manager.py) 有 CP1-CP4 阶段，但**无"暂存区含他人活跃写集文件"的检测/提示**——竞争发生时没有协调信号。

### 2.4 缺陷 D (P1): 提交被拒无事件记录

staging-guard/D328 拒绝提交时**不写事件日志**（degraded-events.log 无 parallel 事件类别）——竞争不可追溯，K3 审计 L3 无法查"并行合规"。

### 3.2 修复模式

**staging_guard 拒绝输出升级（CT-10 + CT-13）**:

```python
# 被拒时（status=block）：
active = [s["session_id"] for s in reg.list(active_only=True) if s["session_id"] != session_id]
result["guidance"] = {
    "active_sessions": active,
    "suggested": "等待对方 CP4 释放 / 与对方协调串行 / 或 git worktree 隔离后重试（D307）",
}
# CT-13: 事件记录
with open(REPO_ROOT / ".codex/control-tower/logs/parallel-conflicts.log", "a", encoding="utf-8") as f:
    f.write(f"{time} | session={session_id} | blocked_by={active} | files={[x['file'] for x in result['foreign_files']]} | action=suggested\n")
```

**attach.py 强制 register（CT-11）**:

```python
# SessionStart: 写 current-brief.<sid> 后
subprocess.run(["python3", str(REPO_ROOT / "scripts/control-tower/session_registry.py"),
                "register", "--session-id", session_id,
                "--brief", f".claude/task-briefs/{brief_name}", "--pid", str(os.getpid())],
               capture_output=True, timeout=10)
```

**wait_manager 竞争检测（CT-12）**:

```bash
# check-staging-race: 暂存文件命中他人活跃写集 → 提示
python3 - <<'PY'
# 读 registry 活跃 session 写集 vs git diff --cached --name-only
# 命中 → print 提示: 文件 X 属于活跃 session Y, 建议等待/串行
PY
```
