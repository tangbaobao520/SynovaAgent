## 2. 代码审计——现状

### 缺陷 A（P0-1）：loader 从不把 manifest 挂到哨兵对象

* `src/sentinel/sentinel-loader.ts:136` `registerLoadedSentinels()`：`const sentinelObj = mod[manifest.exportKey || 'default']`（L136）后直接 `sentinelObj.check(store, teamId, traversal)`（L205）——`manifest` 变量在作用域内但只用于 config，从不 `sentinelObj.manifest = manifest`。
* `extensions/sentinels/cash-runway/aggregate.ts:14`：`export const cashRunwaySentinel = { manifest: null as SentinelManifest | null, ... }` + `:28` `if (this.manifest) { ... }`（阈值 finding 全在这个 if 里）。`this.manifest` 恒 null → 阈值告警永不触发。
* `extensions/sentinels/revenue-health/aggregate.ts:11`：同款 `manifest: null` + `:50` `if (this.manifest)`（客户集中度/收入增长率阈值 finding 全在 if 里）。
* 现有测试盲区：`tests/sentinel/sentinel-loader.test.ts` 只覆盖 `loadSentinels()`/`getSentinelsByExpert()`，未覆盖 `registerLoadedSentinels()` 装配路径——manifest 未挂载因此漏检。
* 物理事实：`grep -rn "\.manifest =" src/` 全仓无 loader 侧赋值；K3 活运行 [A] 组（生产形态 manifest=null）findings=0。

### 缺陷 B（P1-1）：degraded 结果穿过阈值门控

* `extensions/sentinels/cash-runway/aggregate.ts:25` `const runwayMonths = runwayResult.value;` 后 `:30` `if (runwayMonths <= t.cash_runway_months.critical)`——没有先检查 `runwayResult.degraded`。compute 降级时 value 常为 0（≤ critical 6），一旦修好 P0-1 挂上 manifest，无数据场景会误报 critical 现金流危急（K3 活运行 [B] 组已证明）。
* `revenue-health/aggregate.ts` 的 growthResult 有 `!growthResult.degraded` 检查（合规样本），但 cash-runway 的 runway/overdue 两个阈值判断缺 degraded 拦截。

### 缺陷 C（P1-3）：capital-health 缺失字段默认为 0

* `extensions/sentinels/capital-health/aggregate.ts`：`await import('../_extinct/capital-efficiency/aggregate')` 等三处动态 import 退役子哨兵，直接 `findings.push(...r1, ...r2, ...r3)`。
* 子哨兵（`_extinct/capital-efficiency/aggregate.ts` 等）读 `props.revenue/totalRevenue/totalDebt/equity/operatingExpenses/taxRate` 等字段，缺失时 `Number(x) || 0` 兜底成 0（如 capital-efficiency `revenue: Number(n.props.revenue) || Number(n.props.totalRevenue) || 0`、`totalDebt: Number(n.props.totalDebt) || 0`），被当真实值产出 critical（K3 T3-a 实测：注入部分字段 → capital-health 产出 2 critical 误报）。

## 4.5 决策参考

* 决策点：capital-health 的 P1-3 是「逐 finding 守卫」还是「子哨兵显式返回 degraded + aggregate 汇总降级」？
* 参考系：第一性原理——缺字段就是数据不可用，不应被 Number(undefined)||0 兜底成真实 0；Anthropic 基线——降级要可观测（degraded 标记），不是静默改值；收敛——窄修（守卫）不重写 _extinct（重写是 D358）。
* 结论：采用「capital-health 入口字段完整性校验」——调用子哨兵前查 Financial 节点、校验必填字段，缺失即返回 degraded/跳过，不改 _extinct 子哨兵（重写是 D358）。完成报告必含本决策记录（K3 可核）。
