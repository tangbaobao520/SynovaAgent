# JTBD Phase 2 Part B2 — DIAGNOSE / PREDICT 因果信息需求推导

> 对去重后统一 JTBD 集中全部 DIAGNOSE 类和 PREDICT 类 U-JTBD，
> 逐一推导其因果信息需求，使用标准化语法表达。

---

## 元方法论：两类决策动词的认知特征

| 维度 | DIAGNOSE | PREDICT |
|------|----------|---------|
| 认知姿态 | 回溯归因——追溯因果链找到断裂点 | 前瞻外推——基于历史模式推演未来状态 |
| 核心信息需求 | 断裂检测 + 多边联合推理 | 趋势外推 + 时序基线 + 结构性断点检测 |
| 关键边参数 | AFFECTS（因果推断）、PRODUCES（产出异常）、BUYS_FROM（客户行为变化）、DEPENDS_ON（依赖断裂） | CUMULATIVE_LEARNING（历史模式）、PRODUCES（产能趋势）、FLOWS_TO（现金流预测） |
| 时间取向 | 回溯（现在异常→过去根因） | 前瞻（现在趋势→未来状态） |
| 核心假设 | 异常不是正常波动；因果链未被外部因素中断；根因在可观测系统内 | 历史模式延续；无结构性断点；趋势外推的有效性 |
| 错误代价 | 误诊（错误归因→错误干预→问题恶化） | 预判失败（高估→资源浪费；低估→错失窗口） |

### U-JTBD-0079 | DIAGNOSE | Customer | BUYS_FROM,AFFECTS
> 我需要诊断为什么A客户最近三个月下单量逐月下降，但我不确定是客户自身业务萎缩、客户找到了更便宜的替代供应商、还是我们上次交货延迟导致客户不满了。
> 等价变体 (4个): S1-JTBD-004, S1-JTBD-045, S3-JTBD-005, S4-JTBD-008
> 来源场景: S1, S3, S4

因果信息需求：

1. ND-079-A {需要[Customer][BUYS_FROM.下单量时序][最近12个月][按月聚合(订单数x订单金额)][vs 该客户历史12个月均值的Z-Score偏离度]}
   [前提假设: 下单量逐月下降不是季节性波动，下降幅度超过2sigma视为异常信号]
   [数据源覆盖度: 自动 -- ERP订单系统 + CRM客户档案 -- 涉及2个数据源]
   [时间约束: 周(小于1h)]

2. ND-079-B {需要[Customer][AFFECTS.客户业务健康指标][最近6个月][按客户聚合(公开财报/行业指数/同类客户群均值)][vs 该客户自身历史趋势]}

   [时间约束: 月(小于4h)]

3. ND-079-C {需要[Market][COMPETES_WITH.替代供应商竞争力][当前][按该客户品类枚举竞品报价与服务对比][vs 我方报价与服务水平]}
   [前提假设: 客户转投竞品一般有价格或服务驱动的可追溯原因]
   [数据源覆盖度: GA手工 -- 销售拜访记录 + 竞品情报 + 行业价格基准 -- 涉及3个数据源]
   [时间约束: 月(小于4h)]

4. ND-079-D {需要[Operation][PRODUCES.交货履约表现][最近6个月][按该客户聚合(准时率x质量合格率x投诉次数)][vs 全体客户同期均值]}
   [前提假设: 交货延迟或质量问题与客户流失之间存在可量化的滞后关系（滞后1-3个月）]
   [数据源覆盖度: 自动 -- 物流追踪 + 质量检验 + 客户投诉系统 -- 涉及3个数据源]
   [时间约束: 周(小于1h)]

5. ND-079-E {需要[Customer][AFFECTS.多因素归因权重][最近6个月][Shapley值分解(业务萎缩/竞品替代/履约不满/其他)][vs 预期各因素的先验贡献分布]}
   [前提假设: 四个因素的独立贡献可以近似分离，且交互效应在可接受范围内]
