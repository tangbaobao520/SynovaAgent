# JTBD Phase 2 Part C — DESIGN / CONTROL / NEGOTIATE 因果信息需求推导

> 对去重后统一 JTBD 集中全部 DESIGN 类、CONTROL 类和 NEGOTIATE 类 U-JTBD，
> 逐一推导其因果信息需求，使用标准化语法表达。

---

## 元方法论：三类决策动词的认知特征

| 维度 | DESIGN | CONTROL | NEGOTIATE |
|------|--------|---------|-----------|
| 认知姿态 | 构造新方案（空白画布） | 反馈闭环（监控→对比→纠偏） | 多方信息不对称下的博弈 |
| 核心信息需求 | 外部基准 + 内部约束 + 反事实模拟 | 实时基线 + 偏离检测 + 调节因子 | 对方底牌推断 + 备选方案比较 |
| 时间取向 | 未来导向（设计未来状态） | 实时/近实时（现在与目标的差距） | 双方时间窗口不对称 |
| 假设依赖 | 方案可行性的前提条件 | 基线是否稳定、偏差阈值 | 对方行为模型的假设 |
| 错误代价 | 设计锁定效应（改不动） | 控制滞后（错过纠偏窗口） | 信息不对称损失（让步过多或破裂） |

### U-JTBD-0059 | DESIGN | Customer | UNKNOWN
> 我需要决定私域会员等级体系的设计——分几级、每一级的权益和升级门槛怎么设，但我不确定不同权益（折扣/优先购/专属服务/积分翻倍）对不同客群的实际吸引力。
> 等价变体 (2个): S2-JTBD-044, S2-JTBD-048
> 来源场景: S2

因果信息需求：

1. ND-059-A {需要[Customer][SIGNAL_TRANSMITS.权益偏好强度][过去12个月][按客群分位聚合(P25/P50/P75)][vs 无权益基线组]}
   [前提假设: 不同客群对权益类型的偏好差异足够大（组间差异 > 组内差异），分层设计才有意义]
   [数据源覆盖度: 自动 — 会员系统交易记录 + 优惠券核销数据 + 积分兑换日志 — 涉及3个数据源]
   [时间约束: 周(<1h) — 历史聚合一次，月度刷新]

2. ND-059-B {需要[Customer][METRIC_BINDS.权益弹性系数][过去12个月][按权益类型×客群分组计算][vs 行业分位基准]}
   [前提假设: 权益弹性 = △客单价/△折扣成本，且弹性在不同客群间稳定可测]
   [数据源覆盖度: 企业补充 — 历史促销数据 + A/B测试结果 + 行业品类通用弹性参考 — 涉及2个数据源 + 1个外部参考]
   [时间约束: 月(<4h) — 需要A/B测试周期]

3. ND-059-C {需要[Customer][FLOWS_TO.升级门槛敏感性][过去24个月][按当前等级聚合][vs 同品类竞品会员体系基准]}
   [前提假设: 升级门槛与复购频率之间存在可量化的关系，太高导致放弃、太低导致成本浪费]
   [数据源覆盖度: 自动 — 会员升级行为日志 + 消费频次分布 + 放弃升级节点记录 — 涉及2个数据源]
   [时间约束: 月(<4h)]

4. ND-059-D {需要[Market][COMPETES_WITH.竞品会员设计参数][当前][枚举映射][vs 自身设计方案的差异化得分]}
   [前提假设: 竞品的会员体系设计是否成功可通过其会员活跃率和公开财报推断]
   [数据源覆盖度: GA手工/公开 — 竞品官网 + 行业报告 + 第三方会员对比工具 — 涉及3个数据源]
   [时间约束: 月(<4h) — 竞品监测定期更新]

5. ND-059-E {需要[Product][PRODUCES.会员等级模型反事实模拟][模拟期12个月][蒙特卡洛][vs 现状基线]}
   [前提假设: 客户对等级变更的行为响应可被历史弹性和替代弹性近似建模]
   [数据源覆盖度: 企业补充 — 历史弹性参数 + 模拟引擎 — 涉及2个数据源]
   [时间约束: 月(<4h) — 模拟计算]

中层可控性：2 — 可设计等级参数，但客户反应不可控
可行动性映射：输出"N级M权益"方案矩阵（每个方案含预期活跃率、成本、竞品差异度）
主动触发器标记：当某客群复购频率连续3个月下降 > 15% 时触发会员体系重设计告警
决策反馈闭环需求：追踪"方案上线后6个月内的升级完成率、活跃率变化、权益成本变化"

### U-JTBD-0060 | DESIGN | Customer | PRODUCES,FLOWS_TO
> 我需要建立一套统一的"客户分级标准"——销售按营收排名、财务按利润排名、生产按"好不好做"排名。三个排名矛盾时，到底听谁的？
> 来源场景: S4

因果信息需求：

1. ND-060-A {需要[Customer][PRODUCES.营收贡献][过去12个月][按客户聚合∑订单金额][无基准，输出排名分布]}
   [前提假设: 营收贡献 = 发票金额 - 退货 - 折扣，且历史数据完整]
   [数据源覆盖度: 自动 — ERP销售模块 + 财务系统应收 — 涉及2个数据源]
   [时间约束: 周(<1h)]

2. ND-060-B {需要[Customer][PRODUCES.利润贡献][过去12个月][按客户聚合∑(营收 - 完全分摊成本)][vs 公司平均利润率]}
   [前提假设: 完全分摊成本可分配到客户级别（直接成本 + 按驱动因素分摊的间接成本）]
   [数据源覆盖度: 企业补充 — 成本核算系统 + 物流/仓储分客户成本数据 — 涉及3个数据源]
   [时间约束: 月(<4h)]

3. ND-060-C {需要[Customer][COUPLES.生产难度评分][过去12个月][按客户聚合(平均换模次数/min订单量/特殊工艺占比)][标准化为0-1难度指数]}
   [前提假设: "好不好做"可量化为可测量的生产参数组合]
   [数据源覆盖度: 自动 — MES生产执行系统 + 工艺BOM数据 — 涉及2个数据源]
   [时间约束: 月(<4h)]

4. ND-060-D {需要[Customer][PRODUCES.综合价值评分][过去12个月][加权聚合(营收×w1 + 利润×w2 + 战略重要性×w3 - 难度×w4)][vs 行业同规模客户基准]}
   [前提假设: 权重w1-w4由管理层通过AHP层次分析法设定，且战略重要性可被量化（如:是否旗舰客户、是否新市场入口）]
   [数据源覆盖度: 企业补充 — 三个维度的基础数据 + 管理层权重输入 — 涉及4个数据源]
   [时间约束: 月(<4h)]

5. ND-060-E {需要[Operation][FLOWS_TO.产能占用率][过去12个月][按客户聚合∑生产工时占比][vs 该客户营收占比的差值]}
   [前提假设: 产能占用 vs 营收贡献的失衡是可识别的分级矛盾根源]
   [数据源覆盖度: 自动 — MES工时记录 + 排产系统 — 涉及2个数据源]
   [时间约束: 周(<1h)]

中层可控性：2 — 可设计算法和权重，但最终分级标准的采纳需要跨部门协商
可行动性映射：输出"三维排名 + 综合评分 + 矛盾客户突出展示"的仪表板，支持权重滑块调整
主动触发器标记：当某个客户的营收排名与利润排名的差值 > 20个百分位时触发告警
决策反馈闭环需求：追踪"分级标准上线后不同部门对排名的争议率变化、大客户决策一致性"

### U-JTBD-0058 | DESIGN | Channel | BUYS_FROM,AFFECTS,COMPETES_WITH
> 我需要判断是否该采用产品驱动增长（PLG）模式作为销售驱动增长（SLG）的补充——我们一直是SLG为主，但竞品通过"免费试用+自助升级"拿走了我们很多中小客户。我不确定我们的产品是否适合PLG（上手门槛有多高？自助购买意愿有多强？），以及PLG会不会蚕食我们的SLG价格体系。
> 来源场景: S6

因果信息需求：

1. ND-058-A {需要[Customer][CONSUMES.自助上手成功率][过去12个月][初次使用后7天/14天/30天留存][vs SLG引导客户的同期留存率]}
   [前提假设: "自助上手成功率"可以用"未接触任何销售/CSM人员的用户在关键激活事件完成率"来测量]

   [时间约束: 周(<1h)]

2. ND-058-B {需要[Customer][BUYS_FROM.自助购买意愿强度][过去12个月][按客群规模分组(1-10/11-50/51-200人)][vs 行业PLG标杆(如Slack/Figma)同类指标]}
   [前提假设: 自助购买意愿 = 官网注册后72h内自行完成付费转化的比例]
   [数据源覆盖度: 自动 — 支付系统 + 用户行为日志 — 涉及2个数据源]
   [时间约束: 周(<1h)]

3. ND-058-C {需要[Customer][COMPETES_WITH.竞品PLG侵蚀率][过去24个月][按季度聚合"从我方流失且转向PLG竞品"的客户数][vs 总流失数占比]}

   [数据源覆盖度: GA手工 — CRM流失记录 + 竞品情报 + 客户访谈 — 涉及3个数据源]
   [时间约束: 月(<4h)]

4. ND-058-D {需要[Product][AFFECTS.PLG/SLG价格套利风险][模拟][按客户规模分组][vs 当前ASP(平均售价)]}
   [前提假设: PLG定价低于SLG定价时，SLG客户会主动寻找套利路径（如先用个人账户试用PLG再合并到企业版）]
   [数据源覆盖度: 企业补充 — 当前价格表 + 竞品PLG价格 + 客户行为数据 — 涉及3个数据源]
   [时间约束: 月(<4h)]

5. ND-058-E {需要[Product][COUPLES.PLG适配度评分][当前][枚举评分(Time-to-Value/Self-Serve Completeness/Viral Coefficient/Product-Qualified Lead Rate)][vs PLG成熟度模型各阶段基准]}
   [前提假设: PLG适配度可被分解为可测量的4个维度子指标]
   [数据源覆盖度: 自动/GA手工 — 产品分析 + 用户旅程数据 — 涉及2个数据源 + 外部基准参考]
   [时间约束: 月(<4h)]

6. ND-058-F {需要[Operation][AFFECTS.混合GTM模式模拟][模拟未来12个月][方案对比(SLG-only vs PLG-only vs SLG+PLG)][按ARR/CAC/NDR/NPS四维比较]}
   [前提假设: PLG对SLG的蚕食效应在第一年内呈现，且可被增量客户的总价值抵消]
   [数据源覆盖度: 企业补充 — 销售数据 + 产品数据 + 财务模型 — 涉及4个数据源]
   [时间约束: 月(<4h) — 模拟计算]

中层可控性：2 — 可决策是否启动PLG，但PLG成功取决于产品本质适配度（非意志可控）
可行动性映射：输出"PLG适配度诊断报告 + 混合GTM模拟对比 + 启动条件清单"
主动触发器标记：当竞品PLG侵蚀率连续2个季度 > 15% 时触发PLG启动必要性告警
决策反馈闭环需求：追踪"PLG启动后12个月的PLG自助转化率、SLG ASP变化、总ARR变化"

### U-JTBD-0065 | DESIGN | Product | COMPETES_WITH
> 我需要决定产品配方/包装升级的时间窗口，但我不确定老版本库存消化需要多久，以及升级期间消费者是否会因为"新旧版本交替"而转向竞品。

   [前提假设: 历史月均销量是未来消化速度的合理预测，且促销降价可加速消化但影响毛利率]
   [数据源覆盖度: 自动 — WMS仓库管理系统 + ERP库存模块 — 涉及2个数据源]
   [时间约束: 实时(<5s)]

2. ND-065-B {需要[Market][COMPETES_WITH.竞品替代风险][过渡期(新旧版本共存窗口)][枚举(竞品同期促销/竞品新品发布/竞品价格变动)][vs 自身过渡期的品牌搜索量变化]}
   [前提假设: 品牌搜索量下降 > 20% 意味着消费者已开始转向竞品]
   [数据源覆盖度: GA手工/公开 — 电商平台竞争情报工具 + 百度/淘宝搜索指数 — 涉及2个数据源]
   [时间约束: 周(<1h) — 过渡期内高频监控]

3. ND-065-C {需要[Customer][BUYS_FROM.版本交替期间流失率模型][历史同类升级事件][按客群×渠道分组聚合][vs 无升级的正常期流失率基线]}

   [时间约束: 月(<4h)]

4. ND-065-D {需要[Channel][CONSUMES.渠道库存分配方案模拟][模拟未来3-6个月][按渠道×区域分配新旧版本库存比例][vs 各渠道缺货率和积压率预测]}

   [数据源覆盖度: 企业补充 — 渠道销售预测 + 库存数据 + 历史铺货数据 — 涉及3个数据源]
