# 场景3 JTBD穷举：制造·中小 (20-99人)

> OEM/ODM代工厂。微信+Excel管理全厂。利润极薄，靠量生存。
> 中层不是"经理"——是高级执行者。但他们的判断同样决定工厂生死。

---

## 角色编号速查

| 角色编号 | 角色名称 | 核心职责 |
|---------|---------|---------|
| R1 | 厂长 / 生产经理 | 车间全面管理：排期、质量、设备、工人 |
| R2 | 跟单员（客户对接） | 接收订单、确认交期、跟踪进度、处理客诉 |
| R3 | 采购 | 原材料采购、供应商询价、成本控制 |
| R4 | 质检主管 | 来料检验、过程检验、出货检验 |
| R5 | 财务（外包/兼职） | 记账报税、工资发放、应收应付 |

---

## 一、厂长 / 生产经理 (R1) 的 JTBD

> 厂长80%时间在现场救火。核心困境：工厂状态对他半透明——只能通过"车间走一圈"感知情况。

### 1.1 预测型 (PREDICT)

**S3-JTBD-001**
> "我需要预测未来两周的产能是否够交付在手订单，但我不确定各产线的实际产能利用率、工人出勤率、以及设备可用状态。"

| 字段 | 值 |
|------|-----|
| JTBD类型 | 预测型 (PREDICT × Operation) |
| 执行角色 | R1 厂长 |
| 频率 | 每周 |
| 重要性 | 5 |
| 中层可控性 | 3 — 排期调整、加班安排、外包决定，完全在厂长权限内 |
| 可行动性 | 高 — 提前发现产能缺口，可在交期到期前安排加班/外发/与客户协商延期 |
| 数据可得性 | 需GA手工采集 — 产线利用率需从Excel工单手工推算，设备状态靠人工巡检记录，无实时数据源 |
| 对应盲区 | 盲区2：产能利用率 |

**S3-JTBD-002**
> "我需要预测这批原材料的市场价格走势，决定是现在锁价还是再等两周，但我不确定价格波动的历史规律和供需变化信号。"

| 字段 | 值 |
|------|-----|
| JTBD类型 | 预测型 (PREDICT × Resource) |
| 执行角色 | R1 厂长 / R3 采购 |
| 频率 | 月度（大宗）/ 按需（急单） |
| 重要性 | 4 |
| 中层可控性 | 2 — 采购时机决策可影响，但市场价格本身不可控 |
| 可行动性 | 中 — 可决定采购时机和采购量，但价格预测本身有不确定性 |
| 数据可得性 | 需企业补充数据 — 无历史采购价格数据库，无供应商报价系统归档。当前全靠采购员个人记忆和微信聊天记录。 |
| 对应盲区 | 盲区4：原材料囤货时机 |

**S3-JTBD-003**
> "我需要预测下个月可能有多少新订单进来，但我不确定老客户的续单概率、新客户的意向转化率，以及行业淡旺季规律。"

| 字段 | 值 |
|------|-----|
| JTBD类型 | 预测型 (PREDICT × Customer) |
| 执行角色 | R1 厂长 / R2 跟单员 |
| 频率 | 月度 |
| 重要性 | 5 |
| 中层可控性 | 1 — 订单由客户决定，中层只能通过客户关系维护间接影响 |
| 可行动性 | 中 — 可提前调整原材料采购和人员排班，但预测本质上高度不确定 |
| 数据可得性 | 需GA手工采集 — 客户历史下单记录在微信聊天里。无CRM系统。需跟单员凭记忆和翻聊天记录手工整理。 |
| 对应盲区 | 盲区3：大客户会不会跑 |

### 1.2 诊断型 (DIAGNOSE)

**S3-JTBD-004**
> "我需要诊断B产线这周不良率为什么突然从3%跳到8%，但我不确定是工人操作问题、某批材料问题、还是设备参数漂移。"

| 字段 | 值 |
|------|-----|
| JTBD类型 | 诊断型 (DIAGNOSE × Product) |

| 频率 | 按需（异常触发） |
| 重要性 | 5 |
| 中层可控性 | 3 — 根因确定后可直接干预：换人/换料/调设备/改工艺 |
| 可行动性 | 极高 — 定位根因即可立即纠正，每延迟一天多产出一批不良品 |
| 数据可得性 | 需GA手工采集 — 不良品数据在质检员的手写本上。工人排班表和材料批次号需要从Excel和纸质工单中手工关联。设备参数无记录。 |
| 对应盲区 | 盲区5：质量根因分析 |

**S3-JTBD-005**
> "我需要诊断为什么A客户最近三个月下单量逐月下降，但我不确定是客户自身业务萎缩、客户找到了更便宜的替代供应商、还是我们上次交货延迟导致客户不满了。"

| 字段 | 值 |
|------|-----|
| JTBD类型 | 诊断型 (DIAGNOSE × Customer) |
| 执行角色 | R2 跟单员 / R1 厂长 |
| 频率 | 季度（或异常触发） |
| 重要性 | 5 |
| 中层可控性 | 2 — 若是质量问题或交期问题可改善；若是客户业务萎缩则不可控 |
| 可行动性 | 高 — 定位原因后可针对性补救：降价、改善交期、增加沟通频次 |
| 数据可得性 | 需GA手工采集 — 客户下单数据在微信聊天记录里。没有客户沟通历史归档。跟单员凭记忆判断"客户态度变化"。 |
| 对应盲区 | 盲区3：大客户会不会跑 |

**S3-JTBD-006**
> "我需要诊断这个月实际利润为什么比预期低了40%，但我不确定是原材料涨价吃掉了利润、某个订单算错了报价、还是不良品返工成本超了。"

| 数据可得性 | 需企业补充数据 — 当前无订单级成本核算。料+工+费分摊全靠估计。需先建立成本归集机制。 |
| 对应盲区 | 盲区1：订单真实利润 |

**S3-JTBD-007**
> "我需要诊断为什么最近交货延迟的比例从10%上升到30%，但我不确定是排期太满、某个产线效率下降、还是原材料到货延迟。"

| 字段 | 值 |
|------|-----|

| 可行动性 | 高 — 定位瓶颈后可调整排期、调配工人、加速采购 |
| 数据可得性 | 需GA手工采集 — 交期记录在Excel或微信里。延迟原因需手工追溯——问跟单员、问车间主任、问采购。 |
| 对应盲区 | 盲区2：产能利用率、盲区5：根因追踪 |

**S3-JTBD-008**
> "我需要诊断最近三个月工人流动率为什么突然升高，但我不确定是工资太低、加班太多、还是隔壁工厂在挖人。"

| 字段 | 值 |
|------|-----|

| 数据可得性 | 需GA手工采集 — 离职原因无人系统记录。靠离职面谈（口头）和车间主任反馈。附近工厂工资水平需人工打听。 |
| 对应盲区 | 画像识别：工人流动性大 |

**S3-JTBD-009**
> "我需要决定今天三条产线的工人怎么分配，但我不确定每条产线今天的实际任务量和工人技能匹配度。"

| 对应盲区 | 盲区2：产能利用率 |

**S3-JTBD-010**
> "我需要决定这个月有限的现金流应该优先付给哪个供应商、延迟付给哪个，但我不确定每个供应商的催款紧迫度、断供风险、以及我们各自的依赖关系。"

| 字段 | 值 |
|------|-----|

| 对应盲区 | 画像识别：现金流管理 |

**S3-JTBD-011**
> "我需要决定是否值得给A大客户降价5%来保住这个订单，但我不确定这个客户现在的真实利润贡献、降价后还能不能覆盖固定成本、以及丢了A客户的后果有多大。"

| 字段 | 值 |
|------|-----|
| JTBD类型 | 干预型 (ALLOCATE × Customer) |
| 执行角色 | R1 厂长 / R2 跟单员 |
| 频率 | 按需（客户压价时） |
| 重要性 | 5 |
| 中层可控性 | 2 — 定价策略可调整，但客户接受度不确定 |
| 可行动性 | 中 — 知道真实利润才能做理性降价决策，否则只是"怕丢客户"的恐惧驱动 |
| 数据可得性 | 需企业补充数据 — 当前不知道每个客户/每个订单的真实利润。需要建立成本归集和客户利润核算。 |
| 对应盲区 | 盲区1：订单真实利润、盲区3：客户健康度 |

## 二、跟单员 (R2) 的 JTBD

> 跟单员是工厂与外部世界的唯一信息接口。客户关系全靠个人维护。客户流失往往"突然发生"——其实早有信号。

### 2.1 预测型 (PREDICT)

**S3-JTBD-019**
> "我需要预测这批货能不能在承诺交期内完成，但我不确定当前生产进度到哪了、有没有产线异常会影响交期、以及有没有其他急单插队。"

| 字段 | 值 |
|------|-----|
| JTBD类型 | 预测型 (PREDICT × Operation) |
| 执行角色 | R2 跟单员 |
| 频率 | 每日（每个在途订单） |
| 重要性 | 5 |
| 中层可控性 | 1 — 跟单员只能跟踪和催促，不能直接调整排期 |
| 可行动性 | 中 — 提前发现延期风险可提前通知客户，减少违约损失和信任损耗 |
| 数据可得性 | 需GA手工采集 — 当前做法：去车间看一眼、问班组长、翻Excel工单。进度信息分散在多个人的脑子里。 |

## 六、跨角色协同 JTBD

> 以下JTBD需要两个以上角色同时协同才能完成。在中型制造企业中，这些协同决策往往靠"微信群里喊一声"——信息不全、时效性差、责任不清。

### 7.6 按数据可得性分布

| 可得性 | 数量 | 占比 | 典型JTBD |
|--------|------|------|---------|
| 需GA手工采集 | 25 | 52.1% | 跟单进度追踪、质量数据关联、库存水位监控——数据存在但分散在Excel/微信/脑子里 |
| 需企业补充数据 | 23 | 47.9% | 订单级成本核算、客户利润分析、供应商绩效评估、价格预测——数据根本不存在 |
| 自动可得 | 0 | 0% | 无。中小制造没有任何系统能自动提供数据。 |

### 7.7 关键发现

1. **数据可得性是最大瓶颈。** 零个JTBD可以"自动可得"满足。52%需要GA手工从分散的Excel/微信/手写本中采集和整合，48%需要企业从零建立数据采集机制。Synova要服务这个场景，GA（数据采集代理）的角色远比compute函数重要——没有数据，再好的算法也没用。

2. **可控性与重要性倒挂。** 45.8%的JTBD重要性为5（生死攸关），但同样45.8%的JTBD中层可控性仅为1（只能预警不能决策）。这意味着系统价值主要体现在"让中层看到问题"而非"让中层解决问题"——预警功能占比极高。

3. **财务角色的潜力被严重低估。** 当前财务只做税务合规，但S3-JTBD-039到S3-JTBD-044显示财务可以是成本洞察和现金流预警的核心角色。激活这个角色不需要换人——只需要给现有财务（即使是外包）更好的数据整合工具。

4. **盲区1（订单真实利润）贯穿7个JTBD。** 这是中小制造的根本性信息盲区——定价靠同行参考、利润靠老板直觉。解决这个盲区会联动改善报价决策、客户选择、成本控制等多个JTBD。

5. **跨角色协同JTBD本质上是"信息汇合"问题。** 四个协同JTBD的共同模式：三个角色各掌握一块信息，但无人有完整视图。当前靠"微信群里喊一声"协同——Synova的干预点在于提供一个三方可共享的实时信息面板。
