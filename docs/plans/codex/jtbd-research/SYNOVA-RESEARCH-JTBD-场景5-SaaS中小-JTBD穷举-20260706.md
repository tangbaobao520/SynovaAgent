# 场景5 JTBD穷举 — SaaS·中小（20-99人）

> 垂直/工具型SaaS，ARR 1000万-2亿，工程师文化。产研与GTM之间数据断裂——自研DB、CRM、埋点、CS、财务五套独立数据体系。

**JTBD**: "我需要决定技术债偿还的优先级顺序，但我不确定哪些模块的技术债对研发效率的拖累最大。"

| 字段 | 值 |
|------|-----|
| JTBD类型 | 诊断型 + 干预型 |
| 执行角色 | CTO/工程VP, 工程经理/Tech Lead |
| 频率 | 月度 |
| 重要性 | 5 |
| 中层可控性 | 3（CTO可直接决策重构优先级） |
| 可行动性 | 高——分配重构Sprint到具体模块 |
| 数据可得性 | 中低——需要Jira（story point完成速度趋势）+ GitHub（PR review延迟、代码churn）+ 线上故障率。三个源的数据需手工整合，中小SaaS通常没有工程效能平台。 |
| 跨角色协同标记 | 需与CPO协调Roadmap取舍（"修技术债 vs 做新功能"的Sprint分配） |
