# JTBD 穷举 — 场景6：SaaS · 中大（100-499人）

> Platform/General SaaS, ARR 3B-20B+, listed or Pre-IPO, multi-product BU structure,
> data middle platform built but metric calibers inconsistent — "too much data, don't know which to trust."

## 场景速览

| 维度 | 描述 |
|------|------|
| 核心业务 | 平台型/通用型SaaS，多产品线BU制，ARR 3-20亿+ |
| 组织架构 | 成熟BU制，各BU独立P&amp;L，共享技术/数据中台 |
| 增长阶段 | 增长→效率转型期，资源分配政治化，组织熵增 |
| 团队特征 | 职业经理人主导，"老员工"与"空降高管"文化融合 |
| 核心数据矛盾 | 数据中台有数百张表但指标口径打架——"数据太多不知信哪个" |
| 核心盲区 | 产品线真实健康度 / Win-Loss分析 / 组织效率熵增 / 定价弹性 / 资源机会成本 |

## 角色清单 (10)

1. BU GM / 事业部总经理
2. 产品VP
3. 工程VP / 平台架构师
4. 销售VP
5. 客户成功VP
6. 增长VP / CMO
7. CFO / 财务VP
8. HR VP / CPO
9. 数据VP / 数据中台负责人
10. 安全与合规负责人

## JTBD 穷举
---

### S6-JTBD-001

**语句:** 我需要决定三条产品线之间的工程师资源如何分配，但我不确定每条产品线的真实边际贡献率和增长弹性——财务口径、产品后台口径、销售口径的ARR增速相差8个百分点。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 干预型 (ALLOCATE × Product) |
| 执行角色 | BU GM, 产品VP, 工程VP |
| 频率 | 季度（每季度资源复盘时）+ 事件驱动（新产品线启动申请时） |
| 重要性 | 5 — 资源分配是大SaaS最核心的战略决策，分错=增长失速+人才流失 |
| 中层可控性 | 2 (BU GM可调整本BU内分配，跨BU分配需CEO/董事会) |
| 可行动性 | 高 — 明确各产品线的边际ARR/工程师比后，可立即调整Roadmap优先级和headcount分配 |
| 数据可得性 | 困难 — 三套系统三套口径（财务ASC 606递延收入确认 vs 产品后台实际消费 vs 销售签约ARR），需要统一口径层 |
| 跨角色协同标记 | 是 — BU GM发起，需产品VP提供Roadmap影响分析，工程VP提供技术债务约束，CFO提供财务口径验证 |

### S6-JTBD-002

**语句:** 我需要判断产品线B是否已经进入衰退期应该缩减投入，但我不确定它的NDR下降是暂时的竞品冲击还是结构性需求转移——CS团队说"客户关系很好"，数据中台却显示健康度持续走低。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 诊断型 (DIAGNOSE × Product) |
| 执行角色 | BU GM, 产品VP, 客户成功VP |
| 频率 | 季度 + NDR连续两季下滑时触发 |
| 重要性 | 5 — 错误判断导致砍错产品（丧失市场）或死不砍（沉没成本持续扩大） |
| 中层可控性 | 1 (BU GM可提出建议，但产品线裁撤需CEO/董事会批准) |
| 可行动性 | 高 — 诊断清楚后可制定"观察期+关停线"机制（如连续3季度NDR<85%则启动退出流程） |
| 数据可得性 | 中等 — NDR、续约率、客户健康度数据存在，但CS主观判断与系统指标冲突；需要按客群切片的流失原因分类（竞品替代/预算削减/不再需要/功能不满） |
| 跨角色协同标记 | 是 — BU GM × 产品VP × CS VP × CFO（财务口径NDR确认）三方数据对不齐是常态 |

### S6-JTBD-003

**语句:** 我需要评估本BU是否应该在下一财年申请新增30%的headcount，但我不确定当前团队的人均ARR是否在行业合理区间内——HR给的benchmark是去年数据，中台的人效看板和财务报表差了15%。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 干预型 (ALLOCATE × Resource/人力) |
| 执行角色 | BU GM, HR VP, CFO |
| 频率 | 年度（预算季）+ 半年度复盘 |
| 重要性 | 4 — 过度扩张→人效崩盘；扩张不足→增长天花板。大SaaS上市公司核心指标 |
| 中层可控性 | 2 (BU GM可提案，但预算批准需CFO+CEO) |
| 可行动性 | 中高 — 需要按职能（产研/销售/CS）拆解人均产出趋势，明确"新增人头预计带来的ARR增量" |
| 数据可得性 | 困难 — headcount数据（HR系统）与ARR数据（财务/CRM）口径不一致；行业benchmark缺失（上市公司不公开人效按BU拆的数据） |
| 跨角色协同标记 | 是 — BU GM × HR VP × CFO — 典型的三方数据打架场景 |

### S6-JTBD-004

**语句:** 我需要决定大客户A的续约折扣底线——给到7折能不能保住这个占总收入3%的客户，但我不确定客户真实流失概率和竞品报价。CSM说"客户满意"，但系统上该客户过去60天工单量飙升了3倍。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 干预型 (NEGOTIATE × Customer) |
| 执行角色 | BU GM, 销售VP, 客户成功VP |
| 频率 | 事件驱动（大客户续约前60天） |
| 重要性 | 5 — 3%收入客户流失→财报miss→股价暴跌（上市公司的硬约束） |
| 中层可控性 | 3 (BU GM可直接决策续约折扣，除非超过授权线) |
| 可行动性 | 高 — 基于客户行为信号（工单量、产品使用频率下降、决策人变更）的续约风险定价模型，直接输出建议折扣区间 |
| 数据可得性 | 中等 — 产品使用数据 + CS工单数据 + CRM沟通记录三者存在，但未联动建模；竞品报价需销售手工收集 |
| 跨角色协同标记 | 是 — CS VP提供健康度信号，销售VP提供竞品情报和关系评估，BU GM做最终折扣决策；CFO需确认对ARR确认的影响 |

| 字段 | 值 |
|------|-----|
| JTBD类型 | 诊断型 (DIAGNOSE × Resource/人力) |
| 执行角色 | BU GM, 销售VP, CFO |
| 频率 | 月度 |
| 重要性 | 4 — 大SaaS从"增长优先"到"效率优先"转型期的核心效率指标 |

| 可行动性 | 高 — 诊断到具体问题（新人培训不足？优质线索分配不均？某区域市场饱和？）后可直接调整 |
| 数据可得性 | 中等 — CRM有完整漏斗数据，但需要按入职月份cohort分析、按销售个体做归因，当前BI只看团队总量 |

### S6-JTBD-006

**语句:** 我需要预测下个季度的ARR能否达到董事会预期（QoQ +8%），但我不确定当前的Pipeline转化率是不是虚高——销售为了冲季度目标把"口头承诺"标成了"预算已批"。历史数据显示每季度最后一月有40%的Pipeline魔幻消失。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 预测型 (PREDICT × Resource/收入) |
| 执行角色 | BU GM, 销售VP, CFO |
| 频率 | 月度（滚动预测）+ 季末close前30天（周度） |
| 重要性 | 5 — 上市公司季报miss=股价暴跌+分析师降级+董事会问责 |
| 中层可控性 | 1 (BU GM无法改变Pipeline质量，只能通过加大线索量和加速close来补救) |
| 可行动性 | 中 — 预测本身不解决问题，但准确预测可以触发提前干预（如追加营销预算、调整折扣策略、向董事会预警） |
| 数据可得性 | 中等 — CRM Pipeline数据存在，但数据质量和销售行为挂钩；需要历史Pipeline→Close的转化模式+阶段滞留时长异常检测 |
| 跨角色协同标记 | 是 — 销售VP提供Pipeline自评，财务VP做保守估计，BU GM做最终判断→三方口径无一相同 |

### S6-JTBD-007

**语句:** 我需要判断今年该不该启动国际化（东南亚/日本）——CEO在董事会上承诺了"国际化战略"，但我不确定现有产品对海外市场的适配成本、当地合规风险和真实TAM。咨询公司给的报告和公司内部测算差了3倍。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 预测型 + 干预型 (EVALUATE × Market / ALLOCATE × Market) |
| 执行角色 | BU GM, 产品VP, 增长VP, CFO |
| 频率 | 年度（战略规划季） |
| 重要性 | 5 — 国际化是大SaaS的第二增长曲线，失败成本巨大（至少烧2年×50人=1亿+） |
| 中层可控性 | 0 (最终决策在CEO/董事会，中层提供分析输入) |
| 可行动性 | 中 — 明确"进入成本/合规成本/本地化成本/预期ARR回收期"后，可为董事会提供清晰的"Go/No-Go标准" |
| 数据可得性 | 困难 — 海外市场数据依赖第三方报告和竞品公开财务；内部无海外运营历史数据；合规成本需法务手动评估 |
| 跨角色协同标记 | 是 — 六个角色卷入（BU GM/产品VP/工程VP/增长VP/CFO/安全合规）——最大的跨角色协同JTBD |

### S6-JTBD-008

**语句:** 我需要决定产品A的定价是否应该从"按用户数"改为"按用量"——销售说大客户天天抱怨按用户贵，但我不确定Packaging变更会如何影响净收入留存率（NDR）和中小客户的流失。定价委员会开了三次会没结论。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 干预型 (DESIGN × Product) |
| 执行角色 | BU GM, 产品VP, 销售VP, 增长VP, CFO |
| 频率 | 年度（或竞争态势剧变时） |
| 重要性 | 5 — 定价是SaaS利润结构最敏感的一根杠杆，调错=收入降10%+客户关系受损 |
| 中层可控性 | 2 (BU GM可在本产品线定价范围内调整Packaging，跨产品线打包需CEO/定价委员会) |
| 可行动性 | 中高 — 基于客户分层（大/中/小）的用量分布+价格弹性模拟，但模型结果需要小范围A/B测试验证 |
| 数据可得性 | 困难 — 缺少历史定价变更数据（因为从未改过）；需要推算不同客群的用量分布和价格敏感度；竞品定价需销售手工收集 |
| 跨角色协同标记 | 是 — 定价委员会（多VP参与），销售VP关心打单难度，CS VP关心续约影响，CFO关心收入确认，产品VP关心用户行为变化 |

| 字段 | 值 |
|------|-----|

| 中层可控性 | 1 (BU GM可提案，但并购需CEO/董事会批准) |
| 可行动性 | 中 — 自建成本可量化（工程师·月×单价），但并购的整合风险和隐性成本难以量化 |

| 跨角色协同标记 | 是 — BU GM × 产品VP × 工程VP × CFO（并购财务建模）× 安全合规（技术尽调） |

### S6-JTBD-013

| 数据可得性 | 中等 — 财务系统有历史现金流数据；未来现金流的预测依赖收入预测和成本预测的准确性——这两个预测本身就不准确 |
| 跨角色协同标记 | 是 — CFO × CEO × 各BU GM — CFO做模型，CEO做优先级决策，BU GM承担成本控制责任 |

### S6-JTBD-056

**语句:** 我需要评估各个产品线的工程团队交付质量是否在持续恶化——近半年线上P0事故从每月1次增加到每月4次。但我不确定是代码质量下降、测试覆盖不足、发布流程有漏洞、还是系统复杂度自然增长导致的。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 诊断型 (DIAGNOSE × Operation/工程质量) |
| 执行角色 | 工程VP, BU GM |
| 频率 | 月度（工程健康度review） |
| 重要性 | 4 — 线上故障频率是大SaaS工程质量的硬指标。趋势性恶化=系统信任崩塌+客户投诉+合规风险 |
| 中层可控性 | 3 (工程VP可直接调整测试策略、发布流程、on-call机制) |
| 可行动性 | 高 — 需要故障的RCA（root cause analysis）分类统计（代码逻辑错误/配置错误/容量不足/依赖服务故障/发布流程问题）+ 各分类的趋势变化 |
| 数据可得性 | 中等 — 监控系统和on-call工具有故障数据；RCA通常在事后文档中（非结构化）；代码质量指标（如测试覆盖率/Cyclomatic Complexity）可从CI/CD系统提取 |
| 跨角色协同标记 | 否 — 工程VP主责，但故障影响会传导到CS VP（客户投诉）和BU GM（收入影响） |

### S6-JTBD-057

**语句:** 我需要决定产品生命周期各阶段的资源投入标准——新产品从"孵化"到"成长"到"成熟"到"衰退"，每个阶段该配置多少工程师/多少营销预算/什么样的组织形态？现在每个BU GM凭感觉定，导致有些产品过早获得了太多资源，有些产品被过早放弃。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 干预型 (DESIGN × Product/生命周期管理) |
| 执行角色 | 产品VP, BU GM, CFO |
| 频率 | 年度（产品组合管理策略制定） |
| 重要性 | 4 — 没有标准化的生命周期管理=资源分配全靠政治。这是S6-JTBD-001（资源分配）的上游制度设计 |
| 中层可控性 | 2 (产品VP可制定框架提案，需BU GM和CEO批准) |
| 可行动性 | 中 — 需要定义各生命周期阶段的客观判定标准（基于ARR增速/NDR/市场份额/竞争强度）+ 各阶段的资源配置区间 |
| 数据可得性 | 中等 — 各产品线的ARR/NDR/市场份额数据可获取；但"什么阶段配多少资源"的最佳实践需要在行业中benchmark——公开数据有限 |
| 跨角色协同标记 | 是 — 产品VP制定框架，各BU GM执行（框架限制BU GM的自由度→政策博弈） |

### S6-JTBD-058

**语句:** 我需要判断公司文化是否在从"创业者文化"滑向"大公司病"——员工开始说"这不是我的KPI"、"等领导批了再说"。但我不知道这种话语的蔓延速度、以及它对创新速度的真实影响。HR VP和文化委员会应该做什么？

| 字段 | 值 |
|------|-----|
| JTBD类型 | 诊断型 (DIAGNOSE × Operation/组织文化) |
| 执行角色 | HR VP, CEO (间接), BU GM |
| 频率 | 年度（文化健康度诊断） |
| 重要性 | 3 — 文化是大SaaS长期竞争力的根基，但诊断和干预的手段极其有限 |
| 中层可控性 | 1 (HR VP可诊断和提案文化项目，但文化由CEO和日常管理行为塑造，HR的影响力有限) |
| 可行动性 | 低 — 文化的量化本身就有争议（pulse survey的分数上升=文化变好？）；干预的手段有限且效果滞后 |
| 数据可得性 | 困难 — Pulse survey可获取但员工可能"说好听的"；离职面谈可从侧面反映文化问题；"大公司病"的行为指标（审批时长/跨部门推诿次数/"不是我负责"出现在消息中的频率）可间接量化但需要语义分析 |
| 跨角色协同标记 | 是 — HR VP诊断，但文化问题的解决需要CEO和全体VP的行为改变——这是最难推动的JTBD |

### S6-JTBD-059

**语句:** 我需要评估当前的产品组合中是否存在"僵尸产品"——产品还在运行、客户还在续约、但团队已经不再投入任何新功能。这些产品的ARR合计可能占总收入的5-10%，在分散工程团队的注意力。但我不确定砍掉这些产品会不会引发连锁反应。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 诊断型 (DIAGNOSE × Product) |
| 执行角色 | 产品VP, BU GM, 工程VP |
| 频率 | 年度（产品组合清理） |
| 重要性 | 3 — 僵尸产品消耗维护资源但贡献有限。但大SaaS中"不能砍"的政治理由往往超过经济理由 |
| 中层可控性 | 2 (产品VP可识别并提出sunset计划，需要BU GM和客户影响评估) |
| 可行动性 | 中 — 需要"产品投入产出比"矩阵（维护成本/ARR贡献/战略价值/客户集中度）+ sunset的客户迁移方案 |
| 数据可得性 | 中等 — 产品的维护成本需从工程资源分配中手工归集；ARR贡献可获取；客户集中度（如一个产品只有一个大客户在用→砍不掉）可从订阅数据计算 |
| 跨角色协同标记 | 是 — 产品VP × 工程VP × CS VP（客户迁移方案） |

### S6-JTBD-060

**语句:** 我需要预测如果宏观经济进入衰退（客户IT预算削减10-20%），我们的ARR会受多大影响——SaaS行业已经有信号，但我不确定我们的客户群中哪些会首当其冲、以及我们的产品在客户预算中是"必须保留"还是"可以砍掉"。

| 字段 | 值 |
|------|-----|
| JTBD类型 | 预测型 (PREDICT × Market/宏观风险) |
| 执行角色 | CFO, BU GM, CEO (间接) |
| 频率 | 季度（宏观经济环境监控）+ 事件驱动（重大经济信号出现时） |
| 重要性 | 5 — 2022-2023年SaaS行业已经历了一轮宏观冲击。有预案=从容应对；无预案=被动裁员+股价暴跌 |
| 中层可控性 | 0 (宏观环境不可控，CFO只能做预警和预案) |
| 可行动性 | 中 — 需要基于客户行业分布的宏观敏感性分析（金融/科技客户通常在衰退中先砍SaaS预算，医疗/政府客户相对稳定）+ 产品"必要性"评估（客户把我们的产品归为"必须保留"还是"可砍"？） |
| 数据可得性 | 困难 — 历史宏观衰退数据有限（SaaS行业在2008年时规模很小）；客户预算优先级需要通过调研获取（但客户不一定说真话）；宏观预测本身的准确性极低 |
| 跨角色协同标记 | 是 — CFO主导，各BU GM提供本BU客户的行业分布和产品必要性评估 |

## 统计摘要

### 基本统计

| 指标 | 数值 |
|------|------|
| JTBD总数 | 60 |
| JTBD-ID范围 | S6-JTBD-001 至 S6-JTBD-060 |
| 覆盖角色 | 10/10 (全覆盖) |

### 按JTBD类型分布

| JTBD类型 | 数量 | 占比 | 典型JTBD IDs |
|----------|------|------|-------------|
| JTBD类型 | 数量 | 占比 |
|----------|------|------|
| 干预型 (ALLOCATE/DESIGN/CONTROL/NEGOTIATE) | 24 | 40% |
| 诊断型 (DIAGNOSE) | 25 | 42% |
| 预测型 (PREDICT) | 6 | 10% |
| 复合型 (EVALUATE + ALLOCATE等) | 5 | 8% |

> 注：复合型指JTBD明确包含两种类型（如S6-JTBD-007同时包含EVALUATE × Market和ALLOCATE × Market）。单类型的JTBD按其主类型归入前三类。

### 按决策动词类 (S1) × 实体类型 (S2) 矩阵

> 矩阵展示了60个JTBD在49个格子（7动词类×7实体类型）中的分布。
> 格式：格子中数字 = 该格子的JTBD数量。

| | ALLOCATE | PREDICT | DIAGNOSE | EVALUATE | DESIGN | CONTROL | NEGOTIATE |
|---|---|---|---|---|---|---|---|
| **Customer** | 4 | 0 | 3 | 0 | 0 | 2 | 1 |
| **Channel** | 1 | 0 | 2 | 0 | 1 | 0 | 0 |
| **Product** | 4 | 0 | 5 | 1 | 1 | 0 | 0 |
| **Resource** | 3 | 5 | 2 | 1 | 0 | 0 | 0 |
| **Market** | 2 | 2 | 3 | 2 | 0 | 0 | 0 |
| **Operation** | 2 | 1 | 9 | 2 | 3 | 2 | 0 |
| **Supplier** | 0 | 0 | 1 | 0 | 0 | 0 | 0 |

**关键观察：**
- **DIAGNOSE × Operation（9个）是最密集的格子** — 诊断组织效率/流程/技术债/数据治理是大SaaS中层的核心任务
- **DIAGNOSE × Product（5个）** — 产品健康度诊断是第二大品类
- **PREDICT × Resource（5个）** — 现金流/收入/人力预测集中在资源维度
- **Supplier 实体几乎空白（仅1个）** — 供应商管理在大SaaS中不是中层的核心痛点（更多是工程/采购执行层的问题）
- **NEGOTIATE 类仅1个（S6-JTBD-004，大客户续约折扣）** — 谈判场景在中层有限，更多是销售执行层的工作

### 按角色分布

| 角色 | 作为主执行角色的JTBD数 | 作为协同角色的JTBD数 | 总涉及JTBD数 |
|------|---------------------|---------------------|------------|
| BU GM / 事业部总经理 | 28 | 20 | 48 |
| CFO / 财务VP | 8 | 20 | 28 |
| 产品VP | 10 | 18 | 28 |
| 销售VP | 6 | 16 | 22 |
| 客户成功VP | 8 | 10 | 18 |
| 工程VP / 平台架构师 | 7 | 14 | 21 |
| 增长VP / CMO | 6 | 10 | 16 |
| HR VP / CPO | 8 | 6 | 14 |
| 数据VP / 数据中台负责人 | 4 | 6 | 10 |
| 安全与合规负责人 | 3 | 4 | 7 |

> "主执行角色"定义：该角色在JTBD中承担决策或推动责任（标注在最前）。
> "协同角色"定义：该角色在JTBD中被标注为协同参与。

**关键观察：**
- **BU GM 是绝对的核心角色** — 参与80%的JTBD。大SaaS的中层决策高度集中在BU GM层
- **CFO 作为协同角色的参与度极高（20个协同）** — 几乎每个涉及资源、预算、收入的JTBD都需要CFO参与
- **产品VP 和 工程VP 的JTBD密度相当** — 产品-工程的二元对立贯穿多个JTBD（技术债、功能膨胀、架构策略）
- **安全合规角色独立JTBD最少（3个）** — 更多以协同角色出现在国际化、M&A、大客户审计等场景中

### 按重要性分布

| 重要性 | 数量 | 占比 |
|--------|------|------|
| 5 (战略级) | 21 | 35% |
| 4 (高重要) | 27 | 45% |
| 3 (中等) | 12 | 20% |
| 1-2 | 0 | 0% |

**观察：** 80%的JTBD重要性≥4——大SaaS中层的决策质量直接关系公司生死。不存在"日常琐事"级别的JTBD。

### 按中层可控性分布

| 可控性 | 数量 | 占比 |
|--------|------|------|
| 3 (可直接决策) | 11 | 18% |
| 2 (可调整/提案) | 28 | 47% |
| 1 (可诊断/建议) | 17 | 28% |
| 0 (无权决策) | 4 | 7% |

**观察：** 仅18%的JTBD中层可以直接拍板——大多数需要跨级审批或多方协同。这与大SaaS"层级多、决策慢"的特点一致。

### A. 方法论遵循

本文档严格遵循研究方法论文档（`SYNOVA-RESEARCH-JTBD驱动哨兵重定义研究方案-20260706.md`）中定义的 Phase 1 步骤 1.1-1.5：

- **步骤1.3**: JTBD类型分类 — 预测型/诊断型/干预型标注 ✓

- **步骤1.5**: 跨角色协同JTBD独立标注 ✓

### C. 数据可得性详细说明

场景6的"数据可得性"评估基于以下系统假设：
- **CRM**: Salesforce（含Pipeline/活动/客户数据，数据质量中低—销售行为污染）
- **CS平台**: Gainsight/Totango/自研（客户健康度/工单/续约预测）
- **数据中台**: Snowflake/ClickHouse（数百张表，ETL覆盖主要业务系统，指标口径不统一）
- **财务系统**: SAP/Oracle/用友NC（ASC 606收入确认，与业务系统数据对账有差异）
- **产品埋点**: 自研+Amplitude/神策（功能使用率，事件定义团队间不一致）
- **BI**: Tableau/Looker/自研（各BU有独立看板，同一指标不同看板数值不同）
- **HR系统**: Workday/北森（headcount/薪酬/绩效数据，与财务/业务系统的人效数据口径分离）
- **协作工具**: 飞书/钉钉/Slack + Jira/Confluence（可间接提取组织效率指标，但需语义分析）
