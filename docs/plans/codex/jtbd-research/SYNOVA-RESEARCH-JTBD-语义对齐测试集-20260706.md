# Gate 3：语义对齐测试集

> 根据研究方案步骤3.0，Gate 3的目的是确保在并行设计compute函数之前，
> 所有研究者对16条边参数的理解一致。测试集是工程上唯一可行的对齐验证方法——
> "开会统一文档"的偏差在并行压力下会被成倍放大。

---

## 1. 测试设计原则

1. **覆盖全部16条边**：每条边至少1个测试用例，高频边（PRODUCES/FLOWS_TO/AFFECTS）3-5个
2. **跨行业场景**：同一道题在不同行业（消费品/制造/SaaS）可能有不同答案——测试"理解的一致性"
3. **边界条件**：包含空值、异常值、规模差异、时间窗口差异
4. **偏差阈值**：任意两人对同一测试用例的输出偏差 > 5% → 未通过，需要重新对齐

---

## 2. 测试用例（共28题，覆盖16条边）

### 2.1 PRODUCES 边（5题 — 最高频边，230条ND引用）

**P-01：边际贡献率计算**
```
查询：某SKU的PRODUCES.marginal_contribution_rate 在2026年Q1的值是多少？
给定：该SKU Q1收入 = 500万，直接变动成本 = 300万，分摊固定成本 = 100万
正确答案：40%（(500-300)/500），不含分摊固定成本
偏差容忍：±2%（即38%-42%）
常见错误：将分摊固定成本计入（输出20%）
```

**P-02：产能利用率时间序列**
```
查询：某产线PRODUCES.capacity_utilization 在2026年3月的日均值？
给定：3月实际产出 = 24000件，理论产能 = 30000件（22个工作日，设备可用20天）
正确答案：80%（24000/30000），分子是实际产出，分母是理论满负荷产能
偏差容忍：±2%
常见错误：用可用天数代替理论天数（输出100%）/ 混入维修停机时间
```

**P-03：跨行业利润率对比**
```
查询：分别计算消费品企业(S1)和SaaS企业(S6)的PRODUCES.gross_margin含义有何不同？
消费品：毛利率 = (GMV - 平台扣点 - 产品成本 - 退货损耗) / GMV
SaaS：毛利率 = (ARR - 云服务成本 - 第三方授权费) / ARR
判定标准：两段描述都正确反映行业特征 → 通过
常见错误：用消费品口径套SaaS（忽视ARR递延收入概念）
```

**P-04：质量缺陷率归因**
```
查询：某批次产品PRODUCES.defect_rate 从2%跳升至8%，需要哪些边联合推理？
正确答案：PRODUCES(缺陷率时序) + AFFECTS(来料批次→缺陷率) + DEPENDS_ON(设备参数→缺陷率) + CONSUMES(新工人→缺陷率)
判定：答出至少3条边且包含AFFECTS → 通过
```

**P-05：OEE计算**
```
查询：设备PRODUCES.OEE 的三个分项是什么？
正确答案：可用率(Availability) × 性能率(Performance) × 质量率(Quality)
偏差容忍：0%（标准定义）
```

### 2.2 FLOWS_TO 边（4题 — 次高频边，110条ND引用）

**F-01：现金流瀑布**
```
查询：企业未来3个月的FLOWS_TO.cash_waterfall 包含哪些核心流入流出？
正确答案至少包含：应收账款回收、应付账款支付、工资发放、税费缴纳、贷款本息、资本支出
判定：答出≥5项 → 通过
```

**F-02：客户LTV计算**
```
查询：某客户的FLOWS_TO.lifetime_value 用什么公式？
给定：月均贡献毛利 = 2万，月流失率 = 5%
正确答案：LTV = 月均贡献毛利 / 月流失率 = 2万 / 5% = 40万
偏差容忍：±5%
常见错误：用收入代替毛利 / 忘记折现
```

**F-03：跨行业价值流**
```
查询：消费品(S1)和SaaS(S5)的FLOWS_TO 边消费的核心参数有何本质不同？
消费品核心：FLOWS_TO(应收账款周转天数, 库存周转天数, 应付账款周转天数) → 现金循环周期
SaaS核心：FLOWS_TO(MRR, ARR, NDR, CAC回收期, LTV/CAC) → 单位经济模型
判定：两段描述分别准确 → 通过
```

**F-04：账期影响模拟**
```
查询：将某大客户账期从30天延至60天，FLOWS_TO 边需要模拟什么？
正确答案：应收账款增加 → 现金缺口扩大 → 融资需求增加 → 坏账风险上升
         同时需关联BUYS_FROM(客户购买行为是否因账期变化而增加)
判定：答出现金流+坏账两个维度 → 通过
```

### 2.3 AFFECTS 边（4题 — 102条ND引用）

**A-01：归因分解**
```
查询：某客户NDR从105%降至95%，AFFECTS边需要分解哪些因素？
正确答案至少包含：AFFECTS(流失客户特征) + AFFECTS(降价影响) + AFFECTS(竞品动作) + AFFECTS(产品功能差距)
判定：答出≥3个因素 → 通过
```

**A-02：因果延迟**
```
查询：AFFECTS边如何处理因果延迟（如：营销投入→3个月后销售增长）？
正确答案：AFFECTS.delay_days 参数存储延迟天数，计算AFFECTS时自动引入滞后变量
          通过 CUMULATIVE_LEARNING 边的时序模型训练延迟参数
偏差容忍：±1天（对延迟天数的理解差异）
```

**A-03：混杂因子控制**
```
查询：当观测到GMV下降，如何分离AFFECTS(自身定价问题) vs AFFECTS(竞品大促) vs AFFECTS(季节因素)？
正确答案：使用双重差分(DID)或合成控制法，以同期竞品未做活动的同类目SKU为对照组
判定：提及对照组概念 → 通过
```

**A-04：多因一果**
```
查询：交付延迟的AFFECTS边需要联合哪些边？
正确答案：AFFECTS→PRODUCES(产能不足) + AFFECTS→DEPENDS_ON(物料短缺) + AFFECTS→SIGNAL_TRANSMITS(信息传递延迟) + AFFECTS→COUPLES(工序耦合瓶颈)
判定：答出≥3条关联边 → 通过
```

### 2.4 COMPETES_WITH 边（3题 — 80条ND引用）

**C-01：竞品价格弹性**
```
查询：COMPETES_WITH.price_gap 从-10%（我方便宜）变为+5%（我方贵），对BUYS_FROM.conversion_rate的预期影响？
正确答案：需用历史价格差-转化率数据训练的弹性系数来估计，不同行业弹性不同
         消费品：高弹性（价格差1%→转化率变化0.5-2%）
         SaaS：低弹性（切换成本高，价格差5%以内对续约率影响极小）
判定：区分行业弹性差异 → 通过
```

**C-02：竞品功能差距矩阵**
```
查询：如何构建COMPETES_WITH.feature_gap_matrix？
正确答案：维度=我方功能×竞品功能，值={领先,持平,落后,缺失}×重要性权重
         消费端权重来自客户调研，供应端权重来自Sales团队Win/Loss数据
判定：提及权重概念 → 通过
```

**C-03：竞品信息数据源**
```
查询：COMPETES_WITH边的参数从哪些数据源获取？（诚实回答）
正确答案：竞品价格——公开信息(官网/电商平台)/非公开信息(Win/Loss访谈)
         竞品功能——公开信息(产品文档/发布会)/第三方测评
         竞品战略——公开信息(财报/招聘岗位)/GA手工采集(行业人脉)
判定：承认"无法完全自动获取" → 通过（诚实比完美重要）
```

### 2.5 BUYS_FROM 边（3题 — 63条ND引用）

**B-01：客户流失预测**
```
查询：BUYS_FROM.churn_risk 的计算需要哪些信号？
正确答案至少包含：使用频率下降、客单价下降、支持工单增加、合同到期日临近、
         竞品接触信号（来自COMPETES_WITH）、关键联系人离职（来自REPORTS_TO）
判定：答出≥4个信号 → 通过
```

**B-02：价格弹性矩阵**
```
查询：BUYS_FROM.price_elasticity 如何按客群分层？
正确答案：按客户规模(大/中/小) × 行业 × 使用深度分群
         大客户+深度使用 → 低弹性（锁定效应）
         小客户+浅度使用 → 高弹性（随时可切换）
判定：提及分层逻辑 → 通过
```

**B-03：NDR分解**
```
查询：BUYS_FROM.NDR 从100%降至90%，如何分解？
正确答案：NDR = 留存收入 + 增购收入 - 流失收入 - 降级收入
         分解到四个子指标，每个子指标对应不同的根因和干预策略
判定：答出四项分解 → 通过
```

### 2.6 DEPENDS_ON 边（2题）

**D-01：供应商依赖度**
```
查询：DEPENDS_ON.supplier_concentration 的阈值是多少时触发警报？
正确答案：单一供应商采购占比 > 50% 或 前三供应商占比 > 80% → 触发
         同时检查：该供应商的可替代性（替代供应商数量×切换成本×切换时间）
偏差容忍：±10个百分点（对"阈值"的精确值不同团队可能有不同设定）
```

**D-02：技术架构锁定**
```
查询：DEPENDS_ON.tech_lock_in 如何量化？
正确答案：迁移成本(工程师月×人月单价 + 停机损失) / 年度IT预算
         同时考虑：切换后的效率提升、新架构的维护成本
判定：提供可量化公式 → 通过
```

### 2.7 CONSUMES 边（2题）

**CS-01：获客成本归集**
```
查询：CONSUMES.CAC 应该包含哪些成本？
正确答案：市场人员薪酬 + 广告投放费 + 内容制作费 + SDR团队成本 + 销售工具成本 / 同期新获客数
偏差容忍：±10%（"SDR团队是否全计入还是按比例"有讨论空间）
常见错误：只算广告费、漏了人员成本
```

**CS-02：资源消耗效率**
```
查询：CSM团队的CONSUMES.efficiency 用什么指标衡量？
正确答案：每CSM管理的ARR / CSM平均薪酬，或每CSM服务的客户数 × 平均NDR
判定：给出可量化指标 → 通过
```

### 2.8 REPORTS_TO 边（1题）

**R-01：决策周期**
```
查询：REPORTS_TO.decision_latency 在什么情况下触发警报？
正确答案：当某类决策（如预算审批、ECN变更）的平均周期超过历史基线 + 2σ 且趋势上升
         可能原因：管理层级增加、审批人负载过重、信息传递延迟
判定：答出"历史基线+标准差"概念 → 通过
```

### 2.9 低频边（4题，覆盖 SIGNAL_TRANSMITS/METRIC_BINDS/COUPLES/OCCUPIES/CAPITAL_ALLOCATES/CUMULATIVE_LEARNING）

**S-01：信号衰减检测**
```
查询：SIGNAL_TRANSMITS.attenuation 如何检测？
正确答案：对比信息源头和终点的指标差异，逐跳追踪衰减位置
         例如：客户投诉→客服记录→产品需求池→实际开发→上线，每跳检查信息完整性
判定：提及"逐跳追踪"概念 → 通过
```

**M-01：度量博弈**
```
查询：METRIC_BINDS.gaming_susceptibility 如何检测KPI博弈？
正确答案：当某KPI达标率突然跃升但关联的业务指标（如客户满意度、复购率）未同步改善
         即为Goodhart's Law——度量一旦成为目标，就不再是好的度量
判定：提及Goodhart's Law或"KPI达标≠业务改善" → 通过
```

**CP-01：工序耦合**
```
查询：COUPLES.bottleneck 如何定位产线瓶颈？
正确答案：计算每个工序的利用率和在制品积压量，利用率最高+积压最多的工序=瓶颈
         使用TOC（约束理论）五步法
判定：提及利用率+积压两个维度 → 通过
```

**OC-01：资本配置效率**
```
查询：CAPITAL_ALLOCATES.ROI 在企业内部各部门间的比较意味什么？
正确答案：如果部门A的边际ROI(30%) > 部门B(5%)，则追加投资到A更高效
         但需同时考虑：A的规模上限、B的战略必要性、风险差异
判定：既提到ROI比较又提到非财务因素 → 通过
```

## 3. 测试执行规范

### 3.1 独立完成要求
- 每位参与Phase 3/4的研究者独立完成全部28题
- 不允许讨论、不允许查阅他人答案
- 完成时间：2小时内

### 3.2 评分标准

| 评分 | 标准 |
|------|------|
| 通过 | 答案在偏差容忍范围内，推理逻辑正确 |
| 争议 | 答案超出容忍范围但推理逻辑合理（需仲裁） |
| 未通过 | 答案超出容忍范围且推理逻辑错误 |

### 3.3 通过阈值
- 个人通过线：28题中 ≥ 24题"通过"（通过率 ≥ 85%）
- 团队对齐线：任意两人对同一题的答案偏差 < 5%（定量题）
- 未达标的个人/团队 → 重新对齐后补测
