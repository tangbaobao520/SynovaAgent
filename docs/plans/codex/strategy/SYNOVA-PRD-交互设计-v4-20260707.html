一、产品定位

1.1 一句话定义

Synova 是一个驻扎在企业内部的数字化麦肯锡。持续观测全量数据，主动发现问题，自动诊断根因，提出可落地方案，跟踪执行效果。最终决策永远是人做的。

1.2 两层价值：诊断 + 落地

层次诊断层落地层
agent8 位专家按需唤醒，找出增长瓶颈帮企业识别：哪些工作可被 Agent 替代？哪些必须人做？
skill46 哨兵 + 61 个计算指标帮企业封装重复流程为可复用 skill
data哨兵读取 GraphStore 本体数据帮企业整理数据：字段映射、补齐方案

1.3 交互核心原则

#原则
1对话是唯一入口。不需要菜单、不需要导航学习。打开就能问。
2Agent 主动，人被通知。系统托盘红色角标 → 点击 → 看到问题。不需要每天登录检查。
3面板可折叠。参考 Codex：左侧可收起到图标条，右侧可完全关闭。专注对话时只留中间一栏。
4消息有操作。每条 Agent 回复可复制、重新生成、反馈。不是只读文本墙。
5多专家透明但不抢占。折叠式展示贡献专家。默认隐藏，追问时展开。
6零配置启动。下载 → 双击 → 填企业名 → 开始使用。无命令行，无配置文件。

二、用户角色

角色核心场景界面
GA (Growth Advisor)管理 10-20 个客户。上传数据、审阅专家结论、纠错、生成落地方案、与客户对话。完整三栏桌面应用。左栏客户列表，中栏对话，右栏可切换：行动跟踪 / 专家推理链 / 哨兵原始数据。
企业对接人接收推送 → 审阅方案 → 确认或调整 → 推动落地。日常与 Synova 对话。桌面应用。左栏工作区列表，中栏对话，右栏行动跟踪。无 GA 管理功能。
企业主被动接收。每周摘要邮件。异常时即时告警。在 IM 中 @Synova 对话。无桌面应用。IM + 邮件。
部门负责人本部门问题咨询。独立与 Synova 协作。桌面应用或 IM。数据可见性受部门限制。

三、桌面应用全局框架

3.1 窗口结构

参考 Codex 桌面端。一个窗口，三个可折叠面板：

┌──────────────────────────────────────────────────────────┐ │ Synova · 某母婴品牌 · B轮 · 300人 [铃铛] [头像] │ ← 标题栏 ├────┬───────────────────────────────────────┬──────────────┤ │ │ │ │ │ 左 │ 中栏 │ 右栏 │ │ 栏 │ 对话区 │ (可切换) │ │ │ │ │ │ ▣ │ 用户: 为什么现金流在恶化？ │ 行动跟踪 │ │ ▣ │ │ 专家推理 │ │ ▣ │ Synova: 正在分析... │ 哨兵数据 │ │ ▣ │ [财务顾问] [战略顾问] │ │ │ ▣ │ │ │ │ ▣ │ 应收账款周期从30天延长到59天... │ │ │ ▣ │ ▸ 财务顾问主导 · 置信度 78% │ │ │ │ │ │ │ │ ────────────────────────────────── │ │ │ │ [输入框] [发送] │ │ ├────┴───────────────────────────────────────┴──────────────┤ │ ● 哨兵: 2个活跃告警 │ ● 上次诊断: 7月12日 │ 状态栏 │ └──────────────────────────────────────────────────────────┘

3.2 面板行为

面板默认状态收起后快捷键
左栏展开，240px 宽收起到 40px 图标条。只显示图标。鼠标悬停临时展开。Ctrl+B
右栏收起展开为 300px。内容根据上下文自动切换。Ctrl+J

面板宽度可拖拽调整。最小 180px，最大 450px。拖拽到 < 100px 时自动收起。

3.3 标题栏

元素行为
企业名GA 界面显示当前客户名。点击可切换客户。对接人界面固定显示本企业名。
铃铛图标通知中心。未读数角标。点击展开通知列表：哨兵告警、方案更新、GA 纠错通知。
头像当前用户。点击展开菜单：设置、切换客户(GA)、锁定、退出。

3.4 状态栏

窗口底部单行状态栏。从左到右：活跃哨兵告警数（点击跳到对应工作区）、上次全量诊断时间、在线状态指示灯。非侵入式，不抢占注意力。

3.5 系统托盘

应用最小化到系统托盘，不退出。托盘图标显示未读通知角标。右键菜单：打开主窗口、今日摘要、暂停通知 2 小时、退出。

哨兵 critical 告警触发时：系统通知弹出 + 托盘图标变红 + 任务栏闪烁。用户点击通知 → 打开主窗口 → 定位到对应工作区。

四、三栏布局详解

4.1 左栏：工作区 + 会话历史 + 全局搜索

顶部：全局搜索

┌──────────────────────────┐ │ 🔍 搜索工作区、对话、数据... │ └──────────────────────────┘

Ctrl+K 打开全局命令面板。输入关键词搜索：工作区名称、对话内容（FTS5 全文检索）、专家结论、哨兵数据。搜索结果按类型分组：工作区 / 对话 / 数据。

中部：会话列表

当前企业的对话历史。每个会话显示：标题（自动摘要或手动命名）、最后消息时间、未读数。点击切换对话。右键菜单：重命名、归档、删除。

底部：工作区列表

当前活跃的工作区。每个工作区：优先级图标、一句话概括、负责专家头像。按"需要关注的程度"排序。每条可拖拽到对话区创建关联。

最底部：客户切换（GA 专属）

GA 的左栏底部有客户列表。点击切换客户 → 整个应用上下文切换（对话历史、工作区、哨兵数据全部切换）。切换时有 0.3s 过渡动画，无加载 spinner。

4.2 中栏：对话区

详见第五章。

4.3 右栏：上下文感知面板

右栏不是全局配置。内容由用户角色 + 当前上下文两个变量共同决定。

无工作区选中时：全局视图

用户右栏内容
GA客户仪表盘：飞轮转速 + 活跃告警数 + 待审阅方案数 + 待确认行动项。GA 一眼判断这个客户今天需不需要紧急关注。
对接人待确认方案列表：GA 已推送、等待对接人审阅的方案。按紧急程度排序。
企业主飞轮仪表盘（极简）：三个数字 + 一个瓶颈。30 秒看完。无操作入口。
部门负责人本部门待办：与本部门相关的哨兵告警和待处理工作区。

选中工作区时：角色定制视图

用户右栏内容是否可手动切换
GA 三个标签可切换：
① 行动跟踪：方案执行进度 + 关联哨兵数据
② 哨兵原始数据：compute 输入值、公式、阈值对比、历史趋势
③ 落地模式：匹配的 skill 清单 + 数据依赖 + 字段覆盖度 		✅ GA 手动切换标签

关联影响：这个工作区的问题影响哪些其他部门或指标。 		❌ 系统自动选择，不提供切换
企业主企业主不走工作区流程。他在 IM 中对话。如偶然打开桌面应用，右栏保持飞轮仪表盘。—
部门负责人 关联影响 + 跨部门背景：
当前问题的全局影响——"品牌定位模糊导致销售转化率下降 12%，
财务部门已注意到收入结构变化"。
不是让部门负责人去管别的部门，是帮他理解问题在全局中的位置。 		❌ 系统自动选择，不提供切换

面板控件

  • GA 的右栏顶部有三个标签（行动 / 数据 / 模式），可手动切换。默认根据当前操作自动选择——点击专家标识 → 切换到数据视图，点击方案卡片 → 切换到行动视图。
  • 对接人和部门负责人的右栏无标签。只有一个标题 + 内容区。系统根据角色自动决定显示什么。
  • 所有角色的右栏都可以通过 Ctrl+J 或点击右栏边缘的折叠按钮收起。收起后中栏全屏。

五、对话区：消息系统

5.1 消息结构

对话区是应用的主画布。每条消息不是纯文本——是结构化组件：

[用户消息] ┌──────────────────────────────────────────────────────────┐ │ 👤 你 · 刚刚 │ │ │ │ 为什么现金流在恶化？我们上个月明明回款正常。 │ └──────────────────────────────────────────────────────────┘ [Agent 思考中] ┌──────────────────────────────────────────────────────────┐ │ Synova 正在分析... │ │ ▸ 财务顾问 分析中 │ │ ▸ 战略顾问 交叉验证中 │ │ [收起思考过程] │ └──────────────────────────────────────────────────────────┘ [Agent 回复] ┌──────────────────────────────────────────────────────────┐ │ 🤖 Synova · 刚刚 │ │ │ │ 你的现金流在过去两个季度持续收紧。 │ │ 根因是应收账款周期从30天延长到59天—— │ │ 主要因为客户A的采购系统迁移导致付款流程中断。 │ │ │ │ 建议：与客户A协商临时缩短付款周期， │ │ 同时在下一份合同中加入逾期罚息条款。 │ │ │ │ ┌─ 分析贡献 ─────────────────────────────────────────┐ │ │ │ 财务顾问 主导分析 · 战略顾问 交叉验证 · 置信度 78% │ │ │ │ [展开完整推理链] [查看哨兵原始数据] │ │ │ └────────────────────────────────────────────────────┘ │ │ │ │ [📋 复制] [🔄 重新生成] [👍] [👎] [… 更多] │ └──────────────────────────────────────────────────────────┘

5.2 消息操作

操作行为
📋 复制复制 Agent 回复的纯文本到剪贴板。不含专家标识折叠区。
🔄 重新生成用相同输入重新调用专家推理。旧消息折叠标记为"已替换"，新消息出现在下方。
👍 / 👎快速反馈。👍 → 记录 positive feedback 到 AgentMemoryStore。👎 → 弹出简短的反馈输入框："哪部分不准确？"
… 更多展开菜单：追问战略影响、生成 CFO 版摘要、创建关联工作区、标记为关键判断

5.3 思考过程展示

当用户提问触发专家推理时，在 Agent 回复之前显示"思考中"状态。默认折叠，显示当前活跃的专家名称和状态。用户可展开查看实时推理步骤（如果专家引擎支持流式输出）。

Level 1 响应（缓存/检索）不显示思考过程——直接出结果。Level 2+ 才显示。

5.4 流式输出

Agent 回复以 token 级流式输出。不是一次性弹出整段文字。和 Codex 体验一致：文字逐字出现，用户可以边读边思考。专家标识在流式输出完成后追加（不打断阅读流）。

5.5 对话中的工作区引用

Agent 发现跨工作区关联时，以卡片形式嵌入对话中：

┌──────────────────────────────────────────┐ │ 🔗 关联发现 │ │ 现金流紧张和「人员流失预警」工作区密切相关—— │ │ 新人员工支出立即产生，收入贡献滞后。 │ │ [打开关联工作区] │ └──────────────────────────────────────────┘

5.6 对话历史搜索

对话区顶部有搜索框。搜索当前会话的历史消息。匹配结果高亮，滚动到对应位置。支持 Ctrl+F。

六、输入框与快捷操作

6.1 输入框设计

固定在对话区底部。多行文本，按 Enter 发送，Shift+Enter 换行。和 Codex 一致。

输入框内支持：

功能触发行为
@ 提及专家输入 @弹出专家列表。选择后该专家的分析视角被优先唤醒。如 @财务顾问 分析一下应收账款的趋势
@ 提及工作区输入 @ + 关键词弹出工作区列表。选择后对话上下文注入该工作区的核心结论。
/ 快捷命令输入 /弹出命令列表：/诊断（触发 Level 4 全量诊断）、/摘要（生成本周摘要）、/导出（导出当前工作区报告）、/方案（生成落地方案）
文件拖拽拖文件到输入框自动识别 CSV/JSON/Excel。触发数据上传流程。显示字段映射预览，确认后写入 GraphStore。
粘贴图片Ctrl+V 粘贴图片截图直接粘贴到对话中。如报销审批单截图、合同条款截图。

十三、通知与系统托盘

13.1 系统托盘

应用关闭窗口时最小化到系统托盘，不退出。托盘图标：

  • 正常状态：绿色 Synova 图标。无未读。
  • 有待处理事项：橙色角标。有未读工作区更新或方案待确认。
  • 有 critical 告警：红色角标 + 系统通知弹出。

右键菜单：打开主窗口、今日摘要、暂停通知 2 小时、暂停通知至明早 8:00、退出。

13.2 通知类型

类型触发通知内容点击后
🔴 紧急告警哨兵 critical + 置信度 ≥ 0.8"现金流预警：缺口扩大至 12%。对接人 14 天未响应。"打开主窗口 → 定位到该哨兵的工作区
🟡 方案更新GA 确认方案并推送"GA 已确认'缩短付款周期'方案。请审阅。"打开该工作区 → 滚到方案卡片
🔵 诊断完成Level 4 全量诊断完成"本周诊断已完成。总体健康度 62/100 ↑+3。"打开飞轮仪表盘视图
⚪ 纠错通知GA 纠错了专家结论"GA 修正了'市场定位'的判断。建议查看。"打开被纠错的结论

13.3 应用内通知中心

标题栏铃铛图标。点击展开通知列表面板。显示最近 20 条通知。每条通知可：标记已读、跳转到相关工作区、一键忽略。

通知按优先级排序：紧急告警 → 方案更新 → 诊断完成 → 纠错通知。

13.4 免打扰

右键系统托盘 → "暂停通知 2 小时"或"暂停至明早 8:00"。暂停期间所有通知静默存入通知中心，不弹系统弹窗。免打扰结束后，未读的紧急告警立即弹出。

十六、空状态与首次引导

16.1 GA 首次启动

GA 下载安装 → 双击打开 → 看到欢迎页：

演示模式：如果 GA 跳过了数据上传，系统加载母婴行业的示例数据。GA 可以立即体验完整功能——哨兵告警、专家分析、对话、方案生成。演示模式下，数据标注"示例数据"水印。GA 随时可切换为真实客户数据。

16.2 对接人首次登录

对接人收到 GA 的邀请链接 → 打开 → 看到自己的企业首页。左栏已有 GA 预创建的初始工作区。中栏显示 Synova 的欢迎消息："我是 Synova，你的企业企业第二个大脑。我已经完成了一次初步诊断，发现了 3 个需要关注的问题。点击左栏的工作区开始查看。"

16.3 空状态指南

场景空状态内容
左栏无工作区"还没有工作区。当你向 Synova 提问或哨兵检测到异常时，工作区会自动创建。或者你可以 [手动创建]。"

16.4 首次诊断引导

GA 首次上传数据后，系统自动触发 Level 4 诊断。诊断运行时：中栏显示进度（哨兵扫描中 → 专家分析中 → 报告生成中）。进度条不是百分比——是当前正在执行的步骤描述："正在分析财务数据（F1-F5 哨兵）..."、"战略顾问正在交叉验证..."。

诊断完成后：左栏自动创建 5-8 个工作区。第一条系统消息："诊断完成。我发现了以下问题。建议从'现金流预警'开始，这是当前最紧急的。"

二十三、部署和安装

23.1 交付物

平台格式说明
Windows.exe 安装包（NSIS 或 MSI）双击安装。自动创建桌面快捷方式和开始菜单条目。
macOS.dmg 磁盘映像拖入 Applications 文件夹。自动签名公证。

23.2 安装流程

  1. 下载安装包
  2. 双击安装（Windows 可能需要管理员权限以创建系统托盘）
  3. 首次启动：欢迎页 → 输入企业名称 → 选择行业 → （可选）上传初始数据 → 开始使用
  4. 应用自动在后台启动 Synova 服务进程（Electron 主进程管理子进程生命周期）
  5. 系统托盘出现 Synova 图标。关闭窗口不退出应用。

零命令行。零配置文件。零数据库配置。SQLite 数据库自动创建在用户应用数据目录。企业数据不出本机。

23.3 自动更新

应用启动时检查更新。有新版本时：系统托盘弹出通知"新版本 v1.2.0 可用"。点击 → 后台下载 → 下次启动时自动安装。不需要用户手动下载安装包。

23.4 离线支持

所有数据存储在本地 SQLite。离线时：

  • 对话可用（本地 LLM 或缓存的历史回复）
  • 哨兵停止运行（需要云端 LLM）
  • 状态栏显示离线图标
  • 恢复在线后自动补齐离线期间的哨兵扫描

23.5 多设备同步（远期）

GA 可能在办公室桌面和出差笔记本上同时使用。远期支持：企业数据通过加密通道同步到 Synova 云端。多设备间工作区状态、对话历史自动同步。冲突时以最后修改时间为准。GA 可手动触发同步或设置自动同步间隔。

七、专家按需唤醒机制

7.1 三层唤醒

层级机制延迟LLM调用
Layer 1关键词匹配 (DEFAULT_DOMAIN_KEYWORDS)0ms0
Layer 2轻量LLM意图分类<500ms1 (小模型)
Layer 3专家自主调度 (crossReferences)异步按需

7.2 身份感知回答

同一个问题，不同角色得到不同粒度的回答。路由逻辑不受身份影响，但 system prompt 中注入用户角色和可见数据边界。

7.3 专家池扩展

新增专家 = 创建 expert/{name}/ 目录 + 5个Markdown文件 + expert-registry.yaml一行 + domain-keywords.ts注册关键词。路由代码零改动。从8到20个专家迁移成本为零。

八、对话中的多专家协作

8.1 专家生命周期

闲置 → 唤醒 → 分析中 → 出结论 → (被采纳/被质疑/需要其他专家) → 休眠。

8.2 沉默机制

专家说话规则
strategy, finance, org, tech, marketing, business_model前台专家。被唤醒后可主动发言。
action延迟专家。所有前台专家完成后自动唤醒。不说话——右栏产出行动清单。
knowledge后台引擎。永远不直接对话。持续结构化信息存入知识库。

8.3 冲突呈现

专家意见矛盾时不模糊处理。同时呈现双方论据和置信度，让人选择。不替人决策。

九、四级响应模型

级别触发专家调用响应时间
Level 1: 即时回答信息查询、哨兵缓存0 次 LLM<1s
Level 2: 单专家分析因果推理1-2 次2-5s
Level 3: 多专家协作GA发起、用户质疑2-4 次5-15s
Level 4: 全量诊断Cron / GA手动8+ 次后台 1-5min

LLM 调用队列全局最大 8 并发。Level 1-2 优先，Level 3-4 排队。

十、多员工并发

每个员工独立 messages[]。企业事实共享。专家是共享资源。权限自动注入。

十一、工作区系统

工作区 = 一个问题 × 一个主责专家。生命周期：待审阅 → 分析中 → 方案已确认 → 执行中/搁置 → 已解决。Agent 监测复活条件。

十二、上下文管理

共享对话历史 + 专家视角过滤。压缩时保留结构化结论，压缩对话原文。跨工作区引用自动注入。

十四、GA 管理界面

14.1 客户导航

GA 左栏底部客户列表。点击切换客户 → 整个应用上下文切换。每个客户独立的数据、对话、工作区。

14.2 专家仪表盘

GA 审阅所有专家结论。每条可确认/纠错/追问。纠错写入叠加层，不覆盖原结论。

14.3 GA 方案工作台

点击 [生成落地方案] → 系统自动匹配落地模式 → 组装 skill 清单 + 数据依赖 → GA 校准 → 推送对接人。方案是活文档，哨兵持续监控落地效果。

14.4 GA 权限边界

GA 不可删除数据、不可修改审计日志、不可导出全量数据。所有写操作有叠加层。企业主可随时撤销 GA 访问权限。

14.5 GA 行为监控

8 条自动检测规则。可疑行为主动通知企业主和对企业接人。严重级别同步通知 Synova 官方。

十五、老板信箱

老板不需要打开桌面应用。每周摘要邮件 + IM 即时告警。在 IM 中 @Synova 对话调整信息密度。

十八、企业事实层

AgentMemoryStore enterprise_fact 类型 + 版本链。每条事实标注来源专家。多专家分歧时并存，标记"待 GA 裁决"。

十九、多专家记忆系统

记忆归属标注 source (expert:finance / user_feedback / sentinel:F1)。生命周期：结论 → 纠错 → 推翻 → 关联。记忆归属是 L0 进化的前提。

二十、工具调用的专家隔离

每个专家在 expert-registry.yaml 声明 tools。未声明不可调用。数据权限根据调用专家的 DataAccessPolicy 自动过滤。跨专家工具调用通过 crossReferences 转发，不直接越权。

二十一、企业内部知识库

任何员工向 Synova 提问。Agent 根据角色自动过滤可见范围。回答包含：答案 + 数据来源 + Agent 判断（可选）。

二十二、文件化扩展架构

新增专家/哨兵/行业/落地模式 = 加文件。不改代码。落地模式库：extensions/implementation-patterns/ JSON 文件驱动。

二十五、验收标准

  1. 面板行为：左栏可收起到图标条。右栏可完全关闭。面板宽度可拖拽。快捷键全部生效。
  2. 对话体验：消息流式输出。思考过程默认折叠。消息可复制/重新生成/反馈。
  3. 通知：critical 告警 → 系统通知 + 托盘红色角标。免打扰可暂停。
  4. 空状态：新用户看到欢迎页。演示模式可用示例数据体验全部功能。
  5. GA 安全：GA 不可删除数据。可疑行为自动通知企业主。企业主可一键撤销。
  6. 10 专家扩展：新增 2 个专家。路由代码零改动。新专家通过关键词自动激活。
  7. 零命令安装：下载 → 双击 → 填企业名 → 开始使用。全程无终端。
