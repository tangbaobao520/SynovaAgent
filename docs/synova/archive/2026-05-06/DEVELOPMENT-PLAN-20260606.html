Phase 0: TUI Bug 修复 P0 · 0.5 天

Bug 0.1 — 流式叠词

根因：conversation-engine.ts:528 display() 同时调用 onToken() 和 viewAdapter?.appendToken()，两者最终都调用 app.chat.appendToken()，每个字符写入两遍。

修复：删除 this.viewAdapter?.appendToken(token) 一行。 ✅ 已完成

Bug 0.2 — 蓝色分隔线

根因：app.ts:54-60 divider 用 fg:'black'，Windows 终端映射为蓝色。

修复：改用 content:'│' + fg:'gray'。 ✅ 已完成

Bug 0.3 — ANSI 序列截断（p M p 垃圾字符）

根因：chat-panel.ts:360 wrapText() 用 text.length 包含 ANSI 转义序列，切分时截断 \x1b[36m → 渲染为垃圾字符。

修复：ANSI-aware 断行：用 stripAnsi() 计算可见宽度，跳过转义序列再切分。 ✅ 已完成

Bug 0.4 — 流式重复拼接

根因：chat-panel.ts _streamingLine 包含已提交到 contentLines 的文本，每次 render 显示两次。

修复：拆分为 _fullText（完整）+ _currentLine（仅当前行）。 ✅ 已完成

Bug 0.5 — Logger JSON 打穿 TUI 画面

根因：logger.ts:45 pino destination 写 stderr，Windows + blessed 交替屏幕模式下 stderr/stdout 混合渲染。

修复：TUI 启动时 process.env.LOG_LEVEL='silent'。 ✅ 已完成

Phase 1: ExpertRouter 协调者 P0 · 3 天

1.1 数据接口

ExpertSelection（路由决策输出）

interface ExpertSelection {
  mode: 'none' | 'selective' | 'all' | 'knowledge';
  experts: ExpertId[];           // strategy | org | finance | tech | marketing | action | knowledge
  confidence?: number;            // 0-1
  matchedBy?: 'phase' | 'keyword' | 'llm';
  knowledgeAgent?: boolean;
}

type ExpertId = 'strategy' | 'org' | 'finance' | 'tech' | 'marketing' | 'action' | 'knowledge';

RouteContext（路由上下文输入）

interface RouteContext {
  phase: number;                  // 0-5
  orgSize?: string;               // 如 "50-100"
  industry?: string;              // 如 "SaaS"
  conversationSummary?: string;   // 最近 3 轮摘要
}

DomainKeywordSet（关键词扩展接口）

interface DomainKeywordSet {
  strong: string[];  // 命中 1 个即匹配
  weak: string[];    // 命中 ≥2 个匹配
}
// 运行时注册: registerKeywords('new_domain', { strong:[], weak:[] })

1.3 路由决策流程

用户输入 → ExpertRouter.route(input, context) │ ├─ Layer 1: Phase 硬约束 │ phase=0 → { mode:'none', experts:[] } │ phase≥2 → { mode:'all', experts:ALL_6 } │ ├─ Layer 2: 关键词快路径（0 次 LLM 调用） │ tokenize → 匹配 strong/weak → 打分排序 → 命中则返回 │ 命中率预估：70%+ 的用户输入包含明确领域关键词 │ ├─ Layer 3: LLM 分类（1 次轻量 Flash 调用） │ Prompt: "领域" + 用户输入 + 上下文 → JSON { domains, confidence } │ 仅在 Layer 2 未命中时调用 │ └─ Layer 4: 知识兜底 返回 { mode:'knowledge', experts:['knowledge'] } 走 PKB 检索，不调诊断专家

Phase 3: RBAC 认证接线 P0 · 2 天

3.1 数据接口

Token 格式（生产模式）

tenantId:role
例: acme:admin     → 租户 acme, 管理员权限
例: acme:employee  → 租户 acme, 员工权限（仅公开+团队知识可见）
默认: token 不含冒号时 → tenant='default', role='employee'

UserContext（注入到 AsyncLocalStorage）

interface UserContext {
  userId: string;
  identity: { openId: string; email: string; name: string; source: 'api' };
  auth: { roles: string[]; teamId: string; tenantId: string; sensitivity: 'normal' | 'sensitive' };
  permissions: { version: number; expiresAt: number };
}

FilterClause（权限过滤条件）

interface FilterClause {
  conditions: Array<{
    field: string;        // 'access.level' | 'access.teamId' | 'access.sensitivity'
    operator: 'IN' | 'EQ' | 'NOT_EQ';
    value: unknown;
  }>;
}
// admin → conditions: []
// employee → conditions: [{ field:'access.level', operator:'IN', value:['public'] }]

Anthropic 开发流程（每模块强制执行）

铁律 0-2：每个模块严格按 7 步流程交付。接线审计是硬门禁——单元测试绿 ≠ 产品可用。

7 步流程

Step名称操作命令
1Spec 写接口签名 + 算法选择 + 性能目标 + 边界条件 + 接入点（≤50行） —
2Test 先写测试文件。每个 public 函数 ≥2 用例（happy + sad）。测试即规范。 创建 .test.ts
3Impl 实现代码。只对标 spec 和测试，不对标"感觉"。 —
4Verify 编译 + 测试全绿 + coverage 不降 npx tsc --noEmit && npx vitest run
5WIRE CHECK grep 新函数名/类名在 src/server.ts|src/tui/|src/routes/|src/agent/ 中出现。零结果 = 未接线 = 不准提交 bash scripts/workflow/wire-check.sh <函数名>
6Integration ≥1 集成测试覆盖生产入口→新组件→结果呈现 创建 .integration.test.ts
7Commit 单模块独立提交，独立 review。不批量提交。 git commit -m "feat: ..."
