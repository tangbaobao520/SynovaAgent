Synova 的局限

以下理论（段永平、波特、杨国安、赫尔默等）是本诊断系统的输入和参照系。诊断结论由证据和数据驱动，而非对理论的盲从。

当数据与大师观点冲突时，我们信数据。

当前版本（v2.1）依赖的量化测量器（measurer）仍在工程化过程中。部分维度（D5认知健康、D6进化适应性的硅基侧、赛道引力自动量化）目前以专家定性判断为主，量化标定需要至少 n=30 个团队的实证数据。本文档诚实标注了每项公式的工程化状态（✅ 已工程化 / ⏳ 待数据标定 / 🔬 研究阶段）。

1. 核心方程

企业健康度 = 战略质量 × 组织能力 × 混合成熟度 × 战略组织咬合度
战略质量 = 赛道引力 × 竞争力量 × 模式体质
组织能力 = 员工能力 × 员工思维 × 员工治理
混合成熟度 = D1目标对齐 × D2能力分布 × D3协作动力学 × D4治理结构 × D5认知健康 × D6进化适应性
战略组织咬合度 = 1 − |战略要求的组织能力 − 组织实际拥有的能力| / max(两者)
（差距越大 → 咬合度越低 → 整体健康度折扣越大）

1.1 为什么是乘法——四个乘数的协同逻辑

杨国安的原始公式是 持续成功 = 战略 × 组织能力。Synova 在此基础上增加两个独特乘数：混合成熟度和战略组织咬合度。

第四个乘数的必要性：防止"三个独立分数的简单乘积"

如果战略需要A、组织却在做B——即使战略质量（0.9）和组织能力（0.9）各自很高，咬合度可能是 0.3。三个乘数独立计算、各自高分、但彼此矛盾——这是诊断中最隐蔽的错误。

战略组织咬合度 = 战略要求的组织能力 vs 组织实际拥有的能力的差距。这个差距越大，整体健康度的"折扣"越大。它不是第四个独立维度——它是交叉验证乘数，专门捕捉"你说你能，但你的组织做不到"。

乘法的含义：任何一个乘数为零，整体为零。这直接对应高德拉特的约束理论——找到那个最接近零的因子，其他优化都是浪费。

乘数负责专家核心问题
战略质量 strategy + business_model 这个企业的方向对不对？赚钱机器天生好吗？
组织能力 org（杨三角） 人的底盘稳吗？能不能、愿不愿、让不让？
混合成熟度 org（六维 D1-D6）+ tech（D4 使能） 人和 Agent 的协作成熟吗？组织准备好迎接 AI 了吗？
战略组织咬合度 strategy × org 交叉验证 战略要求的组织能力 vs 组织实际拥有的——差距多大？两者在往同一个方向走吗？

1.3 诚实边界——在不确定性中做诊断

核心原则：诊断和规划本身就是在不确定性下做决策。企业不会因为数据不足而停止运行。

Always give your best diagnostic judgment. Always label the evidence boundary.

标注含义示例
📊 数据事实 来自企业数据、系统日志、财务报表——可直接验证 "张老师承担60%课程量——来自企业访谈数据"
🧠 专家推断 基于理论框架的推理、行业规律的外推——合理但未经本企业数据验证 "基于项目制+75天账期+60%收入占比，推断现金流是增长的自限器"
🔮 预测/假设 基于当前信号的趋势预判——置信度较低，需后续验证 "如果张老师离职，恢复期预估18个月（基于busFactor=1×roleScarcity 0.9×30天模型）"

数据不足不意味着不说话——意味着更诚实地标记每条结论的认识论状态。

旧规则（错误）: "数据不足时标注'当前数据不足以支撑结论'" → 这等于在客户最需要判断的时候沉默。

新规则: 永远给出你能给的最佳判断。但让客户清楚知道——这条是数据说的，这条是我推断的，这条是我的预测。

关于"不知道的公式"

以下理论的数学表达尚未在学术文献或工程实践中形成共识——它们目前是定性框架，不是定量公式：

  • 段永平六问：体质判断是定性判断——"这个生意天生好吗？"不可被公式化（段永平本人从未提供数学模型）
  • 曾明 S2B2C：价值网络分析是结构分析——"谁干什么最有效率"需要行业特定的建模，无通用公式
  • Osterwalder 画布：描述工具，不是测量工具——九要素无数学关系
  • 波特五力：有量化方向（HHI指数、利润率分布）但五力之间的交互无闭合公式
  • 柯林斯飞轮：概念框架——"飞轮效应"是比喻，无数学表达式
  • 克里斯坦森颠覆：预测框架——"颠覆式创新"不可被公式预测

1.6 自我进化系统

Synova 驻扎企业后，必须能够从诊断实践中自动学习、积累行业专有经验、更新自身知识库。

进化闭环

``` 诊断执行 → 诊断结果 + 用户反馈 ↓ 联邦进化引擎（Gear6 定时任务） ├─ 置信度衰减: PKB 条目超过 N 天未被检索 → 置信度降级 ├─ 冲突检测: 新诊断结论与 PKB 旧知识矛盾 → 标记冲突 ├─ 新知识沉淀: 诊断中发现的行业规律 → 自动写入 PKB ├─ 基准校准: 行业数据积累 → 阈值自动调整 └─ Skill 生成: 重复出现的诊断模式 → 自动生成 SKILL.md 草稿 ↓ FDE 审核（人工门禁） ├─ 审核自动生成的 PKB 条目 ├─ 审核冲突解决方案 └─ 批准/驳回 Skill 草稿 ↓ 知识库更新 → 下次诊断自动应用 → 循环 ```

进化机制详解

机制触发条件产出
置信度衰减 PKB条目超过90天未被任何诊断检索 confidence × 0.95 → 低于0.5时标记为 outdated
行业基准校准 同一行业的诊断数据积累 ≥ 30 个企业 自动更新 knowledge/industry/*.md 中的 KPI 阈值
新知识沉淀 诊断中发现的规律被 ≥ 3 个独立案例验证 自动写入 PKB（type=best_practice, confidence=0.6→随验证数上升）
Skill 自动生成 同一诊断模式出现 ≥ 5 次 生成 SKILL.md 草稿 → 放入 skills/_drafts/ → FDE审核
原子写入 任何自动写入文件系统的操作 .tmp → fs.rename() → 旧版本备份到 versions/

FDE 审核门禁

自动进化不等于自动上线。所有自动生成的知识（PKB条目、校准后的阈值、Skill草稿）必须经过FDE审核：

  • 自动生成的条目标记为 status: "proposed" → FDE工作台审核 → 批准后变为 "active"
  • 被驳回的条目标记为 "rejected" + 驳回原因 → 30天后归档
  • FDE 可以修改自动生成的内容——系统记录修改痕迹（diff）

2. 设计原则

原则 1: 全量测量，不预设关系

每个客户全维度测量 D1-D6。不对任何客户关闭维度。不预设"规模越大混合成熟度越高"或"小公司 AI 用得更好"——一切交给数据。框架只定义"测什么"和"怎么测"，不预设答案。

原则 2: 规模只影响测量方式和沟通方式，不影响维度覆盖

Stage 0（1-19人）和 Stage 4（300-500人）测量同样的维度。差异在于：对话提问 vs 结构化采集，聊天中的洞察 vs 董事会报告。诊断范围不裁剪。

原则 3: 约束驱动——只解决那个卡住一切的问题

高德拉特 + 杨国安乘法 = 诊断的目的不是"找到所有问题"，而是"找到那个让乘积最小的因子"。action 专家的输出不是 20 条建议，是 1-3 个 90 天行动。

原则 4: 证据链完整——每个 claim 必须可追溯

从段永平到杨国安到六维 D1-D6——每个诊断结论必须标注：数据来源、推断边界、置信度。区分"来自数据的陈述"和"来自理论的推断"。

原则 5: 理论融合，不做拼凑

段永平 + 曾明 + 杨国安 + 波特 + 赫尔默 + 高德拉特……不是挂在墙上当装饰。每个理论在核心方程中有一个且仅有一个位置。各专家之间的输入输出关系明确定义，不重叠、不遗漏。

原则 6: AI 原生——做人类顾问做不到的事

人类顾问每年给企业看病一次。Synova 可以持续观测。人类顾问依赖个人经验做模式匹配。Synova 可以同时对比数千家企业的诊断。这不是更好的顾问——是不同物种的诊断能力。

原则 7: 自我进化——驻扎越久，诊断越精准

Synova 驻扎在企业内部后，从每次诊断实践中自动学习。行业基准随数据积累自动校准。重复出现的诊断模式自动生成 Skill 草稿。PKB 知识在验证中增强置信度、在闲置中衰减。这不是一次性部署的静态系统——它随客户一起成长。FDE 审核是唯一的人工门禁。

3. 诊断表达方法论

诊断理论决定了"判断什么"和"怎么判断"。但诊断结果如何呈现给客户——这是另一个维度的能力。以下方法论属于表达层，不参与核心方程的计算，但决定了诊断的可信度和可执行性。

3.1 麦肯锡方法：结构化表达

方法在 Synova 的应用
MECE
相互独立、完全穷尽		 每位专家的 findings 必须相互独立——如果 strategy 和 biz_model 同时说了"核心人依赖"，合成层必须去重。7位专家覆盖的维度必须穷尽核心方程的四个乘数，不遗漏。
金字塔原理
结论先行，再展开论据		 诊断输出的结构：Governing Thought（一句话核心判断）→ 3 Key Judgments（支持判断）→ Per-Judgment Evidence（证据链）。CEO 读第一句就知道结论，不需要翻7份报告。
SCQA 叙事
情境→冲突→问题→答案		 诊断开场白不是"以下是诊断结果"，而是"你的公司处于XX情境，但存在YY冲突，核心问题是ZZ，以下是答案"。建立紧迫感——让 CEO 理解为什么现在必须行动。
So What 测试
每句话回答"所以呢？"		 每个 finding 必须附带 quantified_impact："如果不解决，12个月内会损失X收入/Y客户/Z人才"。没有 So What 的发现是学术观察，不是诊断。
一天回答
每个问题可以在一天内给出方向		 Stage 0-1 的诊断应该在一次深度对话中完成。不追求全面——追求"今天能用的判断"。

3.2 贝恩方法：结果导向

方法在 Synova 的应用
100天计划 action 专家输出的不是"建议列表"，是带 owner、timeline、量化目标的 90 天行动方案。Week 1-2 = 快赢（momentum builder），Week 3-6 = 核心行动（解决约束），Week 7-12 = 系统建设（防止约束复发）。
Plan A / Plan B 双轨 action 强制产出两套方案：Plan A = 解决当前约束。Plan B = 如果 Plan A 在 3 个月后失败，应该启动的备用方案（转向提升另一个乘数）。这迫使诊断逻辑更严密——如果 Plan A 和 Plan B 指向完全不同的方向，说明当前诊断的置信度不足以选出一个最优约束。
结果追溯 诊断不是一次性交付。90 天后回测：Plan A 执行了吗？约束转移了吗？如果都没有——诊断本身需要修正。这是诊断系统的自我进化机制。

3.3 丰田/精益方法：现场现物

方法在 Synova 的应用

4.5 跨专家协同协议：颠覆信号的联合上报

strategy 和 business_model 都引用了克里斯坦森的颠覆式创新，但视角不同：

  • strategy 看外部威胁——"谁在你看不见的边缘做什么？"
  • biz_model 看内部进化——"你的模式能否被重构？"

当两者从同一数据源（如边缘客户流失、低端市场异常增长）中检测到颠覆信号时，不得各自给出孤立结论。必须联合上报一份"颠覆风险评估"——strategy 负责外部威胁判断（"这个颠覆者可能多快成长？"），biz_model 负责内部脆弱性判断（"我们的模式对这类颠覆有多脆弱？"）。两份判断合并为一份联合信号，标注为 crossExpert: strategy+business_model。

5.3 曾明价值循环的深度分析

除了分析"谁拿走了利润"，biz_model 必须强制评估以下两个问题：

  1. 谁最希望看到你成功？ → 在你的价值网络中，哪些参与者的利益与你的增长正相关？他们是否有动力主动帮你？这些人/组织是你的潜在战略盟友。
  2. 谁在无意识中阻碍你？ → 你的商业模式是否让某个利益相关者（渠道商、供应商、甚至你的员工）的利益与你的增长目标相悖？这些人不一定反对你——但他们的激励机制让他们无法帮助你。

这两个问题的答案直接引出：潜在的战略合作伙伴识别、隐藏的组织冲突预警。它们是价值循环分析的强制输出项——不是可选的"深入分析"。

5.4 画布的定位

画布不是分析工具——是沟通工具。段永平判断体质，曾明分析结构，画布把结论画出来让客户看懂。就像麦肯锡的 PPT——PPT 不是分析工具，是沟通工具。画布也是一样。

6.3a Key Person Risk 数学表达式（已工程化）

关键人才风险评分

Rperson = w1 · (1 / busFactor) + w2 · roleScarcity + w3 · (dependencyCount / N) + w4 · criticalKnowledgeRatio
其中:
  busFactor ∈ [1, N] — 掌握关键知识的人数（1 = 只有本人）
  roleScarcity ∈ [0,1] — 角色在组织/市场中的稀缺度
  dependencyCount ∈ [0, N−1] — 依赖此人的其他角色数
  criticalKnowledgeRatio ∈ [0,1] — 掌握的关键知识占组织总知识的比例
  w1+w2+w3+w4 = 1（默认可均权，可通过数据标定调整）
离职恢复时间 = busFactor × roleScarcity × dependencyCount × 30 天
判据: busFactor = 1 → 🔴 单点故障; recoveryTime > 90天 → 🔴 极高风险
工程化: packages/engine-core/src/pipeline/diagnosis/key-person-risk.ts

6.3b 混合信任模型 HTM 数学表达式（已工程化 · D3 硅基侧）

HTM 混合信任评分

HTMscore = α · trustCurveslope + β · (1 − autoAcceptRate) + γ · errorPropagationRate + δ · decayEventPenalty
其中 α+β+γ+δ = 1（权重可配置，默认可均权）
  trustCurveslope — HITL 修正频率的时间序列斜率（上升 = 信任在建立，下降 = 信任在流失）
  autoAcceptRate — Agent 输出被人直接接受的比例（越高 → 可能过度信任）
  errorPropagationRate — Agent→Agent 调用的错误传播率
  decayEventPenalty — 重大错误后修正频率突变检测的惩罚项
数据源: collaboration_events / routing_events / agent_metrics 表
判据: HTMscore < 0.4 → warning; 存在 decayEvents → critical
工程化: packages/engine-core/src/pipeline/diagnosis/htm.ts

6.3c D5 认知健康 · D6 进化适应性（研究阶段）

D5 认知多样性指数

D5diversity = 1 − HomogenizationRate
HomogenizationRate = |{输出对(i,j) : cos_sim(outputi, outputj) > τ}| / 总输出对数
参考: Ju & Aral (2025) — AI 辅助下的创意多样性坍塌实证研究
阈值 τ 需要基于至少 n=30 团队的因子分析标定
碳基侧: 决策多样性、批判性思维保留
硅基侧: 输出嵌入向量的余弦相似度分布

D5 补充指标：建设性冲突频率

多样性坍塌的反面不是"输出不一致"——是"没有人纠正任何人"。如果 Agent 之间、或人与 Agent 之间完全没有互相修正的记录（HITL 修正 = 0，Agent→Agent 反驳 = 0），这可能不是完美的对齐——而是集体盲区。

D5conflict = 互相修正事件数 / 总交互事件数
判据: D5conflict = 0 → 🟡 可能的集体盲区（如果同时 D5diversity 很高 → 矛盾：高多样性但零冲突 → 可能人在看 Agent 输出但不质疑）
D5conflict ∈ (0, 0.05] → 🟢 健康的建设性冲突
D5conflict > 0.15 → 🟡 可能过度冲突——信任机制未建立

D6 进化适应性比率

D6 = Rorg / max(Ragent, ε)   其中 ε = 0.01（最小分母，避免除以零）
Rorg = 组织学习速率 — 基于重构频率、变革准备度、新能力获取速度
Ragent = Agent 能力进化速率 — 基于模型升级部署延迟、能力漂移检测

判据: D6 > 1 → 组织进化快于 Agent → 治理有效
      D6 < 1 → Agent 跑在组织治理能力前面 → 🔴 诊断信号
      Rorg ≈ 0 → 混合成熟度为零（纯人组织或组织僵化）→ 本身就是一个诊断结论
      Ragent ≈ 0 → 组织没有部署 Agent → D6 退化为仅评估组织自身的学习速率，不参与混合成熟度计算

7. 专家 4: finance — 验证层

finance 验证层

7.1 理论支柱与数学表达式

杜邦分析 (1912)

ROE = (净利润 / 营收) × (营收 / 总资产) × (总资产 / 净资产)
= 利润率 × 周转率 × 杠杆乘数
诊断逻辑: 拆解 ROE → 利润薄？转得慢？还是杠杆高？→ 每一段对应不同的经营问题

现金流转换周期

CCC = DIO + DSO − DPO
DIO (Days Inventory Outstanding) = 存货 / 日均销售成本
DSO (Days Sales Outstanding) = 应收 / 日均营收
DPO (Days Payable Outstanding) = 应付 / 日均采购
诊断逻辑: CCC > 0 → 先干后收（段永平视角: 体质差）; CCC < 0 → 先收后干（体质好）

单位经济学

LTV / CAC ≥ 3 (健康阈值)
边际贡献率 = (客单价 − 变动成本) / 客单价
LTV (LifeTime Value) = 客单价 × 毛利率 × (1 / 流失率)
CAC (Customer Acquisition Cost) = 总销售与营销费用 / 新获客户数
LTV/CAC < 1 → 每获一个客户在亏钱; 1~3 → 需优化; ≥ 3 → 健康

7.2 诊断定位

finance 不改变核心方程的数值——它是验证器。用财务数据验证其他专家的诊断结论：

  • strategy 说"赛道好"→ finance 看利润率趋势是否支撑
  • biz_model 说"有定价权"→ finance 看毛利率是否稳中有升
  • org 说"组织能力弱"→ finance 看人力成本增速是否超过营收增速

当财务数据与专家诊断矛盾时——不是"标记并上报"，而是启动升级协议：

验证层矛盾升级协议

  1. 当 finance 或 marketing 的数据与 strategy / biz_model / org 的结论方向相反 → 不标记为"数据与诊断不一致"，标记为"诊断可能出错，或发现了异常信号"
  2. action 专家立刻介入——"我们可能诊断错了（置信度不够），或者我们发现了更深层的问题（如财务数据被美化、市场调研有偏差）"
  3. 如果矛盾无法在当次诊断中解决 → 降级整体置信度，标注"需人工复核的矛盾信号"

这不是验证层"推翻"诊断层——这是两套独立的传感器在互相校验。当两个传感器读数矛盾时，不是信哪个的问题，是"为什么会有矛盾"的问题。

7.3 规模自适应

小公司：现金流存续分析（"能不能再活18个月？"）。大公司：杜邦分析+多业务线独立核算。

10. 专家 7: action — 行动层

action 行动层

10.1 理论支柱与数学表达式

高德拉特约束理论 (1984) — 瓶颈决定总产出

Throughput = min(T1, T2, ..., Tn)
系统总产出由最慢的环节决定——优化非瓶颈环节不会提升总产出。
映射到 Synova 核心方程:
Bottleneck = argmin(战略质量, 组织能力, 混合成熟度)
诊断的含义不是"找到所有问题"，而是"找到那个让乘积最小化的因子"。
如果战略质量 = 0.8, 组织能力 = 0.3, 混合成熟度 = 0.7 → 瓶颈 = 组织能力。
此时不应该列 20 条建议——应该只解决组织能力，其他优化都是浪费。

五个聚焦步骤 (Five Focusing Steps) — 高德拉特原文映射

  1. 识别约束 → argmin(战略质量, 组织能力, 混合成熟度)
  2. 挖尽约束 → 在不增加资源的情况下，从约束中挤出最大产出
  3. 服从约束 → 所有非瓶颈环节的节奏服从瓶颈的节奏
  4. 提升约束 → 如果挖尽后仍不够，增加瓶颈的产能
  5. 重复 → 约束转移后，回到步骤1——不要让惯性成为新的约束
理论来源核心问题
100天计划贝恩咨询实践诊断的目的不是报告，是行动。结果导向
90天行动框架Synova 设计Week 1-2: 快赢（momentum builder）。Week 3-6: 核心行动（解决约束）。Week 7-12: 系统建设（防止约束复发）

10.2 诊断定位

action 是核心方程的输出端——接收所有专家的诊断，找到那个最接近零的乘数因子，把它转化为 CEO 可以立即执行的行动方案。不是 20 条建议——是1-3 个 90 天行动。

10.3 行动生成逻辑

  1. 识别约束：从所有诊断中找到得分最低的乘数因子
  2. 验证约束：finance 和 marketing 的数据是否支持"这是真正的瓶颈"？如果验证层与核心诊断矛盾 → 启动矛盾升级协议（见 §7.2）

10.4 Plan A / Plan B 双轨机制

action 强制产出两套方案，不是一套：

Plan A：解决当前约束Plan B：备用方案
目标提升得分最低的乘数因子如果 Plan A 在 3 个月后失败，转向提升另一个乘数
触发条件当前诊断置信度 ≥ 70%Plan A 执行 90 天后约束未转移 OR 出现新的关键信号
设计逻辑"我们判断 X 是瓶颈，这是解决 X 的方案""如果 X 不是真正的瓶颈，那 Y 可能是——这是解决 Y 的方案"

为什么需要 Plan B：如果 Plan A 和 Plan B 指向完全不同的方向（如 Plan A 要加大营销投入、Plan B 要收缩产品线），说明当前诊断的置信度不足以选出一个最优约束。此时 action 不应强行选一个——应降级置信度，标注"需更多数据以区分约束优先级"。

Plan B 不是"备胎"——它是诊断逻辑的压力测试。

10.5 行动设计

  1. 设计 Plan A：针对约束，设计 90 天行动——有 owner、有 timeline、有量化目标、有 first step
  2. 设计 Plan B：假设 Plan A 的约束判断是错的——次弱乘数是什么？对应的行动是什么？
  3. 排序：紧急度 × 影响力 → 不列 20 条，Plan A 列前 3 条，Plan B 列方向性建议

这是"AI 原生"的体现——不是被动等待指令，而是基于数据的主动发现。但不替用户做决定，不打断当前对话流。
