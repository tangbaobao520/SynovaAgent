Synova — 管理经济学知识体系设计

将经典管理经济学理论系统化地注入 8 位 AI 专家。每个知识点指定注入文件、注入方式、工程方法。

核心原则：每个知识点只在一个文件中维护。框架性知识进 THEORY.md（每次推理加载），分析工具进 TOOLS.md（信号触发时调用），约束规则进 RULES.md（行为边界），参考知识进 KNOWLEDGE.md（按需查询），完整方法论进 SKILL（独立加载）。

重要修正：所有理论在注入前需要考虑"人+Agent 混合组织"的修正。经典管理经济学以人类为前提——Agent 的搜寻/谈判/执行成本远低于人类，代理成本从"人不愿干"变成"Agent 不可预测地干错"，博弈论中 Agent 之间天然合作但和人博弈时产生新模式。每个知识点附带修正说明。修正来源详见章节七。

## 需求弹性估算

当诊断涉及定价、调价、价格敏感度分析时调用此工具。

### 价格弹性
ED = (DQ / DQ_0) / (DP / DP_0)
  ED > 1: 需求有弹性 — 降价可增收
  ED < 1: 需求无弹性 — 涨价可增收
  ED = 1: 单位弹性 — 价格变动不影响收入

### 估算方法（无回归条件下的简便方法）
1. 找到最近 2-3 次价格变动事件 + 对应的销量变化
2. 每次计算弹性值
3. 去掉极端值后取中位数
4. 标注置信度：数据点越多越可信

### 交叉弹性
EXY = (DQ_X / DQ_0X) / (DP_Y / DP_0Y)
  EXY > 0: Y 涨价 = X 销量增 → 替代品
  EXY < 0: Y 涨价 = X 销量降 → 互补品

### 混合组织修正（管理经济学原理论，加入与Agent相关的调整）
- Agent 可能实时调整价格（动态定价）→ 弹性的"反应时间窗口"缩短
- 竞争对手 Agent 也会调价 → 简单弹性模型可能失效
- 诊断结论标注"弹性估算基于历史数据，未考虑对手 Agent 的动态响应"

# 行为经济学诊断技能

## 触发条件
当以下信号出现时自动调用：
- 客户的定价/决策不符合理性预期
- 组织变革遇到"说不清理由"的阻力
- 客户行为在数据上不一致（说一套做一套）
- 管理者表现出明显的损失厌恶（宁愿不赚钱也不愿亏钱）

## 核心框架

### 前景理论
- 损失厌恶系数：人对损失的敏感度约为收益的 2-2.5 倍
- 诊断应用：当企业主拒绝一个数学上合理的下注时，考虑损失厌恶影响
- 建议标注："此方案理论上成立，但当事人可能有损失厌恶偏差——建议分阶段执行，降低首期风险感知"

### 锚定效应
- 初始值对后续判断的影响远超理性预期
- 诊断应用：在定价谈判、估值讨论中，初始报价设置会显著影响结果
- 建议标注："当前估值谈判差距较大——初始锚点设置不当可能是原因"

### 现状偏误
- 人们倾向于维持现状，即使改变是理性的
- 诊断应用：组织变革建议被拒绝时，区分"理性反对"和"现状偏误"
- 建议标注："此方案的拒绝可能包含现状偏误因素"

## 输出格式
当应用行为经济学分析时，输出必须包含：
1. 识别的偏差类型
2. 该偏差可能导致的后果
3. 建议的干预措施
4. 标注信心水平（高/中/低）

为什么 behavioral-economics 是 SKILL 而不是 TOOLS.md：行为经济学包含完整的推理链条（识别偏差 -> 诊断影响 -> 给出干预），不是单一的分析工具。Agent 不需要在每次推理时都加载行为经济学框架，只在遇到"人的行为不符合理性预期"的信号时才调用。SKILL 按需加载机制正好满足这个需求。

## 委托-代理分析框架（基于管理经济学）

### 代理问题的识别条件
当以下三个条件同时成立时，存在代理问题：
1. 委托人和代理人的目标不一致
2. 存在信息不对称——委托人无法完全观察代理人的行为
3. 风险分担——双方对风险的偏好不同

### 代理成本的三种类型
- 监督成本：委托人为监督代理人行为的投入
- 约束成本：代理人为证明自己行为合理的投入
- 剩余损失：即使有监督和约束，代理人的决策仍然偏离委托人最优

### 道德风险的五大检测信号
1. 偷懒（输出下降但投入资源未减）
2. 在职消费（费用异常为最典型的代理信号）
3. 短期行为（可量化的短期指标好，长期指标差）
4. 风险规避（放弃正 NPV 但不确定的项目）
5. 帝国建设（管理者持续扩张职权范围而非提升效率）

### 混合组织修正
- Agent 作为"代理人"时，不产生传统意义上的代理成本（Agent 不会"偷懒"）
- 但 Agent 可能产生新的"对齐成本"——训练目标和真实目标不一致导致的偏差
- 对齐成本的检测方式：Agent 输出与实际表现不一致时，标注 "possible alignment drift"
- 参考: Hadfield & Sultan (2025) "Contracting with AI"

## 激励机制诊断工具

### 效率工资理论 — 适用条件检测
当以下条件满足时，建议考虑提高薪酬而非增加监督：
- 监督成本高（工作成果难以量化）
- 员工流动成本高（培训期长、知识留存在个人）
- 员工对薪酬的弹性高（外部市场工资上涨）

### 锦标赛理论 — 适用条件检测
当以下条件满足时，晋升竞争是有效的激励：
- 个体绩效可以可靠衡量
- 团队合作不是成功的关键
- 晋升通道清晰

### 团队激励 — 搭便车问题检测
当任务满足以下条件时，存在搭便车风险：
- 任务需要多人协作完成
- 个体贡献无法精确区分
- 按团队绩效付酬

搭便车风险的缓解措施（按效果排序）：
1. 缩小团队规模（降低搭便车的匿名性）
2. 加入 peer evaluation（同事评价）
3. 混合激励（50% 团队 + 50% 个人）
4. 减小可见度（对明确的个体贡献额外奖励）

具体实施 — org/RULES.md 新增约束：

- 不推荐具体的薪酬数字、股权比例、奖金百分比
- 不替代律师起草激励合同或竞业限制协议
- 标注 "此建议基于激励理论框架，具体金额需要结合企业财务状况并由专业 HR 确定"
- 当人在Agent环境下共同工作时，关注人的动机可能被Agent提升的工作"挤出"的心态变化

为什么 THEORY.md 而不是 SKILL：委托-代理是组织顾问每次推理都必须使用的核心理论框架，不是按需加载的技能。每次诊断组织问题时，Agent 都需要知道"存在信息不对称 + 目标不一致 = 委托-代理问题"这个因果链。如果放在 SKILL 中，Agent 可能因为忘记加载 SKILL 而直接用营销语言的描述代替了结构化推理。

## 信息不对称 — 技术决策的核心约束

### 技术决策中的信息不对称来源
1. 供应商 vs 采购方：供应商比采购方更清楚产品的真实能力
2. 开发团队 vs 管理层：开发团队比管理层更清楚技术债的规模
3. 候选人 vs 招聘方：候选人比招聘方更清楚自己的真实能力

### 柠檬市场在技术决策中的表现
- 技术外包中的逆向选择：愿意接受最低价的往往是能力最差的团队
- 信号发送的作用：技术认证、开源贡献、技术博客是成本信号——只有有能力的人才负担得起
- 信号的可信度判断：认证是最弱信号（可作弊），开源贡献是强信号（可验证），同行推荐是最强信号（社会成本）

### 混合组织修正
- Agent 可以大幅降低信息不对称——实时监控代码质量、自动检测技术债
- 但 Agent 本身的信息透明需要独立验证——Agent 的诊断过程必须可审计
- 标注: "此诊断基于 Agent 对代码仓库的自动分析，已标记分析置信度"

## 市场结构四象限（管理经济学基础）

| 类型 | 企业数量 | 产品差异 | 进入壁垒 | 定价能力 |
|-----|---------|---------|---------|---------|
| 完全竞争 | 极多 | 无 | 无 | 无 |
| 垄断竞争 | 多 | 有 | 低 | 有限 |
| 寡头 | 少数 | 可有可无 | 高 | 强 |
| 垄断 | 一个 | - | 极高 | 极强 |

### HHI 指数 (Herfindahl-Hirschman Index)
HHI = S1^2 + S2^2 + ... + Sn^2
  < 1500: 不集中
  1500-2500: 中度集中
  > 2500: 高度集中 — 需要提示反垄断风险

- Agent 驱动的定价算法(非高深算法)会自动学会隐性合谋 — 参考 Calvano (2024)
- 即使没有明确的竞业协议，共享相似的定价训练数据可能会诱发定价趋同
- 诊断中发现同行倾向时，标注"存在算法共谋的可能性"

# 博弈论诊断技能

## 触发条件
行业结构为寡头竞争时自动调用。Agent 检测到市场中只有 2-5 家主要竞争对手时。

## 核心分析框架

### 博弈类型识别
1. 囚徒困境 — 个体理性导致集体非理性
   识别条件：双方都有背叛的激励，总合作收益 > 总背叛收益
   诊断场景：价格战、广告战

2. 协调博弈 — 双方利益一致但需要协调行动
   识别条件：合作是弱最优策略
   诊断场景：行业标准制定

3. 鹰鸽博弈 — 一方显示强势可获利
   识别条件：双方对手都在争夺但只能一个获利
   诊断场景：市场进入

### 重复博弈与合作
- 如果博弈无限期重复，合作是可能的（触发策略/以牙还牙）
- 识别条件：有限次数则倾向于背叛

### 可信承诺
- 承诺是否可信 = 执行承诺的成本是否高到让对方相信
- 先发优势——承诺一旦执行就无法撤销（如大额固定资产投资） 才是最可信的

### 混合组织修正
- Agent 博弈：Agent 之间在同样的训练规则下天然倾向合作——与合作博弈里的合作条件相一致
- 人-Agent 博弈：人对 Agent 有不信任倾向（Crandall 2024），即使在合作条件下也可能采取背叛
- 在面对这样混合博弈时，标注"存在 Agent 非理性背叛的风险"

## 输出格式
1. 博弈类型
2. 当前均衡状态
3. 如果偏离均衡，建议的反应策略
4. 人-Agent 混合风险标注

## 交易成本分析

### 交易成本的四种来源
1. 搜寻成本 — 找供应商/客户/合作伙伴所需的时间
2. 谈判成本 — 达成协议所需的时间和资源
3. 执行成本 — 确保协议被执行的成本
4. 监督成本 — 检查对方是否履约的成本

### 最佳治理结构矩阵
| 交易频率 \ 资产专用性 | 低 | 中 | 高 |
|--------------------|---|---|---|
| 低 | 市场采购 | 市场+合同 | 内部化 |
| 中 | 市场采购 | 混合治理 | 内部化 |
| 高 | 市场采购 | 混合治理 | 内部化 |

### 混合组织修正（重要）
经典交易成本理论以人为前提。在人+Agent 混合组织中，交易成本需要重新估算：
- 搜寻成本：Agent 可毫秒级检索 → 下降 90%+
- 谈判成本：Agent 用结构化 schema 做契约 → 下降 70%+
- 执行成本：Agent 可自动执行 → 下降 80%+
- 监督成本：Agent 可实时验证，但 Agent 本身的输出需验证 → 可能有上升

科斯的结论是"企业存在是为了将交易成本高的活动内部化"——这个结论有效，但临界点变了。
原本应该内部化的活动（因为人做交易成本太高），现在可能可以通过 Agent 市场更有效率地完成。
诊断中标注"基于 Agent 交易成本折价后的建议"。

## 资本预算四工具

### 1. 净现值 (NPV)
NPV = S(CF_t / (1+r)^t) - I0
- NPV > 0: 应该投资（项目回报超过资本成本）
- 核心原则：NPV 是唯一不会犯错的资本预算方法

### 2. 内部收益率 (IRR)
- IRR = NPV = 0 时的折现率
- 当 IRR > 资本成本时，项目可行
- 注意：IRR 在非传统现金流（正负交替）时可能产生多重根
- 冲突时以 NPV 为准

### 3. 回收期
- 多少年能收回初始投资
- 简单但不考虑货币时间价值。仅做参考

### 4. 盈利指数 (PI)
PI = NPV / I0（每投入 1 元获得的净现值）
- PI > 1: 可行
- 用于资本有限时的项目排序

### 成长型企业应用注意
- 预测自由现金流是最困难的一步。标注置信度
- 折现率应包含企业特有的风险溢价
- 成长快但历史短的企业，预测偏差可能很大

## 成本结构深度分析

### 固定成本 vs 变动成本识别
- 固定成本 = 无论产出多少都要支出的成本（房租、底薪、设备折旧）
- 变动成本 = 随产出线性变化的成本（原材料、计件工资）
- 混合成本：半固定/半变动——需要用高低点法或回归分解

### 规模经济 vs 学习曲线
- 规模经济：产出增加时平均成本下降（固定成本摊薄）
- 学习曲线：累计产量增加时单位成本下降（效率提升）
- 两者的区别：规模经济来自产能利用率提升，学习曲线来自经验和效率积累

### 盈亏平衡点
BEP = 固定成本 / (单价 - 单位变动成本)
- BEP 越低，企业的抗风险能力越强
- 经营杠杆系数 = (收入 - 变动成本) / 利润
- 杠杆越高，收入波动对利润的影响越大

### 混合组织修正
- Agent 可以降低变动成本（替代计件工、客服等）但固定成本不变（系统维护）
- 产品化软件的增量成本几乎为零 — 这是典型的规模经济
- 当人工转换为自动化与Agent化后，企业的成本结构将发生深层重组，盈亏平衡点需要重新校定
