2. Q2: 人+AI 协作实证研究（2023-2026）

2.1 元分析级证据

⚠️ 核心发现：不存在人+AI 协同效应（Synergy）

RCT元分析 Vaccaro, Almaatouq & Malone (2024), Nature Human Behaviour — 106 个实验、370 个效应量的系统性元分析。[6]

比较效应量 (Hedges' g)95% CI解读
人+AI vs 纯人+0.64[0.53, 0.74]显著增强
人+AI vs 最优单方−0.23[−0.39, −0.07]显著损失
决策任务中协同−0.27—显著损失
创造任务中协同+0.19—正向但不显著 (n=34)

当 AI 单独表现优于人类时，人+AI 反而产生 −0.54 的协同损失——人类难以判断何时信任 AI，拖累了组合表现。

2.2 大规模现场实验

2.2.1 客服领域

准实验 Brynjolfsson, Li & Raymond (2025), Quarterly Journal of Economics — 5,172 名客服人员，GPT-3 实时辅助。[7]

  • 平均生产率 +15%（解决问题数/小时）
  • 新手增益 +35%，高经验者几乎无增益
  • AI 断线时技能持续保留（不是"工具依赖"，而是"技能转移"）
  • 客户满意度微升，员工离职率下降（尤其新人）
  • 关键机制：AI 充当了"隐性知识捕获器"——将高绩效者的经验编码并传播给新人

2.2.2 创意团队协作

RCT Ju & Aral (2025), MIT MindMeld — 2,234 名参与者随机分配人+人 vs 人+AI 团队，创作 11,024 条广告，5M+ 曝光量实地验证。[8]

  • 人+AI 团队广告产出 +50%/人，文字质量更高
  • 通信量 +137%，但社交消息 -23%（任务导向更强）
  • 多样性坍塌（Diversity Collapse）：人+AI 产出更同质化
  • 人+AI 团队更倾向委托（+17% delegation），直接编辑量 -62%
  • 关键机制：AI 降低了社会协调成本，让人类专注于内容

2.2.3 软件开发

准实验 Cui et al. (2025) — 4,867 名开发者，Microsoft/Accenture/Fortune 100 企业使用 GitHub Copilot。[9]

  • 周完成任务 +26%，代码编译量 +38%
  • 经验少的开发者受益更大（技能差距缩小）
  • 无质量损失

2.2.4 创业与知识工作

  • RCT Otis et al. (2023) — 640 名肯尼亚创业者，GPT-4 via WhatsApp：整体平均效应为零。高绩效者收入 +15%，低绩效者 −8%。效果取决于如何筛选和应用建议，而非使用频率。[10]
  • 准实验 Dillon et al. (2025) — 7,137 名知识工作者，66 家企业使用 Microsoft 365 Copilot：邮件时间 −31%（~3.6小时/周节省），文档完成速度 +5～25%，但总产出量无变化，对会议和团队工作的影响极小。[11]

2.3 跨研究涌现规律

五个可复现的实证规律

  1. 任务类型决定一切 — 结构化/创造性任务受益最大；模糊/判断密集型任务效果混合甚至为负
  2. 技能水平决定方向 — AI 可以是"平等器"（客服、编程）或"放大器"（电话营销、创业）——取决于整合设计
  3. 整合设计是关键杠杆 — 实时副驾驶帮助新手；顺序性分工帮助专家
  4. "锯齿状技术前沿"（Dell'Acqua et al., 2023） — AI 在某些领域出色但在其他领域意外失败，专业人士存在"自动化忽视"[12]
  5. 多样性代价 — 在无干预情况下，人+AI 产出趋于同质化（Ju & Aral 2025 的"多样性坍塌"）

3. Q3: 经典组织理论的 AI 盲区

3.1 三大经典模型核心假设及失效分析

模型 核心维度 隐含假设 在混合组织中的失效
McKinsey 7S
(Peters & Waterman, 1982)		 Strategy 战略由人类高管制定，执行由人类员工完成 ✗ Agent 可以自主生成策略选项、执行策略步骤、实时调整策略参数——战略制定与执行的边界模糊化

Shared Values 价值观是人类共享的信念和规范 ✗ Agent 没有内在价值观，只有训练时对齐的偏好。需要"价值观治理层"对外输出行为约束（宪法 AI、护栏 Agent）

Style 领导风格是人类管理者的行为模式 ✗ "领导力"从"控制范围"转向"认知范围"（Forbes 2025）。管理者领导的不只是人，还有人+Agent 混合团队
Galbraith Star
(Galbraith, 1960s-2014)		 Strategy 战略决定组织设计方向，战略→结构→流程→人 线性推导 ✗ Agent 能力边界以月为单位扩张，战略需实时调整。"设计序列"假设环境变化慢于设计周期——在AI时代不再成立
Structure 权力和决策权分布在人类层级中 ✗ 决策权可以委托给 Agent（Forbes "委托章程"）。决策权的分配不再是人类零和游戏

Rewards 激励系统对齐人类员工目标与组织目标 ✗ Agent 不需要薪资、晋升、奖金。激励系统需重构为"目标对齐机制"——不仅激励人，还要配置 Agent 的目标函数和护栏
People 人才通过招聘、培训、职业发展路径培养 ✗ "人才"概念扩展为"碳基人+硅基人"。人力政策从招聘变为"配置+编排+监督"

(容不容许)		 组织架构和流程允许员工施展能力 ✗ 治理对象从纯人扩展为人+Agent。"容许"的含义从"给员工授权"变为"给Agent设定操作边界"。杨国安3.0已部分意识到这点但未系统化

3.2 经典模型共同的四个致命假设

  1. "组织由人组成" — 三大模型的设计单元都是人类。Agent 不是人，不需要激励、不跳槽、不疲劳、能力可瞬间复制。组织设计的最小单元需要从"人"扩展为"能力承载者"。
  2. "能力通过学习和经验线性积累" — Agent 能力通过模型升级跳跃式提升。组织能力发展从"学习曲线"变为"部署曲线"。
  3. "层级是协调的主要机制" — Agent 可以通过编排层（API 调用、消息传递）实现无层级协调。Mintzberg 的五种协调机制中，"直接监督"和"工作流程标准化"被 Agent 编排替代。
  4. "决策权是人类管理者的专属" — Agent 可以在定义好的边界内自主决策。决策权从"官大一级压死人"变为"谁的模型在这个任务上更可靠"。

4.2 跨模型涌现的共同维度

对上述 9 个模型做语义聚类后，出现了 5 个高度一致的维度主题：

  1. 治理与控制 — 所有模型都强调：实时治理、护栏机制、人类最终问责、信任架构
  2. 角色与能力重构 — 新角色（编排者、AI赋能者、桥梁型人才）；新能力（算法素养、混合协作、快速伦理判断）
  3. 结构扁平化/网络化 — 从层级制到 Agent 团队网络；"认知范围"取代"管控范围"
  4. 数据与基础设施 — Agent 网格、MCP/API 接口标准、专有数据护城河
  5. 人机协作动态 — 不是"人用工具"，而是"人+Agent 双向反馈+共同进化"

但缺失了一个关键维度：没有任何模型系统化地处理"组织能力在混合团队中如何测量和诊断"——这正是 Synova 的核心差异化空间。

5. Q5: Synova 工作假设 — 理论框架 v0.1

🎯 Synova "人+Agent 混合组织能力模型" v0.1

设计原则

  1. 简约性：≤ 6 维度，对标杨三角的三维简洁性
  2. 诊断性：每个维度可被测量（通过 Synova 诊断管线）
  3. 可行动性：诊断结果指向具体干预（而非仅描述问题）
  4. 混合视角：每个维度同时覆盖"碳基人"和"硅基Agent"
  5. 动态性：承认 Agent 能力边界以月为单位位移

5.1 工作假设体系

核心假设（6 条）

  1. 目标对齐假设：混合组织的失效首先发生在目标对齐层——人不知道 Agent 在做什么，Agent 的目标函数与组织目标存在隐性偏移。D1 是最优先的诊断入口。
  2. 能力拓扑假设：组织能力不是"人+Agent"的简单叠加，而是特定组合在特定任务上的"匹配质量"。Vaccaro (2024) 的"谁更擅长什么任务"是 D2 的诊断核心。
  3. 协作回路假设：持续有效的协作需要双向反馈回路（HITL + AI2L），断掉的回路是性能损失的早期信号。D3 测量反馈回路的完整性。
  4. 治理缺口假设：大多数组织的 Agent 部署存在"治理真空"——Agent 在运行但没有委托章程、护栏或审计。D4 缺口是最危急的安全风险。
  5. 认知健康假设：无干预的人+AI 系统趋于同质化（多样性坍塌），D5 是早期预警。认知异化（Lin et al. 2025）是进阶风险——人对 AI 输出的解释性控制丧失。
  6. 适应速率假设：组织的进化速率必须大于 Agent 能力的进化速率，否则 Agent 会跑在组织的治理能力前面。D6 测量这个速率差。

6.2 关键工程决策

  1. 数据采集：D1-D6 依赖的数据源是混合的——日历/消息/任务系统（结构化）+ 对话日志（半结构化）+ 组织图/角色定义（文档）。需要新的 Collectors 覆盖这些源。
  2. 评价指标：铁律 29（调优前指标验证）在此处关键。D5 的"多样性指数"需要用真实团队数据验证——两个确认应相似的团队得高分、两个确认应不同的团队得低分——才能进入优化循环。
  3. 隐私边界：D1（目标对齐）和 D2（能力分布）涉及个体层面的敏感数据。需要匿名化聚合层 + 团队级别的报告（不暴露个人）。
  4. Agent 审计：D4（治理结构）需要能审计 Agent 的系统提示词、护栏配置、决策日志——这要求与 Agent 运行时有接口（MCP 或 API 端点）。

7. 未解问题清单

理论层面

  1. 六维框架的结构效度 — D1-D6 是理论推导的维度，是否真的独立？需要因子分析验证（至少 n=30 个团队）。
  2. 跨文化有效性 — Lee (2025) 的实证来自韩国企业，杨三角来自中国经验，McKinsey/Deloitte 来自欧美大型企业。六维框架对东南亚/中东/非洲中小企业的适用性完全未知。
  3. 组织规模效应 — 5 人创业团队 vs 500 人中企业 vs 5000 人大企业——六维框架是否对规模有结构性偏移？小团队可能 D6 占优但 D4 缺失。
  4. Agent 能力水平的调节 — 如果 Agent 能力极弱（如当前 2026 年水平的客服机器人），六维框架哪些维度退化？如果 Agent 能力达到 AGI 级别呢？
  5. D5 认知健康的"正常范围" — 多样性坍塌到什么程度算病态？所有组织都有一定程度的同质化（企业文化本身是认知对齐）。正常与病态的阈值在哪里？

实证层面

  1. 因果性与相关性 — 当前最强的实证证据（Vaccaro 2024）是元分析而非因果实验。我们无法确定"好的治理结构（D4）导致好的性能"，还是"性能好的公司有多余资源建治理结构"。
  2. 纵向数据缺失 — 零个研究跟踪同一个混合组织超过 2 年。Agent 能力在进化、人在适应、组织在重构——三重共同进化缺乏时间序列数据。
  3. 失败案例的发表偏倚 — 所有已发表研究都是"有 AI 接入的团队"——选择偏差严重。最需要研究的是"接入 AI 后崩溃的团队"，但这些人不会参与学术研究。
  4. D6 进化适应性的测量 — 如何在不干扰组织的情况下测量"组织学习速度"？现有工具（组织变革准备度问卷）是为年度调查设计的，不适配持续监测。

工程层面

  1. Agent 审计的接口标准 — D1 和 D4 需要读取 Agent 的内部状态（提示词、护栏、决策日志）。当前没有标准化的 Agent 审计接口——Anthropic 的 MCP 是最接近的但不够。
  2. 诊断频率 — 持续监测 vs 定期诊断？Agent 能力以月为单位进化，但组织结构的重构以季度/年为单位。多频繁才算"够快"？
  3. 推荐的可行动性 — "多样性指数过低"是诊断，但"如何增加多样性而不引入噪音"是产品问题。诊断→推荐的映射需要领域知识。可以用 LLM 生成推荐但需要验证。
