Agent 生态对接方案

客户主动接入，不碰厂商利益 · 2026-06-05

纠正思路

前两个版本都错了：

  • 第一版（Hook 注入）：错在试图修改别人的商业产品
  • 第二版（文件系统观测）：错在用"偷看"的方式，不是客户主动的行为

正确的逻辑：

  • 客户已经部署了 Synova，目的是看清自己的组织和 Agent 生态
  • 客户愿意把自己的 Agent 接进来——这是价值交换
  • 我们提供的是对接工具，不是监控手段
  • 用每个平台官方支持的扩展方式接入——不会触犯任何厂商的利益

一、核心理念：用各平台的官方扩展机制对接

平台/生态官方扩展方式我们提供的对接工具能否被封杀？
OpenClaw 生态（含 QClaw/AtoClaw/EasyClaw）Skills 机制 + 插件系统一个 OpenClaw Skill，客户安装后 Synova 即可感知 Agent🟢 不能——Skill 是 OpenClaw 官方的扩展方式
MCP 生态（Claude Code 等支持 MCP 的 Agent）MCP Server 注册一个 MCP Server，Agent 配置后 Synova 即可通信🟢 不能——MCP 是开放的标准化协议
HermesPlugin 系统 + 工具注册一个 Hermes Plugin，安装后自动上报🟢 不能——Plugin 是 Hermes 官方的扩展方式
LangChain / CrewAI / AutoGenTool/回调注册一个 Python SDK，一行代码接入🟢 不能——使用官方的 Tool 注册 API

二、各平台的对接实现

2.1 OpenClaw 生态 — Skill 方式

客户安装一个 Skill，就像安装任何其他 Skill 一样

客户在 OpenClaw 中安装 Synova 的 Skill：

# ~/.openclaw/agents/team-a/skills/synova-telemetry/SKILL.md
---
name: synova-telemetry
description: 向 Synova Agent 汇报本 Agent 的活动
allowedTools: ["skill_view", "skill_manage", "file_read"]
triggers:
  - after_tool_call
  - after_subagent_spawn
  - on_completion
---

安装方式：
  cp -r synova-telemetry ~/.openclaw/agents/team-a/skills/
  # 或者通过 OpenClaw 的 skill marketplace 一键安装

效果：
  当 Agent 执行工具调用、创建子 Agent、完成任务时，
  这个 Skill 会通过 HTTP 向 Synova 汇报活动摘要。
  Synova 收到后写入 SOG → 专家可分析。

Skill 内部的实现：

// 一个轻量级的 HTTP 上报客户端
// 不会影响 Agent 的正常工作
// 上报数据是 Agent 活动摘要，不含敏感对话内容

type ActivityReport = {
  agentId: string;
  agentName: string;
  teamId: string;
  activityType: 'tool_call' | 'subagent_spawn' | 'task_complete';
  toolName?: string;
  durationMs?: number;
  success?: boolean;
  timestamp: string;
};

// 上报失败不影响 Agent——不阻塞、不重试
fetch('http://localhost:3000/api/agent-telemetry/report', {
  method: 'POST',
  body: JSON.stringify(report),
  signal: AbortSignal.timeout(1000), // 1s 超时
}).catch(() => {}); // 静默失败

为什么不会被封杀：

  • OpenClaw 官方支持 Skills 扩展机制——这是设计时就预留的能力
  • QClaw/AtoClaw/EasyClaw 如果兼容 OpenClaw 的 Skill 系统，这个 Skill 就能用
  • 如果某家厂商的封装不支持 Skill 系统，那是他们自己的兼容性问题，不是我们"注入"

2.2 MCP 生态（Claude Code 等） — MCP Server 方式

客户在 Agent 的 MCP 配置中加入 Synova

Claude Code 的 MCP 配置：

// ~/.claude/settings.json
{
  "mcpServers": {
    "synova": {
      "command": "npx",
      "args": ["@synova/mcp-server"],
      "env": {
        "SYNOVA_URL": "http://localhost:3000",
        "AGENT_NAME": "claude-code-dev",
        "TEAM_ID": "engineering"
      }
    }
  }
}

// 配置后，Claude Code 在每次对话结束时会自动调用
// synova 的 report_activity 工具，汇报本轮活动摘要

// 同时，Synova MCP Server 也提供诊断工具供 Claude Code 调用：
// - get_org_health: 查询组织健康状态
// - query_team_insight: 查询特定团队的诊断发现
// 实现"Agent 能感知组织健康"的闭环

OpenClaw 同样支持 MCP，配置方式类似：

// ~/.openclaw/openclaw.json
{
  "mcpServers": {
    "synova": { ... }
  }
}

MCP 的优势：

  • MCP 是开放的标准化协议（Anthropic 提出，已广泛采用）
  • Claude Code、OpenClaw、Cline、Continue 等都支持
  • 一个 MCP Server 对接所有 MCP 兼容的 Agent
  • 双向通信——Synova 接收上报，Agent 也能查询诊断结果

2.3 Hermes — Plugin 方式

客户在 Hermes 的配置中加载一个 Plugin

// ~/.hermes/config.yaml
plugins:
  - name: synova-telemetry
    path: ~/.hermes/plugins/synova-telemetry/
    enabled: true

2.4 LangChain / CrewAI / AutoGen — SDK 方式

一行代码接入

# 客户在自己的 Agent 代码中添加一行
from synova_telemetry import SynovaCallback

# LangChain
chain = create_chain(callbacks=[SynovaCallback()])

# CrewAI
crew = Crew(agents=[...], task_callback=SynovaCallback())

# AutoGen
agent = ConversableAgent(
    name="my_agent",
    human_input_mode="NEVER",
    callbacks=[SynovaCallback()]
)

# 一行代码，不影响业务逻辑，不改变 Agent 行为。
# 只是多了一个"向 Synova 上报活动摘要"的监听器。

三、对接后能实现的能力

能力实现方式谁受益
看到组织中所有 Agent 的运行状态通过上报数据创建 SOG 的 AGENT 节点客户管理者
分析 Agent 团队协作效率上报的 INTERACTS_WITH 边 → 组织专家客户管理者
Agent 工具调用审计上报的 tool_call 记录 → 安全合规客户安全团队
Agent 成本分析LLM token 消耗 → 财务专家客户财务
Agent 健康诊断失败率、超时、循环检测 → 技术专家客户技术团队
Agent 获得组织上下文MCP 工具查询诊断结果Agent 本身（更聪明）

四、风险和厂商关系

风险分析缓解
OpenClaw 官方认为 Skill 是"后门"不可能。Skill 是 OpenClaw 官方设计用来扩展功能的机制，所有 Skill 源码可见、行为可控。Agent 管理者可以选择不安置。不需要缓解
QClaw/AtoClaw 的封闭生态不兼容如果他们的封装备了 Skill 系统，就能用。如果砍掉了，我们需要适配他们的私有扩展方式——但那也是他们的官方扩展方式，不是注入。按各平台官方扩展方式适配
上游 OpenClaw 增加反制机制如果 OpenClaw 增加"禁止向 localhost:3000 发 HTTP"的限制，那就影响所有本地服务 Skill，不止我们一家。可能性极低，真发生了可以通过 MCP 通道
客户担心数据安全上报的是 Agent 活动摘要（工具名、耗时、成功/失败），不是对话内容。客户可以配置上报粒度。文档说明 + 可配置的脱敏级别
