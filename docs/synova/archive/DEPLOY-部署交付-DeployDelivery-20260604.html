部署交付方案

非开发者用户 · 数据本地 · 安装即用

核心约束

  • 用户不是开发者——不能要求他们敲命令、配环境、调参数
  • 数据本地是价值——用户愿意给足数据的前提是"数据不出自己的机器"
  • 云服务可选——部分用户可以接受 SaaS，但不是默认选项
  • 安装即用——下载→双击→配置飞书→开始诊断，三步以内

关于方案 A（桌面端）的可行性

前提：Novis 已经有了 Electron 打包基础设施

box/build-desktop.js 已经能打包 Electron 桌面应用。server/public/ 已经 serve 前端页面。SynovaAgent 也是 Express 服务器——和 Novis 共用同一个架构模式。

修改 build-desktop.js 或创建新的 build-synova.js，主要调整：

// 桌面端应用 ≈ Electron 主进程 + Express 子进程 + Python 子进程

┌──────────────────────────────────────────────┐
│  Electron 主进程 (main.ts)                    │
│  ├── 启动 Express 服务器（子进程）             │
│  ├── 启动 Python Bridge（子进程，按需）        │
│  ├── 打开系统托盘 + 自动启动浏览器             │
│  └── 更新检查 + 自动更新                       │
├──────────────────────────────────────────────┤
│  Express 服务器 (server.ts)                   │
│  ├── 健康检查 / SSE / API                     │
│  └── Serve React 前端                         │
├──────────────────────────────────────────────┤
│  Python 侧车 (child_process)                  │
│  ├── 飞书连接器                               │
│  └── NLP/分析（后续）                          │
└──────────────────────────────────────────────┘

用户机器上的目录结构：
~/synova-data/
├── synova.db          # SQLite 数据库
├── uploads/           # 上传的文档
├── .env               # 飞书凭证
└── logs/              # 日志文件

桌面端的安装体验（用户视角）

Step 1: 访问 synova.ai → 下载 Windows/Mac 版
Step 2: 双击安装 → 安装完成 → 自动打开浏览器到 http://localhost:3000
Step 3: 在界面上配置飞书 App ID + App Secret
Step 4: 点击"开始诊断" → 看到自己的组织数字孪生

整个安装过程：< 5 分钟，零命令行。

三种方案的关系

时间线：

本月（第一个客户，你就是 PDE）：
  └── 方案 B（Docker）或直接 npm run dev
       └── 你在客户机器上配好环境

下个月（有 3-5 个客户）：
  ├── 方案 A（桌面端）发布
  │    └── 用户自己下载安装
  └── 方案 C（SaaS）MVP
       └── 简单的多租户版本

远期（产品规模化）：
  ├── 桌面端 = 主要获客渠道（数据在本地 = 信任）
  ├── SaaS = 愿意交数据换便利的用户
  └── Docker = 有 IT 团队的企业客户

三个方案共享同一套核心代码（Express + Python + SQLite），区别只在于外层包装。所以不是"做三个版本"，是"一套核心 + 三种包装"。先做 Docker（你帮客户部署），桌面端和 SaaS 后续加。

对你当前交付的影响

本次只做一个改动：把 Docker 方案调整为 PDE 友好

原计划（假设有 IT）:
docker compose up -d    # 需要客户理解 Docker

调整为（PDE 实施）:
# 步骤 1: 你登录客户的 Windows 机器
# 步骤 2: 安装 Node.js 20 + Python 3.12（一键安装包）
# 步骤 3: 运行我们提供的 setup.ps1（PowerShell 脚本）

# setup.ps1 自动完成：
# 1. git clone / 解压 release 包
# 2. npm ci
# 3. pip install -r requirements.txt
# 4. 交互式配置飞书凭证（提示输入 App ID / App Secret）
# 5. 配置开机自启（Windows Task Scheduler）
# 6. 启动服务 → 打开浏览器

# 你也可以选择 Docker 方式（如果你自己熟悉 Docker）:
# 客户机器上装 Docker Desktop，docker compose up -d
# 但大多数非开发者的 Windows 机器上可能没有 Docker
