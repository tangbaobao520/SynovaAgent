1. Current Ontology Diagnosis

Three fatal flaws:
1. Financial is a monster KV node (17 optionalProps, 29/75 compute functions read it as raw KV)
2. Edges are relationship labels, not causal carriers (5/17 edges unused by any sentinel)
3. Causal logic is hardcoded in compute functions, not encoded in the ontology graph

The problem is NOT 'too few node types'. It's that edges only answer 'does a relationship exist?' — not 'what causal parameter can the compute function extract?'

2. Entity Universe: First-Principles Derivation

Growth is a cycle: Enterprise acquires Resources → organizes Activities to transform resources into value → value crystallizes as Outcomes in the market → part of outcomes feedback as new Resources.
Three entity categories map to three cycle stages.
LayerCountCore Question
Resources13What can be transformed into growth?
Activities8How are resources organized to create value?
Outcomes8What results from activities, and can they feed back?
Causal Edges10What causal parameters connect these layers?

Why 10 edges instead of 17? Old edges were relationship labels (does X relate to Y?). New edges carry causal parameters. Each edge is consumed by 4 sentinels on average (vs 1.2 for old edges). Deprecated old edges: AFFECTS, CONSUMES, CORRESPONDS_TO, HAS_ACCESS_TO, SOURCES_FROM, COMPETES_WITH (6 removed). Merged old edges: BELONGS_TO/ALIGNS_WITH/SELLS_TO/INTERACTS_WITH/VALUE_PROPOSITION into props of DEPLOYS/PRODUCES/AUGMENTS.
Example: FUNDS edge — Wane Baby case
MONEY(30kg) -> FUNDS -> ACTIVITY(Kunlun Consulting)
expected_roi: 1.5 | actual_roi: 0 | allocation_period: 2025Q3-Q4
compute-resource-misallocation (S3): For all FUNDS edges, compute actual_roi - expected_roi, sort by gap, output TOP5. No need to compare Goal text with Financial numbers.
