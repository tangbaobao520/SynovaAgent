🕵️ Synova 综合深度研究报告 — 总论

组织智能诊断系统 · 2026-06-04 · 研究代号: RESEARCH-SYNOVA-COMPREHENSIVE-2026

📋 TL;DR — 五大核心发现

  1. 🚨 3 个运行时崩溃 Bug 必须立即修复：conversation-engine.ts 中两个 L4 函数只导入了类型而非函数定义；routes/chat.ts 中 SSE 解析用 \\n 而非 \n 导致前端完全不可用
  2. 🏗️ "两层编排系统"并存但互相隔离：ConversationEngine（生产中）+ DiagnosisOrchestrator 系列组件（~600 行，从未接线）是两个完整的编排框架
  3. 🔌 L5 数据层是最薄弱的架构层（成熟度 2/10）：所有 5 个连接器都是存根且含 TypeScript 编译错误，产品核心护城河"多源交叉验证"完全无法实现
  4. 📊 L4 本体层存在三大致命断层：图存储未被诊断管线调用、图构建依赖手动触发、图查询未面向诊断场景优化——SOG 是"存在但无人使用的图书馆"
  5. 🛡️ 零灾难恢复与多处资源泄漏：进程崩溃后全部内存状态丢失，SSE 连接/alert 数组/限频 Map 存在资源泄漏风险

一、执行摘要

SynovaAgent v0.1.0 是一个架构愿景宏大但工程实现严重不完整的系统。五层架构（L1-L5）的设计文档质量很高，铁律体系（40 条）展现了优秀的工程纪律意识，但代码实现与设计目标之间存在巨大鸿沟。

三、跨层主题（Cross-Cutting Issues）

3.1 状态持久化——各层各自为政

状态类型L2L3L4L5问题
活跃诊断状态内存 Map---❌ 崩溃丢失
对话消息SQLite---✅
证据-SQLite--✅
本体图 (SOG)--SQLite-✅
专家贡献-内存 Map--❌ 崩溃丢失
Outcome 追踪-内存 Map--❌ 崩溃丢失

建议：所有需要持久化的状态统一到 SQLite 或 StorageBackend 接口。

3.2 降级信号传播链（当前断裂）

模块（L3/L4） →  汇编器（L2）  →  路由（L2）  →  SSE（L1）  →  前端
degraded: true    检查标记         含 degraded      propagating    DegradedBanner
                                                                  ⬆
                                                                  未实现

断点：路由层的 catch 块通常不传播 degraded 标记。SSE 事件类型没有标准的 'degraded' 事件。前端没有 DegradedBanner 组件。4 个断点串联，导致下游完全不知情。

3.3 LLM 依赖——每层都阻塞

层级依赖 LLM 的操作LLM 不可用时影响
L2IntentRouter.classify(), Phase 0 访谈, Phase 1-5 诊断诊断完全不可用
L3ExpertAutonomyEngine 全部 6 个专家专家分析完全不可用
L4TripleReflection.reflectOnTriples()三重反射不可用
L5Connector 数据清洗（可选）数据清洗退化

当前没有任何"LLM 降级模式"——LLM 不可用 = 系统基本不可用。建议：即使 LLM 不可用，SOG 图探索、历史诊断回顾、会话管理应仍然可用。

3.4 数据流——单点断裂全局崩溃

连接器取数据 → 摄取 → SOG 本体 → 证据提取 → 专家分析 → 报告产出
     │           │        │          │           │          │
   存根         脆弱路径   未接      基础        无因果     不存在
   返回 []     import 路径  线      可用        分析      报告路由

当前链中至少 3 个环节断裂，完整的数据流从未真正运行过。这个垂直切片不能走通，是产品最大的风险。

八、研究方法论

本研究的产出包括 8 份 HTML 报告（1 份总论 + 7 份专题），全部自包含、零外部依赖：

  1. 代码深度阅读：全景阅读了 ~80 个源文件（~8,500 行核心代码），覆盖 L1-L5 所有层
  2. 已有审计成果继承：整合了 2026-06-03 代码审计报告的 45 项发现（P0-P3）
  3. 架构对比分析：对照 Airbyte/Singer（L5 连接器）、Palantir/Neo4j Bloom（L1 融合 UI）、Anthropic Claw-Code（工程铁律）等行业最佳实践
  4. 代码质量审计：检查了铁律 1-39 的遵守情况，发现多处违规
  5. 对抗性验证：对每个关键发现做了"能否反驳"的对抗性测试，确保结论不是确认偏差的产物
