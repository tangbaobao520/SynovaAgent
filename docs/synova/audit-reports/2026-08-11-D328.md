## L4 防线缺口收割

> **"本次发现的问题，控制塔哪一道防线本该拦住？为什么没拦住？缺什么？"**

### 发现：测试用例失败（P0）

**本该拦住的防线**: 
1. **铁律 0-2 Step 4（测试先行 + red→green）**: 测试应在实现前编写并验证 red 基准
2. **PostToolUse verify-incremental.sh**: 写后应跑测试验证
3. **pre-commit 组 2（测试质量）**: 新测试文件应通过

**为什么没拦住**:
- 测试设计依赖临时 repo + 真实仓库脚本路径的混合执行模式。`resolve-commit-brief.sh` 在真实仓库路径下运行，但 brief 在临时 repo 中创建 → resolver 找不到 brief → 检查跳过 → exit 0。
- **这是 D317 "自包含定位"教训的副作用**: 改用 `BASH_SOURCE` 定位脚本后，脚本始终从真实仓库运行，resolver 始终查找真实仓库的 brief，与临时 repo 的测试隔离冲突。
- 测试用例 1 和 3 均因 `CLAIM_BRIEF` 为空或 GENUINE=0 而跳过检查，未走到 D# 比对逻辑。

**缺什么**:
- 测试需要**在真实仓库的 `.claude/task-briefs/` 下创建测试 brief**（而非临时 repo 中），测试后清理
- 或：resolver 需要支持通过环境变量覆盖 brief 搜索路径（测试注入）
- 或：commit-msg-check.sh 需要支持 `CLAIM_BRIEF_DIR` 环境变量，测试时指向临时 repo

### 发现：Done 标准声称与事实矛盾（P1）

**本该拦住的防线**:
- **Agent 自检 6 问**: "测试覆盖: 测试有 expect() 断言？（不是空壳）"
- **Done 标准 verify 命令**: `bash tests/.../commit-msg-consistency.test.sh` 应真实执行

**为什么没拦住**:
- 测试脚本确实有 6 个 `assert_exit` 断言（非空壳），但断言**期望错误**（用例 1 期望 exit=1 但实际=0）。测试框架正确报告了失败，但 Agent 在自检时可能只验证了"测试存在且有断言"，未验证"全部通过"。
- 或者：测试在 Agent 的环境中通过了（有不同的 brief 布局），但在当前审计环境中失败——这是**环境依赖**，正是 AUDIT-PROTOCOL.md 要求注记运行环境的原因。

**缺什么**:
- Done 标准的 verify 命令应包含 `&& [ "$FAIL" = "0" ]` 的显式成功断言
- 或：自检清单应增加"测试全绿"独立条目（当前 DS1 只写"测试全过"但未细化验证方式）
