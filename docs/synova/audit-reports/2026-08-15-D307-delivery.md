## 三、决策记录（D333 决策参考框架 — K3 审计可核）

**决策点 1（dev doc §4.5）**: worktree 隔离 = session 分支 + finish merge 回主。
参考：第一性原理（git worktree 硬约束"两 worktree 不能 checkout 同分支"→ 独立分支是唯一物理解）+ DeepSeek 开源实证（git 官方 worktree 标准用法即分支级隔离+合并回主）。收敛。
结论：create 时 `git worktree add -b session/<sid>`；finish 时主 worktree merge session 分支再清理。

**决策点 2（dev doc §4.5）**: attach 并行模式 = 检测提示，不自动 create。
参考：Anthropic 工程基线（SessionStart hook 无法改变宿主进程 cwd；失败即关闭——不能做的就不假装做，降级为显式提示）+ DeepSeek 最少机制（提示由 task-start 在目标 worktree 目录启动，一层机制不叠两层）。收敛。
结论：attach 只 detect + degraded 提示，0 处 os.chdir。

**决策点 3（实现新增）**: create 的 base 分支默认值。dev doc 示例硬编码 "feat/prompt-architecture"（2026-08-12 快照，已过期）。
参考：第一性原理（最新事实来源是主 worktree 当前 HEAD）+ Anthropic 工程基线（显式可验证优于隐藏常量）。
结论：--base 可选参数，默认 = 主 worktree 当前分支（`git rev-parse --abbrev-ref HEAD`），dev doc 示例仅作示意。

**决策点 4（实现新增）**: finish 合并前的安全检查。merge 是破坏性操作，失败时不能丢数据。
参考：Anthropic 工程基线（失败即关闭 fail-closed；数据安全优先于便利）。
结论：主 worktree 或 session worktree 有未提交变更 → block（exit 1）不合并；merge 冲突 → merge --abort + 保留 worktree/分支 + 显式报错。

## 四、实现中发现的缺陷（本任务修复 / 记录）

### 4.1 synova-commit ${RESET} 未绑定变量崩溃（已修复，含于 0f45918）

**现象**: origin/main 版 synova-commit 在门禁阻断路径上，`set -u` 下 `${RESET}` 未定义 → 脚本崩溃，阻断提示信息残缺。
**修复**: 0f45918 中为阻断路径补 RESET 变量定义（仅影响阻断分支，不影响正常提交链）。
**证据**: 扫描任务在 ../synova-wt-scan（origin/main 旧版 synova-commit）中实测复现该崩溃；0f45918 版主 worktree 无此崩溃。

### 4.2 bypass.log 对账顺序缺陷（记录，未修复 — 设计固有）

**现象**: synova-commit 在 push_with_tags **之后**才写 COMMITTED 记录 → 新分支第一次 push 时，pre-push 门禁 7 对账找不到该 commit 的记录（base 回退 origin/main 后包含未记录的新 commit）→ 首次 push 被阻断一次；记录落地后重试即通过。
**定性**: 重试即通过 = 门禁自身的设计内补救；不是 fail-open（门禁确实拦了，且阻断后状态诚实可查）。
**建议**: backlog — COMMITTED 记录前移到 push 之前（或门禁 7 对"本次 push 的 HEAD commit"豁免）。非本任务写集，未动。

### 4.3 🆕 扫描任务 dogfooding 发现：origin/main resolver 在新鲜 worktree 中失效（记录，D366 已修待合流）

**现象**（2026-08-15 扫描任务实测，../synova-wt-scan 内）:
1. git worktree 检出时**所有文件 mtime = 检出时间**（= 今日）→ origin/main 版 resolve-commit-brief.sh 的 `find -newermt` 今日认领池 = **全部 350 个 brief**；
2. 350 个路径内联进 `python3 -c` → 超 Windows 32K 命令行上限（E2BIG "Argument list too long"）→ 被 `2>/dev/null || true` 静默吞掉 → 认领块无结果；
3. 静默降级到 D317 回退 → 无 #CRITERIA 的 brief 被跳过 → 误选 2026-08-14-auto.md → pre-commit G12b 硬阻断。
**根治**: D366 已修复（认领池改文件名日期前缀 + 纯 bash for+case 零子进程——注释明言"mtime 会被 git pull 刷, 不可靠"），随 feat/d307-worktree-isolation 分支推送，**待 PR 合入 main**。
**衍生建议（backlog）**: ① resolver 认领池经 stdin/临时文件传入 python，从根上消除 E2BIG（D366 前缀过滤已把池缩小到个位数，E2BIG 不再可达，此项为纵深防御）；② pre-push 门禁 verify-parallel 在 Windows 上 ~3.4s/doc 对（150+ 对 ≈ 8-10 分钟），同 D366 思路应改为单次 python 批处理。
