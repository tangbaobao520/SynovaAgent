## 五、L4 防线缺口收割

> "本次发现的问题，控制塔哪一道防线本该拦住？为什么没拦住？缺什么？"

### 发现 1：amend 场景误报（P1-1）——hook 测试缺"git 操作矩阵"维度

**本该拦住的防线**: dev doc §4 测试要求（marker 场景枚举）+ 铁律 48（边界条件覆盖）
**为什么没拦住**: dev doc §4 枚举了 5 个 marker 场景（并发写/无 marker/head 匹配/不匹配/超时），全部围绕"marker 内容"维度；**"产生 commit 的 git 操作"维度（普通 commit / amend / rebase 期间 commit / cherry-pick / reset --soft 后重提）不在任何测试契约模板里**。head-hash 对账设计天然假设"一次 pre-commit 对应一次全新 parent"，amend 打破该假设。
**缺什么**: 门禁 hook 测试契约增加 git 操作矩阵清单——凡改动 hook 判定逻辑的交付，测试必须枚举"操作 × 状态"组合（至少：普通/amend/reset 重提 × marker 匹配/不匹配/缺失/陈旧），矩阵入 dev doc §4 模板。

### 发现 2：D 前缀 brief 语义回归（P1-2）——判定语义变更缺"等价集对账"

**本该拦住的防线**: 铁律 47 契约优先 + dev doc §2.3 现状确认 + DS 验收设计
**为什么没拦住**: dev doc §2.3 **明确记录了两种命名形式**（`YYYY-MM-DD-*` 与 `DXXX-*`），但这一事实从未被翻译成方案约束或测试断言——§3.2 草图只有日期前缀过滤器，DS1/DS2 只验"newermt 清零"与"调用数 ≥4"，没有任何 DS 验"新旧过滤器的今日集合语义等价"。讽刺的是 dev doc 自己引用了 CT-28（"审计仅验门禁存在+接线，未覆盖判定语义"），然后在语义层重蹈覆辙。
**缺什么**: 判定类门禁的语义变更，DS 必须含**新旧逻辑等价集对账**——在真实目录上跑旧过滤器与新过滤器，输出集合 diff 为空或逐项显式豁免（一条 bash 即可）。此条应写入 dev doc 模板的 DS 设计规范。

### 发现 3：分支污染 + brief 分支字段不实（P2-5）——分支与 brief 无对账

**本该拦住的防线**: pre-commit 组 12 Task Scope 一致性（认领制）
**为什么没拦住**: ① G12 skip_re 豁免 `docs/` → K3-STD 的文档提交落在 D366 分支上，scope 门禁物理看不见；② brief 头部"分支"字段（D366 brief 写"main"，实际提交在 feat 分支）从不与 `git branch --show-current` 对账——字段是死文本。
**缺什么**: commit 时 brief 声明分支与当前分支的对账检查（不匹配 → 警告或阻断）；或承认字段无意义从模板删除。认领制的"跨 session 隔离"目前只覆盖文件维度，不覆盖分支维度。
