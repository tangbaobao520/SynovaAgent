## 五、L4 防线缺口收割

### 发现 1：版本号幻影（P1-1）

**本该拦住的防线**: 版本编排（审计 item 14 + commit-msg 门禁）
**为什么没拦住**: commit-msg 门禁只查 Conventional Commits **格式**，不查"消息携带的 Vx.y.z 是否已落 VERSION.md/version.log/tag"；版本三处同步目前只有事后审计这一道。
**缺什么**: pre-commit 增加一条——消息携带 `Vx.y.z` 时，同 commit 必须含 VERSION.md 对应条目变更（或未授权任务消息禁带版本号）；铁律"版本只增不减"加序号方向校验（新条目不得落后于现存顶端）。

### 发现 2：dev doc 写集/事实偏差（P2-1）

**本该拦住的防线**: dev doc 编写 skill（S-2 写集=实现+验收）+ S-6 同 commit 回填 + K3 item 12 对账
**为什么没拦住**: doc-audit 静态检查无法发现"写集表少列文件"（需与实际 diff 机器对账）；§2.1 事实错误靠 brief Q0b 文件审计环节人工纠正——流程在下游自愈了，但 dev doc 本体未回填，契约文档与交付物永久漂移。
**缺什么**: ①提交时机器对账 `git diff --name-only` vs dev doc 写集表（CT-23/S-10 DS 对账机制尽快门禁化）；②S-6 回填的执行检查（写集偏差出现时阻断或强制标注 descope）。
**正面记录**: 交付方主动申报全部 3 处偏差（§三/§四）——诚实申报文化首次完整出现，值得固化为正例。
