## 五、L4 防线缺口收割

> "本次发现的问题，控制塔哪一道防线本该拦住？为什么没拦住？缺什么？"

### 发现 1：测试 mock 语义失真掩盖生产不可达（P1-1）

**本该拦住的防线**: 铁律 12（集成测试 cover 真实路由，不 mock 管线）+ CT-30 故障注入契约
**为什么没拦住**: 交付的端到端用例确实走了真实 loader+registry（装配层全真），但 store mock 的 `queryNodes(type, _filters)` **忽略 filters**——mock 比生产宽松，测试因此通过，而生产精确匹配语义下 compute 的过滤器 bug 使阈值路径永不可达。现有测试契约审查只看"有没有断言/有没有走真装配"，不看"mock 与生产的语义保真度"。
**缺什么**: store 类 mock 的**语义保真度要求**——filters 必须被 mock 真实执行（一行 `Object.entries(filters).every(...)` 即可），或测试头部显式声明 mock 与生产的语义差异。建议写入 ctrl-tower/测试技能：mock 忽略参数时必须在注释中声明。

### 发现 2：契约文档（dev doc/brief）未入库（P1-2）

**本该拦住的防线**: pre-commit 组 6（Task Brief 字段质量）+ 写集契约
**为什么没拦住**: 门禁验证 brief/dev doc **存在且填写**，但不要求其**随提交入库**——新线的 dev doc/brief 从未出现在任何提交里，契约链只靠工作树文件维持。D366 的"dev doc 在另一分支"已是缺口，本次更进一步：任何分支都没有。
**缺什么**: 交付完成（DS 全绿声明）时，dev doc + brief 的**入库硬要求**——或明确声明例外路径（如"统一由 docs-sync 分支入库"）+ 时限 + 责任人；否则 git clean/分支切换即契约湮灭。

### 发现 3：一任务两实现线并存未退役（P2-1）

**本该拦住的防线**: TASK-ROUTING / session registry 的任务生命周期管理
**为什么没拦住**: 旧线（6db5a17，已审计未合并）与新线（82c21d8）并存，registry/路由层无"重新实现时旧线如何处置"的节点；旧分支携带同名修复的不同实现，误合并即双份冲突。
**缺什么**: 任务重开实现线时的**旧线退役动作**（分支删除/归档标记 + registry 状态迁移），作为新线交付的前置检查项。
