## 二、修复明细

### 缺陷 A — action-store 硬编码 'growth'（P1 主缺口）
- 修复: 构造器 `(store?, orgId?: string)` + 私有 `getGraph()` 派生 `${orgId}:growth`（src/growth/action-store.ts L54-58）。
- fail-closed 分方法: createAction 无 store 内存降级（log.warn）；updateLifecycle 无 store/orgId 抛错；三查询返 `[]` + log.warn。
- 6 处硬编码 'growth' 全部替换为派生 graph。

### 缺陷 B — src/l4 查询省略 graph
- graph-traversal.ts: 绑定式 `createGraphTraversal(store, graph='default')` + `traverse(..., graphOverride?)`；L91 空串 bug 修复（`const graphParam = graphOverride ?? graph`）。
- data-purger.ts: 构造器第 4 参 `graph: string = 'default'`；L186/255/266/269/411 五处 `this.graph`。
- 接线: diagnosis-launcher.ts L145 `createGraphTraversal(store, teamId)`；data-lifecycle-service.ts L75 `new DataPurger(gs, sessionStore, memoryStore, tenantId)`。

### 缺陷 B 同型第三文件（缺口 E，本任务实测新增）— entity-resolver 丢弃已收到的 graph
- 现状: `resolveEntitiesL3(store, graph)` 收到 graph（运行时调用方 post-diagnosis-processor.ts L232 传 teamId）但本地 `GraphStoreRO` 接口 L23-24 无 graph 参数 → L51/204/205 三处查询静默回落 store 默认命名空间。check-architecture 多租户告警 5 处全部在此文件。
- 修复: 接口补 `filters?/graph?`（对齐 community-reports.ts 同型接口模式）；L51 `queryNodes(type, undefined, graph)`；computeStructuralSimilarity 增 graph 参并线程穿透 L58 → L204/205。
- 决策参考（Q1c）: 参考：第一性原理（审计本职=堵此类缺口，明知缺口交付=不合格）+ 代码库实证（community-reports.ts L101/123、quality-firewall.ts L54 同型接口均带 graph）+ 收敛检查（调用方零改、测试 mock 向后兼容）。结论：修复而非仅记录。

### 缺陷 C — overflow 快照全局图（写侧 + 消费侧）
- 写侧: 删 SNAPSHOT_GRAPH 常量；模块私有 `snapshotGraph(enterpriseId)` 派生 `${enterpriseId}:cycles`；L70/97/154 三处替换。
- 消费侧（本任务实测新增）: `simulateInvestment` 内部 4 处硬编码 `getLatestSnapshot('default', ...)` — 修复后签名加 enterpriseId 首参（对齐 writeOverflowSnapshot 租户前置惯例），4 处改传参；overflow.ts POST /api/overflow/simulate 从 body 取 enterpriseId（缺省 'default' = 实例默认 org，与 snapshots GET 路由 L88 既有语义一致）。
- 决策参考（Q1c）: 参考：铁律 9（改核心定义后 grep 全仓传播——本缺陷即该 grep 的收获）+ 第一性原理（'default:cycles' 在真实租户下恒空=模拟静默失效）。结论：修复而非记录观察项。

### 缺陷 D — GA 中国墙（路由 + feedback_log）
- ga-annotations.ts / ga-corrections.ts: requireGa 加 `if (!auth.orgId) → 400 { code:'ORG_REQUIRED' }`（role 检查之前）；7 处 `auth.orgId || 'default'` → `auth.orgId`。
- feedback-collector.ts: `FeedbackQueryResult { entries, degraded }` 新返回形态；缺 enterpriseId → log.warn + `{entries:[], degraded:true}`；SQL `WHERE enterprise_id = @enterpriseId` 必带。getAggregatedSignals 一字不动（D472 兼容）。
- 生产调用方 grep 实证为零 → 形状变更只影响测试。

### 缺陷 F — ActionStore 无 orgId 接线
- config.ts: `SynovaConfig.orgId: string` + `loadConfig()` 读 `SYNOVA_ORG_ID || 'default'`。
- synova-agent.ts L139: `new ActionStore(undefined, config.orgId)`。
