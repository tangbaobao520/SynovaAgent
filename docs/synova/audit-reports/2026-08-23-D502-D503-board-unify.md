## 五、审计发现

### P0-1（D503）G12 门禁 fail-open：认领窗口变量 `|` 在 case 模式中是字面量，匹配 0 文件

**现象**：D503 用 `DAY_WINDOW_DAYS`（`2026-08-22-*|2026-08-23-*|2026-08-24-*`）替换 `"${TODAY_DASH}"-*`，放入 `case "$b" in $DAY_WINDOW_DAYS)`。

**物理事实**（bash 3.2 实测 + bash 语法原理，跨版本成立）：
- `case "$b" in $DAY_WINDOW_DAYS)` 中，变量展开后的 `|` 是**字面字符**，不是 alternation（`|` alternation 是 parse-time 语法 token，变量展开是 runtime，永不参与语法解析）。
- 实测 `case "2026-08-22-foo" in $DAY_WINDOW_DAYS)` → **NO MATCH**；`case "foo" in 'foo|bar')` → NO MATCH（`|` 字面量）。
- 结果：`today_files_by_prefix` 对 `.claude/task-briefs/` 里真实存在的 brief 匹配 **0 个文件**（实测函数对真实目录返回空）。

**连锁 fail-open**：
- pre-commit-check.sh:1020 `ALL_TODAY_BRIEFS=$(today_files_by_prefix ...)` → 空
- pre-commit-check.sh:1021 回退依赖 `CUR_BRIEF_PATH`，但 `.claude/current-brief*` 已 gitignore（.gitignore:29）→ CI 上无此文件 → 回退失败
- pre-commit-check.sh:1024 `if [ -n "$ALL_TODAY_BRIEFS" ]` → 假 → **G12 范围检查整段跳过**
- pre-commit-check.sh:1091 `soft_pass "G12: 所有文件均在 Q2 范围内"` → **无检查却报通过 = M1 fail-open**

**影响**：
1. 意图的 ±1 天窗口**从未实现**；
2. CI（ubuntu bash 5.x，行为一致）G12 静默失效——任何「文件不在 Q2 范围」的 scope violation 都放行；
3. 本地亦退化：D296 认领制 v2 的「今日全部 brief 并集」被破坏，回退单 current-brief 语义，跨 session 污染防护回退。

**file:line 证据**：scripts/pre-commit-check.sh:984-993（变量构造）、1001-1003（case 模式）、1020（调用）、1021（回退）、1024（跳过判定）、1091（soft_pass）。复现命令：`case "2026-08-22-foo" in $DAY_WINDOW_DAYS) echo MATCH;; esac` → 无输出。

**归因: implement**（实现者用变量承载 alternation，属 bash 语法误用）。**防线归属: M1（fail-open 静默失效）**——CT-1「三态输出 pass/degraded/fail」未落地到 G12 的「空认领集合」场景。

### P1-2（D502）降级零删除保护不完整：单源 degraded（空 tasks）仍误删该域全部卡

**现象**：设计决策 #3「降级轮零删除（误删破坏性 > 漏删）」只在 `readSnapshot` 返回 null（snapshot 缺失/坏 JSON）时生效。当 snapshot **有效**但内部某源 degraded（如 `win_tasks.degraded=true, tasks=[]`）时，`usingSnapshot=true`，僵尸删除照常运行，该源全部卡片被误删。

**实测复现**：构造「snapshot 有效 + win_tasks degraded 空 tasks + 看板有 D338 Win 卡」→ `syncOnce` 输出 `deleted:1, deleted ids:['D338']`。

**file:line 证据**：sync.js:521-528（删除循环 `if (usingSnapshot)` 无逐源 degraded 判定）、sync.js:442-451（win_tasks degraded 时 winTasks=[]，allIds 缺 Win 卡）。

**影响**：git log 失败（或 product_lines/todos 源读取失败）且 derive 仍产出 snapshot 时，可误删 51 Win 卡 / 26 L 卡 / 48 T 卡。触发条件窄（需 git 命令自身失败），但后果破坏性，直接违背设计决策 #3 声明。

**归因: implement**。**防线归属: M1/M5**（降级保护只挡「整体缺失」，未挡「局部 degraded」）。

### P1-3（D503）声称「修复后 CI 绿」有误导：绿 = fail-open 非修复生效

**现象**：派单声称 #6 与 D503 brief Done 标准「模拟 CI 条件 13 组全过（G12 由红转绿）」把「门禁通过」当成「修复生效」。实测修复是失效的，绿来自 G12 被跳过。

**归因: implement（验收标准选错）**。验收只查「13 组全过」的 exit code，未查「G12 是否正确认领 brief 声明的文件」。正确验收应为「TZ=UTC 下 brief `2026-08-23-D502-*` 被 today_files_by_prefix 命中且其 Q2 文件被认领」。

**防线归属: M2（声称 vs 事实）**——Done 标准 verify 未映射「声称项↔用例」（S-4）。

## 九、L4 防线缺口收割

**本次发现的问题（P0-1/P1-2/P1-3），控制塔哪道防线本该拦住？为什么没拦住？**

1. **P0-1（D503 fail-open）→ 防线缺口：G12 门禁修改自身，无「门禁改动被门禁测试」的闭环。**
   - 本该拦住：`control-tower-tests` CI job（ci.yml:91-111）只跑 U2/U4/U5a/U5c/U7 五个密封测试，**不含 G12 认领窗口逻辑的密封测试**。
   - 为什么没拦住：门禁脚本改动的测试覆盖是盲区；`bash -n`（语法）过、13 组「exit 0」过，但「窗口正确认领 brief」这个**语义**没有被任何测试断言。
   - 缺什么：一个密封的「G12 认领窗口」测试——构造临时 brief（昨日/今日/明日）+ 断言 today_files_by_prefix 正确命中，等价于 derive.test.sh 的沙箱做法搬到 pre-commit 门禁。

2. **P1-2（零删除不完整）→ 防线缺口：降级测试矩阵缺「局部 degraded」维度。**
   - 本该拦住：铁律 48「降级路径」测试应覆盖「snapshot 有效 + 单源 degraded」。
   - 为什么没拦住：测试只写了「无 snapshot」（整体缺失）两种降级，未写「单源 degraded」。
   - 缺什么：sync.test.js 加「win_tasks/product_lines/todos 单源 degraded 且空 → 零删除」用例。

3. **P1-3（声称「CI 绿」误导）→ 防线缺口：Done 标准 verify 未做「声称项↔用例」映射（S-4）。**

**命中已有 M 类，不新增 M 类**（Anti-bloat）：
