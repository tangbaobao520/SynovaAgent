## L4 防线缺口收割（每任务必答）

**本次发现的问题，控制塔哪一道防线本该拦住？为什么没拦住？缺什么？**

1. **F1/F5（M2 声称 vs 事实，commit message overclaim）**：防 M2 的既有防线是「S-2 写集表声称=实现+验收 + DS verify 映射」。但本次 overclaim 发生在 **commit message** 层（非写集表/DS 层）——commit message 说"实测产出 release/...app"，而 task-state note 诚实说"受限/CI 执行"。**缺口**：commit message 的"实测/物理证据"类字眼无任何机器校验（写集表/DS 有，commit message 没有）。**建议**：编码 session 完成报告/commit message 中的"实测/产物/物理证据"字样应强制附带 artifact 路径，且该路径须在 git diff 中可 grep（否则降级为"静态断言"措辞）。归因 implement，机制收敛于 M2 既有防线强化，不新增 M 类。

2. **F3（M4 执行证据链断裂，bypass.log 有 BLOCKED 无 PASS）**：防 M4 的既有防线是「CT-3 bypass.log 对账 + 禁止 --no-verify + synova-commit」。本次 D504 出现"BLOCKED 后无 PASS 无 bypass"的悬空记录。**缺口**：bypass.log 对账（CT-3）只查"有 bypass 记录"，不查"有 BLOCKED 但无对应 PASS 的悬空 commit"。**建议**：post-commit/CI 对账增加"BLOCKED 未闭合检测"——若某 TASK_ID 出现 BLOCKED 但 24h 内无对应 COMMITTED PASS，标记为异常（可能 --no-verify 未记录）。归因 control-tower，机制收敛于 M4 既有防线（CT-3）强化，不新增 M 类。

3. **F6（M8 分支污染，D505 local 混入 D506）**：防 M8 的既有防线是「worktree 隔离 + 认领制 + staging-guard」。本次是同一 agent 在 feat/d505-impl 分支上先提交 D506 fix（2370fc88）再提交 D505（9cb09dbb），导致分支混入他任务提交。**缺口**：认领制（D296 task-scope）防的是跨 session 污染，防不住同一 session 内"顺手提交他任务"的分支污染。**建议**：编码 session 提交前自查"本分支 commits 是否全部属于本 D#"（可加入 pre-commit 组 12 Task Scope 的一致性检查范围，或 agent 自检加一条）。归因 implement，命中 M8 既有防线，不新增。

> **机制数量收敛结论**：本次 7 项发现命中 M2/M4/M7/M8 四个**已有**模式类，**零新 M 类**。按"机制数量收敛于错误模式种类数"原则，只强化既有防线（M2 commit-message 校验、M4 bypass 未闭合检测、M8 分支提交自查），不新增免疫细胞。
