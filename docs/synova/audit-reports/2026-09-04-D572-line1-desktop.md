## 二、核心发现（P0 详述）

### P0-1 验收点 1-2 假绿：自动兑换把「诚实 waiting」洗成「verified」｜归因: control-tower（产品线兑换机制）

物理事实链：
1. D523（Win 双击出窗验证基建）交付的是**验证脚本 + 静态契约测试**，task-state 明确「impl_done_waiting_exe」，DS1/DS2（Win 本机实跑）pending（task-state/D523.json）。
2. K3 切片 B 审计 PASS 的范围是**合并安全性复审**（P0-1 分支基点修复 + 树终验 + 59/3/62 复跑），并明示 Win 物理实跑 ⏸ 不可行（2026-08-25-D522-D523.md:7,58-59,147：「impl 状态 impl_done_waiting_exe 维持至切片 A .exe 落地后 Win 本机实跑」）。
3. redeem-progress.py 的兑换规则为「impl commit 在 git + audit verdict 非 FAIL → k3 pass」（scripts/product-lines/redeem-progress.py:6,51-52,135），不区分审计 PASS 覆盖的是合并安全还是验收点本体。
4. calc-progress.py 对 k3 pass 一票翻绿（scripts/product-lines/calc-progress.py:140-141），且不校验 yaml evidence 绑定（1-2 要求 `founder-demo:win-安装实测`，实际记录 record_type=k3 自动兑换），也无 TTL/stale 检查。
5. 结果：product-progress.json 1-2=verified，而 yaml note 仍写着「从未实测」——**状态与备注自相矛盾**，假绿成型。

这不是交付方伪造——D523/D536 全程诚实标注 waiting，不伪造（值得肯定）。是**机制把诚实 waiting 错误兑现成了 verified**。

### P1-1 证据日期后 electron-renderer 有大变更，k3  verdict 无失效机制
D556（GA 人机协同前端）在证据日期 2026-08-29 之后改动 electron-renderer：ga-collab.ts 新增 452 行、RightPanel.tsx +193 行（commit 69d81c58）。「开窗即用」相关点（1-2/1-4/1-6）的证据均先于该变更。calc-progress.py 的 stale/TTL 检查只作用于 machine 类证据（calc-progress.py:147-164），k3 pass 永久免疫失效检测——机制缺口。

### P1-2 1-6 计时证据可复核性受损
evidence JSON 未入 git（「evidence 不入 git 为既定设计」见 task-state/D536.json audit.note，但同目录另有 12 份 GS evidence 在 git，实践不一致）；1.8s 的里程碑构成无法复核；探针未绑定新启动实例（端口上任意服务都会响应）。

### P1-3 D517/D518/D519 task-state 形式状态未闭环
C1（artifact URL）/C2（dev doc 契约）均已物理闭合（task-state/D517.json DS3 已回填 URL；K3 2026-08-28 批量审计 D524 PASS），但三任务 audit.verdict 至今仍写 CONDITIONAL PASS——形式状态滞后于物理事实，且未妨碍兑换翻绿，说明兑换根本不读 verdict 细则。

### P2-1 1-7 yaml 证据绑定语义错配
product-lines.yaml 1-7 绑定 scenario:GS-07，而 GS-07 是 PII 脱敏/RBAC 越权场景（scripts/golden-scenarios/GS-07-data-security/run.sh:1-8），与「升级/重装不丢数据」无关。实际证据走 D528 脚本路径，绑定应修正。

### P2-2 运行 evidence 落盘物不入 git 的口径不一
GS-01/03/07 等 12 份 evidence JSON 在 git，而 D519/D536 的安装实测 evidence（assertions 等）不入 git。建议至少断言摘要（assertions.txt/md5）入 git 支撑可复核性。

| G2 | k3 verdict 永久免疫失效检测（D556 变更后证据未重验） | A1 规则（modules 变更 → 证据失效转黄） | stale/TTL 分支只覆盖 machine 类证据（calc-progress.py:147-164），k3 pass 直接 return verified（:140-141） | k3 verdict 同样纳入 git_touched_after 检查：证据日期后 modules 有变更 → 转 stale 待复核 |
| G3 | 1-8「审计员复核」点在审计行为发生前已 verified | 验收点语义校验 | 自我指认型验收点（定义本身就是「审计员复核」）被交付任务的自动兑换翻绿——机制不区分「交付证据」与「复核行为」 | 1-8 类验收点应硬编码只接受 record_type=k3 且 quote_ref 指向**线级复核报告**（非任务级兑换记录）；或由 calc-progress 特殊处理 |
