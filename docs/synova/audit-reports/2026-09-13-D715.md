### D706 — synova-commit 部分提交静默丢弃删除项（PR #501，squash 349f7bc3）→ **PASS**

**声称（commit message）**：根因是 `git commit -m msg -- <pathspec>` 部分提交原语对「索引已删除 + .gitignore 命中 + 磁盘仍存在」路径内部 add 被 ignored 跳过 → 删除不进提交但 exit 0 → 提交后索引回填、暂存态静默销毁。修法 = 索引精确提交 + 提交树不变量 + 失败回滚（撤销提交 + 还原索引）。

**K3 独立复现（零上下文沙箱，非采信测试自证）**：

1. **根因复现（原生 git 旧原语）**——`scripts/control-tower/synova-commit:483-490` 注释描述的场景用裸 git 重演：
   ```bash
   SB=$(mktemp -d) && cd $SB && git init -q . && git config user.email t@t.local && git config user.name t
   mkdir vendor && echo w > vendor/widget.txt && echo s > seed.txt && git add -A && git commit -qm base
   echo "vendor/" > .gitignore && git add .gitignore && git commit -qm ignore
   git rm --cached -q vendor/widget.txt && echo o > other.txt && git add other.txt
   git commit -qm "old primitive" -- .gitignore other.txt vendor/widget.txt   # 旧 synova-commit 原语形态
   git ls-tree -r HEAD --name-only | grep -c widget    # → 1（删除静默丢失，且 commit exit 0）
   git status --short                                    # → 空（暂存删除态被回填销毁）
   ```
   实测：widget 仍在树中（1）、commit 成功（exit 0）、暂存态消失——根因描述逐项属实。
2. **修复复现（新 synova-commit）**——同场景续跑：
   ```bash

   SYNO_PRE_COMMIT=/bin/true bash <repo>/scripts/control-tower/synova-commit \

     --message "remove widget" --files .gitignore other.txt vendor/widget.txt
   ```

   实测：删除正确进树（1→0）、以 `D` 记录、ignored 路径的 `git add` 拒绝被逐路径判定豁免（索引即声明）。
