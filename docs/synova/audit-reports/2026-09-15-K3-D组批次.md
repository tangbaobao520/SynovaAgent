**为什么判 NOT-AUDITABLE 而非 PASS**：审计的唯一依据是物理证据。这 8 项：
- 无 `impl.files` → 无法做写集对账
- 无 `impl.evidence` → 无任何可复跑的验证命令
- 无 `note`/`spec` → 无法从任务意图反推验收标准

**唯一可做的旁证**是 commit message 标题（4 项有 commit：D531 AGENTS/CLAUDE 对齐 V5.1.1 + weekly-selfcheck；D532 自检脚本 --report + launchd 落位；D554 post-commit 影子提交限定路径；D562 派单 + 台账登记）——**但「commit message 说了什么」不等于「做成了且验证过」**（M2 模式）。按派单 §三.4，**证据不足 → NOT-AUDITABLE，不写「基本通过」**。

**这不是说这 8 项没做**——它们的状态是 `impl_done`，很可能真做了。而是**交付时未留下可审计的证据链**，导致现在无法验证。作为治理类低优先项，不阻断；但若其中有影响门禁/流程行为的（D530 同类：D554 改 post-commit 行为、D555 改 verify-parallel 行为），建议 CTO 补证据后重审。
