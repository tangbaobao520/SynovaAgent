## 必查 7 条逐条裁决

### ① 释放语义可被伪造吗 —— **可伪造（P1-1）**

攻击路径（沙箱实证，全程无需越权提交）：
1. 基线：D901(claimed) 认领 docs/x.md，session D902 暂存该文件 → `status=block`（正确）。
2. D902 直接改**工作树** `task-state/D901.json` → `status=impl_done`（不暂存、不提交）。
3. 重跑 guard → `status=warn, exit=0`，释放理由 `D901 已释放（依据 task-state:impl_done）`——他人认领被解锁。
4. 提交完成后把卡改回 `claimed`——**零痕迹**（篡改从未进 git 历史）。

复现命令与原始输出（沙箱 `/tmp/k3-sb-*`，脚本为 mktemp 复制件）：
```
$ python3 $G --session-id D902 --staged docs/x.md   # 基线 D901=claimed
  status= block ['2026-09-20-D901-b']
$ printf '{"task_id":"D901","status":"impl_done"}' > $SB/task-state/D901.json   # 未 git add
$ python3 $G --session-id D902 --staged docs/x.md
  status= warn | released= D901 已释放（依据 task-state:impl_done: task-state/D901.json status=impl_done)
```
代码依据：claim_release.py:142（`_read_json(repo/'task-state'/f'{tid}.json')` 读**工作树**文件）、:186-190（status ∈ RELEASED_STATUSES 即释放）、staging_guard.py:196-203（released → 不 block）。

次级路径：`claim_release.py release` 子命令无鉴权、无审计日志，任何本地进程可写台账（沙箱实测 `--by attacker` 成功）。另：暂存**他人** `task-state/<D#>.json` 本身不被拦（`--staged task-state/D901.json → status=pass`，stray 空）——真实仓库里多数 brief 自认领本任务卡（抽查 8/8 含 `task-state/D<self>.json`），提交路径有缓解，但工作树读取路径（上述主攻击）不受此缓解保护。

威胁模型判断：控制塔整体假设本地 agent 非对抗 + PR 人工审查，故不判 P0；但本卡把硬 block 弱化为 warn，且证据源可无痕操纵，属"门禁被削弱面"，必须显式接受风险或加固（建议：释放证据改读 git 可信版本 `git show HEAD:task-state/<D#>.json`，或只认台账+已提交状态）。**归因: devdoc**（契约未定义威胁模型）。
