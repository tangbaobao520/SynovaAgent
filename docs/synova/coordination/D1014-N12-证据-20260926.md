## 一、N12 根因（CTO 2026-09-26 定位）

| # | 根因 | 实测证据 |
|---|---|---|
| ① | `on.push.branches: [main, feat/*]` ⇒ 每次 feature push 跑全量 CI（放大器） | `ci.yml:3-7` 原文 |
| ② | 全 workflow `concurrency` = 0 ⇒ 无"新 run 取消旧 run"⇒ 同分支无限排队 | `grep -n 'concurrency' .github/workflows/*.yml` → **零命中**（5 个 workflow 全无） |
| ③ | 86 open PR × 反复 push ⇒ 触发量 ≫ 消费量 | 全队列一度 **38 queued 不消费**；`feat/d962-2a-merge` 独占 **18 条** |

## 二、改动（10 insertions / 1 deletion）

```yaml
on:
  push:
    branches: [main]          # ← 原 [main, feat/*]
  pull_request:
    branches: [main]

concurrency:                   # ← 新增（顶层）
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

**唯一删除行** = `-    branches: [main, feat/*]`（CTO 指定收窄，非误删）；job/step 判定逻辑零改动。

## 五、附：本次落地过程发现的两处门禁摩擦（如实登记，非本卡修复范围）

1. **Q2 路径加反引号 ⇒ 认领计数归零 ⇒ 被判「他人文件」硬阻断**：
   `brief_parser` 会把反引号算进路径 ⇒ `match_path` 0 命中 ⇒ `resolve-commit-brief.sh` 回退到"别的声明了同一热文件的 brief"（本卡为 `D945-preset-bundle-migration`，它声明了 `.github/workflows/ci.yml`）⇒ `staging_guard.py` 判 block。
   实测：反引号版 `n=0` vs D945 `n=1` ⇒ 归 D945；裸写路径后 `n=4` ⇒ 归本卡 ⇒ guard `warn`（放行）。
   ⇒ **`ci.yml` 是全仓最热共享文件（10 张卡声明）**，凡新卡要改它，都踩同一坑。
2. **session 专属 `current-brief.<sid>` 无自动写入**：新 worktree 里 `task-start.sh` 未被调用 ⇒ 无该指针 ⇒ resolver 只能走认领回退。手工补指针（`.claude/current-brief.D1014`，gitignored）后路径正常。
