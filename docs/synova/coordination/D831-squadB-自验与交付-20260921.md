### F1 自验返工：P0-1 引入的「首个 token 前非不变量错误 → 全链路无头挂死」缺陷（2026-09-21）

**发现来源**：自验队员独立复现——本卡 P0-1 修复**引入的新缺陷**（P1 级），返工前置。

**根因链（三处叠加 → 全链路无人写响应头）**：
1. `src/l1-interaction/web-adapter.ts:135-141` `writeRaw`：`deferred` 时只把帧 `push` 进 `pendingFrames`，不写 socket；
2. `src/l1-interaction/web-adapter.ts:191` `close()`（返工前）：`deferred` 且从未激活时**只清缓冲、不 `res.end()`**——原设计前提「响应由路由终结束」对 InvariantError 的 5xx JSON 分支成立，对非不变量分支不成立；
3. `src/routes/conversations.ts` 非不变量 catch（返工前 `:396-405`）：响应头未发出时只 `adapter.sendFrame(error)` + `sendFrame(end)` → 两帧全进缓冲，`finally` 的 `close()` 又不 end → **客户端无限等待**。

**修法（保持既有对外契约，不动 P0-1 的 5xx 语义）**：
- ① `src/routes/conversations.ts:402`：非不变量 catch 未发头时先 `adapter.ensureActive()`（写头 + flush 缓冲帧）再发 error/end —— 对外仍是「200 + 流内 error/end」，与改动前形态一致（F1 的本质是「挂了」，不是「状态码不对」）；`InvariantError` 5xx 分支（`:378-394`）零改动；
