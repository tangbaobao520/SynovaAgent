## 二、判定边界（一句话判据 + 三问）

### 判据（第一性原理）

> **改动的值是否参与「已建立并驻留的连接/进程内状态」？**
> - **否** → 值在每次使用时被**重新读取**，不存在"旧值还在别处活着"的状态 → **live**
> - **是** → 值在建连/装载时被**捕获**，改一半会造成"部分消费者用新值、部分用旧值"的**半生效** → **restart**

「客户无感改」是 live 的**结果**，不是判据；判据是**是否存在被捕获的驻留状态**。理由是：仅按"客户是否感知"分类会在"改了立刻生效但只生效一半"时判错——那正是决定 ④ 要避免的状态。

### 分类三问（逐项过，任一为「是」则归 restart）

1. **是否在建连/首次调用时被捕获？**（如 HTTP 客户端、DB 连接池、LLM provider 实例、插件 require 时机）→ 是 = restart
2. **改动是否需要换一个"对象身份"？**（如换 endpoint、换凭据、启停插件 → 需要重建对象）→ 是 = restart
3. **半生效会不会产生安全或一致性问题？**（如鉴权用旧凭据、数据源指向两个源）→ 是 = restart

三问全「否」→ live。

### 已识别的边界模糊项（须实现方在 SPEC 显式声明，不得自行推定）

| 项 | 为什么模糊 | 处置 |
|---|---|---|
| **阈值类的"已建连阈值"** | 告警阈值本身是 live（纯数值，每次比较时读取）；但若某阈值**参与**已建连的判定（如"连续 N 次超阈值才升级"的累计器状态），改阈值会与累计器既有状态交错 | 归类 **live**，但要求实现声明「改动何时对进行中的累计器生效」（下一步起算 / 立即重算）——**声明为 live 但行为须可预期** |
| **插件类的"插件内的文案/阈值"** | 插件本身是 restart（启停/装载），但插件**暴露的配置项**可能是 live | 按**被改的那个键**分类，不按所属插件分类：改的是插件的装载开关 → restart；改的是插件读的展示文案 → live |

## 三、逐类「改完是否需重启」的可复现核验方式

> 通用前置：`SETTINGS` 指被改的配置项；`PROC` 指一个**不重启**的常驻进程（生产入口：`POST /api/diagnosis/consult` 或 `Cron→Sentinel.check()` 任一可触达入口）。
> 核验**只采信行为观测**，**禁止以 grep 命中作为通过依据**（总纲 §5 + 研究院撤回清单 #3）。

| # | 类别 | 归属 | 可复现核验方式（不重启） | 通过判据 | 失败信号（fail_when） |
|---|---|---|---|---|---|
| 1 | 展示类 | live | ①起 `PROC`，记下入口返回的面板显示项取值 v0 ②**不重启**改 `SETTINGS` 为 v1 ③再打同一入口 | 第 ③ 步返回 **v1** | 仍返回 v0（＝改完需重启） |
| 2 | 阈值类 | live | ①起 `PROC`，用低于当前阈值的构造数据触发 → 记工单结果 ②**不重启**把阈值改到该数据之上 ③重放同一数据（同去重键需先销单，或换 teamId 隔离） | 第 ③ 步**不再**产生工单（阈值新值生效） | 仍产生工单（＝阈值被缓存，实为 restart 却声明 live） |
| 3 | 文案类 | live | ①起 `PROC`，取一条告警/报告文案原文 t0 ②**不重启**改文案为 t1 ③重放触发 | 第 ③ 步文案为 **t1** | 文案仍为 t0；或 t1 已在**新**输出生效但**进行中**的输出仍 t0（**半生效**） |
| 4 | 连接类 | restart | ①起 `PROC` 并用凭据 A 建连成功 ②**不重启**把凭据改为 B（B 与 A 指向不同上游）③**不重启**触发一次调用，观察实际出口 ④重启后重触发 | 第 ③ 步仍以 **A** 出站且行为可预期；第 ④ 步以 **B** 出站 | 第 ③ 步**部分**请求走 B（**半生效**）；或第 ④ 步仍走 A（＝声明 restart 但重启后未生效） |
| 5 | 插件类 | restart | ①起 `PROC`，记已装载插件集合 P0 ②**不重启**改插件启停开关 ③**不重启**查实际生效的插件集合 ④重启后再查 | 第 ③ 步 = **P0**（未变）；第 ④ 步 = 新集合 | 第 ③ 步集合**部分**变化（**半生效**）；或第 ④ 步未变 |
| 6 | 数据源类 | restart | ①起 `PROC`，以数据源 DS0 接入并落一条已知记录 ②**不重启**改指向 DS1 ③**不重启**再接入一次 ④重启后重接入 | 第 ③ 步仍读 **DS0**；第 ④ 步读 DS1 | 第 ③ 步出现**两个源混合**（**半生效**，一致性破坏）；或第 ④ 步仍 DS0 |
| 7 | 鉴权类 | restart | ①起 `PROC`，以租户/凭据 T0 通过鉴权 ②**不重启**把 T0 轮换为 T1 ③**不重启**用新凭据与旧凭据各打一次入口 ④重启后再打 | 第 ③ 步：旧凭据在重启前**仍按声明行为**（纳入/排除须与声明一致，不得出现"旧凭据时而可用时而不可用"）；第 ④ 步按新凭据 | 第 ③ 步旧凭据**时通时不通**（**半生效** → 安全风险）；或第 ④ 步新凭据不通 |

### 判据的否定面（防误判）

- **「改完恰好重启了才生效」不算 live 通过**——第 1/2/3 行必须在**同一进程生命周期内**观测到新值。
- **「改了没反应」不算 restart 通过**——第 4/5/6/7 行必须同时证明 ③（重启前不半生效）**和** ④（重启后生效）。
- **「声明了分类」不等于「行为符合分类」**——分类声明（`applies`）是**被验对象**，不是通过依据。
