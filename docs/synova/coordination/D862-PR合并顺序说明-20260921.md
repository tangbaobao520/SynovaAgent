## 二 P2-c / M8：`bypass.log` 是六支唯一交集文件

K3 实测 + 队内复核一致：**pr1..pr6 两两交集（`comm -12` 15 对）唯一成员 = `.claude/bypass.log`**
（pr5∩pr6 另有 6 个 pr5 源码/测试文件，因 pr6 是 pr5 的叠栈分支——已由 §1.1 的 base 声明消解）。
`.claude/bypass.log` 是 auto-hook 在每个分支各写 2 行的**机制产物**，故：

### 合并顺序（按此序合并，零冲突）

```
① feat/d821-http-proxy            （前置：唯一出口本体，必须先合）
② feat/d862-pr1-connectors        （connectors 域）
③ feat/d862-pr2-tools             （tools 域）
④ feat/d862-pr3-agent             （agent + l1 + cli-manager 域）
⑤ feat/d862-pr4-services-deploy   （services + mvp-server + deploy/bootstrap 域）
⑥ feat/d862-pr5-routes-tui        （routes + tui-v2 域）
⑦ feat/d862-pr6-docs-state        （base = ⑥；docs + task-state 域）
⑧ feat/p1-outbound-converge       （伞分支；仅作对照，不单独合并）
```

**唯一交集文件 `.claude/bypass.log` 的顺序语义**：每支合并时该文件都会"双方各自修改"，
但它是**追加型台账**、且每次合并后立即被 hook 继续追加 → 合并时取任一版本（ours）即可，
不携带任何产品语义；**不会阻塞顺序合并**。K3 §8.7 实测（正序/反序）均为 0 冲突、落完即等于终树。
