## 3. 代理不可达（判据 3）

env：`http_proxy=https_proxy=http://127.0.0.1:9`（无监听）。`.tmp-verify/live-dead-proxy.ts`：

```
[D1 ima.checkHealth] {"ok":false,"message":"代理不可达（127.0.0.1:9, ECONNREFUSED）: connect ECONNREFUSED 127.0.0.1:9"}
[D2 boss-mailbox] ok = false
[D3 /api/llm/test] {"ok":false,"code":"NETWORK","message":"无法连接到模型服务，请检查网络或 baseUrl"}
[D4 outboundFetch 远端目标] OutboundHttpError code=PROXY_UNREACHABLE phase=connect retryable=true degraded=true ✅
[D5 loopback 死代理下] status = 200（恒绕过不受影响）✅
```

**无静默直连**：远端目标（`upstream-*.test`）不可 DNS 解析、无路由——若出口回退直连，D1/D3/D4 会以 `ENOTFOUND` 直连失败或（对可解析真实域名）成功；实测 D4 得到的是分类后的 `PROXY_UNREACHABLE(degraded)`，D1-D3 全部按降级路径返回，假目标服务不可能收到请求（它们只在假代理的 URI 里存在，代理本身拒绝连接）。D5 证明 loopback 合法绕过不受代理死活影响。

### 3.6 发现 F-2（报队长，不改代码）

`getProxyStatus()` 是**配置级**快照：死端口但合法的 `http://127.0.0.1:9` 会被判 `active=true, kind=http` → healthz `outbound_proxy` 与 bootstrap 启动登记显示 `ok`（D6/D7 输出 `degraded:false`）。这是设计取舍（bootstrap 注释明示"启动期不做真实外网探测"，运行期由出口逐请求抛错兜底），degraded 可见性对 **socks/畸形值** 成立（测试 tests/deploy/bootstrap-proxy.test.ts + healthz.test.ts 已覆盖）。若需要"代理可达性"也进 healthz，须队长另派卡（涉及启动期探测策略），不属本自验修复范围。
