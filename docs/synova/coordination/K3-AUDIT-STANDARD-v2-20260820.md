## 一、模式 A v2 总流程（4 步）

```
步骤 0  门禁与声称表存在性核验（1 分钟，fail-closed）
步骤 1  跑证据命令（机器可验，逐行执行 U4 表）
步骤 2  三列对账（声称 ↔ 证据输出 ↔ 预期）+ 2.5 语义有效性判断
步骤 3  沉默审计 + 逢绿必验 + 抽样（≤8 点 / ≤¥20）
```

### 步骤 0：门禁与声称表存在性核验（新增，fail-closed）

| 检查 | 命令 | 判定 |
|------|------|------|
| G12d 脚本存在 | `ls scripts/control-tower/verify-claims-table.sh` | 不存在 → 记 P1（门禁未部署/工作区漂移），K3 在本批**自行承担格式校验**（降级执行，不放行格式问题） |
| G12d 已接线 | `grep -n "verify-claims-table" scripts/pre-commit-check.sh` | 零命中 → P1（建成未接线，M3 模式） |
| 被审 dev doc 有交付声明节 | `grep -n "^#\{2,4\}.*交付声明" <dev-doc>` | 有代码交付但无此节 → **P1**（自证缺失，S-10/U4 违规）；纯文档任务豁免 |
| 三列格式 | `bash scripts/control-tower/verify-claims-table.sh <dev-doc>`（存在时） | exit 1 → P1；exit 2 → DEGRADED 显式记录 |

> 为什么 fail-closed：没有声称表 = 回到 v1 全量侦探模式，成本失控。交付方不填表 = 审计成本转嫁回 K3，这本身就是缺陷，必须记账而不是默默替他查。

### 步骤 1：跑证据命令

- 对 U4 表逐行执行「证据命令」列（grep/vitest/ls/git 等只读命令）。
- **安全约束**：仅执行已通过 G12d 白名单（或步骤 0 K3 代行格式校验）的命令；含 shell 元字符 `;&$\`<>` 的命令**拒跑**并记 P1（绕过白名单）。
- vitest 类命令在**当前工作树**跑（T2 语义）；需要干净快照判定时（转绿复核、疑似 WIP 污染）才走 T1（`git archive`），与 KIMI-AUDIT-INSTRUCTION v1.1 的 T1/T2/T3 规范一致。
- 每条命令记录：命令原文 / 退出码 / 输出摘要（关键行，非全量粘贴）。

### 步骤 2：三列对账 + 2.5 语义有效性

**对账**（逐行）：

| 声称 | 证据命令 | 预期 | 实测 | 判定 |
|------|---------|------|------|------|

- 实测输出满足「预期」→ 该行 PASS
- 实测与预期不符 → 该行 FAIL（整批结论至少 CONDITIONAL PASS；涉及转绿声称 → FAIL）
- 命令执行失败（非零退出/工具缺失）→ DEGRADED，**不等于**声称证伪，但必须显式记录（M1/M5 模式：环境依赖要先分辨）

**2.5 语义有效性判断**（每行必过脑子，这是 K3 在 v2 下的核心工作）：

证据命令的输出与声称之间必须有**语义推导链**。三类典型无效证据：
1. **答非所问**：声称「已接线」，证据命令 grep 的是定义处而非调用处（铁律：接线=被调用，非被 import）
2. **范围作弊**：声称「测试全绿」，证据命令只跑了 3 个新用例，绕过既有回归
3. **自证循环**：证据命令输出的是脚本自产中间变量，非产品物理输出（v1 维度 16 规则③同构）

语义无效但格式合规 → 记 P1（证据缺陷），该声称降为未验证，转入步骤 3 抽样池重验。

### 步骤 3：沉默审计 + 逢绿必验 + 抽样

**3a. 沉默审计（每批必做，防「不写进表就没人查」）**：

| 检查 | 方法 | 判定 |
|------|------|------|
| DS 对账（S-10） | dev doc DS 列表 ↔ U4 表声称行一一对应，禁重编号 | 缺项无显式 descope → P1（D331 DS13 同型） |
| diff 覆盖 | `git show <提交集> --stat` 的文件列表 ↔ U4 表声称行涉及的文件 | 被改动但无任何声称行覆盖的文件 → 抽入 3b 池 |
| 副作用沉默 | diff 中出现的新增 export / 改的公共接口 | 无对应声称行 → 抽入 3b 池 |

**3b. 抽样（沿用 v1 §四规则，池子扩展）**：

| 优先级 | 池子 | 抽法 |
|:---:|------|------|
| 1 | 新增绿 / 转绿声称 | **全验，不抽**（逢绿必验） |
| 2 | 无背书绿 + 沉默审计检出的未覆盖文件/接口 | 全验（见一个查一个） |
| 3 | 久置绿（>90 天未复核） | 每线至多 1 个，最老优先 |
| 4 | 随机绿 + 15 项清单中本批未被 U4 表覆盖的项 | 随机补足（seed = 报告日期 YYYYMMDD） |

- 批次上限 **8 点 / ≤¥20**，超出截断记入「结转清单」（下批优先）；**禁止**为压成本跳过优先级 1/2。
- 被抽中的点按 v1 维度 17/20a 判定标准执行（evidence 合规 + 必要时 T1 独立重跑）。

**3c. 15 项清单的新角色**：不再是每批全量逐项。U4 表覆盖的项 → 步骤 1-2 已完成；未覆盖的项 → 进入优先级 4 抽样池；下列项**不因 U4 表豁免**（每批仍必查，因为成本极低且历史全中过）：

| 必查项 | 一句话命令 |
|--------|-----------|
| #11 自我报告交叉对比 | U4 表对账本身即覆盖（步骤 2） |
| #13 控制塔执行审计 | bypass.log 对账 + CI job 级结论（job 级，禁整体 run 结论） |
| #14 版本编排合规 | VERSION.md / version.log / git tag 三处同步（CT-42 实证仍在犯） |
| #15 并行合规 | registry 活跃 session / worktree 隔离 / parallel-conflicts.log |

## 二、硬规则（原样保留，v1/v2 通用）

1. **逢绿必验**——不设「攒 N 个才审」
2. **绿必有背书**（K3 复核记录或创始人演示记录；无背书绿 = 应 🟡 而 🟢 → P1）
3. **fail-open 静默放行 = FAIL**（检查未执行 ≠ 检查通过）
4. **线首达 100% 全量复核**（20c，不豁免成本上限，分批 ≤2 周完成）
5. **声明绿 + K3 重跑红 = FAIL**（该批整体结论 FAIL，无中间态）
6. **NOT-AUDITABLE ≠ PASS**（对象不存在必须显式标注）

## 三、成本与 token 模型（定稿）

| 动作 | 成本 | 说明 |
|------|:---:|------|
| 步骤 0 存在性核验 | ≈¥0.1 | 4 条只读命令 |
| 单条证据命令执行+对账 | ≈¥0.5-1 | grep/ls 类近零；vitest 类取上限 |
| 语义有效性判断（每行） | 含在对账内 | 这是 token 主要花费，但已从「通读全 diff 反推声称」降为「读表+读命令输出」 |
| 抽样单点（含 T1 重跑） | ≈¥2-5 | 只在优先级 1-4 池子命中时发生 |
| **批次上限** | **≤8 点 / ≤¥20** | 超出转结转清单 |

**token 节省的来源**（相对 v1 全量侦探）：
- ❌ 消失：通读全部 git diff、自行反推「交付方声称了什么」、逐项追查 15 项
- ✅ 保留：跑命令（机器执行）、对账（表驱动）、语义判断（K3 不可替代）、沉默审计（防绕过）
- ⚠️ 边界：声称表缺失/格式违规时**不许**悄悄回到全量侦探模式——记 P1 并按 3a/3b 最小集执行，把成本压力通过缺陷单传回交付方
