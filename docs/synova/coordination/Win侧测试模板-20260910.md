# Win 侧测试模板（W-4 保优势）

> 2026-09-10 | 来源: K3 D651 评估——W1 的「真实 HTTP 全链路 + 7 段断言」是两侧最好单测之一
> 定位: Win 线测试形态基准，写新测试时对照，保住 C6 卫生 8.75 的优势

## 核心形态（W1 模板，3 个坚持）

1. **真实 HTTP 全链路，不 mock 路由**：测试发真实请求（`supertest`/`fetch` 打真实 Express 路由），不 mock 中间件/路由层——只有底层数据依赖（GraphStore/SQLite）才注入替身。mock 管线 = 测的是「假象」（铁律 12）。

2. **多段断言（≥7 expect），每段对应一个真实契约**：一个用例覆盖「入口校验 → 持久化 → 返回结构 → 副作用 → 边界」的多段，不是「一个用例只 assert 一个字段」的空壳。

3. **失败模式 red 留痕**：先构造「会失败」的输入跑红（如 mock `updateNode` 抛错 → 断言 `ok:false`），再实现跑绿——red 不是「模块不存在」的占位红，是「真实事故场景」的失败红（S-5）。

## 断言强度抽查（配合 W-3 覆盖门禁）

- 只调用不断言的用例**不计数**（空壳测试是 4 次接线失败史的温床）。
- 正常 / 降级 / 边界三类都要有（铁律 48）。

## 红线（防官僚化）

- 不追求「每个文件 N 个用例」的数量；追求「每个分支要么有断言、要么显式豁免」。
- spec 保持 131-153 行的简洁（K3 分寸提醒），加的是「契约表 + red 表」，不是整份长度。
