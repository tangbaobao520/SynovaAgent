## 一、任务与验收（D831）

**缺口**：`src/sentinel/sentinel-events.ts:9-13` 命名了三条 invariant（I1 可重建 / I2 单源 / I3 可审计），但**全是注释与错误码字符串**——没有运行期断言、没有注册表、没有归属、没有 fail-closed。`scripts/check-architecture.sh` 是**静态**门禁，看不见运行期接线。

**做什么**（①范式复用 DSH `dsh-invariants`，123 行，净逻辑约 40 行，**不引包**）：
1. 新增 `src/invariants/errors.ts`（`InvariantError`，`code='INVARIANT'` + `owner`）、`src/invariants/registry.ts`（`register(owner, install)` / `runAll(ctx)` / `list()` / `setEnabled()`，纯函数 + 数组/Map）、`src/invariants/companions/*.invariant.ts`（每域一个伴生，`export const install = (ctx, fail) => {...}`）
2. `src/deploy/bootstrap.ts` 新增 Phase 注册伴生：**任一伴生注册失败 → 启动失败**（原子回滚，不留半截监听器）
3. `src/server.ts` 的 `GET /healthz` 暴露 `invariants: {registered, lastFailure}`（**反接线探针**）

**首批 3 条断言**：① 工具 schema 真的发出去了（对照 D819 已修好的 `base.ts:152`）② tool 消息与 assistant `tool_calls` 配对（`tool_call_id == assistant.tool_calls[].id`）③ 降级信号不被后续成功写入抹掉。

**必须避开 DSH 自己的两个坑**：伴生 `install` **不得返回 Promise**（异步违规会被吞成 warn）；**只挂注册表=零保护** → 启动断言 `registered >= 3`，否则启动即失败。

**验收（禁 grep 命中，全部穿真实入口）**：
| # | 判定 |
|---|---|
| 负向 | 注入一次违规（临时让 provider 组装请求时丢 `tools`）→ 该请求 **5xx** 且日志含 `invariant violated by "<owner>"`；**不许 200 + WARN** |
| 正向 | 正常对话 + 一次真实工具调用 → 200，且 `/healthz` 的 `invariants.lastFailure === null`（不误报） |
| 探针 | `/healthz` 的 `registered >= 3`；跑完正向用例后至少 3 条 `hitCount > 0` |
| 原子回滚 | 第 3 条伴生 `install` 抛错 → **进程启动失败**，且重启后无残留监听器 |
| 异步纪律 | 伴生 `install` 类型上不得返回 Promise（`tsc` 通过 + 一条类型断言测试） |

**前置**：D819 已合入 main（工具接线已修好，断言才有可断言的对象）——**这就是"先修 P0-1 再上不变量"的硬顺序**。
**卡**：`task-state/D831.json` ｜ **工作量**：3–10 天（中值约 5）。

## 五、红线（违反 = 审计 FAIL）

1. **审计留队外**（M3）：K3 不进队；队内只说"自验"。
2. **一队一工作树**（M1）：禁止在在飞 session 的工作区动手。
3. **写集互斥**（M2）：越界先 `send_message` 申请，队长裁决后才动。
4. **指令 ≠ 工具副作用**（M4）：`synova-commit` 自带 push，不要写"不要 push"；禁 `--no-verify`、禁 `git stash`。
5. **证据写入归属**（M5）：证据文件按任务号命名，禁止写别的任务的证据文件。
6. **收尾三件**（M6）：diff / 自验结论 / 遗留清单，缺一不算收尾。

## 六、队长交回主线 CTO 时必须给的三件

① **最终 diff**（文件清单 + 关键差异说明）② **自验结论**（含反向验收的两次原始输出）③ **遗留清单**（文件:行 + 为什么不修）。主线 CTO 收齐后开 PR → 请 K3 独立审计 → 合并。
