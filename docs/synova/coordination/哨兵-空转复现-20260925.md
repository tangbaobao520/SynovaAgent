## 〇、结论先行（拆成两句，不可混谈）

**① 系统缺陷（P7）：`graph_triples` 边读写路径 100% 失效。** 不是"缺一列"，是**整表结构漂移** ——
生产表与仓库 canonical `SCHEMA_SQL` 不是同一张表。读侧静默 fail-open（方法层不抛错、返回空数组），
写侧必失败。**补 `props` 列只能修读侧，写侧仍然红。**

**② 计数影响：当前生产库 finding 计数不受 P7 影响 —— 因为图数据为空所致，不是因为路径健康。**
`graph_nodes = 0` / `graph_triples = 0`。在空库上测"空转"**无意义**：必须构造合成图夹具后，
P7 才显形（同节点集 + 同边集，仅换 schema 断面 ⇒ **15 件哨兵产出改变**，边读取行数 `0 → 144`）。

**③ 因此**：任何"某哨兵空转/零调用"的结论，若不在**可读边断面**上重跑，都无法区分
「图里确实没数据」与「每一次边查询都在 prepare 阶段就死了」。

## 十一、提交期门禁阻断与 ACK 登记（含 2 条批级门禁缺陷）

### 11.1 阻断事实

本卡真提交被 `pre-commit-check.sh` 的 Gatekeeper 段**硬拦 `exit 1`**：

```
[GATEKEEPER] 检测到今日 1 次 --no-verify 绕过记录
[GATEKEEPER] 若该记录系误报且已人工复核, 可用 SYNO_GATEKEEPER_ACK=1 放行本次
[GATEKEEPER] 修复导致绕过的根因后，bypass.log 中今日记录将在次日自动清零
```

命中表达式：`grep -c "2026-09-25.*detected-bypass" .claude/bypass.log` = **1**

### 11.2 「干跑绿 ≠ 真提交绿」已被本卡实证

`synova-commit:445` 的 `--check` 只认硬失败字串 **`提交已拒绝`**，而该字串在
`pre-commit-check.sh:1589` 才输出；Gatekeeper 在 ~253 行即 `exit 1`。
⇒ **`--check` 干跑必绿、真提交必红**。本卡因此改为直接跑 `pre-commit-check.sh` 取真值。

### 11.3 缺陷 A（批级）：跨分支 `head-mismatch` 被 commit 进 main ⇒ 全天锁死全线

| 项 | 实测 |
|---|---|
| 记录内容 | `2026-09-25T00:56:43Z detected-bypass head-mismatch marker=ce5b13b9… parent=2b38d177…` |
| 记录类型 | **`head-mismatch`（D366 三判之一）**，**不是** `no-precommit-marker` |
| 今日类型分布 | `detected-bypass` 仅此 1 条；`no-precommit-marker` = **0 条** |
| 该行位置 | **已 git 跟踪且存在于 `origin/main`**（`git show origin/main:.claude/bypass.log` 第 1758 行） |
| 引入提交 | `0ab457f2`（PR #762，D937-v2 门禁修复） |
| `marker`/`parent` 归属 | `ce5b13b9`、`2b38d177` **均不在 `origin/main`**（属 D937 分支） |

**两个后果：**
1. **文案与事实不符**：门禁输出「1 次 **--no-verify** 绕过记录」，但当日**没有任何** `--no-verify`

### 11.4 缺陷 B（批级）：`TODAY` 本地时区 vs 日志 UTC `Z` ⇒ 每日前 8 小时静默失效

- 比对式：`TODAY=$(date +%Y-%m-%d)`（**本地 +08:00**） × `grep "${TODAY}.*detected-bypass"`（日志戳为 **UTC `Z`**）
