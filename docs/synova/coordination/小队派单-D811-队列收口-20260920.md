## 〇-b、为什么派它 / 做完推动什么

| 项 | 内容 |
|---|---|
| **为什么是它**（实测） | 未合 PR **40 个**；每合并一次其余 PR 变 dirty → 必须重同步 main + 重跑全量 CI（本轮已实测反复 4 次）。**队列不收口，开新车道只会让合并更慢** |
| **做完推动什么** | ① 未合 PR 从 40 降到 ≤12（可签字关闭一批）② 队列健康成为**机器算的旁路指标**（挂看板，不拖慢主路径）③ 队列上限写进机制，超限时**提示退役**而不是拦死 |

| **可并行性判定** | **可并行**：与在飞的 `team/win-batch14`（`src/**`）、K3 审计（`k3` 域）**零文件交集**；**必须串行**：控制塔脚本（见硬边界）等 #657 合并后再动 |

## 一、四件交付物（缺一不算完成）

1. **队列台账扫描器**（`scripts/project/` 下，纯读）：对每个未合 PR 输出 `编号 / 标题 / 主人 / behind=N / CI 状态 / age(天) / 是否可自动关闭`。**机器算，人只看**（DSH 原则④）。
2. **可签字关闭清单**（`docs/synova/coordination/`）：按退役优先排序，**每条给关闭理由**（已被取代 / 已合入 main 的内容 / 无主超期 / CI 长期红）。创始人签一次字即批量关。
3. **队列上限机制（提示层）**：未合 PR > 12 时，在队列派生器/看板输出一条**显式告警**"先退役再开新 PR"。**只提示不拦死**（DSH 原则⑤：诊断旁路，不污染主路径）。
4. **旁路派生指标**：队列长度 / 最老 PR 年龄 / behind 分布 → 挂进现有派生链（`scripts/project/gen-project-board.py` 或同域派生器），**不得让主提交路径多跑任何检查**。

## 二、纪律（照做）

- 全流程按《[DSH 决策镜头](../skills/dsh-decision-lens/SKILL.md)》：**先量，不先加机制**；**超限即退役**；**引用 DSH 必须给 file:line**。
- 验收按《[验收标准-穿真实入口-v1](验收标准-穿真实入口-v1-20260918.md)》：五态 + 三问 + 四条禁止；命令 + **原始输出**。
- 队内只说"自验"；交付标注 `可提请独立审计`（禁自称"审计通过"）。
- 禁 `--no-verify` / `git stash` / force push；`synova-commit` 自带 push。
- **PR ≤12 文件 + 单域**；超了拆。
