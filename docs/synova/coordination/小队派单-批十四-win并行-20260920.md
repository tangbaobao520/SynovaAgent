## 三、流程（照做，不得跳步）

```
① 队长建专用工作树 + 分支；把本文件与 4 张卡读一遍
② 开工前冲突扫描：对每个切片 grep 目标文件的现有引用，把「谁还会改这些文件」写成一页（D819 试点实测：开工前拦下 4 处写集冲突，CI 红 0）
③ 每个切片先写规格（一句话输入/输出/降级契约 + 验收命令），队长批了再写码
④ 编码 → 队内自验（独立队员，M3：队内只说"自验"，禁"审计通过"）
⑤ 反向验收：把修复抽掉/还原缺陷 → 必须报红 → 再还原全绿（给两次原始输出）
⑥ 逐卡提交（走 synova-commit），证据按任务号命名落 `docs/synova/product-lines/evidence/`
⑦ 队长收尾三件：diff / 自验结论 / 遗留清单；**归属逐张收口**（owner 不自动释放：`claim_release.py release` 或 `gc --stale-pid`）
```
