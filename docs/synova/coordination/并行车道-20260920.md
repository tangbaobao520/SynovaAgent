# 并行车道图（2026-09-20 CTO 出件）

> 用途：创始人一眼看清**现在哪些活能同时干**、每件**为什么干**、干完**推动什么**。
> 依据：`task-state/D800+` 30 张未完成卡 + `ownership.yaml` 域规则 + 依赖字段（`depends_on` / `blocked`）。
> 纪律：所有车道均按《[验收标准-穿真实入口-v1](验收标准-穿真实入口-v1-20260918.md)》+《[小队模式-固化件-v1](小队模式-固化件-v1-20260919.md)》交回三件（diff / 自验结论 / 遗留清单）。

## 结论：现在可并行的 = 4 条车道

| # | 车道 | 域 | 为什么现在开 | 干完推动什么 |
|---|---|---|---|---|
| 1 | **win-产品缺陷批** | `src/**` | 这些不是"缺功能"，是**已写好的代码没接线 / 已存在的缺陷**（6 处零生产调用） | 把交付率里"写了没接"的部分**直接兑现**；其中 D826 是**第 2 个客户接入前必须修** |
| 2 | **mac-控制塔固化批** | `scripts/**` | 本轮教训：靠人记的机制必然失效（派单引用不存在小节已第 2 次） | 把「验收标准 / 验收记录 / 三层清单 / 小队纪律」四件**从文档变成物理门禁**，之后所有派单自动受约束 |
| 3 | **K3-独立审计批** | `k3` | 结论只认 K3；线 10 差"10-8 独立复核"这一步 | 产出**第一条真正 100% 的线**（面板数字第一次由证据撑住）+ 试点小队是否可信的数据 |
| 4 | **devdoc-规格批** | 无代码写集 | 线 27/28 已进 yaml，但面板 `lines[]` 由**冻结 V1 标准**驱动 | 新线进面板计分的前置 —— ⚠️ **需你先拍板「新线是否进计分」** |

四条的写集两两不相交（`src/**` / `scripts/**` / `k3 域` / 纯文档），可同时开工。

## 车道 1｜win-产品缺陷批（建议顺序：先安全面，再接线面）

| 任务 | 内容 | 为什么这条排前面 |
|---|---|---|
| **D826** | `search()` 缺租户过滤 | 跨租户泄露面，**第 2 个客户接入前必须修** |
| D827 | 会话统计两处「有雏形零接线」接通 | `agent_metrics` 零写入 + checkpoint 未落 |
| D828 | 趋势算法接线（`computeTemporalBaseline` 零生产调用） | 有算法无出口 = 用户看不到 |
| D820 | 删会话不删诊断报告 | 隐私/数据资产；清理函数已存在却零调用 |
| D822 | 降级信号自遮蔽（写失败被同轮后一次成功抹掉） | 假绿源头之一；测试还固化了缺陷 |
| D823 | im-inbound 调不存在的方法 | IM 历史恢复**静默空转** |
| D829 | `packages/evolution` 接线（2,503 行零生产引用） | 线 17 第一条验收 |

- **不做会怎样**：数据面越接越多客户，D826 就是事故；其余继续"看起来完成了"。
- **并行性**：同域，**默认单 session 串行**；只有逐文件写集互斥（不同文件）时才允许 2 人小队。

## 一条铁律（本轮教训，进了模板）

> 跨车道**不得碰同一文件**；同域多任务**默认串行**，只有逐文件写集互斥才允许并队。
> 每个派单必须写清「为什么派它 / 做完推动什么 / 不做会怎样 / 可并行性判定」——缺一节 = 不具备开工条件。
