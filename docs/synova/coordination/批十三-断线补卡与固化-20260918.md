## 三、两张最重的卡要点（其余见卡面）

### D831 P-2 不变量机制（前提清单第 2 项）
- **为什么它是前提**：它决定"每个能力域是否真的接了线"（总纲 §1.1 的 B 段由它保证）。**没有它，"写了没接"还会继续发生**——已发生 9 次。
- **首批 3 条断言**（照 DSH「比对两个真实值」的形状）：① 工具 schema 真的发出去了 ② tool 消息与 assistant `tool_calls` 配对 ③ 降级信号不被后续成功写入抹掉。
- **必须避开 DSH 自己的两个坑**：异步 listener 的违规会被吞成 warn（→ 类型上禁止伴生 `install` 返回 Promise）；**只挂注册表 = 零保护**（→ 启动断言 `registered >= 3`，否则启动即失败）。
- **验收关键**：负向（注入违规 → 5xx 且日志含 owner）＋ 正向（不误报）＋ 反接线探针（`hitCount > 0`）＋ 原子回滚。

### D834 固化③ 面板与台账跟踪三层
- **现状**：面板只读 `ledger.json`（由 `gen-project-board.py` 从 `product-lines.yaml` + `task-state` + 证据派生）；**三层清单与两条新线还没进派生链** → 面板看不见"前提"和"线外工作项"。
- **要求**：三层都能在面板上看到；每个工作项能回答**自研还是借鉴**（③/①/②）、五态、负责人、卡号；**断线计数必须是机器判定**（删掉证据/卡后数字跟着变 —— 反向验收）。
