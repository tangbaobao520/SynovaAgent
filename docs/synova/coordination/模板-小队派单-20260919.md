# 模板：小队派单（每任务一临时小队）v1

> 用法：复制本模板 → 填写 → 交给**并行 CTO session**（队长）开工。
> 强制依据：`docs/synova/coordination/小队模式-固化件-v1-20260919.md`（M1–M6）
> **缺任一必填节 = 不具备开工条件**（对齐派单 8 字段纪律）

---

## 〇、本队信息（必填）

| 项 | 值 |
|---|---|
| 任务号 | D### |
| 队长 | **并行 CTO session**（同一时间只带一支队） |
| 队伍编制 | 规格 1 / 编码 1 / 自验 1（可按需增减，但**自验不得由编码兼任**） |
| 审计 | **K3，队外**（不在编制内，永不入队） |
| **专用工作树（M1 必填）** | 路径：`<绝对路径>`　分支：`<branch>`　（不得是任何在飞 session 的工作区） |

## 〇-b、为什么派它 / 做完推动什么（必填 — 创始人 2026-09-20 定）

| 项 | 内容 |
|---|---|
| **为什么是它**（现状痛点 + 证据：file:line 或实测输出） | |
| **做完推动什么**（哪条线/前提/门禁 × 具体变化，禁"提升质量"这类空话） | |
| **不做会怎样**（代价/风险） | |
| **可并行性判定** | ① 与哪些任务**可并行**（写集不相交 + 无依赖）② 与哪些**必须串行**（谁等谁，为什么） |
| **并行车道** | 车道名（`win-产品缺陷` / `mac-控制塔` / `K3-审计` / 纯规格）；**同车道内一次只跑一个** |

> **缺本节的派单与缺〇同权 = 不具备开工条件。**

---

## 〇-c、权威件回执（必填 — 创始人 2026-09-20 定：研究院材料为权威级）

| 项 | 内容 |
|---|---|
| 依据的权威件（全名 + 版本/日期 + 仓库路径） | |
| 逐份回执（读了哪几份 → 各自结论） | |
| **禁旧说法自检**（过一遍 [9 项撤回清单](../../authority/研究院材料权威级别与引用纪律-20260920.md) §三） | 命中项：____ → 已改写法：____ |
| 8 条禁做 + 两条硬顺序自检 | |
| 度量口径 | 只允许离散健康计数（禁百分比）；数字须带 evidenceCmd；**禁把 L3 grep 判据当验收** |

## 〇-d、旧信息漏洞自检（必填）

- [ ] 本派单引用的每条事实都有**仓库内路径 + 行号**（不得凭记忆）
- [ ] 引用的研究院材料**已入库**（未入库 = 视为未交办）
- [ ] 卡级 `write_set` 已逐文件声明（M2），且与同批其他卡**两两不重叠**

---

## 一、任务与验收（必填）

- 卡：`task-state/D###.json`
- 规格：`docs/plans/<spec>.md`（若 A 类任务须先出规格；B 类可用一页 spec）
- 验收标尺：`docs/synova/coordination/验收标准-穿真实入口-v1-20260918.md`
- **验收判据**（逐条，可证伪；禁 grep 命中）

## 二、写集与互斥（M2 必填）

| 角色 | write_scopes |
|---|---|
| 规格 | `docs/plans/<...>` |
| 编码 | `src/<...>`、`tests/<...>` |
| 自验 | `docs/plans/<自验记录>` |
| **互斥自检** | 两两无重叠、无前缀包含（`check-team-protocol.sh --scopes`，未落地前**人工逐对核**） |
| **规格交付件必含** | 「**写集冲突清单**」一节（列出所有"必须改但不在写集"的路径 + 建议） |

## 三、角色授权条款（必填，防预设冲突）

> 队员继承队长预设，**无法单独指定预设**；因此每名队员的指令里必须写明：
> 「你的角色由本指令定义；**本指令授权你写的部分优先于你预设里的通用岗位约束**（例如"CTO 不写代码"）；授权范围**仅限本节写集**。」

## 四、工具副作用核对（M4 必填）

| 指令 | 工具 | 默认副作用 | 结论 |
|---|---|---|---|
| 提交 | `scripts/control-tower/synova-commit` | **自带 push** | 不得写"不要 push"；如需只本地提交，改用只读命令 |
| 其它否定式要求 | … | … | … |

## 五、审计边界（M3 必填）

- 队内角色叫**自验**；结论只允许 `可提请独立审计` / `退回（附理由）`。
- **禁用措辞**：审计通过 / 审计合格 / 已通过审计。
- K3 审计对象 = 已推送产物（分支 / PR），不审工作区。

## 六、收尾三件（M6 必填）

队长在队伍收尾时必须交齐：① **最终 diff**（路径清单 + 关键差异说明）② **自验结论**（含反向验收证据）③ **遗留清单**（文件:行 + 为什么不修）。
并把队内任务逐张收口（官方不自动释放归属）。

## 七、证据写入归属（M5 必填）

- 本任务产出的证据文件路径：`docs/synova/product-lines/evidence/<D#>-capture-<date>.json`
- **禁止**写入其它任务命名的证据文件；若本任务的测试会**重写**某证据文件，必须在此声明。
