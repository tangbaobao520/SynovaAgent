# 每周自检对齐任务（2026-08-25 创始人定）

> 背景: AGENTS.md/CLAUDE.md 停在 V4.5.1，控制塔演进 V5.1.1 期间文档冻结 → 门禁语义/版本/定位严重漂移（AGENTS.md 对齐教训，2026-08-25）。
> 机制: CTO 每周自检对齐——用脚本检测文档 vs 代码漂移，发现即安排对齐。

## 自检脚本

`scripts/control-tower/weekly-selfcheck.sh`

**检查项**（漂移检测）：
1. AGENTS.md / CLAUDE.md 版本 vs 控制塔 VERSION.md（应 V5.x 一致）
2. pre-commit 语义（软提示 vs 实际 pre-commit-check.sh）
3. pre-push 语义（门禁 0-5 vs 实际 pre-push-check.sh）
4. 专家数（AGENTS.md 声称 vs expert/ 目录实测）
5. 桌面端定位（AGENTS.md 是否含）
6. 技能双轨同步（.claude ↔ .dsh，sync-dsh-skills --check）
7. cto-handover 派单规范（§〇b DSH 借鉴核查）

**输出**: `[OK]`（零漂移，exit 0）/ `[DRIFT] <文档> <差异>`（有漂移，exit 1）/ degraded（exit 2）

## 定时方式（DSH 原生 — dsh-task-board cron）

在 Web GUI 侧边栏「任务看板」创建每周任务：

| 字段 | 值 |
|---|---|
| 任务名 | 每周自检对齐（文档漂移检测） |
| cron（5 段，Host 本地时区） | `0 9 * * 1`（每周一 09:00） |
| workspace | /Users/wane/SynovaAgent |
| agent 预设 | 🧭 synova-cto |
| 指令 | 跑 `bash scripts/control-tower/weekly-selfcheck.sh`，有 [DRIFT] 则：① 读漂移项 ② 对照实际代码对齐（AGENTS.md/CLAUDE.md 版本/门禁语义/定位）③ 提交 PR ④ 汇报创始人 |

**备选（系统级）**: launchd（先例 scripts/backup/backup-db.sh 每日 03:30）——每周一 09:00 跑脚本，漂移写 `docs/synova/CTO-HEALTH.md` 自检段。若 task-board cron 不可用则用此。
