## 5 项根治（dev doc 详设，此处为执行要求）

### ① gh CLI 安装 + GitHub token 共享（最大杠杆）
- 下载 gh darwin-arm64 官方二进制 → `~/.local/bin/gh`（校验 sha256）
- token 写入 `.credentials.yaml`（GITHUB_TOKEN，权限 actions:read+repo；0600；不 commit）或 `gh auth login --with-token`
- 验证：`gh auth status` + `gh run view --log` 拉到最近 run 日志 + `gh run cancel` 生效
- **纪律**：CI 调试前先 `gh auth status`，日志 5 分钟可见

### ② CRLF 规范化
- 定位 `tests/control-tower/*.test.sh` 等脏文件 → `git add --renormalize` + `.gitattributes` 加 `*.sh text eol=lf` / `*.py text eol=lf`
- 验证：`git status` 干净 + `git diff origin/main` 零 CRLF 噪音

### ③ 机器人提交 merge 豁免
- CI 环境提交（GITHUB_ACTIONS 或 bot 作者）自动登记 bypass.log（COMMITTED 行），不拦人工
- **红线**：人工 --no-verify 仍严格对账（不削弱真实绕过检测）
- 验证：CI 提交无需人工补记 + 人工绕过仍被拦

### ④ CI 步骤挂起探针 + 首行输出
- desktop-build.yml 构建步骤：首行 `::group::` + 进度 echo + 挂起探针（10 秒报卡点，不等到 10 分钟超时）
- 验证：构造挂起 → CI 日志 10 秒内显示探针

### ⑤ CI debug 回传纪律
- 写进控制塔文档：未来 debug 回传必须推 `ci-debug/*` 独立分支，永不动工作分支；首选 gh CLI 日志
- 验证：控制塔文档（CT 队列/复盘纪律）有明确条目

## 写集约束
