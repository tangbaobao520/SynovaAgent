## 5 项根治（Win 侧建议 #2-#6，均为修已有 bug）

### ①（#2）主树占用检测前移（M8 变体治本——P1 清单落地）
**问题**：并行污染只拦"新开工"（task-start），不拦"存量"（已在主树工作的 session 直接改文件）→ M8 变体第四次复发（D394→D481/482→D486）。
**方案**：
1. pre-commit 检查：主树工作区脏 + session_registry 有活跃 session → 拦截（提示 worktree 隔离）
2. 用既有 session_registry.py + git status 脏检测（不新建 registry——复用）
3. **验证**：主树脏 + 活跃 session → pre-commit 拦；worktree 内不拦；单 session 不拦

### ②（#3）merge/补记提交走轻量门禁（fastlane 扩展）
**问题**：fastlane 只覆盖"纯 bypass.log 提交"（synova-commit L333-337），merge commit + "补记+bypass 组合"跑全量 13 组 → 每次合并 5-8 分钟纯门禁成本。
**方案**：
1. fastlane 扩展：merge commit（MERGE_HEAD 检测，同 D328 豁免模式）+ 纯补记组合提交跳过非证据链组
2. **验证**：merge commit / 补记组合提交 → 轻量门禁（<10s）；普通提交仍全量

### ③（#4）D331 worktree 场景补记自动同步
**问题**：worktree/merge 场景的提交记录落主树 bypass.log，分支 worktree 缺行 → 每次 merge main 后 push 再补记一轮。
**方案**：
1. hook 登记写共享日志（主树 .claude/bypass.log——worktree 也共享主树 .git 的 hooks？）或对账时自动补
2. **验证**：worktree 提交 → 主树 bypass.log 有记录（无需人工补记）；对账通过

### ④（#5）baseline 漂移自动归因
**问题**：merge main 引入 mac 提交（如 D527-D535）后 tsc 基线变化（src/server.ts:396），每次人工确认"main 现状 vs 本分支引入"。
**方案**：
1. push 时对比 origin/main 基线：main 现状的漂移不拦（自动归因），本分支引入的才拦
2. 用 baseline-check.sh 扩展
3. **验证**：main 既有漂移 → 自动归因不拦；本分支新增漂移 → 拦

### ⑤（#6）控制塔测试双平台 CI（ubuntu + windows-latest）
**问题**：Mac（LF）开发测不出 CRLF bug → task-start/verify-parallel 同型第三次（平台差异靠 Win 实测才暴露）。
**方案**：
1. ci.yml 控制塔测试 job 加 windows-latest（与 ubuntu 并行跑 tests/control-tower/*.test.sh）
2. scripts/ 变更 PR 必须双平台全绿（门禁）
3. **验证**：控制塔测试在 windows-latest 全绿；CRLF 类 bug 在 CI 暴露（不再等 Win 实测）
