## 一、事实（CTO 实测）

```
$ git -c core.quotepath=false diff --name-only origin/main...docs/d780-k3-audit-batch4 | wc -l
  51        # 14 报告 + 33 task-state + 1 bypass.log + 1 台账 + 1 brief + 1 派单文档

$ bash scripts/control-tower/check-pr-budget.sh --base origin/main --files "<该 51 文件>"
  ❌ ① 变更文件数 51 > 上限 12 —— 拆 PR（禁调高上限）
  ❌ ② 变更跨域（k3 的 audit-reports/** 与 mac 的 coordination/** 同 PR）
  ❌ FAIL PR 超预算
```

**判定：这是门禁口径问题，不是审计方的问题。**

PR 预算门禁（`check-pr-budget.sh` 头注释自述，编号见该文件）的自述口径是「**冲突概率 ∝ 改动大小 × 分支存活时间**」，其保护对象是**审查面**（代码/门禁/CI 配置）。而审计批次的产物是 **append-only 治理产物**：`docs/synova/audit-reports/**`（K3 独占、逐份新增）+ `task-state/**`（每任务一个文件、零冲突）+ 共享台账。按代码 PR 的 12 文件上限去卡它们，只会把唯一的落地路径堵死（并诱导"拆 5 个 PR"这种纯开销动作）。

**同族摩擦（已积三例）**：`.claude/bypass.log` 每次提交自动登记也计 1 件 → 实际可用额度 11；#536（批次三派单 24 文件）卡死至今；本次审计批次 51 文件。

## 二、任务：把「只计审查面」写成门禁口径

1. **计数口径**：`check-pr-budget.sh` 的文件数只统计**审查面路径** —
   `src/**` · `scripts/**` · `tests/**` · `packages/**` · `extensions/**` · `electron/**` · `electron-renderer/**` · `app/**` · `.github/**` · 根级配置文件（`package.json` 等）
   **不计入**：`docs/**` · `task-state/**` · `.claude/**` · `memory/**` · `synova_worker/**` 之外的纯文档/治理产物
2. **域判定同步**：② 项只在**被计入的文件**上做单域判定（不计入的治理产物不再触发跨域）
3. **输出必须显性**：打印「审查面 N 件（上限 12）／治理产物 M 件（不计入）」——**不许静默**（铁律 11：口径变化必须可见）
4. **测试**：`tests/control-tower/check-pr-budget.test.sh` 增加用例 —
   ① 12 件代码 + 30 件 docs → 通过（并打印治理产物件数）
   ② 13 件代码 + 0 件 docs → 拦（上限未被放宽）
   ③ 跨域仍拦：`src/x.ts` + `scripts/y.sh`（两域审查面）→ 拦
   ④ 反向验证：把 `src/` 从审查面列表移除 → 用例② 变绿（证明列表真被读）
5. **Note + K3**：本变更改的是门禁口径 → 必须写 `memory/notes/implemented/` Note（含"为什么放宽""放宽后什么仍被拦"），并在 PR 里显式请 **K3 审这道门禁变更**（开发者改过的门禁同样受审）
