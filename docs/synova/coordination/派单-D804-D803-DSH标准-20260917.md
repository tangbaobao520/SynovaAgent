## 一、DSH 标准派单模板（**从本单起强制**，适用于 A 类任务）

```
【派单 D###｜里程碑 M?】<一句话目标>

〇 为什么（背景 + 里程碑锚定 + 不做的后果）
一 依据与边界
   依据计划: v<ver>@<sha256-8> ｜ V1 分母: <文件>
   域: <win|mac|k3> → 单域单 PR ｜ 文件预算 ≤12（含 spec 与测试；超了先拆）
   红线: 不碰 scripts/audit/** ｜ 不改判分 calc-progress.py ｜ 禁 --no-verify
二 阶段 0 — dev doc（**未过复核不得动 src**）
   产出: docs/plans/<域侧>/implementation/SYNOVA-IMPL-<域>-D###-<主题>-<date>.md
   必含八节（缺一退回）:
   S1 价值与入口（谁 / 什么场景 / 触发什么 / 预期可观测结果）
   S2 契约：每个新增或改动接口 @input/@output/@degraded/@error/@idempotent（三态 0/1/2）
   S3 数据流图：端到端链路，每步标出失败分支
   S4 失败模式表（≥6 条）：行为 + 降级动作 + **用户可见信号**（禁静默）
   S5 切片计划（≥4 片）：每片"改哪些文件 + 断言 + 回滚方式"，可独立验收、可独立回滚
   S6 验收断言表：逐条绑定 verify 命令 / 场景 ID / 证据类型 / fail_when
   S7 幂等与可观测：重复执行行为、日志与计数、证据落盘路径
   S8 回滚方案（版本回退 / 特性开关）
   复核门：CTO 复核后冻结；冻结后改口径须附变更说明
三 阶段 1–N — 按 S5 切片推进
   每片节奏：改代码 → 跑该片断言 → **贴原始输出** → 提交 → 下一片
   禁止：一个提交混多片；跳过断言进入下一片
四 提交纪律
   隔离 worktree + 自开分支 + 先建 task brief（写集用 `declare-write-set.sh` 机器生成）
   `synova-commit` → push → 开 PR（PR 正文附断言表）；**"文件写好了"不算完工**
五 汇报格式（缺项即退回）
   ① dev doc 链接 ② 断言表逐条：命令 + 原始输出 ③ 反向验证（破坏一处 → 必红）
   ④ 未做 / 未能验清单（显式）⑤ 红线自查（git log 证明未碰禁区）
六 交付后
   合并 → 次日跨天重跑一次（证据日期滚动，避免同日 stale）→ 交 K3 复核点
```

## 四、阶段与门（排队规则）

1. **dev doc 车道 WIP=1**：当前线3 spec 收尾中 → **D804 先出规格**，D803 排在 D804 规格冻结后（或经创始人批准插队）
2. **规格冻结门**：dev doc 经 CTO 复核前，**不得提交任何 `src/**` 变更**（违反 = 该 PR 退回）
3. **编码车道 WIP=2**：D804 实现 + D803 实现（各自独立 worktree/分支/PR）
4. **域**：D804 = win（`src/agent`、`electron/**` 侧实现归 win 域，Mac 代行按 D773）；D803 = win（`src/connectors`、`src/l4`、`extensions/**`）→ 两卡各自单域单 PR

## 五、CTO 验收方式（防"写完就完"）

1. **抽查复跑**：从 dev doc 的断言表随机抽 5 条，按它给命令重跑 → 必须逐字对上
2. **切片完整性**：S5 每片必须有独立提交 + 独立断言输出（缺片 = 未完工）
3. **反向必红**：破坏一处关键实现 → 对应断言必须红（对不上 = 断言是空壳）
4. **K3 独立审计**：两卡完成后进 K3 定向批次（禁自我审计）
