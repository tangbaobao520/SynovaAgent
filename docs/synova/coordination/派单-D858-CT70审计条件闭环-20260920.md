## 一、四条条件（缺一不算完成）

**P1｜canary 支持 glob，覆盖语义由物理展开承载**
- 现状：`check-canary-drift.sh` 只匹配字面路径 → 两条 `tests/project/*.test.sh` 靠**注释文本**声明被收录 = 假覆盖风险。
- 要求：脚本**真实展开 glob**；注释不再是覆盖依据。
- **夹具（先红后绿，两次原始输出）**：把 `tests/project` 的接入删掉（模拟回退）→ 脚本**报红**；恢复 → 绿。

**P2｜告警在绿腿也可见**
- 现状：分隔符告警在 `stdout` 被重定向时**只失败才 cat** → 绿态吞告警。
- 要求：改为 CI 可检索的 `::warning`（或独立日志文件），给**一次真实运行**的可见性证据。

**L4-1｜注释与物理覆盖一致性检查**
- 注释声明 N 条、实际展开 < N → **报红**（防「glob 删了注释还在」）。

**L4-3｜证据包标准化**
- 匿名/无 token 场景**取 job 日志**的可行方法：给**一条命令 + 示例输出**（K3 本次取证受限，正是缺这个）。

**回归**：既有清单判定**不变**（给基线 vs 闭环后输出对比）。

## 二、流程（M1–M6，照做）

1. **M1** 建专用工作树（`.synova-wt-d858` / `gate/d858-canary-glob`），**不复用任何在飞工作树**；
2. **开工前冲突扫描**：对写集内每个文件 `grep -rn` 现有引用与调用方，写成一页（**给命令与完整输出，不许 `head -N` 截断**）；
3. 先写规格（输入/输出/降级契约 + 验收命令），队长批准再写码（铁律 47/48）；
4. 编码 → **队内自验**（自验员独立，只读 + /tmp）；
5. **反向验收**：抽掉修复必须报红（两次原始输出）；
6. 逐条提交，走 `synova-commit`（**自带 push，不要再手工 push**）；证据按任务号命名落 `docs/synova/product-lines/evidence/`；
7. **M6 队长收尾三件**：diff / 自验结论 / 遗留清单 → **提交进仓库**（git 追踪，给路径）；**归属逐张收口**（owner 不自动释放）。
