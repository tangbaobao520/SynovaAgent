## 四、W1 三项规格（Phase 0 复核通过后执行）

### D923 = D1｜K3 升级为必经合并门禁 + 异构交叉评审

- **做什么**：把 K3 审计从"交付后可选环节"变成**合并通道上的必经门禁**——**三类路径硬门禁**（安全 / 财务计算 / 数据迁移），其余 PR **抽样 20%** 异构交叉评审；评审清单加入「**边界值 / 负值 / 越权**」三节（裁定 §二第 9 条 + 清单 §二.5 的证据：同源评审员集体漏边界型缺陷）
- **不做什么**：不做"全 PR 硬门禁"（会把队列吞吐绑死在 K3 在线率上，违反裁定给的失效条件）
- **验收（三路径 + 反例）**：
  - 正常：三类路径 PR 缺 K3 结论 → **合并被拒**（贴 exit code 与拒绝语）
  - 降级：K3 不可用 → **显式 degraded 提示 + 不静默放行**（贴输出）
  - 反例：把门禁判定函数改坏（例如恒 return true）→ 必须**报红**（判别性夹具）
- **失效条件**：K3 资源不可持续 → 退化为"关键路径抽样异构评审"，**不可全免**（清单原文）
- **写集（Phase 0 细化，预期落点）**：`scripts/control-tower/`（门禁判定 + 配置）、`tests/control-tower/`（三路径 + 反例夹具）、`.github/workflows/ci.yml`（如需 CI 侧）

### D924 = B4｜子进程输出协议规范（半天级）

- **做什么**：立"子进程输出协议"规范：**禁止"标记字符串分割混合流"**（清单 §一.4 的活证据形态：把状态码用标记字符串混进 stdout 再字符串分割 → 响应体含该标记即解析错乱）；规范落点 = 仓库规范文档 + 一条可执行 lint/check（而非纯文档）
- **不做什么**：不重构历史调用方（存量清单化，新增即拦）
- **验收**：正常路径（合规写法通过）/ 降级（检查器不可用 → 显式 degraded）/ 反例（写一个"标记混流"样例 → 必红）
- **失效条件**：全仓无"标记字符串分割混合流"后，规范转为 lint 规则，文档撤（清单原文）
- **写集（预期）**：`docs/synova/coordination/`（规范件）、`scripts/`（检查器）、`tests/control-tower/`（夹具）

### D925 = C2｜deps-interface + setter 注入立为标准模式（半天级）

- **做什么**：把 Win 侧验证过的可测试性范式（6 组 `setXxxDeps` 接口 + setter 注入 + 传 null 恢复生产默认，清单 §一.3）提炼为**仓库标准模式**：写进 dev doc / 任务模板；新模块验收加一条「**单测无需真实环境即可跑**」
- **不做什么**：不改存量模块（只对新模块生效）
- **验收**：正常（按模板写的样例模块单测零真实环境依赖通过）/ 降级（模板缺失 → 显式提示）/ 反例（"无注入点"样例必须被判红）
- **失效条件**：新模块默认采纳后，模板条目并入通用规范（清单原文）
- **写集（预期）**：`.claude/skills/`（模板/规范）、`docs/synova/coordination/`、`tests/control-tower/`

## 五、红线（违反 = 事故）

- **门禁类改动**（D923/D924）**必须**先红后绿夹具 + 反例夹具；**改门禁者不得自判通过**——受 K3 独立审计（裁定第 9 条）
- 不碰 `scripts/audit/**`、不写审计标准、禁自我审计
- 不改 `src/` 下产品代码（W1 三项均为控制塔/规范面；W2 的 B1 才涉及 `src/`）
- 禁 `--no-verify` / `git stash` / force push；不宣称"通过"——**自验只给「自验结论」**
- 所有数字贴**命令原始输出**；交付附 `git ls-remote --heads origin | grep <branch>` 回执
