## H. D798 一页轻量 spec（CTO 出，B 类；执行方按此实现）

**链路**：每日 cron（Host 本地时区）→ ①保鲜重跑（D774 `rerun-evidence.sh`，现有）→ ②重算账本（`gen-project-board.py`）→ ③写入工作区 →
④ **workflow 只产分支**（禁直接开 PR —— F6 教训：`GITHUB_TOKEN` 建的 PR 无 check-runs，永久 blocked）→ ⑤ CTO 用 PAT 开 PR → CI 全绿 → 合。

**契约**（铁律 47）
```
@input   — repoRoot / ledger 路径 / 当天日期（SYNO_* 注入缝覆盖 → 测试零真实写入）
@output  — docs/synova/project/ledger.json（同日同源去重）+ docs/synova/project/weekly-<YYYY-Www>.md
@degraded— 任一步失败：不产半成品；显式 degraded 记录（禁静默）；退出码三态 0/1/2（D328）
@幂等    — 连跑两次除 generated_at 外逐键相等；重复运行不产生第二个 PR
```
**三个必须处理的失败模式**
1. 上游产物过期（`product-progress.json` > 3 天）→ 警示不阻断，周报标 degraded
2. 同名分支已存在 → 复用 + `--force-with-lease` 更新（**禁 force push 共享分支**）
3. 有人在飞改同一产物 → 冲突**不自动解**，留给 CTO（机器不覆盖人的判断）

**周报固定五段（一页）**：交付度/验证率/保鲜红灯 · 本周完成（合并 PR 列表）· 阻塞 top5（卡了几天 + 需要谁）· 需创始人拍板 · 下周计划

**验收**：① 连跑幂等 ② 周报五段齐 ③ 一天内可查的定时运行记录 ④ 降级路径有测试
