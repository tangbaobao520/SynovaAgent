- 退出码：发现缺失引用 → `1`（与既有检查一致）。
- 测试：`tests/control-tower/pre-dispatch-check.test.sh` 增三类用例（锚点存在 / 锚点缺失 / 目标歧义）+ 1 个真实反例夹具（用本卡 §F 的证据原文）。

### D813｜tests/** 类型网 ratchet（卡 C）（编码 · mac）

**为什么**（CTO 亲测，命令与原始输出见 §F）

**做什么**：新增 `scripts/control-tower/check-test-type-net.sh`：
- 扫 `tests/**`（含 `*.test.ts` 与辅助 `.ts`）中 `as any` / `as never` / `as unknown as` 的**计数**；
- 与冻结基线 `tests/control-tower/test-type-net-baseline.txt`（新建）比对：**高于基线 = 红并点名 `文件:行:模式`**，低于或等于 = 绿（ratchet，不要求一次清零）；

- **生产口径不变**：`src/`+`packages/` 的 `as any|never|as unknown as` 仍是零容忍（铁律 38 / CT-46），本卡只补 `tests/**` 这一网。

### D814｜D708 任务号推断：merge-main 后被错锚到 main 侧任务号（编码 · mac）

**为什么**（CTO 实测复现）
`git merge origin/main` 刷新分支后，`scripts/control-tower/merge_writeset_gate.py` 的 `infer_did()` 在分支名无 D# 时按**提交日期**扫 subject 取首个 D#；merge 带入的 main 提交（日期新）排在分支自身提交之前 → 推断到 **D806**（别人的任务）→ 用 D806 的 brief 当声明源 → 本 PR 自己的 9 个文件被判「夹带」。原样输出见 §F。
**影响面**：所有做了 refresh（merge main）的 PR —— 而 refresh 是队列收口的常规动作。

**做什么**：`infer_did()` 的回退链改为只扫**分支自身提交**（`git log --first-parent --max-count=<N> --format=%s <head>`；merge 的第二父链不参与），保留 `did_source` 诊断字段；新增夹具测试：构造「分支自身提交 `docs(D797): …` + 在其之上 merge main（main 侧含更新的 `fix(D806): …`）」→ 断言 `did == D797`；再加一条"纯 merge 分支（自身无 D#）"的边界用例。
（**不得**顺手改 `pre-dispatch-check.sh`：与本卡无关。）

**写集**：`scripts/control-tower/merge_writeset_gate.py`、`tests/control-tower/merge-writeset-gate.test.sh`（新建；若仓库既有同族测试风格为 `.py` 则跟随）、`task-state/D814.json`、`.claude/task-briefs/*D814*`、`memory/notes/**`

**前置**：无。

**Done**：夹具红→绿；对真实分支复跑
`python3 scripts/control-tower/merge_writeset_gate.py --base origin/main --head origin/docs/dispatch-batch7-20260917 --branch docs/dispatch-batch7-20260917` → 输出 `任务: D797` 且不再出现 D806 的声明源。
