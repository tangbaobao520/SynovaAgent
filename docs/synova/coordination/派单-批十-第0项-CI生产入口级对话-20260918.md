## B. 验收（全部穿真实生产入口，禁 grep、禁 mock 管线）

| # | 验收项 | 判定方式 |

| 1 | **CI 模式下被包含且通过** | `CI=1 npx vitest run tests/integration/production-entry-conversation.integration.test.ts` → 绿；且断言其**不在** `vitest.config.ts` 的 CI 排除面内 |
| 2 | **真实服务 + 真实路由** | 测试内 `createServer()`（`src/server.ts`）+ `listen(0)` + `fetch`；走 `POST /api/conversations/:id/messages`（`src/routes/conversations.ts:359`）→ 断言 HTTP 正常收束（SSE 有终结事件） |

| 4 | **工具循环被真实驱动** | 假上游首轮返回含 `tool_calls` 的响应 → 断言工具**确实被执行**（工具执行点可观测，非 mock） |

| 6 | **零外网零真实 key** | 全程无真实 provider 调用：上游地址经既有配置缝指向 `127.0.0.1` 假上游 |
| 7 | **反向：不许靠改排除清单变绿** | `git diff` 不得出现 `vitest.config.ts` 的 `exclude` 被放宽；不得把文件挪回 `tests/e2e/**` |

## C. 红线（违反 = 审计 FAIL）

1. **不得在生产代码（`src/**`）加「测试专用分支/开关」**。上游指向必须走**既有配置缝**：`createProvider(type, config).baseUrl`（`src/providers/index.ts:54-59`）、装配点 `src/providers/registry.ts:144`、env 读点 `src/providers/detect.ts:22`。
   **若既有缝不足以指向假上游 → 停手报阻塞**，给出最小合法缝方案（由 CTO 裁决），**不要私自改产品代码**。
2. **不得为了变绿放宽 CI 排除清单**（不许改 `vitest.config.ts` 的 `exclude`、不许把文件挪回 `tests/e2e/**`）。
3. **不碰** `scripts/audit/**`（K3 域）、`scripts/control-tower/**`（另有两条线在改）。
4. 断言必须真的打到 HTTP 与假上游；**禁止只断言状态码**、禁止 mock 管线（铁律 12）。
