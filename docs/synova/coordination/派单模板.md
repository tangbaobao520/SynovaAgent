## 〇、路由判定（2026-09-13 固化 —— 创始人提问"D712 究竟发给谁"暴露的歧义，写死防再猜）

**判定一句话**：这次要产出的是「**设计**」还是「**事实**」？

| 类 | 任务类型 | 下一跳 | 为什么 | 实例 |
|---|---|---|---|---|
| **一** | 产品功能 / 切片（要定接口、契约、数据流、写集） | **先 📋 dev-doc 出 spec（含编码指令）** → 再 🛠 编码实现 | spec 是必须产物，否则编码各写各的 | D577、D556、D-1 通知模型步 2-4 |
| **二** | 控制塔 / 治理 / 缺陷修复（根因清楚、改动局限、验收物理可复现） | **直接派执行方**（DSH 域内可派并行 CTO；🛠 编码） | `scripts/` 门禁 + coordination 文档 + 预设技能 = **Mac DSH 专属**（TASK-ROUTING §四）；派单文档本身即准 spec，再走 dev-doc 是空转 | D706 / D707 / D664 / D708 |
| **三** | 验证 / 证据（不是"实现什么"，而是"去实测并落盘证据"） | **直接派执行方，无 spec** | 无 spec 输入物可产出；dev doc 在这一类写不出东西 | **D712 桌面端重验** |

**多执行方派单的发送规则（D712 型）**：**都发，但不同时**——
1. 先发**做事方**（并行开工，各自只拿与自己相关的部分，避免互相等）
2. 后发**复核方**（如 K3）——复核的输入物是做事方的产出，早发没意义

**代码归属 ≠ 测试机器归属**：跨平台验证时，按"**谁拥有该目录**"定归属（如 `electron/` = Mac DSH），但"**在哪台机器跑**"按平台定（Windows 实测必须在 Win 机器上跑，由 Win 侧执行但不算 Win 的代码域）。
