1. **数据源不可信**：旧第③面从 `task-state/*.json`（**手工维护的卡字段**）生成 ⇒ **卡片自助申报制**。

   大量卡是事后补登记 ⇒ **垃圾进垃圾出**。
2. **产物已死**：`docs/synova/CTO-HEALTH.md` 最后提交 `8f34ccc4 2026-08-29` = **26 天未更新**；
   生成器在 main 上崩（`AttributeError` 于 `gen-cto-health.py:305`，遇 string spec）。
3. **修它没意义**：修好也只是"把一个过时的单页重新生成一次"，**schema 与申报习惯都没变**。

**⇒ 处置**：
- `docs/synova/CTO-HEALTH.md`：**标注 retired（不再作为第③面）**；**不修、不再重生成**。
- `scripts/control-tower/gen-cto-health.py`：**冻结**（保留历史，不再维护）。
- **PR #725（D928）：冻结，不再作为关键路径**（其目标是修复该已废工具）。其**唯一可复用资产** =
  「**spec 形态容忍**」这条输入契约 ⇒ 并入新第③面的输入契约（见下）。

## 二、第③面新定义：**观测式看板（Observation Board）**

**核心转向**：**从"卡片自助申报"改为"系统观测真实事实"**。

| 维度 | 旧（废） | 新 |
|---|---|---|
| 数据源 | 手工维护的 `task-state/*.json` 字段 | **机器可观测事实**：`git`（分支/HEAD/工作树）、`CI check-runs`（真红/真绿）、`PR`（mergeable/state/review）、**门禁原始输出** |
| 生成方式 | 人工跑一次 | **官方 schedule 每日自动**（`daily 09:10`，已挂） |
| 可信度要求 | 字段有没有填 | **每一项都必须能给出产生它的命令**；给不出命令的项**不得入板** |
| 卡字段的角色 | **事实源** | **仅作补充/索引**，不得作为事实来源 |

**载体（已在建，不重起炉灶）**：
- `scripts/control-tower/daily-cto-board.sh`（三态 `0/1/2`；工作区自检 + 失败显式告警，吸收 D796 静默失败教训）
- `docs/synova/coordination/CTO-看板-自动.md`（每日产物）
- 断面门禁 `check-dsh-anchor.py` + K3 报告机械保险 `check-k3-report.py` 的输出**并入板面**

**板面最少须含**（每项附"产生命令"）：
1. **断面**：`DSH-ANCHOR: OK|VIOLATION|DEGRADED`（命令：`check-dsh-anchor.py --repo .`）
2. **合并队列真实状态**：每条 PR 的 `mergeable/state` + **红项名**（命令：`gh`/REST check-runs）
3. **门禁真实状态**：本地 13 组通过与否（命令：`pre-commit-check.sh`）
4. **工作树与孤儿**：数量 + 孤儿候选（命令：`git worktree list` / `find -maxdepth 1 -name .synova-wt-*`）
5. **台账 P0 → 队列对账**：≥7 天未开卡的 P0（已实现，第 6) 节）
6. **K3 待审**：报告是否落 main（命令：`git grep` over `docs/synova/audit-reports`）
