## 五、对比分析要求

创始人关心以下关注点（**非约束参考**——可纳入、可替换、可加权，最终以你制定的维度为准）：

- 正确性与健壮性：错误处理完整性、降级是否诚实（静默吞错检测）
- 测试质量：断言强度、覆盖真实性、空壳测试检测、mock 语义保真度

- spec ↔ 实现一致性：传递损耗（编码偏离 spec 的比率与性质）
- 文档诚实度：overclaim 检测（声称 vs 可验证事实）
- 管线级观察：dev doc 质量本身、自检/复核诚实度、返工痕迹（git log 迭代次数与原因）

**输出纪律**：每样本给分维度评分 + 证据；跨侧对比给分维度对照与两侧各自的 Top 3 优点 / Top 3 问题（全部 file:line）+ 可操作改进建议。**不做「谁好谁坏」的笼统标签**——只报可复核的物理事实与分维度证据，最终判断留给创始人。
