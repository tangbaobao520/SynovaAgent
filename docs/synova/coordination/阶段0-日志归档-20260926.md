### 2.3 `include-hidden-files: true` 的必要性（一手来源）

- 官方 README「Uploading Hidden Files」：**"By default, hidden files are ignored by this action…"**、
  **"Hidden files are defined as any file beginning with `.` or files within folders beginning with `.`."**
- `actions/upload-artifact@v4` 的 `action.yml`：`include-hidden-files` → `default: 'false'`
  （"If false, hidden files will be excluded from the artifact."）
- 本 PR 两条 path 全在 `.claude/`、`.codex/` 内 ⇒ 缺此项 = **artifact 为空**，而 `if-no-files-found: warn` 只出警告、job 照绿 ⇒ **判据假绿**。夹具 M1 专门抓这个（§4）。

## 9. 未清项登记

1. **`.claude/pre-commit-failures.log` CI 侧结构不可达**：CI 不 commit ⇒ 无 hook 触发写入。本 PR 由快照补"异机可读"（§6），但**没有** CI 侧持续归档。需另起机制（方向：本机 `scripts/` 侧定时把三个本地日志快照推到专用 ref / 或产物上传），**属新机制、须 Mac-CTO 批准**，本阶段不动手。

4. **`DOC_SCOPE_RE` 不含 `evidence/`**（队长已发现，登记）：蓝图 §八.4 规划的 `evidence/<D>/changes.json` 不匹配 `^(docs/|\.claude/|memory/|task-state/|\.github/)`，且 **`.gitignore:76` 的 `evidence/` 段使该目录整目录被忽略** ⇒ 该规划路径有**两重**结构性障碍（需 `git add -f` 才能入库）。本 PR 的落位（`docs/synova/coordination/gate-logs-20260926/`）即为此规避。
5. **`/tmp/.synova-before-brief` 是机器级共享文件（非 per-worktree）**：现存另一 session（2026-09-24，D941）记录，使任何 session 的 `SYNO_CI=1` 本地复现假红一组；CI 免疫。remediate 命令（`rm /tmp/.synova-before-brief`）会抹掉他人违规证据 ⇒ **未动，待队长/Mac-CTO 定处置**（§5.2）。
