## 1. 为什么是这一条（对四条判据逐条）

| 判据 | 口径⑤ 表现 | 反例（为什么别的口径不行） |

| **跨机可复跑** | 只读 **git 对象面**（`origin/main` 的树），同一 commit 在任何机器/任何 clone 上同值 | 工作树口径依赖 CWD 的 checkout：**同一台机器**上，主工作树（分支 `b8573c7a`）数出 **48**，干净 checkout（`ee721b0a`）数出 **49**（差集 = `scripts/control-tower/check-preset-bundles.sh`） |

| **稳定性** | 连跑 3 次同值（48 / 48 / 48，as_of 同分钟） | — |

## 4. 冻结基线登记（"阶段 0–4 新增门禁 = 0"的测量面）

- **基线值**：`CHECKSTAR_CANONICAL = 48`，`as_of 2026-09-26T03:52:30+08:00`，断面 `origin/main ee721b0a`。
- **用途**：阶段 0–4 冻结期"**新增门禁数 = 0**"的测量面；每个阶段末复跑一次 §0 的**对账式**，与本值比较。
- **判定**：`n > 48` ⇒ 新增了 `check-*` 文件（需解释）；`n = 48` 或下降 ⇒ 未新增。
- **边界（负面断言写范围）**：
  - 本命令只数 **`scripts/` 下、文件名以 `check-` 开头**的文件；因此 **若新门禁不起名 `check-*`（或不在 `scripts/` 下），不在测量面内**——该测量面**不能**单独证明"没有新增门禁"，只能证明"**没有新增 `check-*` 文件**"。
  - `scripts/audit/**`（K3 域）**有意排除**；对外引用时须同时声明"含/不含 audit"（48 / 49）。
  - 文件面 ≠ 门禁面：`check-*` 文件不全是门禁（也有一次性检查脚本），门禁也不全叫 `check-*`。
