## 二、取号器缺陷登记（**只登记不改**，缺陷本体不在本卡写集）

### 缺陷 1 — 本工作区 >25s 无输出（O(n²) 字符串累加）

两种环境，各贴原始输出：

| 环境 | 实测 | 原始输出 |
|---|---|---|
| 本工作区（249 worktree / 1648 remote-tracking ref / Σ各 worktree task-state 文件 = **69484**） | `perl -e 'alarm 25; exec @ARGV' bash …` → **RC=142**，elapsed 25s，**stdout 0 行 / stderr 0 行**（alarm 30 重跑同 RC=142，stdout/stderr 各 0 行） | `bash: line 2: 86501 Alarm clock: 14 …` |
| 干净 clone（`git clone --depth 1` → /tmp，1 worktree / 2 remote ref） | **RC=1**，elapsed 8s，**fail-closed 拒绝发号** | `❌ 撞车: D965 已被占用 — 拒绝发号（fail-closed，不自动跳号）` / 点名 `remote-branch chore/d965-d968-declarations-v2` 等 4 条 |

**根因（到行）**：`scripts/control-tower/alloc-task-id.sh:281-300` 扫全部已注册 worktree；
`:295` `WORKTREE_USED="${WORKTREE_USED}${n}"` 对每个 `task-state/D*.json` **逐号字符串累加** ——
bash 循环内字符串拼接是 **O(n²)**（二次方复制，GB 级 memcpy）⇒ CPU 燃烧（与队长实测 `user 19.296s` 吻合）。
`bash -x` 佐证：14218382 行 trace 中 **14166665 行**是累加串被逐次展开出的裸数字。
**旁证（脚本自陈）**：`:286-289` D940 注释已记「该循环实测 258s」，并明写
「WORKTREE_USED 累计展开等其它噪音**不在本卡**」——O(n²) 属**已知并搁置**，非本次新引入。

**被推翻的旧归因（登记以防复发）**：`SYNO_ALLOC_LSREMOTE_TIMEOUT:-20` 在本机是**死参数**——
`:152` `command -v timeout || command -v gtimeout` **双双不存在**（实测）⇒ `:158` 走无超时分支，
`git ls-remote --heads origin` 单独实测仅 real 4.886s / 730 行（I/O 等待，user 0.041s），
**无法解释 CPU 燃烧**。

### 缺陷 2 — 占用表读取面 ≠ 拒绝面（撞号风险，安全相关）

- 读取面（其自身注释 `:32-37` 自陈）：**本地 `task-state/` ∪ `origin/main`**；
  `ls-remote` **只喂发号前校验，不喂「下一个号」计算表**。
- 实测：`origin/main` 的 `task-state/` 只到 **D964**；而全 refs 真实占用面已达 **D1007**（开工时）。
- 后果实测（干净 clone）：脚本算出 NEXT=**D965**（`本地 task-state 最大号: D964` + `干净 clone origin/main
  task-state 最大号: D964`），而非 1008+ ⇒ **任何人此刻跑取号器都不知道 D1008–D1013 已被本批占用**。
- 拒绝面（`_occupied_check`，`:190-217`）只匹配**分支名 / 本地分支名 / worktree 目录名**里的 `d<num>`
  （正则 `(^|[^0-9a-z])d${num}([^0-9]|$)`），**从不读其他 worktree 的 task-state 内容**做占用判定
  ⇒ **拒绝面比读取面窄**。
- 本次干净 clone 之所以被拦，是撞上 `chore/d965-d968-declarations-v2` 等**分支名**里的 `d965`，
  而非读到任何 task-state —— 这恰证明：号只写在 task-state 而分支名不含该号时，**拦不住**。

**建议**（属另卡，本卡不擅自实施）：① 把 ls-remote 快照（或全 refs 的 task-state 面）同时喂号表；
② 让 `origin/main` 尽快吸收本批 `task-state`；③ 修 `:295` 的 O(n²) 累加（改数组/一次 printf）。
