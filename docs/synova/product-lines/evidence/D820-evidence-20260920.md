## 三、FTS 卡外阻塞缺陷（折入，单独 commit `98c24872`）

根因: `agent_messages_fts` 是普通 FTS5 表（`src/store/session-store.ts:221-225`，无 `content=''`），但 `AFTER DELETE` 触发器用 contentless 专用 `('delete', ...)` 命令 → SQLite 拒绝（`SQL logic error`）⇒ ① 删消息抛错 → `deleteSession` 全路径 500 ② FTS 索引残留已删消息全文（`search()` 仍可召回）。自初始提交 `a6160381` 存活至今。

复现（最小，未改仓库）:
```
FAIL plain (a,b) -> SQL logic error            # 纯 FTS5 表执行 ('delete', ...)
plain DELETE by rowid     -> OK, rows now []   # 同表普通删除正常
FAIL BASELINE DELETE agent_messages -> SQL logic error   # 按修复前语句顺序手工执行
```
修复后（真 SessionStore）:
```
search(customer) 删除前 = [{... "snippet":"<mark>customer</mark> concentration is too high"...}]
deleteSession = OK
FTS 残留行数 = {"c":0}
search(customer) 删除后 = []
（旧库迁移路径）迁移前 FTS 行数 = {"c":3} → 迁移后 = {"c":2}（孤儿被清）；rowid 对齐 [{1,1},{2,2}]；search(orphan) = []
```
