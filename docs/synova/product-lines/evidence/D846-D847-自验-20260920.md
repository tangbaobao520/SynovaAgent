### 发现 #2（自验第二阶段）：证据源可被 `GIT_DIR`/`GIT_WORK_TREE` 环境变量替换 → 端到端无痕解锁

```
── D0 对照：无注入（本仓 HEAD 卡=claimed）──
  status=block degraded=False                                                     EXIT=1
── D1 端到端注入 GIT_DIR=<外部仓>/.git（本仓零改动、零提交）──
   注入前本仓状态: （空） / HEAD 卡: {"task_id":"D901","title":"t","status":"claimed"}
  status=warn degraded=False release_reason=D901 已释放（依据 task-state:impl_done: 已提交 task-state/D901.json status=impl_done）
   注入后本仓状态: （仍为空 = 零痕迹）
── D2 同注入下 claim_release 直测 ──
{"task_id": "D901", "released": true, "basis": "task-state:impl_done", "detail": "已提交 task-state/D901.json status=impl_done", "degraded": false}   EXIT=0
── D3 反面对照：GIT_DIR 指向本仓 → 仍 block ──
  status=block degraded=False                                                     EXIT=1
```

机理：`claim_release.py:131` 的 `subprocess.run(["git", "-C", str(repo), "show", f"HEAD:{rel}"])` **继承调用者环境**，未固定 `GIT_DIR`/`GIT_WORK_TREE`；`git -C <dir>` 只改工作目录，`GIT_DIR` 仍优先生效（对照命令：`GIT_DIR=<R2>/.git git -C <R1> show HEAD:task-state/D901.json` → 输出 `impl_done`；不注入 → `claimed`）。

**同时满足**：① 门禁输出 `warn`/`exit 0`（他人认领被解锁）；② `degraded=false`；③ 被守护仓库 `git status` 全程为空、无提交、无任何可核痕迹。**前提**：能控制门禁进程的环境（同机同用户；非远程）——属同一"本地可篡改"类，但**是本卡修复后仍然存在的无痕通道**（第一阶段的文件级无痕路径已封）。
