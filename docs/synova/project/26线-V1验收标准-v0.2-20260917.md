## §〇 口径（元断言 M1–M5）

**M1（DSH 复用口径 · 全 26 线适用）**
凡某验收点的能力与现行 DSH 已有能力重叠时，该点**必须**写成「接入/配置/约束 DSH 的 <能力> 并验证」，不得写成「实现 <能力>」。
判定：verify 须同时指向 ① DSH 侧配置/接入点 ② 本仓验证断言两段；只写「实现 X」视为口径不合格，**不计通过**。

**M2（G3 物理化 · 借鉴卡必须回写台账）**
每张 DSH 借鉴卡（B-01…B-20）**必须回写**到至少一个 26 线验收点，并生成绑定该点 id 的证据文件；未回写、或无绑定证据者，该卡不计通过。

**M3（合规边界 · 创始人裁定）**
抄代码 = 允许且鼓励（对方实现更优时，该抄就抄）；**桥接引用 = 禁止**（禁 `import @deepseek-ai/*`、禁 re-export 壳）；抄写处必须留锚点注释（包 + 文件 + 符号）+ 现验命令（行号现查）。

**M4（借鉴发现机制 · 发现即登记）**
任何 session 发现新的可借鉴能力（含 UI/前端组件、页面范式、交互形态）必须走三步：① 立借鉴卡 ② 回写对应线验收点 ③ 生成绑定证据。
**发现而不登记 = 漏账**，计入审计 findings（M2 的 G3 守卫延伸）。

**M5（UI / 前端面复用口径）**
凡 DSH 客户端已有的 UI 范式，界面元素**一律「复用/对齐 + 验证」，禁止从零造组件**。事实依据（现行安装实测存在）：
`dsh-client-ui-agent-preset` / `-model-selection` / `-permission-presets` / `-schedule` / `-session` / `-settings-models` / `-settings-unarchive-sessions` / `-skill` / `-workspace`；`dsh-user-questions`（seam，composer takeover 卡片）；`dsh-tool-ask-user`（模型面工具）；`dsh-agent-tool-presentation`；`dsh-client-ui-deliverables`。
落地：线1/线2/线3 的 **UI 类断言**按本口径逐条复核，凡该"复用"却写成"实现"的走变更单改写。

**元断言不计入分母**（M1–M5 是判定规则，不是验收点）。
