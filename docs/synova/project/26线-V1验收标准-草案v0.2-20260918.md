## 〇、口径（签字即冻结）

> ⚠️ 判定规则以 v0.2 §〇 元断言 M1–M5 为准（M1 DSH 复用口径 / M2 G3 物理化 / M3 合规边界 / M4 发现即登记 / M5 UI 复用口径）；下表为**账目**。

| 项 | 定义 |
|---|---|
| **V1** | 一条线的**最小可用闭环**：做完 V1 断言 = 这条线"可用"。V1 之外一律进 V2 backlog，**不计入完成度** |
| **完成度** | = V1 断言通过数 / V1 断言总数。**分母冻结**；新增需求进 V2，不得改分母（要改走变更单） |
| **通过（判定）** | 一条断言要通过，必须**同时**满足：① 声明（yaml 状态）② 证据在档且未过期（scenario/test/ci/k3 报告/founder-demo） |
| **已验证** | 在"通过"基础上，再加 **K3 独立复核 PASS**（每线最后一条断言 = 该线的 K3 复核点；红线：禁止自我审计） |
| **保鲜** | 证据单独计时：🟢≤7 天 / 🟡8–14 天 / 🔴>14 天（**过期不影响"通过"记录，只进重跑队列**） |
| **阻塞** | 必须写清三要素：原因 + 起始日 + 需要谁；否则不许标阻塞 |
| **判据来源** | scenario=`scripts/golden-scenarios/GS-0X` 场景 exit 0 且产出证据；test=对应测试套件绿；k3=审计报告 PASS；founder-demo=创始人实机/演示记录 |

**当前实况（诚实版）**：
- V1 断言合计 **128 条**（总 164 点；V1 外 36 条，其中 3 条已裁决"不做"）——v0.2 §三：125 +2（20-5 / 25-6 由 backlog 提入 V1）+1（26-7 线26 新增）
