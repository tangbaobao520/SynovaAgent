# 第三章 其他类似开源项目与应用研究

> 2026-08-16 | 范围：A 类=同类"公司大脑/企业 Agent"应用；B 类=DSH 之外的 Agent 框架；C 类=记忆/知识底座
> 方法：每个对象提炼"最强机制" + 与 Synova 的差异；证据带日期与来源

---

## 3.1 A 类：同类"公司大脑 / 企业 Agent"应用

### 3.1.1 Sylph（getnao/sylph，YC X25）——最接近 Synova 概念的开源项目

定位："open-source company brain，run your entire company with AI agents, skills, and a self-improving context."

核心机制：

- **CAO（Chief Agent Officer）= 老板本人**；AGENTS.md 是唯一事实源；CONTEXT.md 是公司身份
- 按业务域建目录（brand/content/sales/product/finance/hr/legal 等 13 个域）
- **Skills**：每个 skill 末尾带"self-improving loop"——批准输出后 diff 草稿 vs 保留，重写自己的规则匹配你的修改
- **Agents**：8 个"AI 员工"（Chief of Staff/CMO/PM/CS/Head of Data/Head of Sales/EA/Brand Designer），各有角色 + cadence（Daily/Weekly/On-demand）
- Connectors（MCP）+ agent-agnostic（Claude Code/Codex/Cursor 都能用）
- 无后端、无遥测、无网络调用——纯 markdown + AI coding agent 读

与 Synova 的差异（关键）：

- Sylph 是"markdown 模板 + skills"，靠通用 AI coding agent 读文件干活；没有诊断引擎、没有因果本体、没有 42 边、没有测量器/哨兵、没有专家体系
- Sylph 的"self-improving loop"和 Synova 的 N13（反馈→规则闭环）是同一个思想，但 Sylph 是"diff 重写 skill 文本"，Synova 是"因果规则调权"
- Sylph 的"Agents cadence"和 Synova 的"六循环×3尺度"同构

战略判断：Sylph 证明"公司大脑"这个概念正在被开源快速模板化，但它停留在"流程自动化 + 知识库"层，没有"组织诊断"的因果深度。这正是 Synova 的差异化空间——Synova 卖的不是"让 agent 帮你干活"，是"诊断你的增长卡在哪、现在该做什么"。

### 3.1.2 Push / Paperclip / Biro / Envisiq（@masslessai 系，zero-human company 编排器）

定位："Open-source orchestration for zero-human companies"——Node.js server + React UI，编排 AI agent 团队经营企业（BYO agents、分配目标、追踪成本，像任务管理器但有组织图/预算/治理/目标对齐/agent 协调）。

与 Synova 差异：这一类是"agent 编排看板"（把人替换成 agent 的任务管理），没有组织诊断、没有增长导航、没有因果分析。是"AI 员工管理平台"，不是"企业增长医生"。与 Synova 不冲突，但提示市场对"AI 经营企业"的想象正从"工具"走向"编排"。

## 3.2 B 类：DSH 之外的 Agent 框架（快速对照）

| 框架 | 语言 | 核心机制 | 与 Synova 关系 |
|------|------|---------|---------------|
| LangGraph | Python/JS | 图工作流 + 显式状态管理 + 持久化执行 + 人类介入 | C 线已对标；Synova 曾采纳 Graph 架构 |
| CrewAI | Python | 角色化团队 + 最快原型 | 6M+ 月执行量，增长最快 |
| AutoGen/AG2 | Python | 对话式 agent + human-in-the-loop（微软） | — |
| OpenClaw | Node.js | 24/7 自治 agent + 心跳 | Synova 曾对标（C线 S3-4 心跳） |
| Dify | Python | 低代码 agent 编排平台 | — |
| Hermes | Python/TS | 自治 agent | — |

结论：这些框架都是"通用 Agent 运行层"，没有一个做"组织诊断"。DSH 的出现不是新增一个同类，而是用"一切皆插件 + 事件溯源"把运行层范式推高一级——框架竞争在底座层，Synova 在应用层，二者不直接冲突。

## 3.3 C 类：记忆/知识底座

### OpenViking（volcengine/OpenViking，28575 star）

定位："Self-evolving Context Database for AI Agents. Unify Agent Memory, Knowledge..."

对 Synova 的含义：这是第一个真实威胁——火山引擎在做"自进化上下文数据库"，统一 Agent 的记忆与知识，直接覆盖 Synova 的 S5-3（知识沉淀）、S5-4（组织记忆自动生成）方向。若 OpenViking 成熟，Synova 的"记忆/知识沉淀"能力将被开源底座化，正如 Harness 底座化了"通用 Agent 工程"。

应对方向（研究触发点）：Synova 的差异化不在"记忆存储"（那是通用底座），而在"组织诊断的知识结构"——42 边因果本体是"组织如何运转"的因果知识，不是"上下文存储"。需专项评估：OpenViking 存的是什么、Synova 的本体是什么、两者是"存储层 vs 知识层"还是"直接重叠"。

---

## 3.4 第三章结论

1. "公司大脑"概念已被开源模板化（Sylph），但停留在"流程自动化 + 知识库"，无诊断因果深度——Synova 的差异化空间仍在。
2. "zero-human company"编排器（Push 系）是"AI 员工管理"，不是"增长诊断"，与 Synova 不冲突。
3. 框架层竞争与 Synova 不直接冲突——DSH 把运行层范式推高，Synova 在应用层。
4. 唯一真实威胁是 OpenViking（记忆/知识底座化）——需专项深挖，这是"走出自己特色"的重点。
