### 产品定位（2026-08-01 澄清，客户范围 08-01 二次修正，市场表述 08-02 修正中——待创始人补充）

- **目标市场**：5–1000 人的企业——请不起麦肯锡级咨询的企业（原"没有成熟 AI/IT 系统"表述 2026-08-02 判定不精准，见下方修正）
- **理论上所有企业都需要**，但大企业有自己的 IT 系统 + 麦肯锡级咨询 → 不是主战场
- **第一客户画像 ≠ 市场定义**："业务出身、一线打拼、被天花板困住、招人没用、越管越乱"恰巧是第一个客户（哇呢宝贝）的画像；盛和塾 8 月演示/演讲针对同类客户——这是获客切入点，不是产品定位
- **与咨询的差异**：麦肯锡=项目制、贵、人走知识走；Synova=驻扎型订阅制 Agent、数据沉淀在系统里、越用越准
- **对产品能力的要求**（已有研究支撑）：无数据诊断（SME 数据不全）、企业多用户部署、成本模型与单位经济（定价可负担）、部署独立（客户自装）、权限与知识治理（多人使用）

#### 市场表述修正（2026-08-02，创始人指出——待继续补充）

- ❌ 原表述："没有成熟的 AI/IT 系统"——不精准
- ✅ 修正方向（创始人原话要点）：
  1. 当今时代，一定规模的企业**一定有 IT 系统，可能也有 AI 应用**——严格说并非"没有"，而是**不全、散乱、不成体系**
  2. 不同信息可能分散在不同 IT 系统（ERP/CRM/财务/办公/行业软件……）
  3. 关键差异在**形态**：传统软件是**给人看的**（人读界面/报表），处理信息的方式不同；**未来的软件是给 Agent 用的**（Agent 读数据/接口/执行），必然是另一种形态——Synova 的定位是后者
  4. 客户有系统对 Synova **反而是利好**：有数据可获取（连接器/导入路径），不是障碍

### C线方案评审补充（2026-08-02，创始人第一波，后续还有）——待补充齐后统一修订方案

**评审 A（方法逻辑）四点：**
1. **标准定义顺序存在"先射箭后画靶"风险**：第一章"标准维度框架"应放在第二章"对标证据库"之后或并行迭代。正确顺序 = 先提取标杆"为什么被客户认为世界级"的最强机制（麦肯锡=结论先行、证据分层的结构化汇报；Palantir=本体驱动的跨源因果推理；Culture Amp=让 HR 看懂的组织健康仪表盘）→ 抽象共性维度 → 第一性原理验证完备性。否则定义的标准可能恰好是自己擅长的维度，漏掉竞品最强而自己缺失的维度。
2. **五层框架缺"时间"维度**：现五层是静态能力，缺"持续改善速度"（诊断准确率每季度自动提升、联邦进化、GA 反馈回流、因果模型自我校准；Palantir Foundry 部署到价值需数月、麦肯锡进场到汇报需数周，Synova 数天完成部署到首次诊断——"时间"本身就是世界级差异化）。需显式定义：首次价值时间、诊断周期、模型校准周期、从反馈到规则更新的闭环时间。
3. **对标对象缺"开源 Agent 框架"类别**：LangGraph、CrewAI、AutoGen 等——不是直接竞品，但提供"工程质量"层面对标（Agent 自主性机制、错误恢复策略、多 Agent 协调协议），代码公开、文档完善、社区可追溯，证据强度可达"强"级。六类对象给"产品功能"层面证据，开源框架给"工程质量"层面证据。
4. **SMB 市场的核心约束是"没有人"不是"钱少"**：无专职 IT、无数据分析师、无 HRBP——任何需要"技术人员配置/数据清洗/模型训练"的产品都落不了地。SMB 世界级 = 一个只有老板和行政文员的企业，能否零外部帮助完成"部署 → 第一份诊断报告"全流程。部署独立的标准不是"支持 Docker 部署"，是"双击 exe、下一步下一步、不打开命令行"。

**评审 B（参照系）三点：**
1. **"世界级"参照系错位**：麦肯锡/Palantir 不是 SMB 市场玩家，其最强机制是在 500 强/政府场景锤炼的（专职数据科学家、数月部署、数百万预算）——把它们当参照系再"重定义"到 SMB，推导链断裂。SMB 市场真正的参照系是**老板自己**：Synova 的世界级不是击败麦肯锡，是**"让老板觉得这个系统比我自己的判断更可靠"**。标准不是诊断深度/数据接入/方法论框架，而是"老板愿意放下自己的直觉，相信这个系统的判断"。麦肯锡做不到（顾问不驻扎、不 24 小时盯数据流、不在老板冲动决策时给出客观提醒）。
2. **五层框架是"产品功能分级"，不是"世界级标准"**：世界级应从"信任建立"视角推导——① **价值第一印象**：第一次诊断就发现老板自己从未意识到的问题（比"首个价值时间"更根本）；② **闭环验证**：老板按建议行动后看到可量化改善（比"诊断准确率"更有说服力）；③ **制衡机制**：老板想"自己来"时系统给出客观提醒让他三思（比"权限管理"更触及本质）。
3. **"对标弹药"用途被狭隘化**：不是问答环节被动防御，而是演示开场**主动预埋植入记忆**——"麦肯锡收费 200 万、做完项目走人；Synova 收费 5 万、驻扎企业 24 小时、永不离开"应在老板脑子里还没有这个问题时就把答案钉进去。方案需明确对标弹药在演示剧本中的**预埋点**（哪个环节、用什么方式、主动抛出哪个对标结论）。

**评审 C（第二波补充）四点：**
1. **定位细节：双重"世界级"的紧张关系**——方案既要"定义世界级"又要"重新定义世界级"。"完全由市场约束决定"会削弱演示说服力（老板问"你和麦肯锡什么区别"，答"我们定义了另一个世界级"有框架但缺**外部锚点**）。**建议双轨制**：保持"重新定义"核心定位 + 每层标准保留一个"通用世界级"参照刻度。演示话术结构："在这个维度上，麦肯锡的标准是 X，我们在 SMB 市场把它重新定义为 Y，原因是 Z。"——先有可锚定的参照系，再讲重定义。
2. **核心模型必须推演到"具体值"**：五层框架目前只有结构、没有量化值——这是 C线最有价值、也最容易被模糊化的部分。避开两个极端：①"比行业平均高一些"（失去标尺意义）；②"细分市场追求全面世界级"（不现实，假设大企业资源+小企业敏捷并存）。**推演要求**：对标证据收集完成后，每个标准回答三问：a) 该维度通用世界级是多少？b) SMB 市场约束下合理的世界级是多少？c) 差异的推导依据是什么？
3. **方法论三处细化（确认/补充）**：①"证据过时"的判定边界需明确定义（超 12 个月/24 个月？还是版本变更即过时？）——执行时先定规则；②"最强机制"应定义为"该对象在五层框架中**得分最高的那一层**"，而非主观判断其最强——保证对象间对比有统一标尺；③ 第三章只消费 A线审计结论、不重新审计——**创始人确认为正确且必要**，保持 C线（外部参照）与内部验证的工作边界，避免生成矛盾结论。
4. **市场实际接触面（对标对象关键补充）**：SMB 老板极少数能接触或用得起麦肯锡级顶级咨询——他们实际接触的是：**盛和塾**（稻盛和夫经营哲学研修）、**长松咨询**（组织系统/管理培训）、**昆仑定位**（定位理论）、**和君咨询**等国内机构，或商学院自学。方法论口径：**对标顶级（提取机制），也要结合实际（对标老板心智里真实的参照系）**。→ 对标对象清单需新增类别：SMB 老板实际接触的国内咨询/培训机构（这也与 B线盛和塾受众研究衔接）。

## 四、研究方法（官方：权威文档14附录 + 实践惯例）

### 4.1 五原则（权威文档14-附录-研究工程方法论提炼）

1. **第一性原理推导**：从最简不可约简模型演绎，不照搬竞品。42条边是推导结果，不是设计目标
2. **物理现实锚定**：每个理论定义必须在真实案例中验证（哇呢宝贝零基验证）；硬度=参数覆盖率≥80%且预测偏差<15%
3. **正交性保证**：四层分离（表达/编排/计算/存储），每层只与相邻层通信，变更频率从上往下递减
4. **端到端验证**：黄金数据集checksum机制——升级后同一案例同一问题必须给出同一答案，不能解释的变化=回滚
5. **持续进化**：hard/soft/heuristic成熟度标注，soft边注明"缺失什么数据、何时可重新评估"

### 4.2 研究执行流程（实践惯例）

1. **研究方案先行**：研究问题(Q1-Q4) → 定位（回答什么/不做什么） → 核心模型/第一性原理 → 研究任务分章 → 交付物目录 → 定量验收标准
2. **前置/零基验证**：正式研究前用真实数据验证核心假设
3. **分章交付**：`第一章/第二章/...`，每章独立可消费，末尾必须有"与现有体系对齐"章节
4. **对抗性验证**：结论经受反向攻击（JTBD对抗性验证、NCI Epsilon验证）
5. **代码审计式研究**：涉及现有系统时逐行读源码，结论带文件名+行号，标注三态：存在 / 存在但未接线 / 不存在
6. **定量验收**：每条标准可验证（如"≥30条边hard、覆盖率≥80%"）
7. **命名归档**：`SYNOVA-RESEARCH-{主题}-{版本}-{日期}.md`，目录 `{主题}-{日期}/`；旧版移入 archive/
8. **边界诚实声明**：应用研究类写清适用区间与局限（幸存者偏差、相关≠因果等）

### 4.3 与工程铁律的衔接

- 契约优先（铁律47）：新增模块先定义输入/输出/降级契约再实现——研究方案中的"验收标准"即契约前置
- 测试非空壳（铁律48）：测试必须有 expect() 断言，覆盖正常/降级/边界
- 接线审计（WIRE CHECK）：研究产出若指向新函数，必须 grep 确认生产入口有调用
- 与权威文档一致性：任何新研究先检索 01–17，标注消费哪些文档、修改哪些章节
