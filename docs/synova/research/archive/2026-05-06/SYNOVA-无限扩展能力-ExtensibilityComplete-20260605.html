任务 1：Extension Registry discover/hotload（1 天）

当前已有的（不需要再写）：
  ExtensionRegistry.register()         → 注册
  ExtensionRegistry.unregister()       → 注销
  ExtensionRegistry.resolve()          → 查找

  register → loaded → validated → active → deactivated 状态机

需要补的：
  discover(baseDir: string): Promise<ExtensionManifest[]>
    → 扫描 baseDir 下所有子目录，读取 manifest.json
    → 返回清单供用户选择安装

  hotload(manifest: ExtensionManifest, baseDir: string): Promise<ResolvedExtension>
    → import(baseDir + manifest.entryPoint) 动态加载
    → 调用 ExtensionRegistry.register()
    → 返回激活的扩展实例

⚠️ 安全审计是强制环节，用户命令也不例外

即使来自用户本人的安装命令，也必须经过云鼎 7 步安全审计。审计结果在安装前展示给用户，有风险时必须明确提示。

这是防止以下场景：

  • 用户从不明来源复制了安装命令
  • 用户不知道 Skill 中有恶意脚本
  • 用户误装了名称相似的假冒 Skill（如 "Brav Search" 冒充 "Brave Search"）

四、IM 交互通道的扩展方式（L1 层）

IM 对接（飞书/企微/Slack/Teams/Telegram/WhatsApp）不属于 L5 连接器。它属于 L1 交互层，因为处理的是"用户交互"而非"数据采集"。

4.1 统一接口

// src/l1-interaction/messenger.ts — IM 通道统一接口

interface IMSender {
  readonly platform: string;       // 'feishu' | 'wecom' | 'slack' | 'teams' | ...
  readonly label: string;          // '飞书' | '企业微信' | 'Slack' | ...

  // 发送纯文本消息
  sendMessage(chatId: string, text: string): Promise<void>;

  // 发送卡片消息（带交互按钮）
  sendCard(chatId: string, card: CardPayload): Promise<void>;

  // 发送每日简报（纯文本无按钮）
  sendBriefing(chatId: string, briefing: BriefingContent): Promise<void>;

  // 处理 incoming webhook（用户回复、按钮点击）
  handleWebhook(payload: unknown): Promise<WebhookResult>;
}

4.2 注册与使用

// src/l1-interaction/messenger-registry.ts — IM 通道注册中心

class MessengerRegistry {
  private channels = new Map<string, IMSender>();

  register(platform: string, sender: IMSender): void {
    this.channels.set(platform, sender);
  }

  send(platform: string, chatId: string, text: string): Promise<void> {
    const channel = this.channels.get(platform);
    if (!channel) throw new Error(`IM 通道未注册: ${platform}`);
    return channel.sendMessage(chatId, text);
  }

  // 每日 19:00 简报通过所有已注册的通道发送
  async broadcastBriefing(chatIds: Record<string, string>, briefing: BriefingContent): Promise<void> {
    for (const [platform, chatId] of Object.entries(chatIds)) {
      const channel = this.channels.get(platform);
      if (channel) await channel.sendBriefing(chatId, briefing);
    }
  }

  list(): string[] { return [...this.channels.keys()]; }
}

4.3 技术实现

接口定义和注册中心用 TypeScript（L1 层），平台实现用 Python（通过 Python Bridge 调用）。和 L5 连接器同一个模式。

// L1: 接口定义 (TypeScript) — src/l1-interaction/messenger.ts
interface IMSender {
  readonly platform: string;
  readonly label: string;
  sendMessage(chatId: string, text: string): Promise<void>;
  sendCard(chatId: string, card: CardPayload): Promise<void>;
  sendBriefing(chatId: string, briefing: BriefingContent): Promise<void>;
  handleWebhook(payload: unknown): Promise<WebhookResult>;
}

// 注册中心 (TypeScript) — src/l1-interaction/messenger-registry.ts
class MessengerRegistry {
  private channels = new Map<string, IMSender>();
  register(platform: string, sender: IMSender): void { ... }
  send(platform: string, chatId: string, text: string): Promise<void> { ... }
}

// L5: 平台实现 (Python，通过 Python Bridge) — synova_worker/messengers/feishu.py
from feishu import FeishuClient

class FeishuMessenger:
    def send_message(self, chat_id: str, text: str):
        client = FeishuClient(app_id=..., app_secret=...)
        client.im.send_text(chat_id, text)

    def send_card(self, chat_id: str, card: dict):
        client = FeishuClient(...)
        client.im.send_card(chat_id, card)

// TS 侧通过 Python Bridge 调用
class FeishuMessengerProxy implements IMSender {
  async sendMessage(chatId: string, text: string): Promise<void> {
    await pythonBridge.run('messengers.feishu', 'send_message', { chatId, text });
  }
}

messengerRegistry.register('feishu', new FeishuMessengerProxy());

新增一个 IM 平台只需要：在 synova_worker/messengers/ 下新建一个 Python 文件，实现 send_message / send_card / handle_webhook 三个方法。不需要改任何 TypeScript 代码。
