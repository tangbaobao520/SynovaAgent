TUI 改造计划

结合 Synova 增长导航产品定位 · 不是抄 CodeWhale，而是做对的事

首先搞清楚：TUI 到底是给谁用的？

根据产品架构最终版，Synova TUI 不是给 CEO 用的——CEO 用 Web 端（增长驾驶舱）。TUI 是给 PDE、开发者、高级用户 做运维用的：

  • 查看系统状态（连接器健康度、LLM Provider、DB 状态）
  • 检查日志、调试连接器
  • 手动触发诊断/简报
  • 部署和维护

这意味着：不要做第二个 CodeWhale TUI。我们不写 291 文件 258K 行的通用编码 TUI，我们写一个 专注、稳定、可测试的运维工具。

Step 4：useReducer 统一状态管理（4h，P1 下轮）

// app.tsx — 全局唯一状态源
type Action =
  | { type: 'ADD_MESSAGE'; role: MessageRole; text: string }
  | { type: 'SET_STREAMING'; isStreaming: boolean; text?: string }
  | { type: 'UPDATE_EXPERT'; name: string; status: ExpertStatus }
  | { type: 'SET_PHASE'; phase: number }
  | { type: 'SET_STATUS'; status: string }
  | { type: 'ADD_OBSTACLE'; obstacle: ObstacleItem }
  | { type: 'RESOLVE_OBSTACLE'; name: string };

function reducer(state: TuiState, action: Action): TuiState {
  switch (action.type) {
    case 'ADD_MESSAGE':
      return { ...state, messages: [...state.messages, { role: action.role, text: action.text }] };
    case 'SET_STREAMING':
      return { ...state, isStreaming: action.isStreaming, streamingText: action.text ?? state.streamingText };
    // 每个 action 都是纯函数，可测试
  }
}
好处：所有状态变更通过 dispatch → reducer → 新 state，单向可追溯。reducer 是纯函数可直接写测试。ChatPanel/SidePanel 变纯展示组件。

六、为什么这是对的

✅ 对 PDE 友好

部署时一眼看出哪些连接器离线、LLM 延迟多少、引擎是否健康。systemctl status 式的体验。

✅ 对开发者友好

useReducer + 纯函数 reducer = 状态可预测。加功能只加一个 action + 一个测试。

✅ 对产品方向正确

CEO 不走 TUI，TUI 不需要目标/障碍/专家。把 Web 端做好是产品成功的关键。

✅ 不上 Rust

CodeWhale 用 Rust 是做通用编码 TUI 需要极致性能。运维 TUI 用 ink + TS 完全够用。

改造不是重写。Step 1+2 只用 8 小时就能让 TUI 从"不敢改"变成"可测试、可维护"。
