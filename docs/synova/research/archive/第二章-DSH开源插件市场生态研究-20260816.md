## 2.5 发布机制与治理风险

**发布机制**：插件仓库添加 GitHub `dsh-plugin` topic → 自动同步（4 小时内初筛）→ 人工策展择优收录。官方已建议加 topic，形成可检索、可复用的插件生态。

**治理风险**（36氪点出，Oh-My-DSH 免责声明印证）：
1. 插件来源验证缺失——一个工具插件可接触文件/外部服务，一个存储插件掌握完整会话，一个循环插件可改变决策路径
2. 权限边界、依赖冲突、版本兼容、供应链安全是生产前提，开放度越高治理成本越高
3. 目录收录不代表官方背书，活跃度信号≠安全性结论

**对 Synova 的含义**：DSH 生态的"快"是双刃剑——生态快，但治理没跟上。Synova 若走路径 C，必须自己解决"插件可信度"（这正是 C 线 S3-3 权限安全、S3-5 自诊断可信度的延伸）。

## 2.6 第二章结论

1. **DSH 生态是 2026 年最快速的开源引爆**：3 天 12 万+ star（官方仓库 123909）、1320 插件，且"Agent 能力"类最大。
2. **Synova 自研的通用能力正在被插件化**：反馈/调度/子代理/记忆都有开源插件在补——护城河判断进一步坐实。
3. **发现第一个真实竞争威胁：OpenViking（火山引擎自进化上下文数据库）**——覆盖 Synova 的组织记忆/知识沉淀方向，需专项深挖。
4. **路径 C（生态并存）有现成分发管道**：插件市场 + 排行 + 推荐已成熟，Synova 自成一个插件可直接被收录。
5. **治理风险是生态的软肋**——Synova 的差异化可以落在"可信的企业级插件"（安全 + 审计 + 可复现），而非"又一个插件"。
