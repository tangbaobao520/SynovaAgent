## 一、研究背景

Synova 的定位是**驻扎企业的 AI 增长诊断师**（5-1000 人市场）。当前专家体系三处未解问题指向同一本质：**从未从产品定位出发认真定义"专家架构应该长什么样"**。

1. 双权威分叉：ARCHITECTURE.md（专家=管 N 哨兵）vs 权威文档16（1主+6子按循环）。
2. 设计-实现脱节：权威文档16 说循环专家"始终激活"，代码却把 background:true 的循环专家排除出 LLM 派发。
3. 术语撞车：capital-cycle 等同时指专家、业务循环、系统动力学模型、方向监测分类。

DSH（本地已部署）提供了完整参照：subagent seam（多后端子 agent）、capability seam（provider 可换）、agent-loop 可替换、agent preset + cordis.yml 配置——正是"专家如何组织、调度、可配置"的工程范式。

## 二、研究定位（回答什么 / 不做什么）

**回答**：从市场定位出发，回答 Synova 究竟需要怎样的专家架构——专家按什么维度组织、host 扮演什么角色、循环层与专家层如何分层、专家如何调度、**如何做到可配置可调整**（含 DSH 借鉴与理由），并据此统一权威口径。

**不回答**：不改代码、不改 ARCHITECTURE.md（出报告+建议）；不重做 42 边本体/诊断方法论；不挑战"增长三循环"第一性原理本身（只裁决它落在计算层还是专家层）。

## 三、研究问题（Q1-Q5）

- **Q1 需求推导**：5-1000 人企业增长诊断，对专家架构提了什么硬要求？（诊断深度、可解释、老板信任、成本、可持续、**可配置**——由 C 线 C1/C2/C3 约束 + S0 信任建立 + 老板画像差异倒推）
- **Q2 组织维度**：专家按什么组织最能让"结论有用、老板可懂"？三大循环是"诊断因果维度"还是"专家组织维度"？
- **Q3 运行时真相**：代码"事实上"已收敛为 host 唯一主 agent + 循环层 compute 两元结构吗？方向对不对？
- **Q4 调度与可配置（DSH 参考）**：专家如何调度？DSH 的 subagent seam / capability seam / agent-loop / agent preset / cordis.yml 配置，哪些可借鉴、哪些是领域深度不可替代，各给理由？
- **Q5 权威统一**：基于 Q1-Q4，统一术语 + 权威口径 + 文档治理。

## 四、核心模型 / 第一性原理

**三层分层假设（待验证）**：

```
计算层   → 测量器 compute + 哨兵 + 循环模型(cycles) + 方向监测(direction-monitor)
          职责：确定性计算，"数据偏离了什么"
推理层   → 专家(LLM)：拿信号，推理、交叉验证、给判断
          职责：非确定性解读，"意味着什么、该怎么办"
主持层   → host 主 agent：面向老板，统筹诊断、整合结论、"增长卡在哪、现在该做什么"
```

**关键判断**：权威文档16 的"三循环"是增长第一性原理（资源闭环），**应落在计算层（循环模型），而非专家组织维度**。把循环当专家是 D282 命名错误——混淆了"资源流转计算"与"结论解读推理"。

**可配置性准则（创始人定调）**：专家架构必须是**声明式可调**的——专家 prompt / tools / 输出结构都是配置文件（而非硬编码），可随时改，适配不同老板（不同行业、不同老板的阅读与决策偏好）。这直接对应 DSH 的"一切皆插件 + cordis.yml 配置 + agent preset"范式，也对应 Synova 既有"文件驱动架构"哲学。

## 五、研究任务分章（6 章 + 附录）

**第一章｜市场定位 → 专家架构需求推导**：从产品定位倒推专家架构硬约束（可解释/可信任/可持续/低成本/可扩展/**可配置**），产出"专家架构设计准则"（≥6 条，每条绑产品定位约束）——后续所有裁决的标尺。

**第二章｜证据全景与三态审计**：逐条 CLAIM + file:line，还原双权威分叉、设计-实现脱节、"循环"四义、专家-计算层错位；三态打标（设计权威/代码现状/历史遗留）。

**第三章｜第一性原理重推专家架构**：验证三层假设；裁决 Q2/Q3——专家按什么组织、host 角色、循环专家归层、**如何做成声明式可配置**；产出"专家架构目标态"。

**第四章｜DSH 借鉴评估（含理由）**：读 DSH 的 subagent seam / capability seam / agent-loop / agent preset / cordis.yml，逐条对照 Synova 专家调度与可配置需求，给出"可借鉴/不可借鉴/领域深度不可替代"清单，每条带具体理由。

**第五章｜术语消歧 + 权威口径统一**：术语表（"循环"四义唯一词）；ARCHITECTURE.md 更新方案；权威文档16 定位裁决（保留/降级/合并）；待更新权威档清单。
