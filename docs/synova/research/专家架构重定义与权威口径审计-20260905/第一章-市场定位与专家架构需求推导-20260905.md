# 第一章 市场定位 → 专家架构需求推导

> 2026-09-05 | 目的：从产品定位倒推"专家架构应该满足什么"，产出设计准则作为后续所有裁决的标尺
> 方法：复用 C 线（世界级基准）、B 线（演示叙事）、A 线（内部真相）已定结论，不重新论证

---

## 1.1 市场定位回顾（既定，不动）

Synova = 驻扎企业的 AI 增长诊断师，目标市场 5-1000 人、请不起麦肯锡级咨询的企业。核心问题："这家企业增长卡在哪里？现在该做什么？"诊断是手段，增长是目的。

来源：ARCHITECTURE.md §1 + C 线 + 底座研究。本次研究不动定位，只据此推专家架构。

## 1.2 用户分层：决策层（老板）+ 执行层（中层，最大用户群）

目标用户不是单一"老板"，而是**两个层次**，且部署后**中层是最大的用户群体**：

- **决策层（老板）**：业务出身、一线打拼、被天花板困住、招人没用、越管越乱。老板要的是"结论"——公司最终问题在哪、现在该做什么。他不读长报告、不分析数据，决策靠直觉（C3 没有时间），但愿意为"经营智慧"付费（盛和塾 4800/年、行动教育 35.8 万、昆仑定位 30 万——C 线价格锚）。
- **执行层（中层/部门负责人）**：财务、市场、产品、销售、运营……他们专业、是执行主体，要的是"和自己有关的根因 + 证据 + 因果链 + 思维链"——因为这是他们**下一阶段改善的起点**，他们要**去核查、去证实**，然后执行。

关键含义（创始人 2026-09-05 定调）：**诊断的价值实现是"老板决策 × 中层执行"两条腿**。只给老板"结论"、不给中层"可核查的证据链"，结论就会束之高阁——这正是昆仑定位 30 万咨询无效果的教训（老板拿到报告，中层不知道为什么、怎么查、怎么改）。因此专家架构的输出必须**服务两个层次**，且不能只做"老板版"。

## 1.3 三大约束（C 线 C1/C2/C3）

| 约束 | 内容 | 对专家架构的含义 |
|------|------|----------------|
| C1 没有人 | 无专职 IT/数据分析师/HRBP | 专家不能要求"人来配置/清洗/维护"，必须声明式自动装配 |
| C2 没有钱 | 心理账户=员工年薪/研修/SaaS 级，请不起麦肯锡 | 专家调度要省 token：能用计算层确定性算的，不派 LLM 专家 |
| C3 没有时间 | 决策带宽稀缺，不读 100 页报告 | 专家输出必须"结论先行 + 证据分层 + 一页纸"，10 分钟能复述 |

## 1.4 信任建立（C 线 S0）

Synova 的价值 = 让老板放下直觉、相信系统判断。三条信任来源：

- **价值第一印象（S0-1）**：首诊命中 ≥1 个老板"之前没意识到"的盲区——专家要有真实深度，不能是泛泛的财务/客户/人才常识
- **闭环验证（S0-2）**：老板按建议行动后看到可量化改善——专家结论要能回溯到"做了什么→指标变了"
- **制衡机制（S0-3）**：老板冲动决策时系统客观提醒——专家要有"踩刹车"的判断力

## 1.5 专家架构设计准则（从定位推导，≥6 条）

> 以下 7 条是本研究的"标尺"，第三、六章的所有裁决都要能回溯到这些准则。

| # | 准则 | 来源（定位约束） |
|---|------|----------------|
| G1 可解释 | 专家输出"结论先行 + 证据分层"，老板 10 分钟能复述核心结论 | C3 没有时间 + S0-4 报告一看就懂 |
| G2 可信任 | 专家结论有"因果深度"，首诊命中盲区，可回溯到"证据→结论"链 | S0-1 价值第一印象 + S1-3 因果链 |
| G3 可持续 | 驻扎型，专家能随企业数据持续更新（周级），不是一次性项目 | C 线 R6 进化闭环 + 底座"驻扎"定位 |
| G4 低成本 | 调度分"计算层（确定性）/推理层（LLM）"，能用计算层解决的绝不派 LLM | C2 没有钱 + DeepSeek 峰谷定价 |
| G5 可扩展 | 加专家/改专家=改文件不改代码（文件驱动） | ARCHITECTURE.md §5 文件优先哲学 |
| G6 可配置 | 专家 prompt/tools/输出结构**声明式可调**，随时改以适配不同老板（行业/阅读偏好/决策习惯） | 创始人 2026-09-05 定调 + 权威文档16 profiles 表达行业差异 |
| G7 领域深度 | 专家必须挂在"42 边因果本体 + 三循环资源闭环"上推理，不空谈 | 权威文档16 §零第一性原理 + 底座"领域深度是护城河" |
| G8 可核查可下钻 | 专家结论要能回溯到"根因 + 证据 + 因果链 + 思维链"，供中层执行层核查、证实、作为改善起点；且按职能分层（财务看财务、市场看市场） | 创始人 2026-09-05 定调 + C 线 S1-3 因果链 / S2-1 证据分层 |

## 1.6 第一章结论

专家架构必须同时满足"可解释、可信任、可持续、低成本、可扩展、可配置、可核查可下钻、有领域深度"八条。其中 **G6 可配置**（老板差异）与 **G8 可核查可下钻**（中层执行层）是两条本次新增的硬要求——前者让专家随老板调整，后者让诊断从"结论"下沉到"执行层可核查的因果链"，两者共同决定第三章的架构设计。
