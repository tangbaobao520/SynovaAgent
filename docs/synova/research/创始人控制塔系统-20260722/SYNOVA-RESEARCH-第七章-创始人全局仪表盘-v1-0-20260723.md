# 控制塔 第七章：创始人全局仪表盘

> 定位：消费前六章数据的"创始人深度驾驶舱"——双模式。静态模式：按需生成HTML双击打开。服务模式：本地HTTP服务+5分钟自动刷新。
> 与D213的关系：D213=值班监控屏（实时轮询，5分钟刷新），Ch7=创始人驾驶舱（本地双模式——按需或持续）。

---

## 一、与 D213 的定位关系

D213 control-tower.html 是一个已经可工作的仪表盘——6个组件健康卡片 + 阻断清单，5分钟轮询刷新。它挂在服务器上，回答一个问题："现在有没有着火？"

Ch7 是"创始人深度驾驶舱"——**双模式运行**。静态模式：Python 脚本一次性生成 HTML，双击打开。服务模式：Python 脚本启动本地 HTTP 服务（`localhost:8899`），浏览器打开后每 5 分钟自动刷新数据，无需手动重跑脚本。不看代码，不看日志。回答的问题是："过去一周火势趋势如何？哪个Agent在改善、哪个在恶化？"

三者互补，不替代。D213 是值班人员的实时监控屏（挂在服务器上持续轮询）。Ch7 静态模式是你（创始人）每周看一眼的战略视图。Ch7 服务模式是你开发电脑上持续打开的仪表盘——看到的是你自己的项目，实时数据。

整个页面分为四个区域。深色主题，与 Electron UI 风格一致。

### 3.1 顶部：项目全局信号条

一行信息。从左到右：

- **权威文档完成状态**：15份文档的完成情况。已完成 / 进行中 / 未开始。统计 15份中已完成 X 份。

### 3.1-A 产品完整性门禁（16门禁）

## 五、技术实现

一个 Python 脚本（约 300 行）+ 一个 HTML 模板。**双模式**。

### 静态模式

```bash
python scripts/control-tower/generate-dashboard.py
# 输出: app/synova-founder-dashboard-{timestamp}.html
```

脚本执行步骤：扫描 15 份权威文档目录 → 推导流水线状态 → 读取六个信号源 → 统计趋势 → 自检 → 渲染 HTML。双击打开。

### 服务模式（实时更新）

```bash
python scripts/control-tower/generate-dashboard.py --serve
# 输出: 仪表盘服务已启动 → http://localhost:8899
# Ctrl+C 停止
```

启动后，Python 内置 `http.server` 监听 `localhost:8899`（零外部依赖）。浏览器打开页面后，每 5 分钟 JavaScript 自动向后端请求最新的 JSON 数据。后端重新读取六个信号文件 + 重新扫描目录 → 返回最新数据 → 前端局部刷新四个区域（不需要整页重载）。

**降级保护**：如果某个信号文件读取失败或 JSON 解析失败，该卡片显示"信号文件不存在"——不影响其他卡片刷新。网络中断时，页面保留上次成功的数据，不做任何 UI 变化，静默等待下次刷新。

### HTML 模板中的 JavaScript 刷新逻辑

页面加载时启动 5 分钟定时刷新。每次刷新向后端 `/api/dashboard-data` 发请求，拿到最新数据后局部更新四个区域（顶部信号条、左栏流水线、右栏健康雷达、底部可靠性趋势）。刷新失败时静默降级——保留上次成功的数据，不做任何 UI 变化。

## 七、验收标准

1. Python 脚本可独立运行，静态模式输出可双击打开的 HTML 文件
2. `--serve` 模式下启动本地 HTTP 服务，浏览器可访问
3. `--serve` 模式下每 5 分钟自动刷新数据，局部更新不影响当前浏览位置
4. `--serve` 模式下单个信号读取失败不影响其他卡片的刷新
5. 仪表盘显示 15 份权威文档完成状态
6. 仪表盘显示所有活跃任务的 R/D/C 流水线状态
7. 仪表盘从六个信号源读取数据并渲染六维健康雷达
8. 每个不可用的信号源标注"信号文件不存在"（当前 5/6 缺失——这是诚实的）
9. 每个指标标注可实现性分层
10. Agent 可靠性趋势标注"数据积累中(N/10)"（Phase 2 功能）
11. 仪表盘自检行显示快照时间戳 + 6/6 信号文件检查结果
12. 红色信号可点击展开详情
13. 网守卡片可点击展开 11 行子状态
