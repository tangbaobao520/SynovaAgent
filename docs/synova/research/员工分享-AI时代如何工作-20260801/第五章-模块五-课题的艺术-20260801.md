# 第五章 模块五：解决复杂问题——课题的艺术（25 分钟）

## 目的

这是全场的方法论核心：教员工**把模糊问题变成好课题**（目标/边界/验收/背景），并看到 Agent 如何"接课题→出研究计划→深度研究→证据交付→复查迭代"。用 Synova A 线/B 线真实案例 + 现场演示。

## 脚本

### 第一段：课题公式（6 分钟）

【互动 0:00】"我先演示一个反面教材。谁现在提一个工作中的困扰？随便说。……好，比如'客户流失越来越多，怎么办？'——现在我把这个问题直接丢给 AI，你们猜它会怎么答？……（现场演示或口头模拟）它会给出一堆'要提高服务质量、加强回访'的正确废话。"

【讲 0:03】"问题出在哪？出在**课题的质量**。梁文锋 #16 说得很清楚：'把问题描述得很清楚，给它完整的上下文和指令，它已经超过人类了。'——**前提是你得会描述。**

我们把'描述清楚'工程化成四个要素，叫**课题公式**：
> **好课题 = 目标（要什么结果）+ 边界（不做什么）+ 验收（怎么算完成）+ 背景（为什么重要）**

同一个问题，重新说：
- 目标：找出近 3 个月客户流失上升的可能原因，输出可验证的假设清单
- 边界：只看回访和投诉数据，不做定价调整
- 验收：每个假设有数据支撑，或明确标注'待验证'；清单不超过 10 条
- 背景：Q3 流失率环比升 12%，老板需要在下周经营会前有个判断

同样的 AI，从'正确废话'变成'可执行的判断'。"

【幽默 0:06】"记住一句话：**AI 不负责'你看着办'，只负责'你说了算'。** 你说得越清楚，它干得越靠谱。"

### 第二段：Agent 如何自主建立研究计划（6 分钟）

【讲 0:07】"好课题交给 Agent 后，第一件事是什么？——**先出计划，不是先干活。** 我们的研究方案模板是这样的（展示真实文档结构）：

1. 研究问题（要回答什么）
2. 定位（做什么、不做什么）
3. 方法（怎么查、怎么验证）
4. 分章任务（拆成几块，每块交付什么）
5. 交付物（最后给你什么）
6. 验收标准（怎么算完成）

计划出来，**人确认了才开工**。这就是'自主'的正确含义：Agent 自己设计方案，但方案必须经过人批准——是受托的自主，不是失控的自主。"

【互动 0:11】"你们带过新人吗？带新人的第一课是不是'先让他说打算怎么做，再让他动手'？Agent 一样。区别是：这个新人 24 小时在线、不闹情绪、还能同时开十个。"

### 第三段：深度研究长什么样（6 分钟）

【讲 0:13】"复杂问题不是问一次就完，是**系统化怀疑**。我们用真案例讲——上个月我们做了一次'产品完整性审计'（A 线），流程是：
1. **拆章**：把一个大问题拆成 5 个独立章节，互不干扰
2. **证据纪律**：每个结论必须带出处（文件+行号），没有出处的结论不算数——我们攒了 360 行证据日志
3. **对抗验证**：每个重要结论反向质问自己：'如果我错了呢？'答不上来就降级
4. **复查回补**：做完再整体复查，结果真抓出 3 处错误——把推送去重的窗口时长写错了（文档说 30 分钟、代码是 5 分钟）、把哨兵数量算错了、把一个循环的处理器映射搞错了——全部当场修正并记录。另一份报告复查时还抓出跨文档时间轴不一致。

【讲 0:16】"你们注意，**查出错误不是失败，是深度研究的正常环节。** 真正可怕的不是有错，是没人查、查不出、还说'应该没问题'。"

### 第四段：现场演示（7 分钟）

【互动 0:19】"现在轮到你们。我要现场征集一个真实课题——最好是你们工作中真正头疼的问题。

（征集 1 个 → 用课题公式现场填充 → 演示：把课题交给 Agent → Agent 1 分钟内输出研究方案：研究问题、定位、分章、交付物、验收标准）

看，这就是完整的闭环：**人提课题 → Agent 出计划 → 人批准 → 深度研究 → 带证据交付。**"

【备选】"如果现场网络/环境不允许，我放一段预录的完整过程——同样的课题，同样的流程。"

【讲 0:25】"回去以后，你们可以先从一个小课题开始练：这周找一个真问题，套公式，喂给 AI，看它出的方案。第一次会很生涩，第三次你会开始觉得'回不去了'。"
