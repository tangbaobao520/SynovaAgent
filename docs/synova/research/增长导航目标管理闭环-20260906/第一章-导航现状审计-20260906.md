## 1.1 权威文档13 的既有设计（6 介入节点）

权威文档13（2026-07-14）把导航定义为"诊断建议 → Goal → 执行 → 追踪 → 偏离告警 → 调整 → 闭环验证"的 Action 闭环，6 个介入节点 + 5 章设计：

| 节点 | 环节 | 设计要点 |
|------|------|---------|
| 1 | 目标设定 | 诊断建议 → 可度量/可分配/有时限的 Goal |
| 2 | 路径选择 | Proposal 三选一（超时/变更/拒绝非理想路径） |
| 3 | 执行追踪 | Goal → 方案级哨兵（基线建立期 2-4 周） |
| 4 | 偏离检测 | 三因子模型（阈值/趋势/基线），P0/P1/P2 分级 |
| 5 | 方案调整 | 轻量级再诊断（1 专家 + 3-5 边 + 5 分钟） |
| 6 | 目标关闭 | 闭环验证（改善/未改善 → 执行有效性审查） |

## 1.3 核心发现：诊断驱动导航已完整，但"企业目标管理"维度空白

审计结论一句话：**权威文档13 设计的"诊断驱动导航闭环"（诊断建议 → Goal → 执行 → 追踪 → 纠偏 → 验证）核心闭环已完整实现，代码是真实接线、不是空壳（个别细节如方案级哨兵的"离线适应"未实现，详见 1.2）。但用户强调的"企业目标管理"维度（多来源、对齐约束、方式适配）是空白。**

### 已完整实现（诊断驱动导航）

从诊断到验证的完整闭环：诊断建议 → Proposal 三选一 → Goal 7 态 → 方案级哨兵三因子追踪 → 免打扰分级告警 → 轻量级再诊断纠偏 → closeGoal 闭环验证 → N13 规则回流。这条链是通的。

### 空白（本次研究要补齐的"企业目标管理"维度）

| 缺失维度 | 现状 | 用户强调的需求 |
|---------|------|--------------|
| 决策驱动来源 | `goal-types.ts` 的 source 只有 `diagnosisId`，无决策来源；`decision-capture.ts` 只记录"对诊断结论的确认/驳回"，不覆盖"老板忽略诊断、凭直觉定新方向" | 老板拍板新目标，也要记录决策 + 跟踪 |
| 纵向对齐 | 无"部门目标 ↔ 公司目标"的对齐检查 | 部门 OKR 对齐公司 OKR |
| 约束注入 | 无"目标 ↔ 财务预算/资源"的约束检查；`goal-conflict-detector.ts` 只检测"部门内 Goal 维度冲突"（direction/resource/timeline/duplicate），不覆盖"市场计划不超财务预算" | 市场做营销计划，要记住财务预算约束 |
| 目标管理方式适配 | 无 OKR/KPI/MBO 结构，Goal 是 Synova 自有结构 | 企业用 OKR 就用 O/KR，用 KPI 就用指标 |
| 外部驱动来源 | 无"市场变化/客户流失"驱动的目标来源 | 外部变化逼出的目标也要记录跟踪 |

## 1.5 第一章结论

1. 权威文档13 的"诊断驱动导航闭环"核心闭环已完整实现（含 Proposal 非理想路径），代码真实接线，N13 已修复——这是好的基础；个别细节（方案级哨兵离线适应）部分实现。
2. 但导航的真正本质（用户定调：企业目标管理）有四个空白：决策驱动来源、纵向对齐、约束注入、目标管理方式适配。
3. 本次研究的价值不是"审计差距"（差距不大），而是"在已实现的诊断驱动导航之上，补齐企业目标管理的四个缺失维度"。
