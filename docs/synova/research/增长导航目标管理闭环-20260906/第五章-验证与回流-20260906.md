## 5.2 验证对象"来源相关"（本次深化）

闭环验证的"验证对象"应该随目标来源不同而不同：

| 目标来源 | 验证什么 | 结论沉淀为什么 |
|---------|---------|--------------|
| 诊断驱动 | 这个诊断建议对不对（执行后指标改善了吗） | 诊断准确率 + 规则调权（N13） |
| 决策驱动 | 老板这个直觉对不对（拍板的方向带来增长了吗） | 老板决策模式（这个老板的直觉靠不靠谱） |
| 外部驱动 | 这个外部事件应对对不对 | 外部事件应对策略 |

关键（用户强调的核心价值）：**决策驱动目标的验证，是"用结果裁决老板的直觉对不对"**——这是"超越共识"的终极体现。诊断说"该降客户集中度"，老板拍板"偏要发力大客户"，三个月后数据说话：谁对了。这个裁决结果沉淀下来，下次老板再凭直觉拍板时，系统能给出"你上次的直觉命中率是 60%"的客观提醒。

## 5.3 回流：N13 已修复 + 知识沉淀（本次深化）

### N13 反馈→规则闭环（已修复，保留）

`src/agent/loop-handlers.ts:387` 已完整接线：`processFeedbackSignals` + `applyEvolutionActions`，反馈 → 进化动作 → 回写规则。这是"诊断驱动目标验证结果回流调权"的工程基础。

### 知识沉淀（本次深化）：验证结果 → 企业决策经验

验证结果不只回流到"规则调权"（N13），还要沉淀为"企业决策经验"：

```typescript
interface DecisionOutcome {
  /** 关联的决策/诊断/事件 */
  sourceId: string;
  sourceType: 'diagnosis' | 'decision' | 'external';
  /** 验证结果 */
  outcome: 'validated' | 'invalidated' | 'inconclusive';
  /** 依据（指标 before/after） */
  evidence: { metric: string; before: number; after: number }[];
}
```

这个"决策经验"沉淀到企业事实层/组织记忆，形成"这个老板的直觉命中率、这个诊断方向的准确率、这类外部事件的应对效果"——下次诊断/决策时作为背景注入。

## 5.4 越用越懂（红线，严守）

闭环验证 + 回流，让系统"越用越懂企业"。但**对外话术严守红线**（C 线 S5-1 未闭环前）：

- ❌ 不宣称"越用越准/自我进化"（模型层面的持续学习尚未实现）
- ✅ 可说"每次诊断、每个目标的执行结果，都沉淀为企业的决策经验，下次带着上次的知识来"

安全话术（沿用底座研究）："系统记得上个月的结论，下次诊断带着上次的知识来。"

## 5.5 完整验证回流闭环

```
Goal 关闭（目标完成/放弃）
    ↓
closeGoal + verifyEffect（回溯 edge 参数，before/after）
    ↓
验证对象"来源相关"：
  诊断驱动 → 诊断对不对 → N13 规则调权
  决策驱动 → 直觉对不对 → 老板决策模式沉淀
  外部驱动 → 应对对不对 → 策略沉淀
    ↓
回流：N13 规则调权 + 企业决策经验（DecisionOutcome）
    ↓
下次诊断/决策时注入背景 → 越用越懂企业
```

## 5.6 第五章结论

1. 闭环验证 + N13 回流已实现，是"驻扎型增长医生"的工程基础。
