## 6.1 目标管理方式适配（OKR/KPI/MBO/无体系，MECE）

核心原则：适配企业的目标管理和考核方式，不强加 Synova 自己的方式。

| 企业方式 | 结构 | Synova 适配 |
|---------|------|-----------|
| OKR | O（目标）+ KR（关键结果） | Goal = O，Goal.metrics = KR，纵向对齐 = O 的父子关系 |
| KPI | 关键绩效指标 | Goal = 指标，Goal.metrics 绑定 KPI 数值 |
| MBO | 目标管理（目标 + 计划） | Goal = 目标，Proposal = 计划方案 |
| 无正式体系 | 无 | 用 Synova 默认 Goal 结构（权威文档13） |

配置化适配（不强加）：企业目标管理方式通过配置声明，Goal 的核心数据（来源/对齐/约束/度量/状态）不变，只改"呈现层 + 字段映射"。

```yaml
# goal-management-profile.yaml
goal_management:
  method: 'okr' | 'kpi' | 'mbo' | 'default'
  review_cadence: 'weekly' | 'monthly' | 'quarterly'
  scoring: 'binary' | 'graded' | 'none'
```

关键：换企业换配置，不改代码——这是 G6 可配置在目标管理上的延伸，也是"符合企业情况、真正帮助用户"的前提（企业不用 OKR，就别逼它用 OKR）。

## 6.2 DSH 借鉴（导航视角）

| DSH 机制 | 对导航的启示 | 判定 | 理由 |
|---------|-------------|:---:|------|
| goal（持久化同 session 目标 + 续做） | 目标持久化 + 续做 | 可借鉴 | Synova Goal 已有持久化，借鉴"同 session 目标续做"冷恢复 |
| schedule（session 提醒 + 冷恢复） | 提醒持久化 + 冷恢复 | 可借鉴 | Synova 免打扰告警可借鉴"冷恢复续做" |
| feedback（log-only 不进模型） | 反馈隔离 | 可借鉴 | 反馈记录不污染诊断推理，保持"反馈"与"推理"分离 |
| spill（超大输出持久化） | 证据/周报溢出处理 | 可借鉴 | 导航证据链、周报可能超大，借鉴溢出持久化 |
| 无领域目标概念 | — | 不可借鉴 | DSH 无"企业目标/OKR/诊断驱动目标"领域概念，这是 Synova 领域深度 |

## 6.3 导航权威模型（整合 5 个 MECE 维度）

```
导航 = 企业目标全生命周期管理

来源（3）    诊断驱动 / 决策驱动 / 外部驱动
生命周期（8） 设定 → 分解 → 对齐 → 执行 → 跟踪 → 纠偏 → 验证 → 回流
关系（3）    纵向对齐 / 横向依赖 / 约束注入
适配（4）    OKR / KPI / MBO / 无体系
角色（3）    老板 / 中层 / 个人
```

诊断是目标最重要的来源，但不是唯一来源。决策驱动的"决策记录 + 验证回流"是"超越共识"的工程承载。

## 6.4 术语（与专家架构研究衔接）

| 词 | 定义 |
|----|------|
| 诊断 | 发现增长卡点、给出建议（目标设定依据） |
| 导航 | 目标全生命周期管理（执行跟踪 + 纠偏 + 验证回流） |
| Goal | 目标的工程化表达（权威文档13 28 字段） |
| Proposal | 诊断建议 → 目标的三选一路径转换层 |
| DecisionRecord | 老板直觉拍板的决策记录（本次新增） |
| 约束注入 | 企业事实层（预算/资源/制度）自动约束目标 |

## 6.6 第六章结论

1. 目标管理方式适配（OKR/KPI/MBO/无体系）是"符合企业情况"的前提，配置化不强加。
2. DSH 借鉴 4 项（goal/schedule/feedback/spill），但无领域目标概念是 Synova 领域深度。
3. 导航权威模型 = 5 个 MECE 维度整合，诊断是最重要来源但非唯一。
4. 落地 P0 一项（权威文档13 定位更新），P1 三项（决策来源/约束注入/方式适配），P2 两项（决策经验/提醒路由）。
