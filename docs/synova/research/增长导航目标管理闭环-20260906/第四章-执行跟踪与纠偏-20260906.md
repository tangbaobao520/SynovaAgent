## 4.1 执行：多岗位执行主体

目标分解后，按部门/角色执行（维度五：老板/中层/个人）。角色三层：**老板**（决策 + 看全局）、**中层/部门负责人**（执行 + 核查，最大用户群，对应每个 Goal 的 `responsibleRole`）、**个人**（Goal 分解到具体任务后的执行者，`responsibleRole` 落到具体员工）。每个 Goal 有 `department` + `responsibleRole`（权威文档13 已定义），本次研究聚焦中层（最大用户群），个人层是 Goal 分解的末端。

关键：执行不是"各自闷头干"，而是"执行 + 协同"——财务执行财务的 Goal、市场执行市场的、销售执行销售的，但受横向依赖约束（市场获客支撑销售转化，第三章）。

## 4.2 跟踪：方案级哨兵三因子偏离检测（已有实现，保留）

`src/growth/goal-sentinel.ts` 已实现三因子偏离检测（阈值/趋势/基线）+ 基线建立期 2-4 周 + P0/P1/P2 分级。这是成熟的执行跟踪机制，保留。

### 本次深化：跟踪要"来源无关"

不管目标来自诊断驱动、决策驱动还是外部驱动，**跟踪机制一视同仁**。老板凭直觉定的"进军东南亚"，和诊断建议的"降客户集中度"，都进入方案级哨兵追踪。区别只在"验证回流"时（第五章）：诊断驱动的目标验证"诊断对不对"，决策驱动的目标验证"老板直觉对不对"。

## 4.3 纠偏：提醒（P0/P1/P2 分级 + 免打扰，已有实现）

`src/growth/dnd-engine.ts` 已实现免打扰：P0 始终推 / P1 周推 1 次 / P2 周汇总 + dismiss 7 天。保留。

### 本次深化：提醒的"多岗位路由"

提醒不只分"P0/P1/P2 严重度"，还要分"提醒谁"。偏离的是财务的 Goal → 提醒财务负责人 + 老板（若 P0）；偏离的是市场的 Goal → 提醒市场负责人 + 老板。设计：

```typescript
interface AlertRouting {
  /** 偏离的 Goal */
  goalId: string;
  /** 目标部门/角色 */
  targetRoles: string[];       // 提醒对应部门负责人
  /** 升级对象（P0 时） */
  escalationRoles: string[];   // 老板/GA
}
```

对应已有 `proactive-push.ts`（D272 双通道 + D285 按角色），提醒路由到"对这个 Goal 负责的人"，而非广播给所有人。

## 4.4 纠偏：轻量级再诊断（已有实现，保留）

`src/growth/lightweight-diagnosis.ts` 已实现：1 专家 + 3-5 边 + 5 分钟超时 + 升级全量诊断（同一 Goal ≥3 次）。保留。

### 本次深化：纠偏要"来源相关"

- 诊断驱动的目标偏离 → 轻量级再诊断 → 调整建议（已有）
- 决策驱动的目标偏离 → 纠偏时要问"是执行不力，还是老板的方向本身有问题？"——若是方向问题，触发对决策本身的复盘（第五章验证回流）

## 4.5 完整执行跟踪纠偏闭环

```
目标（诊断/决策/外部来源）→ 部门/角色执行
    ↓
方案级哨兵三因子追踪（阈值/趋势/基线）
    ↓ 偏离
提醒（P0/P1/P2 分级 × 多岗位路由 × 免打扰）
    ↓ 持续偏离 / P0
轻量级再诊断（1 专家 + 3-5 边 + 5 分钟）
    ↓ 调整建议
执行调整 → 回到追踪
```

## 4.6 第四章结论

1. 执行跟踪纠偏的机制（三因子哨兵 + 免打扰 + 轻量级再诊断）已有完整实现，是好的基础。
2. 本次深化两点：提醒的"多岗位路由"（偏离谁的 Goal 提醒谁）、跟踪的"来源无关"（诊断/决策/外部目标一视同仁）。
3. 纠偏要"来源相关"：决策驱动的目标偏离，要区分"执行不力"还是"方向错了"。
