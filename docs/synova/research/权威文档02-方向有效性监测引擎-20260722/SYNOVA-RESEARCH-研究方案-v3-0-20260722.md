# 权威文档02：方向有效性监测引擎 — 研究方案 v3.0

> 2026-07-22 | 定位：在01的因果骨架和03的诊断之间，持续回答"企业当前的方向还成立吗"
> 诊断是昂贵的——不应该在没有方向失效信号时频繁触发。

---

## 一、定位

权威文档01定义了"企业如何运转"——42条因果边、池-阀-流-溢出模型。权威文档03定义了"诊断"——50个哨兵、61个compute、8位专家。

**但诊断有一个前提条件：企业已经意识到自己有问题，并且进入了诊断模式。诊断是昂贵的——调用8位专家、遍历42条边——不应该在没有方向失效信号时频繁触发。** 什么机制决定企业是否需要进入诊断模式？

02填补的正是这个空白：**一个持续运行的方向有效性监测引擎。** 它默认回答"当前方向是否还成立"，并在方向失效时触发诊断流程。方向如果已经失效，才需要诊断来定位根因。方向如果还成立，系统不输出任何内容——继续监测。

## 二、核心模型

### 2.1 一句话定义

**02是一个持续运行的引擎，回答一个问题："企业当前的方向还成立吗？"**

不是诊断。不找根因。只判断方向是否仍在预期轨迹上。

### 2.2 三个输出状态

| 状态 | 含义 | 后续动作 |
|------|------|---------|
| 方向有效 | 运行数据在预期轨迹内 | 继续监测，不输出 |
| 方向存在风险 | 偏离正在积累，或行业基准在恶化 | 生成预警信号，但不触发诊断 |
| 方向失效 | 偏离持续超过阈值 | 触发03诊断流程（携带监测阶段已识别的偏离范围） |
| 方向失效 + 需重新选 | 方向失效，且企业表示需要新方向 | 触发03诊断 + 启动NCI子模块 |

### 2.3 与01和03的关系

```
01: 因果骨架（企业如何运转）
         ↓ 提供42边参数
02: 方向监测（当前方向还成立吗？）
         ↓ 方向失效时触发 + 携带已识别的偏离范围
03: 诊断（问题出在哪？）
```

## 三、五个核心功能

### 功能一：方向锚定

企业当前正在执行的方向被显式记录。**包括两个部分：**

**1. 活跃Goal集合 + 资源分配分布。** 消费文档13的增长导航数据。02需要定义数据需求清单（由文档13实现）：当前活跃Goal列表（goalId+类型+部门+优先级+创建时间）、每个Goal的资源分配（预算占比+工时分配）、资源配置快照（定期保存，用于对比变化）、方向变更历史。

**2. 创始人关注信号。** 不局限于已注册Goal。消费SENSING实体采集的弱信号——创始人对话中提到的新方向、会议纪要中反复出现的战略疑问、GA访谈中记录的"老板最近在考虑什么"。这些不构成Goal，但是方向可能即将变化的早期信号。

**资源数据颗粒度**：至少包含财务资源分配（预算）和人力资源分配（工时）。无法获取精确数据的企业，允许GA手动标注。

### 功能二：趋势偏离检测

**绝对偏离检测**：对每条P0级边维持12个月移动平均基线。参数连续3个月低于基线1.5σ→标记为"偏离"。同一条因果链上有3个以上参数同时偏离→触发预警。

**相对偏离检测**：企业自身数据仍在增长，但行业基准正在被颠覆。当ExternalBaseline数据显示行业增长率为负、或行业领先者增长率远超企业、或替代性技术/模式正快速侵蚀行业份额时，即使企业自身参数未偏离基线，也触发"方向存在风险"预警。

### 功能三：方向失效评估

偏离持续超过2个诊断周期→系统判断方向失效。**诊断周期直接引用文档03中定义的值。** 如果文档07和文档03的时间尺度存在差异，02使用文档03的诊断周期为基准，文档07为辅助参考。

方向失效评估区分两种失效模式，由四个感知断裂点的触发情况判断：

| 断裂点 | 默认映射 | 判断依据 |
|--------|---------|---------|
| 沉默检测 | 方向失效 | 信号被压制→组织对方向的信念可能在动摇 |
| 否认检测 | 方向失效 | 拒绝负面信号→方向本身可能已不可持续 |
| 知行差距检测 | 执行问题 | Goal停顿→方向可能对，但执行遇到了障碍 |
| 验证断裂检测 | 方向失效 | 做了但没结果→方向本身已不再成立 |

无法判断时默认进入"执行问题"分支——先检查执行，再判断方向，避免过早启动高成本NCI。

**方向切换过渡期**（默认90天）：偏离阈值从1.5σ放宽到2.5σ。过渡期结束时建立新方向基线。过渡期内不触发方向失效信号。

### 功能四：触发诊断流程

方向失效确认后→自动触发03诊断流程。**不是全量诊断。** 携带监测阶段已识别的偏离范围作为约束。只诊断已偏离的子循环和相关因果边。全量诊断只在定期体检时运行。

诊断两种输出分支：执行问题→调整Goal；方向问题→确认方向失效→如需重新选方向→启动NCI。

### 功能五：NCI子模块

**激活条件**：02确认方向失效 + 企业明确需要重新选方向。

NCI做三件事：扫描外部和内部数据评估被低估方向→经ODC消化能力过滤器→输出候选列表供企业选择（不自动转化为Goal）。

**四个边界**：
- **数据真空运行模式**：外部数据不可用→退化为两层计算+标注"需要GA补充外部数据"
- **休眠信号激活**：E-01~E-04感知边2σ跳变+方向一致/讨论热度≥3次/GA手动标记
- **共识测量反作弊**：行动承诺高但讨论频率低+内部一致性低→标记"强制共识"
- **长期验证归因分解**：ROI分解为"物理优势归因"和"外部事件驱动"，无法分解的标注"归因噪声过大"

## 四、NCI循环——第八个出厂内置循环

溢出监控循环仍然是顶层调度。NCI循环优先级低于溢出监控，高于知识积累。唯一耦合点：当溢出监控循环检测到某子循环溢出持续为负→自动触发NCI循环评估"该子循环是否应被放弃"。

## 五、MVS简化范围

方向锚定+趋势偏离+方向失效评估纳入MVS。MVS阶段简化为"Goal集合+关键42边参数基线"（使用3个月初始化基线）。不使用四个感知断裂点（需中层行为数据积累）。不使用相对偏离检测（需ExternalBaseline数据积累）。NCI不纳入MVS——是MVS后第一个扩展目标。

## 六、研究任务（5章）

### 第一章：方向有效性监测引擎
- 方向锚定（Goal集合+创始人关注信号+数据需求清单→文档13实现）
- 资源数据颗粒度（财务+人力，GA手动标注降级）
- 绝对偏离检测（12个月基线×1.5σ×因果链聚合）
- 相对偏离检测（行业基准恶化判定）
- 方向失效评估（2个诊断周期+断裂点→失效模式映射表）
- 时间尺度引用文档03诊断周期为基准
- 方向切换过渡期（90天+2.5σ放宽）

### 第二章：四个感知断裂点检测
- 沉默检测（90天无讨论）→方向失效
- 否认检测（外因>80%且无行业支撑）→方向失效
- 知行差距检测（Goal停顿/完成但无效）→执行问题
- 验证断裂检测（多个Goal完成但指标未改善）→方向失效
- 消费文档03/07/13/15数据

### 第三章：NCI子模块
- 三层公式+两种非共识类型+STM_Index
- 数据真空运行模式（两层计算+远期候选池）
- 休眠信号激活条件（2σ+方向一致/讨论≥3次/GA手动）
- 共识测量反作弊（强制共识检测）
- ODC资源约束过滤器
- 长期验证归因分解
- NCI循环调度优先级

### 第四章：02与03的诊断流程接口
- 方向失效→触发诊断（携带偏离范围约束）
- 诊断两种分支：执行问题→调整Goal；方向问题→启动NCI
- NCI候选方向→Proposal→三选一→Goal

### 第五章：与现有体系对齐
- 消费文档01/03/07/13/15的数据
- MVS简化范围标注
