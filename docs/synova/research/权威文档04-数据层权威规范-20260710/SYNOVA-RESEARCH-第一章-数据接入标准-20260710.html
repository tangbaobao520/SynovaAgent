1.2 数据适配器规范——三层声明式

不是简单的"A字段到B字段"映射。适配器是一个JSON文件，支持三层声明式转换。

1.2.1 适配器JSON结构

适配器 = 字段映射层 + 转换表达式层 + 验证规则层
所有三层均在单个JSON文件中声明式定义。不需修改管道代码。过程式逻辑（外部API/循环迭代）诚实标记为需定制.ts适配器。
层功能示例载体
字段映射层源字段到目标字段的重命名"营业收入" → total_revenueJSON
转换表达式层声明式表达式计算（四则运算+条件赋值+类型转换）efficiency_rate = total_output / total_cost
margin_category = IF(margin>0.3, "high", "low")		JSON
验证规则层值域约束efficiency_rate ∈ [0,1]
total_revenue > 0		JSON
边界声明 需要调用外部API、循环迭代、复杂聚合的逻辑 → 诚实标记为"需定制.ts适配器"，走第六章的定制适配器生命周期管理

1.2.2 时间字段推导规则

数据层强制携带valid_from/valid_to/observed_at。适配器必须定义如何从源数据推导这些时间字段：

源数据状态推导规则结果
有明确日期列（如"月份""日期"）映射日期列→valid_from和observed_at；valid_to=valid_from+1周期正常写入
无日期列使用文件上传时间+用户手动标注的周期（如"这份是2026年Q2的数据"）写入+标注manual_time_source
两者都没有拒绝写入，返回"缺少时间信息错误"拒绝+错误列表

1.3 数据冲突原则：忠实记录，不裁决

1.3.1 判断"同一数据点"的标准键

标准键 = {enterpriseId}-{poolName}-{paramName}-{validPeriod}
所有数据源在写入时必须遵循此键的生成规则。同一键的多个版本→全部保留在data_versions数组中。

1.3.2 冲突存储结构

字段类型说明
data_versions[]array同一标准键的所有版本
data_versions[].valueany该版本的值
data_versions[].source_originstring数据来源标识（ERP连接器/手动上传/API写入）
data_versions[].observed_atdatetime观测时间
data_versions[].confidencenumber[0-1]该数据源的置信度（由数据质量门禁计算）
is_activeboolean当前默认展示版本（取最新版本的is_active=true）
has_conflictboolean是否有活跃冲突（多个is_active版本且值差异>阈值）

1.3.3 冲突暴露示例

场景：CEO手填毛利率=60%，ERP计算毛利率=35%。
系统行为：两个版本都写入，source_origin分别为"manual_ceo"和"erp_connector"。
诊断报告中暴露："毛利率存在两个版本：手填60% vs 系统计算35%。差距从何而来？是数据错误，还是您对业务的理解有偏差？"
关键原则：数据层不裁决对错。原始数据不可丢弃。裁决权属于上层专家系统和GA。

1.4 上层影响审计——数据冲突感知

数据层采用"忠实记录"原则后，本体层、计算层、哨兵、专家提示词不能默认选择一种"权威"数据源。需审计并标记以下潜在冲突点：

受影响层审计项风险修正方向
GraphStorecreateNode方法/节点属性Schema无data_versions字段——当前写入会直接覆盖旧值新增data_versions数组字段
compute函数76个compute文件中的参数读取逻辑可能硬编码source_origin="erp"优先级compute函数应通过标准键读取is_active版本，而非按source_origin筛选
哨兵aggregate.ts50个aggregate.ts中的边参数获取可能隐式裁决（如"取第一个值"或"取最新值"，而忽略了冲突）哨兵在检测到has_conflict=true时应在Finding中标注
专家提示词8位专家的系统提示词可能默认假设"系统给的数据是唯一权威"（如"根据系统数据显示……"）必须增加"数据冲突感知"指令——当has_conflict时，主Agent必须在综合报告中明确告知用户存在歧义。当has_conflict=true时，主Agent注入数据冲突感知指令到相关专家的推理上下文，专家在推理中标注冲突来源和两个版本解读，主Agent在合成报告时呈现这些解读。，给出两个版本解读
专家提示词数据冲突感知指令（建议模板）：
"当您收到的任何数据参数标注了has_conflict=true时，您必须在诊断结论中明确告知用户该数据存在多个来源的歧义。您应展示至少两个冲突版本的值，并说明不同版本会导致什么不同的诊断结论。不要默认选择其中一个版本作为权威——将选择权交给用户或GA。"
