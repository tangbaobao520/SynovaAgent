2.1 多层级"为什么"协议

核心原则：用户在任何诊断结论上都可以追问"为什么"。Agent从42条因果边中自动追溯根因——从当前症状节点出发，沿42条边的反向图遍历，找到最早偏离基线的边，标记为"根因候选"。

2.1.1 标准追溯路径

当前症状信号 → 消费此信号的哨兵 → 哨兵消费的42边 → 该边引用的上游边（沿因果图反向BFS） → 找到最早偏离基线的边 → 标记为根因候选

2.1.2 追溯层数定义

层级问题Agent回答结构数据来源
L1 直接原因"这个信号为什么被触发？""因为[边X]的[参数Y]从[基线A]偏离到[当前值B]，偏离幅度[C%]。触发条件：[哨兵Z]的阈值[D]。"哨兵规范中的严重度阈值表
L2 因果追溯"为什么[参数Y]会变化？""[参数Y]受上游边[E-N]的[参数W]影响。过去[X]周期内，[参数W]从[P]变为[Q]。这是因为[上游节点的状态变化]。"42边因果图（反向BFS到上游一阶边）
L3 根因候选"所以根本原因是什么？""追溯到最早偏离基线的边是[E-M]——在[时间T]时，[参数R]首次偏离。这说明问题起源于[环节/节点]。如果[E-M]的参数回归正常，下游异常可能自动消失。"全部42边回溯结果，最早偏离时间戳标记
L4 二阶追问"为什么[E-M]会偏离？""[E-M]是[一阶/二阶]边。如果是二阶边——它受[E-P]和[E-Q]共同调节。目前[E-P]状态正常，[E-Q]偏离[X%]——正是[E-Q]的异常导致了[E-M]的偏离。"42边体系中的二阶边调节关系

2.1.3 对话示例：追溯完整因果链

Agent（主动触达）："王总，B产品线毛利率在两周内下降了4.2个百分点。这和原材料价格波动有关。要看看原因吗？"
用户："为什么？"
Agent（L1）："B产品线的单位边际贡献从8.6元降到5.1元——因为环氧树脂价格上涨了18%，而单价未变。您的成本结构：原材料占变动成本67%。"
用户："为什么原材料贵了？"
Agent（L2-3）："追溯到上游——环氧树脂价格在3个月前开始上涨，与您的采购合同锁定到期时间吻合（E-13资本配置中的allocation_ratio没有调整采购策略）。同时，竞品同步涨价意味着这不是独家问题（E-33市场份额获取中的competitor_aggressiveness上升）。根因候选：您的采购合同策略未随市场变化调整。"
用户："那为什么采购没调整？"
Agent（L4二阶+跨环节）："这是二阶问题——涉及E-14决策权（采购决策审批需要3层）和E-02信号衰减（原材料价格信号从采购部传递到决策层用了17天）。实际上，您的采购团队在2个月前就注意到了价格上涨——但这个信号在传递到您这里时被衰减了。"

2.1.4 追溯终止条件

以下情况Agent停止追溯，改为诚实回应：

  • 抵达一阶边且无上游："已追溯至[{边名}]——这是您企业系统的初始输入阀。此边异常的可能原因是[外部因素]，不在Synova的内部因果建模范围内。建议：[外部数据补充方向]。"
  • 数据缺失："追溯在[{边名}]处中断——该边的[参数]数据在过去[N]个周期内缺失。无法判断这是数据采集问题还是真实状态。建议：检查[{数据源}]的数据完整性。"
  • 多根因平局："三条边在同一个时间窗口内首次偏离——[E-A]、[E-B]和[E-C]。它们可能是独立事件，也可能有未被建模的共因。建议：[列出三个并行方向供用户选择追问]。"

2.2 即时"怎么办"引擎

核心原则：Agent不仅是分析师——更是参谋。当用户问"怎么办"，Agent调用三阶推理引擎：治疗（缓解症状）、转换（改变结构）、跳跃（开辟新空间）。

2.2.1 三阶推理框架

阶定义核心问题推理路径适用场景
一阶：治疗在当前结构内缓解症状"如何让这个异常消失？"发现哪个边参数偏离 → 直接调整该参数（或由哨兵识别的直接驱动因子） → 预测调整后的效果短期救急、参数微调、快速止血
二阶：转换改变结构——调整边间关系"如何让类似问题不再发生？"识别导致异常的系统结构（决策权分配/激励对齐/信息传递的组合） → 调整结构（如缩短审批层级、改变KPI权重） → 预测结构变化后的系统行为中期优化、组织调整、流程重构
三阶：跳跃开辟新空间——寻找新增长途径"除了修复这个问题，还有什么被忽视的机会？"扫描全部42边→找"被忽视的正向信号"（学习曲线、品牌积累、独占资产等） → 建议将资源从"修复"转向"放大正向信号"战略转型、第二曲线、主动增长

2.2.2 每个建议的附带信息

附带维度定义示例
预估效果预期改善的量化范围（如"毛利率有望回升3-5个百分点"）基于42边的传递函数逆向推算
所需资源执行此建议需要的资源类型（资金/人力/时间/决策权限）"需要：CFO审批权 + 约2周执行周期"
风险提示此建议的已知风险（如"提价可能导致客户流失率上升"）从竞争位势(E-36)和客户锁定(E-31)交叉推导
验证指标如何验证此建议生效（"如果在2周内X回到Y，则有效"）对应哨兵的跟踪参数变化
置信度此建议的可靠性（基于历史成功率+因果链清晰度）置信度≥80%=建议执行，50-80%=建议验证后执行，<50%=仅作参考

2.2.3 对话示例：从追问到方案

用户："怎么办？"
Agent：
"针对B产品线毛利率下降，三个方向供您参考：

一阶：治疗（立即止血）
• 将B产品提价8%，预计毛利率回升3.2个百分点。
• 预估效果：若需求弹性为-0.7，销量下降<6%，净利润增加约12万/月
• 风险：核心客户可能反对（切换成本0.4，中等风险）
• 验证：2周后观察B产品毛利率是否回到30%以上

二阶：转换（防止复发）
• 将采购决策审批从3层缩短为2层，预计原材料价格响应周期从17天缩短到5天
• 预估效果：下次原材料波动时损失减少60%
• 风险：减少审批层可能带来采购风险（建议保留CFO终审）
• 验证：下一次原材料价格变化时，观察采购响应时间

三阶：跳跃（发现机会）
• 您C产品线的学习曲线表明每翻一番产量成本降7%，当前处于成本陡降区。如果此时扩大C产品线投入，可能在6个月内获得显著的成本优势
• 预估效果：若C产品产量翻倍，单位成本可降15%
• 风险：扩张需占用约10万流动资金（可从B产品线的提价中释放）"
预判式追问按钮：[提价影响详细测算] [C产品线扩张可行性] [对比竞品提价策略] [我选择执行方案一]

2.3 对话意图预判

核心原则：不是等用户问——Agent预判用户下一个可能的问题，主动提供追问入口。降低用户思考成本，引导深度探索。

2.3.1 预判按钮生成规则

当前Agent回应的内容类型预判的下一问题（选2-3个）对应42边检索方向
回答了"发生了什么"（信号+数据）① "为什么会出现这个变化？" ② "影响范围多大？" ③ "什么时候开始的？"上游因果追溯 / 影响节点范围 / 基线偏离时间戳
回答了"为什么"（根因追溯）① "更深层的原因是什么？" ② "有哪些其他环节也受影响？" ③ "历史上有过类似情况吗？"二阶边追溯 / 跨环节联动 / 历史模式匹配
回答了"怎么办"（行动建议）① "执行这个方案的具体步骤？" ② "有更保守/激进的方案吗？" ③ "竞品在这种情况下怎么做？"执行路径 / 参数敏感性 / 竞品参照系
诊断报告整体推送① "最紧急的问题是什么？" ② "和上个季度比怎么样？" ③ "如果我什么都不做会怎样？"严重度排序 / 时间窗口对比 / 基线趋势延长

2.3.2 预判按钮的设计约束

  • 每次最多3个预判按钮——超过3个=用户选择困难
  • 第一个按钮始终是最可能的追问（"为什么"或"怎么办"）
  • 按钮措辞是"自然对话语言"，不是"功能名称"——"成本上升的原因是什么？"而不是"追溯上游边"
  • 包含一个"出口按钮"——"我已知晓，无需追问"或"转为行动"

2.4 可视化证据链

核心原则：从"静态报告"进化为"可交互活图"。用户可以点击因果图上的任意节点或边，展开参数历史、趋势和基准对比。

2.4.1 因果图可视化规格

元素视觉编码交互行为
正常节点（边参数在基线范围内）灰色圆形，标签为节点/边名点击→弹出参数面板：当前值、基线、历史趋势图
异常节点（边参数偏离基线）橙色圆形（警告）或红色圆形（严重），脉冲动画点击→弹出详细偏离面板：偏离幅度、开始时间、影响的下游节点（高亮）
根因候选节点（最早偏离基线的边）红色圆形 + 加粗边框 + "根因?"标签点击→弹出根因分析面板：完整因果链、历史回测验证
因果边（节点间有向连接）灰色细线（正常）或橙色/红色加粗线（异常传播路径）点击→弹出边详情面板：传递函数类型、参数历史、二阶调节关系
异常传播路径橙色→红色的渐变色路径，带箭头动画点击路径 → 展开"为什么这条路径被高亮"的解释

2.4.2 证据链的数据来源

因果图上的每个参数展示，数据来源追溯到：

展示内容数据来源获取方式
参数当前值本体层GraphStore（L4）DiagnosisContextNode → 沿42边 → 目标节点.参数
参数历史趋势本体层时间序列存储参数的时间窗口数组（最近N个周期）

2.4.3 证据链的对话嵌入

Agent在对话中引用因果图时，不是贴一张静态图片，而是生成一个可交互的因果图嵌入：

Agent："B产品线毛利率下降的因果链如下——从环氧树脂价格上涨（根因）传导到原材料成本上升，再传导到边际贡献压缩：[此处嵌入可交互因果图]。您可以点击任意节点查看详细数据。"

2.5 "对话即报告"的范式转化

关键设计决策：传统BI工具和Synova的核心区别在于——Synova的"报告"不是一份文档，而是一场对话的起点。当用户从主动触达消息进入对话后，整个诊断过程就是一场实时生成的"活报告"。

传统报告Synova对话式诊断
静态PDF/仪表盘可交互、可追问的实时对话
所有内容一次性呈现按用户追问逐步展开
数据表+图表因果图+可点击节点
用户被动阅读用户主动探索
写报告的人决定深度用户决定追问到多深
报告完成后过期对话可随时继续，数据实时刷新
