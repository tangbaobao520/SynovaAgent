6.2 SignalAggregator与输出编排器的职责边界

这是架构设计中最重要的边界定义——两者职责重叠会导致重复计算和逻辑踩踏。

维度SignalAggregator（L3，已存在）输出编排器（L2，新增/升级）
处理层级信号级处理用户级处理
输入50个哨兵的SentinelFinding[]（原始信号）SignalAggregator的结构化信号集 + 用户角色画像 + 对话上下文
核心操作• 同类信号合并（如两个哨兵检测到同一趋势→合并）
• 时序对齐（不同哨兵的触发时间对齐到同一时间窗口）
• 去重（相同(哨兵,实体)对→只保留最新）		• 按角色过滤信号（只保留该角色关心的边）
• 按严重度排序
• 去重合并为复合故事
• 选择报告形态
• 填充叙事模板
• 解析用户指令重新渲染
输出结构化信号集（去噪后的、时序对齐的、同类合并的信号数组）用户可消费的内容（推送消息/对话回复/报告/简报）
是否关心用户不关心 "谁在看"关心 "谁在看、什么场景、什么偏好"
状态已存在（L3 sentinel/SignalAggregator）新增——需要新建模块或升级现有ConversationEngine
关键原则：SignalAggregator只关心"信号本身"，不关心"谁在看"。输出编排器只关心"谁在看"，不关心"信号如何聚合"。两者之间的接口就是"结构化信号集"——一个JSON数组，描述去噪后的信号列表。

6.3 三种报告形态的本质差异

全景诊断报告、执行简报、快照——它们不是同一份文档的"长中短版本"，而是三种完全不同的叙事结构。

维度全景诊断报告执行简报快照
目的建立完整认知、支持重大决策快速定位执行偏差、推动行动确认状态、心安
结构首页摘要（3-5条核心发现）→ 因果链地图 → 证据区（数据表+时间窗口对比）→ 行动区（3阶方案）→ 风险区（假设条件）一句话信号 → 根因（1-2句）→ 1-2条可执行行动 → 追问入口（3个预设按钮）3-5个核心指标卡（数字+单位+趋势箭头→/↘/↗）
叙事方式故事化："利润下降的根因在成本结构——具体来说，原材料成本上升侵蚀了您的经营杠杆"陈述式："B产品线毛利率下降了4.2个百分点，从32%至27.8%。根因是环氧树脂涨价18%，建议提价8%"数据式：毛利率27.8% ↘、现金跑道2.3月 ↘、客户留存率84% →
适用场景初次诊断、季度复盘、战略转折每周/每日同步、方案偏离告警例行检查、状态确认
时间窗口多窗口对比（3月/6月/12月）单窗口（当前周/月）当前值
涉及边数多边交叉（3-5条边同时异常）单边或双边（1-2条边）单一边参数
置信度标注每个核心发现带置信度数值+置信区间信号整体置信度每个指标卡带置信度（小字）
导出格式PDF（含完整数据表）文本（可复制到聊天/邮件）截图（可复制到聊天）
用户控制入口"调整报告"按钮（颗粒度/时间/范围）"调整报告"按钮点击任意指标卡→进入对话（快照是极简模式，用户控制通过对话实现）

6.4 形态决策引擎

6.4.1 决策公式

report_morphology = F(severity, complexity, user_preference, dialog_context)

6.4.2 决策规则表（优先级从高到低）

优先级条件强制形态原因
1P0生存威胁（任何信号）全景报告老板需要完整认知才能做出生存级决策
2多边交叉信号（≥2条边同时异常，且边间有因果上下游关系）全景报告需要展示边间因果关系——简报无法承载
3二阶边信号（该异常涉及一条二阶边）全景报告二阶边需要解释其调节关系——简报说不清
4用户历史偏好"详细"全景报告尊重用户偏好
5用户对话中刚追问过（"为什么""详细点"）倾向全景用户明确表示需要深度
6单边信号 + P1效率问题执行简报默认——快速定位+推动行动
7用户历史偏好"简洁"执行简报尊重用户偏好
8P2机会信号（单边）快照简单信号不需要深度展开
9例行检查（无异常信号）快照用户只想确认状态正常

6.4.3 形态决策的架构执行顺序

  1. 信号优先级排序器输出1-3个候选故事
  2. 形态决策引擎根据严重度+复杂度+用户偏好计算初始形态
  3. 安静期管理器检查是否允许触达
  4. 叙事渲染引擎按选定形态+角色画像生成内容
  5. 用户可随时用对话指令覆盖形态（"太长了"→全景→简报）

6.5 用户对话控制协议

用户指令在叙事渲染阶段介入——不重新触发诊断，只重新渲染已有数据。这是"用户感觉Agent听懂了"的实际机制。

用户指令系统响应（不触发新诊断）渲染参数变化
"太长了，给我简短版"当前全景报告 → 折叠为简报（保留核心信号+行动建议）morphology: brief, depth: shallow
"详细点，我要看数据"当前简报 → 展开为全景报告（增加证据区、边参数详情）morphology: full, depth: deep, includeEvidence: true
"只看销售相关的"过滤为销售相关42边（E-31/E-33/E-30/E-25）的信号，重新渲染filter: {causalEdges: ["E-31","E-33","E-30","E-25"]}
"我要过去6个月的趋势"时间窗口从当前周/月扩展到6个月，信号基线重新计算，重新评估形态timeWindow: "6months", recalculateBaseline: true
"把这份报告发给CFO"触发跨角色输出：生成CFO版本（聚焦E-13/E-37/E-05/E-06边信号）并推送targetRole: "CFO", regenerateForRole: true
"改成适合董事会的版本"全景报告→极简版董事摘要（3条发现+3条行动，无数据表，无技术术语）morphology: board_summary, maxFindings: 3
"别只看利润，看看人"当前信号集扩展到E-15（人力配置）+E-38（人才留存）相关信号expandEdges: ["E-15","E-38"], regenerate: true
"保存这份分析"当前对话状态+因果图+信号集打包存储，生成可分享链接saveSnapshot: true, generatePermalink: true

6.5.1 输出指令解析器的实现机制

输出指令解析器（L2，对话引擎内部）：
识别用户指令 → 生成RenderingParams对象 → 输出编排器以当前结构化信号集为输入，按新RenderingParams执行：
① 重新形态决策（如果用户说"太长了"/"详细点"）
② 重新角色过滤（如果用户说"只看销售"/"发给CFO"）
③ 重新叙事渲染（用新参数填充42边模板）
整个过程用户感觉是"Agent听懂了"——实际上是一个独立的渲染流程，不涉及L3/L4的任何新计算。

6.6 置信度计算模块

6.6.1 置信度输入因子

因子权重来源低置信情况
数据完整性评分40%compute规范中的数据源等级（A/B/C）× 数据实际可用性C级数据源 + 大量缺失
因果边类型30%一阶边=0.9，二阶边=0.7，跨环节联动=0.6二阶边信号（调节关系复杂，推理不确定性高）
历史准确率20%该哨兵的历史GA验证通过率（来自GA进化循环）新哨兵（无历史）=默认0.5，历史准确率<60%=低
数据新鲜度10%信号数据的时间戳 vs 当前时间>30天旧数据=0.3，7-30天=0.6，<7天=1.0

6.6.2 置信度计算公式

confidence = 0.4 × data_integrity + 0.3 × edge_type_factor + 0.2 × historical_accuracy + 0.1 × data_freshness

6.6.3 置信度驱动的语言呈现

置信度输出语言风格示例
> 80%陈述句——结论作为事实呈现"利润率下降的原因是X。"
50-80%推断句——标注不确定性"利润率下降很可能与X有关，但需要进一步验证数据Y。"
< 50%疑问句——作为假设提出"利润率下降是否与X有关？建议手动验证数据Z后确认。"
置信度不准时不造假：如果置信度无法计算（数据不完整），Agent会说"当前数据不足以给出置信度评级"，而不是编造一个数字。
