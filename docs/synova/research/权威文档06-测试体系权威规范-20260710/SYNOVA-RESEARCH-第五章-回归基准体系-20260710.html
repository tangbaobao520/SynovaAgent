第五章：回归基准体系

基准快照 + 自动对比 + 退化追踪 + 因果回归联动 | 2026-07-10

5.1 基准快照机制

项目内容
触发时机每次 git tag 发布前，全量执行 vitest → 将结果保存为 JSON 基线文件
基线存储test-baselines/{tag-name}.json ——包含：测试文件列表、通过/失败状态、执行耗时、覆盖率数据
自动对比每次 commit 后自动对比当前 vitest 结果与最新基线 → 任何新增失败 → 告警（标注"本次提交导致的退化"）

5.2 退化追踪

  • 连续 2 次回归 → 自动在 PR 中标记 REGRESSION-RISK 标签
  • REGRESSION-RISK 标签存在 → block merge（阻断）

5.3 与因果回归测试联动

最高级别告警：基准对比通过（代码测试全绿）+ 因果回归测试偏差>30% → 阻断推送。"代码测试过了但诊断结论变了"——这是传统回归测试无法发现的最危险情况。因果回归是最终防线。

5.4 与 verify-incremental.sh 融合

日常开发保持增量测试速度（L1 oxlint→L2 tsc→L3 vitest --changed→L4 接线）。全量基准对比与因果回归联动——每周 1 次或发布前执行——不影响日常速度，但确保关键节点有完整质量检查。
