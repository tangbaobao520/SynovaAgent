  • TelemetryEvent枚举: HttpRequestStarted/Succeeded/Failed, Analytics, SessionTrace 五种

D4-1: Hermes声明式Schema迁移 (零停机)

Declarative Reconciliation: 只ADD不DROP

代码: hermes_state.py L545-L620 (_reconcile_columns)

def _reconcile_columns(self, cursor):
    """Diff SCHEMA_SQL vs PRAGMA table_info, ADD missing columns."""
    expected = self._parse_schema_columns(SCHEMA_SQL)
    for table, declared_cols in expected.items():
        live_cols = {row['name'] for row in
            cursor.execute(f'PRAGMA table_info("{table}")')}
        for col, type_ in declared_cols.items():
            if col not in live_cols:
                cursor.execute(f'ALTER TABLE ADD COLUMN "{col}" {type_}')

SCHEMA_SQL是单一真相源。新字段只需在SCHEMA_SQL中声明，启动时自动ALTER。永不DROP列，保证前向兼容。

D5. 法律合规与治理

D5-1: Hermes Redact 生产级脱敏引擎

13层正则脱敏 + RedactingFormatter

代码: agent/redact.py (全文件，~300行) — 三个项目中最成熟的合规实践

覆盖层: 已知前缀(30+供应商API key) / URL查询参数 / JSON字段值 / JWT / DB连接串 / ENV赋值 / Auth Header / 私钥块 / E.164电话 / Discord mention。

安全设计关键决策:

  • 导入时快照: _REDACT_ENABLED在模块加载时固化，防止运行时env mutation绕过
  • force模式: 安全边界(对外API响应)调用redact_sensitive_text(text,force=True)，无视全局配置
  • code_file模式: 跳过ENV/JSON字段(避免MAX_TOKENS=***误报)，前缀+Auth仍脱敏
  • 性能优化: 每个regex前substring预检(如"eyJ" in text才跑JWT)，典型行从5.6us降至1.8us(-68%)
def redact_sensitive_text(text, *, force=False, code_file=False):
    if not (force or _REDACT_ENABLED): return text
    # ... 13层regex pipeline ...
class RedactingFormatter(logging.Formatter):
    def format(self, record):
        return redact_sensitive_text(super().format(record))
