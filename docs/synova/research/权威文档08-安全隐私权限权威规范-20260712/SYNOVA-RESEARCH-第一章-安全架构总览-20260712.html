1.1 威胁模型归集方法

威胁来源不靠头脑风暴——从六组输入资产中系统化提取：逐资产扫描安全威胁→按STRIDE框架(欺骗S/篡改T/否认R/信息泄露I/拒绝服务D/权限提升E)分类→每个威胁标注来源(研究文档+章节)→P1-P10作为威胁-原则映射框架→六组资产中未覆盖的威胁单独标记为"新发现威胁"。归集完成后设计缓解措施。

1.2 STRIDE威胁归集表

从六组输入资产中系统化提取的全部安全威胁：

#STRIDE威胁来源缓解措施
T1I跨租户数据泄露：GA顾问可访问多家企业数据，缺乏强制隔离机制权限研究(P10中国墙) + rbac.ts(五角色但未实现跨租户隔离)tenantId强制注入所有SQL查询；GA的SQL查询必须携带当前激活租户ID；跨租户查询默认拒绝
T2IPII数据泄露：原始PII(手机号/身份证/薪资)可能被传给LLM或在诊断报告中暴露数据层第四章 + pii-scrubber.ts(S1-S4分级+opt-out)S3/S4字段在数据入口强制脱敏(入口最前端，不可绕过)；S4字段(密码/Token/私钥)不回显/不存储/不传输
T3E中层越权访问：部门经理可能通过GraphStore遍历获取其他部门或全局敏感数据权限矩阵(六角色×五级×六操作) + rbac.ts(manager角色无跨部门限制)TraversalPermissionFilter在节点级实施权限过滤；图遍历不能返回角色权限之外的节点
T4E老板数据过度暴露：CEO拥有全局访问权，但不应看到员工个人敏感信息(薪资/健康)权限矩阵(特殊场景3：老板保护)S3/S4级数据即使对老板角色也需脱敏展示（如薪资显示区间而非精确值）
T5I知识基座隐私泄露：企业上传的内部文档可能包含PII或商业机密，写入KnowledgeStore后被其他GA或系统访问技术实现方案(PreUploadValidator接口) + knowledge-store.tsPreUploadValidator在上传前做PII/机密关键词预检；匿名化聚合必须不可逆(K-匿名性/差分隐私)
T6T审计日志篡改：恶意内部人员或外部攻击者修改或删除审计日志以掩盖违规操作技术实现方案(审计哈希链) + audit-store.ts审计哈希链：每条记录携带前一条hash→不可篡改链；根哈希定期(每小时)发布到外部不可变存储
T7T提示注入攻击：攻击者通过用户输入或数据字段注入恶意指令，诱导Agent执行非授权操作或泄露数据Agent对标路线3(提示注入防护+Claw Code 456-pinpoint)输入层提示注入检测和拒绝；Agent执行行动前的人类确认门禁(L2行动层)
T8T数据投毒攻击：攻击者通过持续注入错误数据改变系统基线，使诊断结论系统性偏离真实Agent对标路线3(对抗性鲁棒性) + 数据层第三章(数据气味)数据源可靠性监控(更新突变/值漂移/格式变化)；应急响应：暂停管道→标记污染期→通知GA→一键回滚
T9S身份伪造：攻击者使用窃取的JWT Token或伪造的认证凭证冒充合法用户auth.ts(JWT HMAC-SHA256) + credential-vault.ts(凭证加密)JWT短有效期(默认24h)+jti唯一性+撤销列表；凭证加密存储(credential-vault.ts)
T10I客户数据未彻底删除：客户合同终止后要求删除数据，但派生数据(诊断报告/基准数据)未清除GDPR/PIPL Art.17(被遗忘权) + P8(传染性删除)DataPurger实现传染性删除——删除源数据时清理所有派生数据(诊断报告/哨兵结论/知识库引用)
T11I数据导出不安全：客户要求导出数据(GDPR可携带权)，但导出过程可能泄露其他客户的数据GDPR/PIPL Art.20(可携带权) + P7(可携带+可删除)DataExporter仅导出该租户的数据；导出前隔离验证(确保tenantId过滤)；导出文件加密传输
T12R操作的不可否认性缺失：关键操作(数据删除/权限变更/诊断推送)无不可否认性，事后无法证明操作者身份技术实现方案(审计哈希链) + audit-store.ts审计哈希链+外部不可变存储根哈希：提供物理级别的不可否认证据
T13D拒绝服务——数据源中断被利用：攻击者通过切断关键数据源使诊断系统"失明"Agent对标路线3(穿透测试) + 数据层第五章(可观测性)数据源健康监控+三级降级策略+数据源中断时使用缓存数据+标注
T14新发现权限配置漂移：长期运行中权限配置可能因为管理操作或bug而偏离安全基线(如manager角色意外获得admin权限)新发现——六组资产中未显式覆盖权限基线快照+定期自动对比+偏离告警+自动回滚到安全基线
T15新发现数据生命周期泄露：客户数据在知识库中被匿名化聚合后，通过差分攻击可能重新识别个体企业新发现——六组资产中未显式覆盖K-匿名性(k≥3)+差分隐私(ε≤1.0)+定期重审聚合数据的匿名化有效性

1.3 四层权限模型（L1数据访问/L2编排控制/L3诊断执行/L4行动执行）

层级架构层管控内容核心机制
L3 行动层L2编排层Agent能否执行诊断推送、发送消息、触发外部系统操作人类确认门禁——P0/P1行动需人类审批；PolicyEngine裁决行动许可
L2 诊断层L3-L4本体/洞察层compute/哨兵/专家能否访问特定节点和边参数TraversalPermissionFilter——图遍历时节点级权限过滤；ABAC基于(角色,数据等级,操作)三元组裁决
L1 数据层L5存储层原始数据字段级访问控制、PII脱敏、租户隔离tenantId强制注入SQL；字段级权限(public/internal/restricted)；PII入口脱敏
三层权限(纵深)与六角色矩阵(横向)的正交声明：四层权限模型（L1数据访问/L2编排控制/L3诊断执行/L4行动执行）定义了"在哪一层执行管控"(纵深防御)，六角色矩阵定义了"谁拥有什么访问权"(横向授权面)。两者不冲突——三层中的每一层都独立使用六角色矩阵进行访问裁决。第一章明确声明这种正交关系，避免第三章出现概念漂移。

1.4 部署模式

维度本地部署云端SaaS
数据隔离物理隔离——每个企业独立SQLite实例/进程逻辑隔离——PostgreSQL RLS + 图命名空间 + tenantId强制注入
PII处理本地完成脱敏，原始PII永不出企业边界客户端SDK侧脱敏后上传
凭证存储本地credential-vault.ts加密存储云端密钥管理服务(KMS)+信封加密
联邦进化物理不可行——GA手动跨客户汇总匿名聚合层——聚合匿名化数据(K-匿名性+差分隐私)
