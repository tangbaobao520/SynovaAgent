# 模块一：权限体系

> 权限的三个独立维度: 数据(能看到什么) x 功能(能做什么) x 时间(多久)

---

## 一、三维权限模型

| 维度 | 含义 | 取值 |
|------|------|------|
| 数据维度 | 能看到什么 | 部门范围(全企业/指定部门/本人) + 数据粒度(汇总/部门级/个人级) |
| 功能维度 | 能做什么 | 查看诊断/触发诊断/创建Goal/审批知识/邀请成员/导出数据/下载原始数据 |
| 时间维度 | 权限有效期 | 永久/合同期内/临时授权(N天自动回收) |

---

## 二、5 个内置角色模板(不可删除)

| 模板 | 数据维度 | 功能维度 | 时间维度 |
|------|---------|---------|---------|
| admin | 全企业全部粒度 | 全部功能——但批量导出和删除审计日志需双人确认 | 永久 |
| manager | 本部门全部粒度 | 查看诊断 + 触发诊断 + 创建Goal + 审批本部门记忆 | 永久 |
| liaison | 全企业只读(汇总级) | 查看诊断 + 冲突检测 | 永久 |
| staff | 本人相关 + 本部门汇总 | 查看诊断 + 创建Goal | 永久 |
| ga | 管理员设定的部门范围 + 敏感度S1以下 | 查看诊断 + 写入observation | 合同到期日 |

管理员可基于内置模板创建自定义模板, 在模板基础上为具体用户增减权限。

---

## 三、管理员制衡机制

管理员是权限体系中权力最大的角色——也是最危险的。以下机制不依赖于管理员是好人的假设:

| 操作 | 限制 |
|------|------|
| 全量数据导出 | 触发安全告警 + 写入不可篡改的审计日志 + 通知创始人 |
| 权限变更 | 每次记录操作上下文 + 变更理由 + 变更前后权限差异 |
| 删除审计日志 | 禁止——任何角色都无法删除审计日志, 日志表只追加不删除 |
| 批量修改权限 | 需管理员+创始人双签(若不是同一人); 若为同一人则退化为二次确认 |
| 连续异常操作 | 1小时内多次数据导出或权限变更 -> 自动触发安全告警 + 临时冻结导出功能24小时 |

---

## 四、GA权限边界与防数据泄漏

| 边界 | 设计 |
|------|------|
| 查看数据 | 管理员授权范围内可看, 默认S1及以下。S2及以上需管理员临时授权(N天自动回收) |
| 下载原始数据 | 管理员可设置禁止GA下载。默认: GA账户 can_download_raw_data = false |
| 数据导出 | 禁止——GA不能将诊断报告导出为可传播的文件格式, 仅可在系统内查看 |
| 合同到期 | 所有权限自动收回。系统自动生成GA数据访问总结报告 |
| 离职/解约 | 管理员可立即冻结GA账户。冻结后所有正在进行的诊断立即中止 |
| 审计追踪 | GA每次查看敏感数据记录: userId + timestamp + 数据内容 + 查看目的 |

---

## 五、GA observation的软删除例外

GA的observation设计为只写不删。但GA如果是独立自然人, 其observation可能被视为个人数据, 受GDPR/PIPL保护。系统为此保留一个受控出口:

- GA可申请删除observation——但删除操作必须由管理员审批
- 审批通过后执行软删除: observation内容被隐藏, 但审计日志中保留删除记录
- 这不是削弱不可删除原则——是为极端合法合规场景保留的受控出口
