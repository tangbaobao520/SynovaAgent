# 模块四：知识审批双流水线

> 企业内部知识的风险由管理员承担。跨企业共享知识的风险由管理员+GA共同承担。两条流水线, 两种审批逻辑。

---

## 一、流水线一：企业内部知识(admin审批)

```
draft -> pending_admin_review -> approved(team/enterprise可见) 或 rejected(退回来源)
```

管理员审批的不是知识的学术正确性——是在当前阶段是否适合公开。

---

## 二、流水线二：跨企业联邦知识(双重审批)

```
enterprise knowledge(管理员已批准+标记可对外共享)
  -> anonymized(系统自动脱敏)
  -> pending_admin_review(管理员确认脱敏版本)
  -> pending_ga_review(GA确认模式有效性)
  -> 需至少两家其他企业产生相似改善 -> federated
```

---

## 三、联邦知识脱敏边界

不能仅去掉企业名称和金额。以下数据类型明确不得进入联邦知识库:

- 可组合识别企业的细粒度指标(如后厨人员8人减至6人需改为优化后厨人员配置)
- 具体的业务模式细节
- 地区标识符(城市名、区域名)
- 企业规模/业务规模的精确数字(改为区间——2000万营收需改为2000-5000万区间)

GA做最终脱敏判断——能否识别企业。管理员做是否敏感判断。两个角色各管一段, 不互相替代。

---

## 四、GA权力制衡与终止规则

- **多企业验证:** 模式必须在至少两家其他企业中产生相似改善(闭环验证指标改善>10%, 且统计上显著p<0.05, 或贝叶斯因子>3), 才升级为联邦知识。改善方向一致但幅度差异过大(如一家50%、一家5%)需标记为可能有效但需更多验证, 不自动升级
- **用户反馈:** 低分知识(<3/5且至少五家企业反馈)自动降级为待重新验证
- **GA离职后:** 联邦知识质量标记不绑定到单个GA——某GA历史确认权重随评分自动降低
- **终止规则:** 超过6个月未达两家验证门槛需标记为搁置, 不再占用GA审批队列。超过12个月仍未激活则归档为历史记录
- **GA权力分散:** 联邦知识的上线不仅依赖单个GA的确认——还需要多企业验证数据+用户反馈。GA的确认是必要但不充分条件
