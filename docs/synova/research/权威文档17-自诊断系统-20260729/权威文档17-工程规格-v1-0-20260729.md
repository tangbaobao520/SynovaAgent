## 二、CLI 工具一：self-diagnosis.py (研发模式)

### 2.1 CLI 接口

```
python scripts/audit/self-diagnosis.py [--mode dev] [--output path]
```

mode 支持: dev(默认)——研发模式六条件判定。

### 2.2 输入

- `check-gates-v2.py` 的 JSON 输出(`gate-status.json`——17 门禁状态)
- 全量依赖图(`dependency-graph.json`——文件×import 关系)
- git log 最近 30 天提交记录
- task brief 目录(`.codex/task-briefs/`)
- 测试文件目录(`tests/`)

### 2.3 判定逻辑 (按 §1.3 审计结论实现)

| 条件 | 实现方式 | 依赖状态 |
|:---:|------|:---:|
| 1. 代码存在 | Test-Path + rg 函数签名——空壳检测(4种模式: 空构造/类型导入/存根函数/死导入) | 无外部依赖 |
| 2. 接线完整 | 依赖图入边分析——排除 .test.ts 文件 | 依赖图已有 |
| 3. 测试存在 | rg "expect(" 计数——检查 >=3 | 无外部依赖 |
| 4. 路径可达 | 从入口节点反向 BFS 搜索依赖图 | 依赖图已有 |
| 5. 依赖可用 | import 路径 Test-Path 验证 | 无外部依赖 |
| 6. 无已知缺陷 | deviation-report.json 中无该函数的 P0/P1 条目 | 偏差报告已有 |

### 2.4 输出

`.codex/snapshots/{ISO 8601 timestamp}/completion-scores.json`

```json
{
  "generatedAt": "2026-07-29T12:00:00Z",
  "mode": "dev",
  "tasks": [
    {
      "taskId": "D106",
      "conditions": {
        "code_exists": true,
        "wiring_complete": true,
        "test_exists": true,
        "path_reachable": true,
        "dependencies_available": true,
        "no_known_defects": true
      },
      "score": 1.0
    }
  ],
  "systemScore": 0.78,
  "baselineScore": 0.75,
  "trend": "+0.03"
}
```

## 三、CLI 工具二：product-health.py (产品模式)

### 3.1 CLI 接口

```
python scripts/control-tower/product-health.py [--check all|pipeline|sentinel|quality|loop|resource]
```

### 3.2 五个检测维度 (按 §1.3 审计结论实现)

| 维度 | 实现方式 | 依赖状态 |
|------|---------|:---:|
| 数据管道 | 调用 GraphStore.queryNodesCreatedAfter(7天)——新增方法 | ⚠️ 需先实现 queryNodesCreatedAfter() |
| 哨兵准确度 | 复用 sentinel-accuracy.ts 计算 precision/recall/f1 | ✅ 可复用——但 GA 反馈接线需先修复 |
| 诊断质量 | 读取 GoalExecutionKnowledge.diagnosisQualityScore——新增字段 | ❌ 需先扩展 knowledge-feedback.ts |
| 循环运行 | 复用 Gate 13 的 checkStagnation() | ✅ 可复用 |
| 资源使用 | psutil 库获取内存/磁盘/CPU——新增模块 | ❌ 需新建 resource-monitor.ts |

### 3.3 输出

`.codex/signals/product-health.json`

```json
{
  "component": "product-health",
  "status": "degraded",
  "timestamp": "2026-07-29T12:00:00Z",
  "dimensions": {
    "pipeline": "healthy",
    "sentinel": "healthy",
    "quality": "degraded",
    "loop": "healthy",
    "resource": "healthy"
  },
  "report_trust": "degraded",
  "degraded_reasons": ["诊断质量连续2次评分为'部分有用'"]
}
```

### 3.4 诊断报告可信度标记规则

| 退化维度数 | trust_level | 标记文本 |
|:---:|:---:|------|
| 0 | healthy | "系统健康度: 正常——本次诊断结论可信" |
| 1-2 | degraded | "系统健康度: 部分退化(原因)——本次诊断结论仅供参考" |
| 3+ | critical | "系统健康度: 严重退化——本次诊断结论不可信, 请联系管理员" |
