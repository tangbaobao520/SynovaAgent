# 第三章：权威文档审计与 CLAIM 标签规范

> 基于 CLAIM-TAG-SPEC.md v1.0 + K3 红队审计方法论

## 3.1 核心问题：权威文档也会跑偏

权威文档是 Codex 写 dev doc 的"宪法"。如果宪法本身有偏差，所有下游都会出错。

D328/D329/D330 审计发现了代码偏差，但更深层的风险是：**文档说"已实现"，代码现实没有**。

A线-产品完整性缺口审计（2026-08-01）给出了量化证据：
- 四条件 C（结论有用）仅 **62%**
- 但部分文档声称更高完成度

## 3.2 红队审计方法论

不是"读文档找错误"，是"用已知负面证据攻击文档的正面声称"。

**已知负面证据**（直接作为判案依据）：
- A线审计：四条件完成度数据
- 跨文档一致性审计：已发现矛盾
- C线差距清单：外部对标偏差
- 控制塔状态：已知盲区

**攻击目标**：文档中所有"已实现/已接线/已验证/已部署"声明。

## 3.3 `<claim>` 标签规范

### 为什么需要机器可读标签

旧文档：
```markdown
方向监测引擎已接线到路由层，支持查询模式。
```

LLM 需要理解自然语言才能判断真假。脚本无法验证。

新文档（加标签后）：
```markdown
<claim id="E02-1"
       status="IMPLEMENTED"
       evidence="src/routes/direction-monitor.ts:45"
       since="D202"
       test="tests/routes/direction-monitor.test.ts">
方向监测引擎已接线到路由层。
</claim>
```

脚本可以直接 `grep` 验证 `src/routes/direction-monitor.ts:45` 是否存在。

### 属性定义

| 属性 | 必需 | 类型 | 说明 |
|------|:---:|:---:|------|
| `id` | ✅ | 字符串 | 全局唯一，格式 `{模块缩写}-{序号}` |
| `status` | ✅ | 枚举 | `IMPLEMENTED` / `PARTIAL` / `PLANNED` / `DEPRECATED` |
| `evidence` | 条件 | 路径 | `IMPLEMENTED`/`PARTIAL` 时必须 |
| `since` | ❌ | D# | 首次成立的 dev doc 任务号 |
| `test` | ❌ | 路径 | 验证测试文件 |
| `gap` | 条件 | 文本 | `PARTIAL` 时必须说明缺失 |

### 适用范围

| 文档类型 | 是否强制 |
|---------|:-------:|
| D329 之后新写的权威文档 | ✅ 强制 |
| 重大修订的旧文档 | ⚠️ 建议 |
| 未改动的旧文档 | ❌ 不强制，偏差进注册表 |

## 3.4 旧文档处理策略：不迁移，只注册表

**17 份旧文档保持原样**，不动格式。偏差通过注册表管理。

```
┌─────────────────────────────────┐
│  旧文档：纯 Markdown             │
│  偏差：AUTHORITY-DEVIATION-REGISTRY │
│  Codex 引用时：先查注册表再引用    │
└─────────────────────────────────┘
            ↓
┌─────────────────────────────────┐
│  新文档：Markdown + <claim>      │
│  验证：doc-audit 自动验证         │
│  Codex 引用时：直接引用，脚本验证  │
└─────────────────────────────────┘
```

## 3.5 中央偏差注册表

**文件**：`docs/synova/research/AUTHORITY-DEVIATION-REGISTRY-v1.md`

**格式**：

```markdown
## P0 偏差（必须修复）

### D-01-§2.3: 方向监测引擎"已接线"声明

- **文档**: 权威文档 01 §2.3
- **声称**: "方向监测引擎已接线到路由层"
- **物理事实**: src/routes/direction-monitor.ts:45 存在，但 tests/... 无测试覆盖（A线数据 C62%）
- **证据**: A线审计 2026-08-01 §4.2
- **影响**: Codex 写 dev doc 引用时可能高估完成度
- **修复建议**: 标注 `status="PARTIAL"`，补充 `gap="测试覆盖不足"`
- **状态**: 待修复

## P1 偏差（建议修复）

...
```

**与 `<claim>` 的关系**：
- 新文档的 `<claim>` 被 `doc-audit` 自动验证 → 偏差在写时被发现
- 旧文档的偏差进注册表 → 偏差在引用时被发现
- 注册表逐步缩小（旧文档修订时迁移 `<claim>`）→ 最终全部自动验证
