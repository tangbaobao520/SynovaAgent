## 分级标准详细定义

### P0：阻断交付

**条件（满足任一）**：
- 核心功能未验证（测试未通过、劫持场景未拦截）
- 安全事故（API key 暴露、PII 泄露）
- 门禁形同虚设（pre-commit 绕过无记录、降级路径静默放行）
- 数据严重不实（声称已实现但实际不存在）

**处理**：必须修复，修复后重新审计。

### P1：建议修复

**条件（满足任一）**：
- 声明与物理事实矛盾（Done 标准声称已验证但实际未验证）
- 文档/记录有缺口（bypass.log 空窗、版本编排不同步）
- 降级策略不完整（catch 块有 log 但无 degraded 标记）
- 测试覆盖有盲区（正常路径通过但降级路径未覆盖）

**处理**：记录跟进，下次审计复查。合并时可接受，但必须在下一版本中修复。

### P2：可选改进

**条件（满足任一）**：
- 代码风格不一致
- 文档格式不统一
- 注释缺失或过时
- 命名可优化

**处理**：采纳或忽略。不阻塞交付。

## 总体结论定义

| 结论 | 条件 | 后续动作 |
|------|------|---------|
| **PASS** | 14 项全 PASS，无 P0/P1/P2 | 审计通过，可合并 |
| **CONDITIONAL PASS** | 无 P0，但有 P1/P2 | 核心功能验证通过，P1 记录跟进，可合并 |
| **FAIL** | 存在 P0 | 阻断交付，必须修复后重新审计 |

## 环境注记规范

每份报告必须包含：

| 项 | 示例值 |
|---|-------|
| OS | Windows（Git Bash / MSYS）、macOS、Linux |
| Shell | /usr/bin/bash、zsh |
| Python | 可用版本 / 不可用 |
| Node.js | 可用版本 |
| Git | 版本号 |
| 测试执行位置 | 真实仓库根目录 / 临时 clone |

**环境差异警示**：如果审计结果可能与执行环境有关（如 PATH、Python 可用性），必须明确标注。
