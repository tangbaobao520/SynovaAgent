# 官方「智能体团队」：能力清单与启用方式

> 日期：**2026-09-19**
> 触发：创始人截图设置页（官方 6 个插件，「智能体团队」ON、「智能体团队 Web 界面」OFF），质疑 *"扯淡，官方都出了团队版插件了"*
> 结论：**创始人正确。官方 Agent Teams 已经在运行，缺的只是一个未启用的 Web 界面 bundle。我方此前的全部第三方路线属舍近求远。**

---

## 一、结论先行

1. **官方已经有 Agent Teams，且已在你的机器上运行。** 证据：`~/.dsh/profiles/web/package.json` **第 44 行** bundles 含 `@deepseek-ai/dsh-experimental-agent-team-profile`。**本会话里的 `spawn_teammate` / `team_task_*` / `send_message` / `wait_agent` 全部由它提供** —— 也就是说，院长做的一切协作都跑在官方 Agent Teams 之上。
2. **设置页那两个开关的机制已确认**：开关 = `dsh.profile.bundles` 里的成员资格。**「智能体团队」ON ↔ 第 44 行存在**，完全吻合。
3. **「智能体团队 Web 界面」是 OFF 的原因**：Host 层（`agent-team-profile`）已装，**Web 界面层（`agent-team-web-profile` / `client-ui-agent-team`）未装** → 工具可用、看板不可见。
4. **官方提供的正是你要的控制塔**：任务看板、任务依赖与 blocker、readiness、**write scope 重叠警告**、成员名册与实时状态、成员会话导航、持久消息（挺过崩溃重启）。
5. **对我此前两个结论的更正**：
   - ❌ "官方不做 git 隔离，所以要用第三方补" → **你要的不是 git 隔离，是控制塔。官方全有。** 我拿一个你从未提出的需求（物理 worktree 隔离）当成了你的缺口。
   - ❌ "用纪律解决 M8 共享竞争" → 官方任务板本身就会显示**重叠 warning**，这是官方对共享竞争的应对（提示而非锁）；纪律是补充，不是替代。

## 二、机制：为什么开关是关的（可复现证据）

```
$ python3 -c "import json;print(json.load(open('/Users/wane/.dsh/profiles/web/package.json'))['dsh']['profile']['bundles'])"
```

当前 bundles（21 项）中与团队相关的**只有一项**：

| bundle | 层 | 状态 |
|---|---|---|
| `@deepseek-ai/dsh-experimental-agent-team-profile` | **Host 层**（roster、邮箱、共享任务 DAG） | ✅ **已装**（第 44 行） |
| `@deepseek-ai/dsh-experimental-agent-team-web-profile` | **Web 层**（Remote + UI 插件） | ❌ 未装 |
| `@deepseek-ai/dsh-experimental-client-ui-agent-team` | **UI 包**（页头 action、roster、任务板） | ❌ 未装 |

官方文档（`dsh-experimental-client-ui-agent-team/README.zh.md`）说明了这个顺序依赖：

> *"在稳定 Web bundle 与 Host-side Agent Teams profile **之后**，通过 `@deepseek-ai/dsh-experimental-agent-team-web-profile` [使用本包]"*

**这解释了截图里的状态：工具在跑（Host 已装），但页头没有 Agent Teams 入口（UI 未装）。**

## 三、官方能力清单（第一方原文，非我的转述）

### 3.1 `dsh-experimental-agent-team`（本体，已启用）

> *"把一个编码会话变成一个小型工作团队：会话中的 agent 成为 **Lead**，创建具名 teammate 处理委派的工作"*
> *"当多个 agent 必须在**同一个共享工作区**协作、且 roster、消息与任务状态需要**挺过崩溃与重启**时，选择它"*

描述字段：*"Implicit-root Agent Teams roster, durable peer mailbox, and **shared task DAG**"*

| 能力 | 官方表述 |
|---|---|
| Lead / teammate 结构 | 会话 agent 成为 Lead；只有 Lead 可创建或中断 teammate |
| 持久消息邮箱 | *"live 成员会立即收到；离线成员的消息会排队，并在其恢复后到达"* |
| 共享任务 DAG | 任务板 + 依赖（`shared task DAG`） |
| 成员状态 | `running` / `idle` / `inactive` / `provisioning` |
| 容量配置 | `maxMembers` 16、`maxTasks` 256、`maxPendingMessagesPerMember` 64、`maxMessageBytes` 65,536 |
| 可隔离启动 | teammate 可 **fresh 启动**（不携带 Lead 对话） |

### 3.2 `dsh-experimental-client-ui-agent-team`（Web 界面，未启用）

描述字段：*"Web Agent Teams roster, **task board**, and teammate navigation"*

> *"向 Web 会话页头添加 Agent Teams action，让用户**检查当前 roster、管理共享任务板并导航到 teammate 会话**"*
> *"**任务板展示 task identity、owner、blocker、readiness、提示性 write scope 与重叠 warning**。用户可以通过 `agentTeams/createTask` 与 `agentTeams/[updateTask]`…"*
> Roster row 展示*"持久 name、运行时 status、model 与 diagnostics"*

**逐条对上你的需求：**

| 你要的 | 官方是否提供 | 依据 |
|---|---|---|
| 任务看板（不单薄的那种） | ✅ | `task board`，展示 identity/owner/blocker/readiness |
| 任务依赖 | ✅ | `shared task DAG` + `blocker` / `readiness` 字段 |
| 并行冲突防护 | ✅ 部分 | **提示性** write scope + **重叠 warning**（注意：官方自称"提示性"，不是锁） |
| 成员名册 + 实时状态 | ✅ | roster row：name / status / model / diagnostics |
| 成员会话导航 | ✅ | *"导航到 teammate 会话"* |
| 状态持久 | ✅ | *"挺过崩溃与重启"* |
| 权限约束 | ✅ | 只有 Lead 可创建/中断 teammate |

## 四、启用方式（沙箱外执行，二选一）

### 方式 A：设置页点开关（先试这个）

**设置 → 插件 → 官方 → 「智能体团队 Web 界面」→ 打开 → 重启 `dsh web`**

依据：该 toggle 与 `dsh.profile.bundles` 成员资格一致（见 §二 吻合证据）。

### 方式 B：直接改 bundles（A 不生效时）

在 `~/.dsh/profiles/web/package.json` 的 `dsh.profile.bundles` 数组中，紧邻第 44 行处加入：

```json
"@deepseek-ai/dsh-experimental-agent-team-profile",
"@deepseek-ai/dsh-experimental-agent-team-web-profile",
```

> ⚠️ 改前备份该文件。**注意 `@deepseek-ai/dsh-base` 与 `@deepseek-ai/dsh-web-app` 在 bundles 里但不在 `dependencies` 里** —— 说明官方 bundle 由 DSH 自带解析，**大概率不需要 npm install**；若启动报缺包，再考虑补 dependencies。
> ⚠️ `~/.dsh` 对本会话只读，**必须由你或外部 Claude Code 执行**。

## 五、启用后立刻该做的一件事（验证而非宣布）

**不要因为"官方有"就认为它一定够用** —— 这与我前几轮的错误是同一种错误（把"存在"当成"适用"）。

**用一次真实任务验证**，观察四件事：

- [ ] 页头是否出现 Agent Teams 入口，roster 是否正确显示成员与状态
- [ ] 创建一个带 `blocked_by` 依赖的任务，看 readiness 是否正确推导
- [ ] 故意让两个 teammate 的 write scope 重叠，看**重叠 warning 是否真的弹出**
- [ ] 关掉浏览器/重启后，任务板与消息是否**真的还在**（官方声称挺过重启）

**四项都过，才把它作为你的控制塔底座。**

**我查了：npm 包名、第三方仓库、下载量、stars、代码危险面、精选列表收录情况 —— 全都查了。**
**我没查：官方包目录里的 `README.zh.md`（第一方穷尽式文档）、以及你设置页上明摆着的那两个开关。**

更关键的是：**`agent-team-profile` 第 44 行一直在我的视野里（我读过这个文件），我却读的是 `dependencies` 段，没读 `dsh.profile.bundles` 段。** 一个我读过两遍的文件，答案就在 20 行之外。

**结论：这不是"审查不严"，是"搜索方向错了"。** 遇到"缺一个能力"时，我的第一动作应当永远是**先穷尽第一方已提供的东西**（官方包 README + 设置页开关 + 官方文档），而不是去第三方生态里检索。

## 八、反例条件（什么会让我改变本文件结论）

| 若出现 | 我会改口为什么 |
|---|---|
| 打开 Web 开关后页头无入口、或 roster 空白 | 机制判断错误 → 转为排查 bundle 依赖（可能是 `client-ui-agent-team` 需单独装） |
| 任务板不存在、或只有 roster 没有 task board | 能力被我高估 → 回到第三方方案评估 |
| 重叠 warning 实际不触发 | 官方 write scope 的"提示性"形同虚设 → 并行安全仍需纪律兜底 |
| 重启后任务板/消息丢失 | "挺过崩溃重启"不成立 → 持久性需求另寻方案 |
| 官方 Web 界面在你的 DSH 版本（0.1.6-alpha.2）上被判 incompatible | 需等版本升级，期间保持现状 |
