# 插件尽调：`dsh-plugins-tower` / `-guard` / `-bench` 的出处、市场收录与代码可信度

> 尽调日期：**2026-09-19**（周六）
> 尽调对象：已装入 `~/.dsh/profiles/web` 的三个第三方插件
> 触发问题（创始人）：*"dsh-plugins-tower，这个插件哪里来的？你让装的插件在 DSH 插件市场里有么"*
> 结论用途：决定留用 / 卸载 / 换等价替代

---

## 一、结论先行

1. **三个包同一出处**：GitHub 个人开发者 **`kouyichi`** 的仓库 `github.com/kouyichi/dsh-plugins`，npm 发布者账号 **`qby324`**。**不是 DeepSeek 官方**（官方是 261 个 `@deepseek-ai/*` 包）。
2. **市场收录真实情况（这是我先前判断的错误，须更正）**：市场的数据源是 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) 精选列表。该仓库在列表里被收录的是 **4 个其它子插件**（`dsh-a2a` / `dsh-guard` / `dsh-meter` / `dsh-learn`）——**我让你装的三个包中只有一个在列表里**：

   | 包 | 在精选列表里？ | 依据 |
   |---|---|---|
   | `dsh-plugins-guard` | ✅ **在** | 列表第 2001 行 `kouyichi/dsh-plugins#dsh-guard` |
   | `dsh-plugins-bench` | ❌ **不在** | 列表全文无 `dsh-bench` 条目 |
   | `dsh-plugins-tower` | ❌ **不在** | 列表全文搜 `tower` = **0 次** |

   **我给你的安装脚本里，3 个包有 2 个在市场里搜不到。这是我建议的缺口，不是你的误操作。**
3. **但代码层面是干净的**：三个包合计 **1,596 行、零依赖、零网络请求、零凭据访问**，`tower` 唯一的外部命令是 `git`（参数数组传参，无 shell 注入面），`guard`/`bench` **完全不执行命令**。**这是"我可以亲自读完并给你担保"的体量**——真正的风险不在代码，在"没人用过"。
4. **官方侧的关键事实（决定第三方有无必要）**：DSH **已有**官方多 agent 协作（`dsh-experimental-agent-team` 一组 5 包——本会话里的 `spawn_teammate` / `team_task_*` 就是它），但官方**完全不做 git 分支隔离与合并门禁**（在其代码里 `worktree` / `git` / `review` 命中均为 **0**）。**`tower` 补的这块是真空，不是重复造轮子。** 详见 §六。
5. **留用建议**：`guard` 留、`bench` 可留可去、**`tower` 先在非产品仓库验证再上 SynovaAgent**（理由见 §七）。

## 四、市场收录的准确含义（避免误读）

必须区分两件事，否则会得出相反结论：

| | 事实 | 含义 |
|---|---|---|
| **市场收录 ≠ 质量认证** | 精选列表自己声明：*"本列表不给插件排名，也不评判优劣"* | 收录只代表"有人提了 PR" |
| **市场收录 ≠ 安全审查** | 列表 `[!WARNING]` 原文：*"安装插件等于在你的机器上跑第三方代码，权限和你本人一样大——能读你的文件、用你的凭据、访问网络，**工具审批管不到插件自己的代码**。收录不等于做过安全审查"* | **没收录也不等于不安全** |

**所以"不在市场里"本身不构成拒绝理由**，它只说明：**没有第三方替你看过它，所以只能自己看。** 而这三个包恰好小到可以自己看（1,596 行）。

## 五、代码审计（我实际读了源码）

审计对象：`~/.dsh/profiles/web/node_modules/<pkg>/index.js`（`tower` 另有 `lib/glob.js`）

### 5.1 代码规模

| 包 | 行数 | 文件 |
|---|---|---|
| `dsh-plugins-tower` | **969** | `index.js` 909 + `lib/glob.js` 60 |
| `dsh-plugins-guard` | **346** | `index.js` |
| `dsh-plugins-bench` | **281** | `index.js` |
| 合计 | **1,596** | 零依赖 |

### 5.2 危险面扫描结果

| 检查项 | tower | guard | bench | 判定 |
|---|---|---|---|---|
| `fetch(` / `http` / `https` / `net.` | **0** | **0** | **0** | ✅ **零网络请求**——不会把你的任何数据发出去 |
| `ssh` / `credential` / `apiKey` / `token` | **0** | **0** | **0** | ✅ 不碰凭据 |
| `child_process` | 1（仅 import） | **0** | **0** | guard/bench 完全不执行命令 |
| 实际执行的外部命令 | `execFileSync("git", ["-C", repo, ...args])` | 无 | 无 | ✅ 参数数组传参、`stdio: ["ignore","pipe","ignore"]` → **无 shell 注入面**，git 输出不外溢 |
| `process.env` | 0 | 1 | 1 | 基本不读环境 |
| 写入位置 | repo 内 `.tower/` | `~/.dsh/guard/` | `~/.dsh/bench/runs/` | 路径可控、可审计 |

### 5.3 `tower` 的关键能力是"真实现"而非纸面声明

已读代码确认存在：
- `git(repoRoot, args)` → `execFileSync`，**唯一 git 出口**，集中在 1 个函数里（好审计）
- `branchTip()` → `git rev-parse <branch>`，用于"review 结论是否还对得上分支 tip"的硬门禁
- `assertScopesDisjoint(mission)` → 拒绝覆盖整个 repo 的 scope、拒绝两个 mission 的 write scope 重叠（**我调用 `tower_plan` 时它确实拒绝了重叠 scope，行为与代码一致**）
- `renderMissionViews()` → 落盘 `MISSIONS.md` + `missions/<id>.md`
- `comms/log/activity.log` → 全量动作审计轨迹（best-effort 写入，失败不阻断）

**这一点很重要**：`review/merge` 门禁是**确定性代码**而不是提示词约束。按 Anthropic AI-Native SDLC 的结论——*skills 是建议性的，hooks 是确定性的*——`tower` 属于后者，这正是它能补上你现有控制体系缺口的类型。

## 六、官方能力对照：第三方补的到底是哪块空白

**这一节回答"有没有必要用第三方"。** 直查 DSH 官方 261 个 `@deepseek-ai/*` 包后的结论：

### 6.1 官方**已经有**多 agent 协作（这是重要事实）

存在一组官方包 `dsh-experimental-agent-team`（5 个：`-profile` / `-web-profile` / `client-ui-` / `tool-` / 本体）。**本 session 里可用的 `spawn_teammate` / `team_task_*` / `send_message` / `wait_agent` 就来自它。**

所以**"多 agent 并行协作"不需要第三方。** 我在此前的建议里没有把这一条讲清楚——这是我该补的。

### 6.2 但官方**没有** git 层隔离与审查门禁

在 `dsh-experimental-agent-team/lib/` 内计数：

| 关键词 | 官方 agent-team 命中 |
|---|---|
| `worktree` | **0** |
| `git` | **0** |
| `review` | **0** |
| `branch` | 3（非 git 语义） |

**判定**：官方 Agent Teams 是**消息层 + 任务板层**的协作，**不做分支隔离、不做合并门禁**。

而系统提示自己写明了这层协作的边界（本 session 原文）：

> *"Split write work into disjoint scopes... **Write-scope overlap is advisory, not a lock**."*

**这句话就是 M8 共享竞争事故的根源**：官方 write scope 是**建议**，不是锁；两个并行 session 仍可能同时占用主工作区暂存区。

### 6.3 因此三类隔离各管一段，不互相替代

| 隔离类型 | 由谁提供 | 防的是 |
|---|---|---|
| **文件系统权限隔离** | 官方 `dsh-sandbox` / `dsh-fs-sandbox` / `dsh-bash-sandbox` / `dsh-pwsh-sandbox` / `dsh-sandbox-windows-acl` / `dsh-sandbox-policy`（8 个包） | 越界读写（防"跑到不该去的地方"） |
| **会话/日志导出** | 官方 `dsh-session-telemetry` / `-otel` / `dsh-session-log-export` | 事后追溯（**是默认关闭的外发管道，不是工具级拒绝**） |
| **git 分支物理隔离 + 合并门禁** | ⚠️ **官方空白** → `dsh-plugins-tower`（第三方） | 互相踩暂存区（M8 事故）、未审先合 |
| **工具级拒绝规则 + 本地审计** | ⚠️ 官方只有 telemetry 层 → `dsh-plugins-guard`（第三方，**且在精选列表内**） | 危险命令、无记录 |

**结论（置信度：中高）**：
- `tower` 覆盖的是**官方确实没有的**能力，且是**确定性代码**而非提示词建议 —— 这是它有存在价值的实证，不只是"作者说好"。
- `guard` 的工具级拒绝 + 本地审计，与官方 telemetry 不重叠。
- 二者都不与官方 Agent Teams 冲突，是**叠加**关系（都读同一套 DSH 上下文）。

### 6.4 但必须同时说清官方侧的短板

`dsh-experimental-agent-team` 名字里就带 **`experimental`** —— **官方自己也不保证它稳定**。所以现实是：**协作层（官方 experimental）+ 隔离门禁层（第三方单版本无测试）都不稳。** 这不是"选官方还是选第三方"的问题，是**两层都要小心**。

## 七、采用建议（落到"该做什么"）

> ⚠️ **本节结论已于 2026-09-19 被推翻，以 [复盘-插件推荐失误与准入标准-20260919.md](复盘-插件推荐失误与准入标准-20260919.md) 为准。**
> 推翻理由两条：① 本节用"在精选列表里"作为 `guard` 留用的依据，与本文 §四 自己写下的"收录不构成质量信号"**直接矛盾**；② 三个包月下载量（188 / 336 / 310）比生态主流（7 万–46 万/月）低 **2–3 个数量级**，不存在"被别人踩过坑"这一安全条件。
> **处置改为：三个全部卸载。**

### 7.1 分插件处置

| 包 | 建议 | 理由 |
|---|---|---|
| `dsh-plugins-guard` | ✅ **留用** | 在精选列表里；346 行、零执行面；**你的处境（非技术创始人 + 需要"谁动了什么"的记录）直接受益于审计轨迹** |
| `dsh-plugins-bench` | 🟡 **可留可去** | 281 行、零执行面，安全；但能力就是"按关键词跑任务集打分"，**当成轻量回归探针可以，不能当验收依据** |
| `dsh-plugins-tower` | ⚠️ **留用，但先隔离验证** | 它提供的能力正好是你最缺的（worktree 隔离 + 确定性 review/merge 门禁，即 M8 共享竞争事故的解法）；但它是三个里最"重"的，见 7.2 |

### 7.2 `tower` 必须在非产品仓库先验证（硬要求）

**理由**：`tower_init` 会在目标仓库里真实地 —
1. 创建 `.tower/` 目录并**改写 `.gitignore`**
2. 创建 `feat/<slug>` 分支
3. 创建 git worktree（`.tower/worktrees/wt-N`）
4. spawn 的子代理**在该 worktree 里改文件**

也就是说，**它会动你的 git 仓库**。`SynovaAgent` 是你唯一的产品资产，`tower` 是 28 天龄、单版本、无测试的第三方代码。

**处置**：先在一个**非产品仓库**（例如本工作区 `山河研究院`，或另建一个试验仓库）跑一次**完整闭环**：
`tower_init → tower_plan → tower_spawn(worker) → tower_spawn(reviewer) → tower_review → tower_merge → tower_teardown`

观察 4 件事：
- [ ] 它把 `.tower/` 写在哪、`.gitignore` 被改成什么样（**用 `git diff` 前后对比**）
- [ ] 它创建的 `feat/*` 分支有没有正常清理
- [ ] `tower_merge` 的硬门禁是否**真的会拒绝**（故意制造 review 未 clean 的状态试一次）
- [ ] `tower_teardown` 之后 `git status` 是否干净

**只有这 4 项通过，才允许在 `SynovaAgent` 里使用。**

### 7.3 卸载方式（若最终不用）

必须由你或外部 Claude Code 执行（沙箱内 EPERM）：

```bash
dsh plugin --profile web remove dsh-plugins-tower
```

`guard` 已在本次会话生效（skill 目录出现 `guard`），移除前先确认 `~/.dsh/guard/` 下有无你想保留的审计记录。
