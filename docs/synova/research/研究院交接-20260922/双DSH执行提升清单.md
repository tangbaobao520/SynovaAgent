# 双 DSH 执行的提升清单（从质量对比证据推导）

> 研究日期：2026-09-22 | 依据：`DSH-agent-team与Win侧Claude-Code质量对比.md`（同日，独立评估）
> 场景：创始人决定未来 mac + win 两台机器都由 DSH Agent team 执行编码，Win 侧 Claude Code 退场。
> 本清单每一条都挂在对比研究的实测证据上，不凭印象。分三类：**DSH 自身短板**（对比中实锤）、**体系风险**（双 DSH 后新增）、**Win 的长处要带走**（退场前吸收）。

---

## 结论先行

DSH 已经赢的部分（提交原子性、任务号追溯、spec 兑现稳定性）不需要再投入；需要投入的是三块：
1. **P0｜切换前必须做（约 1–2 天配置 + 协议修订）**：审计独立性升级（maker 同质化后 K3 从审计变门禁）＋ Win 机器 DSH 环境标准化（身份/hooks/门禁同装，**机器身份保留**）。
2. **P1｜切换后 1–2 周（每项半天–1 天）**：边界值纪律制度化（DSH 三个真 bug 全是边界型）＋ as/! 断言门禁（接口设计规则）。
3. **P2｜一个月内（编排层重构约 3–5 天，其余规则级）**：可测试性标准（吸收 Win 的 setDeps 范式）＋ 编排层第二抽象 + 文件/函数长度门禁 + 路由自卫规则 + 财务 guard 规范。

总成本量级：**规则/门禁/配置级改动为主，唯一有工程量的是编排层抽象重构（3–5 天）**。没有一项需要大型开发。

## 一、DSH 自身短板（对比实锤，全 DSH 后成为唯一短板）

### 1. 边界值纪律缺失 —— P1，最高优先级的编码能力补强

**证据**（本次对比抓到的 DSH 真 bug，全部是「正常路径对、边界错」）：
- `ga-calibration.ts:257` `store.list({limit: 200, offset: 0})` 硬编码——用户 offset 参数算而不用，存量超 200 条后翻页静默返回空、supersedes 链永远挂不上（双盲评审交叉确认）；
- `self-check.ts:195` `hours.length > 1 && hours.length < 24`——每小时执行（恰 24 个小时位）的哨兵落入兜底，陈旧度阈值放大 24 倍；
- `self-check.ts:150` `maxScheduleMs = 0` 时阈值归零，每轮必发 H3 warning，与文件自身「宁缺毋滥」契约矛盾；
- `detect.ts:88` `Math.max(0, ...outDegree.values())`——大图 spread 栈溢出（外层 catch 兜住降级，不致命但属同类边界意识欠缺）。

**提升**：
- dev doc 验收标准模板增加「边界值清单」段——每个数值/集合参数枚举：空 / 单元素 / 恰好临界（=阈值、=limit）/ 超限 / 零 / 负值。照 S-15（D701 假 store 事故→规则）的先例，把这类事故制度化；
- 测试配对门禁升级：涉及数值参数的函数，边界用例 ≥3 条才过；
- 评审 checklist 加「边界枚举」必答项。

### 2. as/! 断言密度高 + 接口设计缺陷 —— P1

**证据**：DSH as 断言 15.7/千行（Win 9.1）；根因之一是接口设计——`ga-auth.ts:20` 返回 `boolean` 而非 `auth | null`，把「auth 非空」不变量藏在实现里，直接导致 `ga-calibration.ts` 四处 `extractAuthFromRequest(req)!`（L124/242/317/422，双盲评审一致点名）。

**提升**：
- 接口设计规则进 dev doc 模板：「**返回值承载不变量**」——guard 函数返回数据（`auth | null`）而非 boolean+副作用，让类型系统替调用方扛住判空；
- 现有 as-any 审计门禁（pre-commit-check.sh L481 一带）扩展到 `as <具体类型>` 强转与非空断言 `!`：新增计数、设阈值、超限需豁免注记。

### 3. 可测试性模式不统一 —— P2

**证据**：DSH 的 `ga-calibration.ts`（动态 import + `getFeedbackCollector()` 活单例，盲评 R5=3/3.5）与 `customer-config-package.ts`（私有函数直连 fs 无注入点，R5=3.5）测试须起真实环境；而 **Win 的 `loop-handlers.ts` 有全场最佳的可测试性范式**——6 组 `setXxxDeps` 接口 + setter 注入 + 传 null 恢复生产默认（盲评 R5 高分，4/4.5）。

**提升**：把 Win 的 deps-interface + setter 注入提炼为仓库标准模式（吸收被替换者的长处）；新模块验收加一条「单测无需真实环境/mock 即可跑」。

### 4. 外部进程协议解析脆弱 —— P3

**证据**：`assert.ts:101-110` 用 `curl -w '__STATUS__:'` 把状态码混入 stdout 再字符串分割——响应体含该标记即解析错乱（双盲评审交叉确认）。

**提升**：子进程输出协议规范：`-o` 分流到文件 / writeOut 独立通道 / 结构化输出（JSON），禁止「标记字符串分割混合流」。

## 二、体系风险（不是 DSH 的错，但双 DSH 后必须补）

### 5. 评审多样性消失 —— P0，切换前必须落

**证据**：本次研究的双盲评审 ρ=0.727，但两位评审员同源（同一模型血统），部分一致性来自共同偏好——这是本对比自己声明的局限。原体系是 Codex 规划 / Claude 执行 / K3 异构审计的三角制衡；maker 全部 DSH 化后，如果审计也同源，制衡退化为「同一套认知查自己」。

**提升**：
- K3（异构模型）从「交付审计」升级为**必经合并门禁**（尤其安全/财务计算/数据迁移三类路径）；
- 关键 PR 保留「异构模型交叉评审」一环（哪怕抽样 20%）；
- 把「同源偏差」写进审计协议：K3 审计清单加「边界值/负值/越权」三节——正是本次双盲评审证明同源评审员也容易集体漏掉的区型。

### 6. 双机 DSH 的环境标准化与归属可审计 —— P0，切换前必须落

**证据**：仓库已有双机事故史——`MULTI-MACHINE-PR-WORKFLOW.md`（Mac 4 天不知 Win 推 11 commit 的教训）、M13 复发（`.git/config` 被测试沙箱污染两次：core.bare=true / 身份被改，见审计发现台账 2026-08-25 条）。门禁共享是本次对比公平性的基石（两组过同一套 pre-commit/CI）——这正是要保住的东西。

**提升**：
- Win 机器 DSH 环境标准化：per-clone 身份（**保留 `Synova-Win` 类机器身份，别统一成匿名**——否则未来的质量归因、事故定位都做不了，本次研究的方法论就依赖身份区分）、hooks、skills、预设与 mac 同装同版本；
- `install-hooks.sh` 的幂等身份初始化（D540 已做）在 Win 机验证一遍；
- 写集冲突扫描进 CI（`conflict-scanner.ts` 已有雏形，扩到写集登记表）；双机并行任务沿用「一人一事一分支、合并走 PR」，对 DSH session 同样成立。

### 7. 编排层抽象债 —— P2（唯一有工程量的项，约 3–5 天）

**证据**：双盲评审的「双峰分布」结论（两组共性，全 DSH 后全部变成 DSH 的债）——叶子层（≤197 行）均分 4.68，编排/聚合层均分 3.71；文件长度与质量强负相关（≤70 行均 4.71，≥438 行均 3.83）。具体形态：Win `aggregate.ts` 8 段同构「missing→compute→阈值→push」、`loop-handlers.ts` 6 段 try-catch+降级样板；DSH 的 `ga-calibration.ts`（479 行）也有 109/95 行的大匿名函数。DSH 的 mega-file 倾向比 Win 轻（>100 行函数 1 vs 2）但不是没有。

**提升**：
- 建第二层抽象：finding 构造器（统一 critical/warning 模板与 evidence 组装）、降级 wrapper（统一 try-catch+log+degraded 样板）、哨兵 check 模板（8 段同构收敛为声明式指标表）；
- 门禁加长度阈值：单函数 >150 行、单文件 >500 行需豁免注记（阈值取本次数据的 P95 附近，先观测后拦截）。

### 8. 安全自卫与财务 guard 规范 —— P2

**证据**：
- DSH `routes/config.ts:26` orgId 取 query 且文件零自卫，越权防护完全依赖 server.ts 挂载顺序（L345/L373 在 L385 之前）——挂载顺序一变即成洞（双盲评审一致点名；对照同目录 ga-* 的 requireGa + `auth.orgId` 是正面样板）；
- 财务 guard 不对称成对出现（Win 的两个 computes，双盲交叉确认）：分母 `===0` 精细设防、分母 `<0`（负利息、负权益=资不抵债）双双裸奔——价值毁灭企业可能拿到正 spread 健康判定。

**提升**：
- 路由层规则进铁律/checklist：「orgId 必须取自认证上下文（`auth.orgId`），禁收 query 传入的租户标识」；
- 财务计算 guard 规范：数值防御必须同时覆盖 0 与负值，负值不设防时须显式声明业务假设并写进契约 JSDoc。

## 三、Win 的长处要带走（退场前固化为资产）

| Win 验证过的范式 | 证据（盲评分） | 固化方式 |
|---|---|---|
| 纯函数 computes：契约 ID 版本化（COMPUTE-XXX-v1 算法冻结）+ 学术引用 + warnings 传播 | interest-coverage 4.88/4.6、roic-wacc 4.63/4.6、wacc 深读无瑕疵 | 提炼为哨兵 compute 模板，DSH 接手哨兵线照此写 |

| 「事故→规则」机制（D701 假 store 事故→S-15 写进所有后续 spec） | D702 spec §0/§2.3 | 机制本身与工具无关，继续运转 |
