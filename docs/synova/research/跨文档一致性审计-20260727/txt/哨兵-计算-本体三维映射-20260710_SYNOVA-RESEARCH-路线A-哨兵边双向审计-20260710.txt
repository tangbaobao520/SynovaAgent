Semantic Consistency Spot-Check (MODIFY edges x compute functions) 3.1 OPERATIONAL_EXECUTION (E-23) <- PRODUCES 42-Edge Definition : Transfer function = efficiency_rate x (1 - defect_rate) -- multiplicative logic, merging efficiency + quality into one edge. Old compute : computeOperationPerformance() uses weighted average Sum(actual_i/target_i x weight_i) / Sum(weight_i) , reading old marginal_contribution . This is addition/subtraction logic. Gap : LOGIC REWRITE NEEDED -- 42-edge requires multiplicative logic (efficiency x quality). Old compute is weighted-average logic. Completely different mathematical structure. Impact : 8 sentinels already reference OPERATIONAL_EXECUTION label but compute still uses old weighted-average. If graph data migrates without updating compute, diagnosis values will deviate from true semantics. Fix : Rewrite computeOperationPerformance to efficiency_rate x (1 - defect_rate) x capacity_utilization . Deprecate marginal_contribution parameter. 3.2 CAPITAL_ALLOCATION (E-13) <- FUNDS 42-Edge Definition : Transfer function upgraded from actual_roi to allocation_efficiency = Sum(budget_i x roi_i) / total_budget , adding reallocation_frequency parameter. Old compute : 11 sentinels use FUNDS edge traversal results, but current compute functions read actual_roi , revenue from node props -- static snapshot. Gap : PARAMETER MAPPING INCOMPLETE -- current compute doesn not use allocation_efficiency . reallocation_frequency is completely missing. Impact : 11 sentinels diagnose only static ROI snapshots, missing the core 42-edge dimension of "capital allocation flexibility" (reallocation frequency). Fix : Add allocation_efficiency and reallocation_frequency fields to FUNDS edge props. Compute functions need dynamic allocation efficiency calculation. 3.3 HUMAN_DEPLOYMENT (E-15) <- DEPLOYS (Split) 42-Edge Definition : DEPLOYS split into people (E-15) + equipment (E-10). People transfer function: person_skill_match x person_capacity . Old compute : 33 sentinels uniformly use DEPLOYS edge traversal, reading utilization_rate from generic node props -- people and equipment mixed together. Gap : SPLIT LOGIC NOT IMPLEMENTED -- All 33 sentinels DEPLOYS calls need routing: PERSON nodes -> E-15, EQUIPMENT nodes -> E-10. Impact : Largest blast radius -- 33 sentinels (66%) edge traversal logic must change. Without routing, talent mismatch and equipment idle are conflated into a single diagnosis. Fix : Three phases. Phase1: sentinel-level routing by node type. Phase2: 16 people-sentinels (talent-density, human-agent-boundary, etc.) use only E-15. Phase3: new equipment sentinels for E-10. 3.4 TECH_INFRASTRUCTURE (E-29) <- AUGMENTS 42-Edge Definition : Promoted from first-order to second-order valve -- technology does not directly control resource flow, it changes the operating environment by modifying other valve parameters (e.g., E-23 efficiency_rate). Old compute : knowledge-accessibility and talent-density sentinels use TECH_INFRASTRUCTURE label for traversal, but compute functions read static fields from node props -- first-order pattern. Gap : SECOND-ORDER CHARACTERISTIC NOT IMPLEMENTED -- current implementation reads edge attributes -> computes score in first-order mode. The 42-edge required second-order effect (e.g., tech_level raises -> E-23 efficiency_rate +5%) is not modeled. Impact : 2 sentinels can detect "technology exists" but cannot answer "what did technology buy us" -- precisely the value of second-order valves. Fix : TECH_INFRASTRUCTURE edge traversal results must include affects_edge and affects_param fields. Compute needs two steps: read second-order edge first, then read affected first-order edge params. 3.5 CROSS_FUNCTIONAL_SYNERGY (E-28) <- COUPLES 42-Edge Definition : Extended from coupling to causal coupling with self-reinforcing loop detection. coupling_strength stays but adds reinforcement loop detection. Old compute : computeCouplingStrength() computes Pearson correlation on marginal_contribution time series, determines direction via cross-correlation lag analysis. Well-implemented but uses old marginal_contribution input. Gap : ZERO CONSUMPTION -- compute exists and is well-designed, but no sentinel aggregate.ts imports or references it . The self-reinforcing loop detection also not implemented. Impact : Coupling logic exists but is invisible to the diagnostic pipeline. compute-coupling-strength.ts is in shared/computes/l2-value/ but zero sentinels consume it. Fix : Wire to sentinels that deal with cross-activity dependencies (routine-diffusion, internal-transaction-cost, business-model-coherence). Add self-reinforcing loop detection using 3-period inertia check. 3.6 ASSUMPTION_LINKAGE (E-42) <- EXTERNAL_ASSUMPTION 42-Edge Definition : Changed from an "edge" to a "cross-valve linkage" -- assumption monitoring triggers capital allocation adjustment.
