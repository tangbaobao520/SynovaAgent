数据目录注册 | 首次启动检查清单 | 2026-07-13 1.1 部署模式声明 Synova以 本地部署 为核心产品形态。引用安全规范第一章（部署模式对比），不重复定义。本文档仅聚焦本地部署的工程规范。 1.2 双进程架构 维度 后台进程 (Headless) 桌面UI (Electron) 运行时 Node.js 22+，独立进程 Electron渲染进程 + Node.js主进程 职责 诊断管线、哨兵扫描、数据接入、LLM推理、HTTP API服务 用户交互界面：对话窗口、诊断报告、GA工作台、状态栏 升级方式 蓝绿热替换（fork新版本→原子切换→旧进程退出） 冷替换（下载→通知→退出→替换→重启） 用户感知 无感知（后台静默完成） 有感知（显示"更新就绪"提示，用户点击重启） 通信方式 HTTP API (localhost:未占用端口) + IPC (Electron ipcRenderer/ipcMain) 1.3 安装包规范 平台 格式 大小目标 内容 Windows 10/11 MSI安装包 Electron桌面端 + Node.js后台进程 + SQLite运行时 + 初始行业模板 macOS 13+ DMG磁盘映像 同上。需公证(Notarization) Linux (Ubuntu 22.04+, Debian 12+) AppImage 同上。不依赖系统包管理器 1.4 数据目录注册规范 这是"双击恢复"成为可能的关键基础设施。 安装时必须将数据根目录写入以下标准位置。恢复包执行时首先读取此路径，然后将文件释放到正确位置。 平台 注册位置 默认数据路径 Windows HKCU\Software\Synova\DataPath (注册表) C:\Users\{user}\AppData\Local\Synova\data\ macOS ~/.synova/data-path (文件) /Users/{user}/Library/Application Support/Synova/data/ Linux ~/.synova/data-path (文件) /home/{user}/.local/share/Synova/data/ 数据目录结构： data/database.sqlite — GraphStore + SessionStore + SentinalStore + AuditStore（单文件SQLite WAL模式） data/config.yaml — 哨兵阈值配置、LLM密钥引用（不存明文密钥，引用credential-vault）、企业GA信息 data/baselines/ — 哨兵基线文件（每个哨兵的历史基线快照） data/backups/ — 本地恢复包临时存放（推送前） data/logs/ — 应用日志和看门狗日志 1.5 首次启动检查清单 # 检查项 验证方式 失败处理 1 SQLite数据库 创建/打开 data/database.sqlite，执行 PRAGMA integrity_check，开启 WAL模式 失败→弹窗提示"无法初始化数据库，请检查磁盘空间和权限" 2 LLM连接 使用配置的API key调用一次最小模型（如deepseek-chat），验证响应正常+记录延迟基线 失败→弹窗提示"API密钥无效或网络不通"；可进入离线模式（仅界面可用，诊断不可用） 3 哨兵基线 如果恢复包中有基线数据→加载；如果全新安装→创建空基线文件，标记为"等待数据积累" 无数据→正常。哨兵在数据积累到≥10个数据点后自动激活 4 GPI初始快照 如果已有财务数据→计算GPI初值；如果没有→GPI=null，标记"待数据接入" 无数据→正常 5 看门狗注册 注册为OS服务（Windows Service / macOS LaunchAgent / Linux systemd user unit） 失败→弹窗提示"无法注册后台服务，系统重启后需手动启动"
