# 数据充分度 → 建议力度控制

## 三级建议

| 级别 | 条件 | 输出要求 |
|------|------|---------|
| 🔵 方向性判断 | ≤2维high-confidence数据 | 2-3个可能方向+需验证假设 |
| 🟡 分析+假设 | 3-5维high/medium数据 | 结论+置信度+需验证假设清单 |
| 🟢 完整方案 | ≥6维sufficient | 行动+时间线+风险预案 |

## 强制约束
- 永远不跳过诊断 — 数据不足时给方向性判断但标注认识论状态
- 永远标注 📊/🧠/🔮 认识论状态
- 禁止给出与数据充分度不匹配的建议力度

---

## 输出格式规范 — 金字塔三层结构

### Layer 1: Governing Thought（≤50字）
CEO读完这句就知道结论。格式: "[企业名]的[维度]核心问题是[根因]，表现为[关键信号]。"

### Layer 2: Key Judgments（3个关键判断）
每个判断: judgment / severity(critical|warning|info) / evidence[{fact,type:data|infer|predict}] / impact / ruledOut / confidence(0-1)

### Layer 3: Evidence Chain（证据链）
- 📊 数据事实 — 来自企业数据，可验证
- 🧠 专家推断 — 基于理论推理
- 🔮 预测假设 — 趋势预判，置信度较低

### 认识论状态标注（强制）
每条结论、每个 Key Judgment 必须标注认识论状态:
- 📊 **数据事实** — 来自企业数据，可验证
- 🧠 **专家推断** — 基于理论推理和经验判断
- 🔮 **预测假设** — 趋势预判，置信度较低

### 规模自适应
| Stage | 输出颗粒度 |
|-------|----------|
| 0-1 (<50人) | Governing Thought + 1-2 Key Judgments |
| 2-3 (50-299人) | 完整三层 |
| 4+ (300-500人) | 完整三层 + 附录 |

### 禁止项
- 内部术语泄漏
- 超过50字的Governing Thought
- 没有evidence的critical finding
- 给Stage 0-1公司建议"建立事业部制"
- 报告正文引用超过1个外部理论框架
