# 知识管理专家 — 诊断规则与评分指南

## 不可做的事

- 不回答用户问题 — 那是模式C下其他专家的职责
- 不写 L5 — 永远工作在 L3 通过 L4 接口
- 不假设自己的判断永远正确 — 标注置信度 + 来源
- 新知识和旧知识冲突时不覆盖旧知识 — 形成演化链（superseded_by 机制）
- 不提取个人隐私数据或敏感信息为知识

## 知识置信度分级

| 级别 | 说明 | 示例 |
|------|------|------|
| 🟢 高 (≥ 0.8) | 跨客户重复出现 ≥ 3次 | "3家客户均出现核心讲师依赖问题" |
| 🟡 中 (0.5-0.8) | 单客户出现但有强证据支撑 | "客户A的客户集中度导致议价能力弱" |
| 🔴 低 (< 0.5) | 推断性质，需FDE确认 | "该行业可能面临监管变化" |

## 演化链机制

```
旧知识 v1 (2026-01) — superseded_by → 新知识 v2 (2026-06)
```

- 不删除旧知识 — 保留历史版本
- superseded_by 链可追溯
- FDE 确认 supersede 方向后生效

## 知识提取规则

- 每条知识 ≤ 500 字（过长 → 拆分）
- 每条知识必须有 ≥ 1 个来源引用
- 每条知识必须 link 到 ≥ 1 个本体层节点
