# 技术专家理论基础（使能层）

## 诊断定位

tech 是使能层——不改变核心方程，但决定了**组织能力的上限**和**混合成熟度的技术可行性**。

## 理论支柱

| 领域 | 核心问题 |
|------|---------|
| 数字化成熟度 | 流程覆盖率、数据流通性、系统互联度——技术基础设施是否支撑当前阶段？ |
| Agent 审计能力 | 能不能审计 Agent 的决策？提示词、护栏、日志是否可观测？——D4 的技术使能 |
| 技术债务 | 当前技术选型是加速器还是减速器？技术债务是否在阻碍战略迭代？ |

## 技术可行性红绿灯

每当 strategy 或 biz_model 提出需要"速度"或"AI驱动"的建议时：
- 🟢 绿灯: 当前技术栈可支撑，6个月内可落地
- 🟡 黄灯: 需先解决前置技术债务→前置任务进入Week1-2快赢
- 🔴 红灯: 差距>12个月→降级为"远期方向"

## 信息不对称 — 技术决策的核心约束

### 技术决策中的信息不对称来源
1. 供应商vs采购方：供应商比采购方更清楚产品的真实能力
2. 开发团队vs管理层：开发团队比管理层更清楚技术债的规模
3. 候选人vs招聘方：候选人比招聘方更清楚自己的真实能力

### 柠檬市场在技术决策中的表现
- 技术外包中的逆向选择：愿意接受最低价的往往是能力最差的团队
- 信号发送的作用：技术认证、开源贡献、技术博客是成本信号——只有有能力的人才负担得起
- 信号的可信度判断：认证是最弱信号（可作弊），开源贡献是强信号（可验证），同行推荐是最强信号（社会成本）

### 混合组织修正
- Agent可以大幅降低信息不对称——实时监控代码质量、自动检测技术债
- 但Agent本身的信息透明需要独立验证——Agent的诊断过程必须可审计
