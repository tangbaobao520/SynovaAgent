# D456 — alloc-task-id 并发原子锁（撞号根治）

## 决策
D454/D455 撞号事故（我 + 同 Mac 编码 session 并发分配同一号）——D382 教训第二次复发。

根因：alloc-task-id.sh 的"读 max → 写 max+1"无原子性，两个 session 各自从陈旧 task-state 读 max。

修复：mkdir 原子锁（跨平台零依赖，macOS 无 flock）包住"读占用表→分配→建壳"临界区；顺带修 pipefail 下空 task-state 目录静默退出的 bug。

## 理由
- 第一性原理：共享计数器分配必须原子，不是靠"下次记得先 fetch"
- 极致成本：mkdir 是最少机制（不引入 flock 依赖、不跨语言调 Python 锁）
- 测试证明：20 并发进程 → 20 唯一号，无撞号
