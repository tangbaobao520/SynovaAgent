# D525+D526 红态清理 + canary 漂移告警 — 决策与教训

> 状态: implemented | 日期: 2026-08-25 | 决策: 测试对齐现行为而非复活旧代码 + 漂移曝光而非全量密封 | 理由: K3 D521 审计遗留闭环

## 决策

1. **D525 测试重写方向**：D507 内联门禁段在 D508 已移除（职责 → D311 staging_guard + D515 task-start 拦截）——修测试对齐现行为，不复活旧代码。行为断言（沙箱实测 block/pass/降级）替代纯 grep，含金量高于原版。
2. **D526 漂移=曝光而非清理**：存量 47 项漂移即刻用 ::warning 曝光；全量密封化是 K3 P2-4 单独立项（多数测试非 hermetic，盲目入 canary 会炸 CI）。本批只纳入 hermetic 的 synova-commit.test.sh + check-canary-drift.test.sh。
3. **staging_guard 不吃 SYNO_CT_DIR**：它从脚本位置解析 registry——沙箱隔离必须整目录复制 scripts/（REPO_ROOT=沙箱），env 注入对它无效（与 session_registry CLI 行为不一致，值得后续统一）。

## 教训

- 测试场景间要清理暂存区（②的 foreign 文件留在 index 会让③的"误拦"变成正确行为——断言语义被场景污染）。
- 路径规约 bug 成对出现：注入缝改了 find 的根，就要同步检查所有 `-f`/sed 的根（ALL 和 GHOST 两处同 bug）。
- 拼接字符串计数前先 `printf '%b'` 展开——字面 \n 会让 grep -c 恒 1（漂移数量报 1 实为 47）。
