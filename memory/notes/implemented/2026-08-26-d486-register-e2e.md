## 一、真实 server e2e 模式沉淀

**运行契约**（测试文件头注释为准）：
```bash
PORT=3099 JWT_SECRET=d486-e2e-test-secret DEV_MODE=true SYNOVA_DB_PATH=./data/e2e-scratch.db npx tsx src/index.ts
npx vitest run tests/e2e/auth-register-flow.e2e.test.ts
```

**关键点**：
1. **显式 JWT_SECRET 是断言正确性的前提** — DEV_MODE 自动 admin 只在无 secret 时触发；阶段①的"无 token → 401"断言天然抓住环境配置错误（自动 admin 环境会 200 而非 401，测试红在未预期处）。
2. **探活优于盲 skip** — customer-flow 用 fetch catch 静默 skip；本切片用 GET /api/healthz + AbortSignal.timeout(3000) 区分"server 未启动"（skip）与"请求失败"（fail），探活结果驱动 ctx.skip()，显式而非空跑。
3. **探测端点选型**：
   - 首诊入口：POST /api/diagnosis/consult + token + 空 body → 400 VALIDATION_ERROR（diagnosis.ts 同步校验在 SSE writeHead 之前，验证 token 穿透认证层 + 路由真实到达，零 LLM 成本）。
   - 企业端点可达（staff）：GET /api/enterprise/status（members 需 admin，staff 会 403，不能作为可达证据）。
4. **时间戳 email** 隔离重复运行（scratch DB 409 DUPLICATE 防污染）+ 专属 scratch DB（不碰真实 dev 库）。

## 二、事故记录（本次交付踩坑）

1. **worktree finish 必须在主树执行** — 在 worktree 内跑 `worktree-manager.py finish`，--repo 默认取 CWD（=worktree 自身）→ merge 变"合并进自己"（no-op 报成功）→ worktree remove 后 branch -d 在死目录解析到父级仓库 → "not found"。**补救：主树手动 FF merge + 分支/目录/registry 清理**。教训：synova-commit 输出"回主 worktree 执行 finish"的字面提示就是字面意思。
2. **worktree 提交的 COMMITTED 记录随 worktree 删除** — synova-commit 写的 bypass.log 记录在 worktree 内，finish 后消失 → 首次 push 被 D331 对账硬拦（"缺 b036d380 记录"）。**补救：主树 bypass.log 追加 worktree 提交补记**（D356 同先例）。
3. **主树并行会话脏文件挡 merge** — 并行 CTO 会话正在编辑 .claude/.dsh skills（未提交），git merge origin/main 拒绝覆盖。**解法：detached worktree（git worktree add --detach <base>）内做 merge + push HEAD:refs/heads/feat/**，零接触主树脏文件。本仓库禁止 stash（并行 stash 事故先例）。
4. **CRLF 归一化噪音** — detached worktree checkout 后 tests/*.sh 全文件"M"（autocrlf 归一化），非真实改动，push 的是 merge 提交树不受影响。
