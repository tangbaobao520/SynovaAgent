理由: D665 期间实证：`git commit -m msg -- <pathspec>` 走 git 部分提交机制，对匹配路径用**工作区内容**内部重算（内部 add）。当路径满足「索引已删除 + .gitignore 命中 + 磁盘仍存在」（D665 摘除 gitlink 的真实形态）时，内部 add 因该路径 ignored 而跳过 → 删除不进提交；批次里其它路径确有变更 → git 仍 exit 0 报「提交完成」→ 提交后 git 用新 HEAD 回填这些路径的索引 → **暂存态被静默销毁**。后果：`9aabd581` 提交消息声称摘除 10 个 gitlink，实际 `git ls-tree -r HEAD | grep -c '^160000'` 仍为 10（M2 族第三次）。

## 决策

1. **提交原语 = 索引精确提交**：`git commit`（无 pathspec、无 `-a`）。逐字提交索引，天然携带删除项，且不吸收工作区未暂存变更（D311 M1b「防误提交工作区杂散文件」的原始诉求由「不用 -a」满足，不依赖 pathspec）。
2. **前置断言**：`--files` 模式下 staged ⊆ FILES，越界即 fail-closed 并点名（保住 D329 防「--files 洗白他人暂存」语义）。
3. **提交后不变量校验**：`暂存声明集 == 实际提交变更集`（相对同一 base 的 `name-status`，两侧均禁 rename 检测）。不一致 → exit 1 + 点名差异 + **撤销该提交 + 还原索引**。
4. **`git add` 逐路径容错**：「被 .gitignore 命中且索引中已是删除态」的路径跳过 add（索引即声明），其余失败照旧硬阻断。

## 为什么「报告失败但提交已进历史」比不拦更危险

初版只在提交后比对并 exit 1，沙箱实证暴露：`git commit` 已经落地（`[main 9e7e483] …`），
调用方收到 exit 1 却有一个坏提交进了历史 → **假阻断**。故不变量失败必须 `git reset --soft <pre>`
撤销（含 post-commit hook 的「登记影子提交」，按父子结构判定真实提交，不 sniff 提交消息文案）。

## 为什么根因不在「失败回滚路径」（推翻派单初判）

派单假设「缺陷在失败回滚路径」。实测证伪：门禁失败分支只在 `:763` 追加 bypass.log 后 `exit 1`，
**不触碰索引**；跨调用复现证明拒绝后暂存态完好（测试断言 ⑥ 第一段）。丢失发生在**成功路径**：
提交真的完成且 exit 0。「沙箱证明 pathspec 可携带删除项」之所以成立，是因为那个实验的路径
**未被 .gitignore 命中**——ignored 与否正是分水岭。

## 为什么拒绝「只测不修」

只加不变量校验（选项①）会把静默腐败换成**每次提交都红**，用户仍无法提交合法摘除。
只改原语（选项②）则无法防御「未知的第三种丢失形态」。故取组合（选项③）：
原语修复负责「不再丢」，不变量校验负责「万一丢必被点名且不丢证据」。
