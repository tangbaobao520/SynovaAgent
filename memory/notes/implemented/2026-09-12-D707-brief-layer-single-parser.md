## 决策

1. **一个语义只允许一个实现**：组 6 架构层段改调 `python3 brief_parser.py --layer`
   （与 `pre-commit-check.sh:1234` 既有的 `--q2-include/--q2-exclude` 用法一致），删除 awk 第二实现。
2. **`parse_layer` 改精确规则**：标题行内联值优先且**不跨行**；否则向下取首个非空非注释行；都没有 → 未填写。
3. **不保留 awk 回退**：回退实现自身就会漂移（实测 `## 架构层：X` 全角冒号在 awk 下解析失败、
   解析器正常）。python3 不可用时显式降级跳过 + 登记 `degraded-events.log`（语义对齐
   `check-brief-parseable.sh` 既有约定），不静默判「未填写」（假红）、也不静默放行（假绿）。
4. **不改 D660 brief**：派单原建议「顺手 1 行修复」该 brief 的内联写法。实测内联写法有 232 份，
   改 1 份属治标；且改 brief 会让「写 brief 的人必须记住某个隐性格式」重新变成负担。
   根因在校验器，改解析器才是治本。

## 顺带修掉的第二个缺陷（派单未列，实测发现）

旧正则 `^## (架构层|本任务在哪一层)\s*[:：]?\s*(.+)$` 中 `\s*` **会吃掉换行**，
`(.+)` 于是匹配到下一个 `## 标题` 行 → **空架构层被判定为「已填写」**：

```
## 架构层:
## 文档引用          ← 旧正则把这一行当成架构层的值
```

实测：`## 架构层:` + `<!-- 待填 -->` → 旧实现报 `<!--待填-->` 为值 → `check-brief-parseable.sh`
判 PASS。**这是 fail-open（假绿）**，比误报更危险。新规则下两种负例均判未填写。

## 为什么这是 M7 族而不是一次普通 bug

M7 = 文档-实现漂移。此处是**实现-实现漂移**：`check-brief-parseable.sh` 头注释自称
「同源解析器（brief_parser.py）」，D313 M3 建它的目的就是同源；组 6 的 awk 恰好违背该设计。
只修暴露的那一处（内联写法）会留下第二处（空值假绿）与无限个未暴露处——
故收敛实现而非修补口径。
