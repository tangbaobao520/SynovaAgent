# PR 预算门禁（D734）

## 触发场景

2026-09-13 CTO 派单 §二背景：**冲突概率 ∝ 改动大小 × 分支存活时间**。
实证两例：① D721 一个 PR 同时背三类门禁问题，挂半天；② K3 审计分支落后 main，合入时差点回退他人成果。
当时没有任何机器约束这三件事 —— PR 多大、跨几个域、落后 main 多少，全靠人看。

## 决策内容

1. **三条判定**（`scripts/control-tower/check-pr-budget.sh`，三态退出码 D328）：
   - ① 变更文件数 ≤ `--max-files`（默认 12）；
   - ② 变更只落一个域 —— **复用 D733 的 `check-ownership.py` 单域模式**，不重写域判定；
   - ③ 落后基线提交数 > `--max-behind`（默认 20）→ ⚠️ 告警但不阻断（防「落后分支直接合」，与 D334 门禁 0-1 同源）。
   `0` 在预算内 / `1` 超预算（超文件数或跨域）/ `2` 检查执行失败（域校验器缺失、python 不可用、变更集算不出）。
2. **接入点 = pre-commit 附加检查块，不并入 13 组编号。** 两条理由：
   - 派单红区已明列 `.github/workflows/ci.yml`（#520 刚改过）→ 派单给的「CI quality job」选项不可用，只剩 pre-commit；
   - 改总组数会打破 `tests/control-tower/fastlane-bypass-only.test.sh` 对快速通道横幅「跳过 12 组」的断言，而该文件**不在本任务写集白名单内**（创始人硬要求「写集白名单外一律不动」）→ 以额外命名的检查块接入，组数与横幅语义均不变（有测试断言守住这条）。
3. **判定用 `soft_check`**：对齐 V5.0.0「本地软提示 + CI 权威」（SYNO_CI=1 转硬），与同文件内其它软检查一致。
4. **基线解析链 + 显式降级**：`--base` → `origin/main` → `main` → `origin/HEAD`；全不可解析 → ⚠️ 显式留痕 + 跳过（exit 0），**不 exit 2**。沿用 pre-push 门禁 0-1 对「fetch 失败」的既有语义（显式提示、不静默跳过），避免环境性缺 ref 把所有 PR 误打成红。
5. **`domain_neutral` 豁免是前置条件（记在 D733）**：`.claude/bypass.log` 出现在**每一个**分支（D521 hook 自动登记），各线的 task brief 又都解析为 mac —— 不做豁免，本门禁的单域判定对每个 PR 都误报跨域，等于虚设。实测见 D733 Note。

## 实测踩到的坑（免疫细胞候选）

**D370 bash + 中文变量边界**：`echo "… $OWNERSHIP（D734 …"` 里全角 `（` 紧贴变量，bash 在 UTF-8 locale 下把 `（` 当变量名字符 → `set -u` 下 `unbound variable`。
阴险之处：**只在失败路径触发**（正常路径不执行该 echo），所以正常跑全绿、一到要报错就崩 —— 门禁最需要说话的时候哑掉。
本任务由测试（§6 域校验器缺失用例）抓到，已全量修 `${VAR}` 并加扫描确认残留 0。
→ 建议：新增/修改 scripts/control-tower 脚本后跑一次「`$VAR` 紧贴非 ASCII」扫描（可脚本化，铁律 35）。
