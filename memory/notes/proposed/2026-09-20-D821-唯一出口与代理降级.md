决策: 出站 HTTP 收敛为**唯一出口** `src/providers/http-exit.ts`（本仓唯一读代理 env 的文件）：解析顺序＝目标 scheme 变量 → `ALL_PROXY` →（仅 https）`HTTP_PROXY`，env **调用时读取**；loopback（`127.0.0.0/8` 整段含 `127.0.0.2`、`::1`、`localhost`、`*.localhost`）**恒绕过**；`NO_PROXY` 支持 host/host:port/`.suffix`/IPv4 CIDR/`*`；`socks5://` 等不可用值 → `degraded=true` + 直连（**不阻断启动**）；代理不可达 → `OutboundHttpError{code:'PROXY_UNREACHABLE', degraded:true}`，**禁止静默直连回退**；出口**不做重试**（重试归既有韧性层）；零新依赖、返回真 `Response`。
理由: ①**第一性原理**——企业内网"能装上"的前提是出网只有一条路；出站解析分散在 providers/connectors/tools/deploy 四层 25+ 处裸 fetch，等价于"有时走代理有时不走"，是前提清单第 1 项（客户内网装不上 = 全盘归零）的根因面。②**Anthropic 工程基线（fail-closed）**——声明了代理而代理不可达时必须报错：静默直连会让客户以为流量过了合规网关、实际绕过了它；降级必须显式 `degraded:true` + `reason`（铁律 11/24/31）。③**开源实证**——`@deepseek-ai/dsh-http-proxy`（lib/index.js 536 行 / lib/types/policy.d.ts 135 行）实证了三条语义：解析顺序（:237-259，注释自陈 "matching undici"）、loopback **整网段**而非四字面量（:185-186 全段正则 + :192-195 注释自陈"只匹配四个字面量会漏掉 127.0.0.2"）、不可用值降级不阻断（:88-110，SOCKS 五种协议 :48-52 记诊断后直连）；同时实证其**不支持** CIDR（:207-213 注释：需改写为后缀）与 SOCKS 真转发 → 我方按 ①范式复用语义 + ③自建补齐 CIDR 与结构化 `ProxyStatus`。④**收敛检查**——三条同向指向"唯一出口 + 显式降级 + 不可达即失败"，无一条支持静默回退。⑤**零新依赖**是本仓硬约束（G1 守卫 `grep "@deepseek-ai" src/ packages/` 保持 0；package.json 18+18 依赖中无 undici/node-fetch/axios/socks）；本机 Node `v22.22.0`，`NODE_USE_ENV_PROXY` 零依赖路线未核实（D818 §3 结论未落盘）→ 取③自建（`node:http`/`node:https` 显式路由，不做 undici 全局 dispatcher 劫持）。
