# D1013 号段水位实测反查 + 对账探针

任务: D1013（task-state/D1013.json，状态 in_progress）

## 背景

三条实测事实（命令与原始输出见交付回执，不转述）：

1. **水位无单一事实源**：`docs/synova/coordination/号段水位.md` 不在 `origin/main`，
   但已存在于 7 条已推分支；其内容为**分段制**（Mac=D9xx / Win=D1000–D1099），
   并已记过一次「CTO 跨段取号 ⇒ 四卡改号」的更正记录。
2. **取号器占用表读取面 ≠ 真实占用面**：`alloc-task-id.sh` 自陈（:32-37）ls-remote
   只喂发号前校验、不喂「下一个号」计算表；号表实读 本地 `task-state/` ∪ `origin/main`，
   而 `origin/main` 的 task-state 只到 **D964**。全 refs 实测最大号为 **D1007**
   （随后批次推进至 D1008）⇒ 取号器算出的 NEXT 会落在已被占用的号上。
   其拒绝判定（`_occupied_check`）只匹配**分支名/目录名**中的 `d<num>`（:197-217），
   **不读其他 worktree 的 task-state 内容** ⇒ 拒绝面比读取面窄。
3. **取号器在本工作区 >25s 无输出**（干净 clone 8s 返回）：根因是 D576 worktree 扫描段
   `:295` 的 `WORKTREE_USED="${WORKTREE_USED}${n}"` 逐号字符串累加 —— bash 循环内
   字符串拼接是 O(n²)；规模因子 = Σ 各 worktree 的 `task-state/D*.json` 文件数
   （本机实测 249 worktree / 69484 文件）。脚本自身 D940 注释（:286-289）已记「该循环实测 258s」，
   并明写「WORKTREE_USED 累计展开等其它噪音不在本卡」——即 O(n²) 被**已知并搁置**。

## 决策

1. **水位文件双区结构**：生成段（由 `--emit` 按实测产出，含生成命令/时间戳/覆盖警告）
   + `<!-- MANUAL:BEGIN/END -->` 人工段（号段约定、保留号段、下一号声明，不被覆盖）。
2. **判定面 = union**：面 A（`refs/heads` ∪ `refs/remotes/origin` ∪ `refs/remotes/ssh`，按 SHA 去重）
   ∪ 面 C（当前工作树 `task-state/`）。理由：只扫 refs 会漏「正在途中的占号」。
   面 B（仅 origin 已推）与 PR 标题面只作对照，不作判定面。
3. **三态 fail-closed**：0 一致 / 1 DRIFT（实测 > 声明 ⇒ 撞号风险；或 声明 − 实测 > 保留窗口
   ⇒ 水位虚高会让判据①永不成立，防手改绕过）/ 2 无法测量（水位缺失、无声明行、零号、git 不可用、无 Python）。
4. **取号器只登记不修**：根因修复（O(n²) 累加 + 号表读取面扩展）属另一张卡，本卡不扩写集。
