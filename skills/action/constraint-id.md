# 约束识别与行动计划

## 触发条件
- 所有诊断专家完成诊断后自动触发
- 对话中出现"优先级"、"瓶颈"、"最该做什么"等关键词
- GA 要求生成行动方案时

## 前置依赖
- strategy 诊断输出: 战略质量得分
- biz_model 诊断输出: 模式体质得分
- org 诊断输出: 组织能力得分 + 混合成熟度得分
- finance + marketing 验证层输出: 是否与核心诊断矛盾
- 如果任一输入缺失 → 标注"部分诊断未完成"，仅对已有数据做约束识别

## 执行流程

1. **提取四个乘数得分**:
   - 战略质量 = strategy.score × biz_model.score 的加权平均
   - 组织能力 = org 杨三角评分
   - 混合成熟度 = org D1-D6 综合评分
   - 战略组织咬合度 = 1 − |S_req − O_actual| / max(两者)

2. **识别约束**:
   - `Bottleneck = argmin(战略质量, 组织能力, 混合成熟度, 战略组织咬合度)`
   - 如果两个乘数得分相近（差距 < 0.1）→ 标记为"双约束"，需更多数据区分优先级

3. **验证约束**: 调用 `cross_validate`
   - finance 的数据是否支持"这是真正的瓶颈"？
   - marketing 的数据是否提供了一致的信号？
   - 如果验证层与核心诊断矛盾 → 启动矛盾升级协议 → 标注置信度降级

4. **生成 Plan A**: 解决当前约束的 90 天行动方案
   - Week 1-2: 快赢（momentum builder）——不需要新增资源、2周内可见效
   - Week 3-6: 核心行动——直接针对约束的干预
   - Week 7-12: 系统建设——防止约束复发的机制
   - 每条行动有: owner + timeline + 量化目标 + first step

5. **生成 Plan B**: 如果 Plan A 失败，3个月后启动的备用方案
   - 假设当前约束判断是错误的 → 次弱乘数是什么？
   - 针对次弱乘数的行动方向
   - Plan B 不展开到 Week 级别 → 只给方向性建议

6. **双轨一致性检查**:
   - 如果 Plan A 和 Plan B 指向完全不同的方向 → 当前诊断置信度不足以选出一个最优约束
   - 不强行选一个 → 降级置信度，标注"需更多数据以区分约束优先级"

## 输出规范
- 格式: 结构化 Markdown
- 必须包含:
  - 四个乘数得分 + 约束识别结果
  - Plan A: 90 天行动方案（Week 1-2 / 3-6 / 7-12）
  - Plan B: 备用方案（方向性建议）
  - 双轨一致性判断
- 质量标准:
  - 行动有 owner + timeline + 量化目标
  - 不列 20 条建议——Plan A 最多 3 条，Plan B 只给方向
  - Stage 0-1 时行动对象是创始人个人

## 反面案例

### 案例 1: 列了 15 条建议没有优先级
- **错误**: 综合所有专家的发现，列出了 15 条"你应该做的事"
- **后果**: CEO 看完不知道该做什么——15 条 = 0 条
- **正确做法**: 找到瓶颈 → 只给针对瓶颈的 1-3 条行动。其他问题如果不是约束，暂时不解决

### 案例 2: 对 20 人公司建议"建立事业部制"
- **错误**: 约束识别正确（组织能力是瓶颈），但建议完全不匹配规模
- **后果**: 客户觉得诊断不切实际
- **正确做法**: Stage 0-1 的行动对象是创始人，建议颗粒度是"你应该..."；Stage 3+ 才是"公司需要建立..."

## 边界
- **适用**: 所有完成诊断的组织
- **不适用**: 诊断未完成（输入不足）→ 标注"部分诊断未完成"
- **核心原则**: 高德拉特约束理论——只解决瓶颈。优化非瓶颈是浪费。
