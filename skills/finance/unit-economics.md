# 单位经济学分析

## 适用场景

客户商业模式涉及重复交易（订阅/复购/续费）时触发。一次性交易模式（如大型项目制咨询、房产交易）使用毛利率 + 项目利润率分析替代 LTV/CAC。无客户级数据时，标注"数据不足以支撑单位经济学分析"。

## 方法步骤

1. 从收入数据分离出客户数量、客单价、复购率/续费率
2. 计算 CAC（总获客成本 ÷ 新客数），区分付费获客 vs 自然流量的 CAC
3. 计算 LTV（客单价 × 毛利率 × 客户生命周期月数），使用实际留存率而非假设
4. 调用 `unit_economics` 工具输出 LTV/CAC 比值、毛利率、边际贡献率
5. 对照 RULES.md 基准判断健康度：LTV/CAC ≥ 3 🟢，1-3 🟡，< 1 🔴

## 输出格式

```
LTV: ¥7,200 (月均客单价 ¥200, 毛利率 60%, 平均生命周期 60 个月)
CAC: ¥2,400 (仅计付费渠道, 含 SEM+信息流)
LTV/CAC: 3.0 → 🟢 健康 (刚好跨过门槛)
毛利率: 60% → 🟢 行业健康 (同行业均值 55-65%)
边际贡献率: 45%
趋势: CAC 过去 6 个月上升 20% (渠道竞争加剧), LTV 持平
数据覆盖: 最近 12 个月, 样本量 3,400 客户
```

## 判断标准

- LTV/CAC < 1 → 🔴 每获一个客户都在亏钱，立刻检查能否优化 CAC 或提升 LTV
- 毛利率 < 30% → 🟡 低毛利业务，如果 LTV/CAC 健康可接受，否则需关注
- CAC 连续 3 个月上升 + LTV 未同步上升 → 🟡 获客效率恶化信号
- 自然流量 CAC 为 0 时标注"自然流量"，不计入 CAC 计算但需标注占比
- 实际留存率 vs 声称留存率差异 > 20% → 标注"留存数据可能被美化"

## 常见陷阱

- 用假设留存率代替实际留存率——声称的"95% 续费率"可能只计算了主动取消，忽略静默流失
- 忽略客户分层——不同渠道来的客户 LTV/CAC 可能相差 5 倍以上，必须分渠道计算
- 把一次性合同按订阅模式算 LTV——项目制合同的复购不是自动续费，不能假设延续
