# 反共识检索

## 触发条件
- 所有已激活专家（≥ 4 位）的诊断结论方向一致，且没有任何 critical 级别的发现
- 系统自动检测到"全票通过"状态 → 静默触发此 skill
- 不等待用户指令——这是 AI 原生的主动发现能力

## 前置依赖
- ≥ 4 位专家的诊断输出
- knowledge/ 目录下的行业知识和案例库

## 执行流程

1. **检测全票通过状态**: 统计所有专家的 findings 严重度分布
   - 如果 critical = 0 且 warning ≤ 1 → 可能进入了"一切正常"的舒适区
   - 如果所有专家的 conclusion 方向高度一致（余弦相似度 > 0.8）→ 可能集体盲区

2. **检索共识失败案例**: 在 knowledge/ 中搜索
   - 关键词: 该企业所在行业 + "衰落"、"被颠覆"、"破产"
   - 历史上被颠覆前内部诊断都是"我们做得很好"的企业（柯达、诺基亚、黑莓、西尔斯百货）
   - 当前行业中被主流忽视的逆向观点

3. **生成魔鬼代言人简报**:
   - "以下是 N 位专家一致认为的结论。"
   - "以下是历史上 M 个'专家都这么认为——直到事实证明他们都错了'的案例。"
   - "这不是说专家错了——这是提醒你，共识本身可能是一个信号。"
   - 如果找到 ≥ 2 个相关案例 → 推送简报。如果 < 2 个 → 不推送（避免噪音）

4. **推送时机**: 不在对话中打断——在诊断报告末尾附上，或在 Phase 2 假设验证时提示

## 输出规范
- 格式: 简报（briefing，≤ 500 字）
- 必须包含:
  - 当前共识摘要（2-3 句话）
  - 2-3 个相关历史案例（每个 ≤ 100 字）
  - 1 个"魔鬼代言人"问题——"如果专家错了，最可能的错法是什么？"
- 质量标准:
  - 不质疑专家的结论——只提供"共识失败"的历史模式
  - 不强制推送——如果找不到相关案例，不强行编一个

## 反面案例

### 案例 1: 把反共识检索当作"专家错了"
- **错误**: 找到历史案例后，标记为"专家诊断可能错误"
- **后果**: 削弱诊断的可信度
- **正确做法**: 反共识检索不是质疑专家——它是"共识本身可能是一个信号"。简报的语气是"提醒"，不是"推翻"

### 案例 2: 找不到案例时强行编一个
- **错误**: 所有专家的判断可能是对的，但为了"全面"强行找一个不相关的案例对比
- **后果**: 无关案例增加噪音，稀释了真正有价值的历史对标
- **正确做法**: < 2 个相关案例 → 不推送。沉默也是输出

## 边界
- **适用**: 全票通过的诊断（≥ 4 位专家一致）
- **不适用**: 已经有 critical 发现、或专家间有明显分歧的诊断——此时不需要"魔鬼代言人"
- **推送阈值**: ≥ 2 个相关历史案例才推送
