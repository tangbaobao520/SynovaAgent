# JTBD 客户需求访谈分析

## 适用场景

有客户反馈数据（访谈记录、NPS 评语、退款原因、支持工单关键词）时触发。纯定量数据不足以做 JTBD 分析——需要客户的实际语言描述"为什么用/不用"。无客户语言数据时不输出 JTBD 结论。

## 方法步骤

1. 调用 `query_graph` 检索客户反馈数据，提取客户描述"任务"的语言片段
2. 按需求四层分类：未满足 / 未表达（行为暗示）/ 未创造（客户不知道可能）/ 已满足但不满意
3. 调用 `behavioral_economics` 工具识别反馈中的行为经济学模式（峰终定律、损失厌恶、锚定效应）
4. 对每条 JTBD 标注证据强度——"客户原话"、"行为数据暗示"、"纯推断"
5. 输出核心 JTBD 1-3 个 + 当前满足程度

## 输出格式

```
JTBD 1: "帮我快速生成可复用的报表模板"
  证据: 客户原话"每次做报表都要从头开始" | 满足: 🟡 部分满足
JTBD 2: "让团队不用培训就能上手"
  证据: "换了几次人，每次都要重新学" | 满足: 🔴 未满足
推荐: 优先 JTBD 2——NPS 中 60% 负面评价与此相关
```

## 判断标准

- "客户原话"级别证据须 ≥ 2 条独立反馈才能列为 JTBD
- "纯推断"级别不在输出中作为 JTBD 呈现——标注"需验证的假设"
- 识别到的 JTBD 能解释 ≥ 70% 的客户反馈 → 覆盖率达标
- JTBD 与已有产品匹配度——不匹配比例 > 50% → 建议重估产品方向

## 常见陷阱

- 把功能需求当 JTBD——"加导出按钮"是方案不是任务，真正的任务是把数据分享给老板
- 只听大客户——大客户需求不典型，标注"该需求主要来自 XX 客群"
- 忽略行为暗示——高频使用某功能可能比客户说的更真实
