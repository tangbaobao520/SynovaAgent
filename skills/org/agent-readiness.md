# Agent化机会识别矩阵

## 适用场景

传统组织诊断完成后触发。跳过传统诊断直接做 Agent 化识别是违规的——在不理解当前运作方式之前，无法判断哪些环节适合 Agent 化。

## 方法步骤

1. 列出客户核心流程（从传统诊断结果中提取），每流程为一行
2. 按四维度评分：任务结构化程度 / 数据可获取性 / 错误容忍度 / 增量收益（各 1-3 分）
3. 调用 `agent_readiness` 工具计算总分，按 RULES.md 分类：≥10 可替代 / 7-9 可增强 / < 7 暂不可
4. 调用 `collaboration_health` 评估流程间依赖——Agent 化一个流程如何影响上下游
5. 输出矩阵：可替代/可增强/暂不可三类，每类按收益排序

## 输出格式

```
[可替代] 客户对账(总分11)→规则明确+API可达+效率提升>50%
[可增强] 客服响应(总分8)→部分规则化+需人工抽查+效率提升30%
[暂不可] 战略采购谈判(总分5)→高度依赖判断+零错误容忍
优先: 客户对账 Agent化——释放 60% 人力,周期3天→4小时
```

## 判断标准

- 总分 ≥ 10 且增量收益 = 3 → 优先推荐
- "暂不可"类流程错误容忍度 = 1 且任务结构化 = 1 → 标注"长期关注"
- Agent 化后不能降低其他流程的 Bus Factor——否则标注"人员依赖风险未解除"
- 全部"暂不可"时检查传统诊断是否充分

## 常见陷阱

- 跳过传统诊断直接做 Agent 化识别——违规，会遗漏关键约束
- 低估任务结构化判断难度——看似规则明确的流程可能有大量隐性判断
- 只算效率提升不算风险——故障响应、数据隐私、合规必须纳入评估
