# 杨三角组织能力评估

## 触发条件
- org 专家被激活
- 团队规模 ≥ 20 人 OR 对话中出现组织/团队/人才/管理问题
- 任何规模的纯人组织能力评估都使用此 skill

## 前置依赖
- 企业基础数据（团队规模、组织架构、关键角色）
- 如有人力资源数据（离职率、绩效分布）→ 使用；如无 → 对话式采集

## 执行流程

1. **员工能力（会不会？）**: 关键岗位有对的人吗？
   - 检查: 技能矩阵 → 关键岗位的匹配度？学习能力？
   - 识别: 单点故障——哪些能力只有一个人掌握？（busFactor = 1）
   - 判断: 人才密度够不够支撑战略目标？
   - 调用: `query_graph` 获取组织数据；如果 busFactor 信号触发 → 自动衔接 `bus-factor` skill

2. **员工思维（愿不愿？）**: 员工为什么努力？
   - 检查: 激励机制 → 激励的信号方向是什么？（鼓励什么行为？惩罚什么行为？）
   - 检查: 价值观对齐 → 员工做决策时，用的是公司的价值观还是自己的？
   - 判断: 激励和公司目标是否一致？有没有"激励A但期望B"的结构性矛盾？
   - 调用: `cross_validate` 与 finance 专家交叉验证（薪酬结构 vs 利润结构）

3. **员工治理（让不让？）**: 流程在帮人还是卡人？
   - 检查: 决策权分布 → 一线员工能做什么决定？需要几级审批？
   - 检查: 信息流通 → 关键信息是否到达需要它的人？还是卡在某个层级？
   - 判断: 流程是使能器还是枷锁？信息在流还是在堵？
   - 调用: `cross_validate` 与 tech 专家交叉验证（数字化是否改善还是恶化了信息流通？）

4. **综合评估**: 杨三角的健康度 = 员工能力 × 员工思维 × 员工治理
   - 三个因子的最低分决定整体得分（乘法逻辑）
   - 如果有一个因子显著低于另外两个 → 那就是当前的瓶颈

## 输出规范
- 格式: 结构化 Markdown
- 必须包含:
  - 三角逐项判定（每项: 🟢健康 / 🟡需关注 / 🔴瓶颈）
  - 综合评估: 三个因子的最低分（乘法逻辑——最弱的那个决定整体）
  - 单点故障列表: busFactor = 1 的角色 + 对应的风险
  - 激励-目标一致性检查: 有没有"激励A但期望B"的矛盾
- 质量标准:
  - Stage 0-1（<50人）时不使用"事业部制"、"流程再造"等大企业语言
  - 每项判定必须有数据支撑或明确标注"基于对话推断"

## 反面案例

### 案例 1: 把组织扁平等同于治理好
- **错误**: "组织扁平，所以员工治理好"——直接给高分
- **遗漏**: 组织扁平但创始人做所有决策 = 员工治理其实很差。信息流是堵的——所有信息必须经过创始人
- **正确做法**: 员工治理看的是"决策权是否在信息最充分的人手里"，不是看层级数量

### 案例 2: 给 20 人公司用大企业框架
- **错误**: 建议 25 人的公司"建立事业部制"、"设立人才发展中心"
- **后果**: 建议完全不匹配规模——客户失去对诊断的信任
- **正确做法**: Stage 0-1 的核心问题是"创始人一个人做所有决策"——从这个问题出发，不套大企业框架

## 边界
- **适用**: ≥ 20 人的组织。所有 Stage (0-5)，但测量方式和工具随规模调整
- **不适用**: 纯个体户（< 5 人且无雇员）——没有"组织"可诊断
- **注意**: 这是纯人组织能力的底盘诊断。如果组织中有 Agent 部署 → 继续衔接六维 D1-D6 技能
