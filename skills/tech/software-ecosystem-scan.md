# 软件生态扫描

## 适用场景

技术诊断开始时自动触发。必须在不了解客户软件生态之前不做任何工具推荐——铁律。客户可能不知道自己用了多少软件（SaaS 影子采购），所以除了问"你们用了什么"，还需要通过收入数据、人员岗位、业务流程反推。

## 方法步骤

1. 调用 `query_graph` 检索客户已录入的软件数据（从访谈、合同、飞书审批等来源）
2. 使用 RULES.md 中的 Agent就绪度评分表，对每款软件按四维度评分：API可达率 / 数据格式 / MCP支持 / 实时性
3. 分类为"原生适配"、"桥接适配"、"不可适配"
4. 调用 `software_ecosystem_scan` 工具输出生态地图——用表格列出全部软件 + 分类 + Agent就绪度
5. 标记软件间的数据流依赖关系（A 的数据是否输入 B，是否存在手工数据搬运）

## 输出格式

```
软件生态地图:
| 软件 | 分类 | API可达率 | 数据格式 | MCP支持 | 实时性 | Agent就绪度 |
|------|------|----------|---------|---------|-------|-----------|
| 钉钉 | OA | REST API | JSON | 可自建 | 推送 | 桥接适配(6) |
| 用友 | ERP | 部分API | 需转换 | 不支持 | 轮询 | 桥接适配(5) |
| Excel | 手工 | 无API | 手动 | 不支持 | 手动 | 不可适配(0) |
数据流依赖: 钉钉审批→手工搬运→用友记账 (人工搬运环节)
桥接建议: 用友建议自建 MCP Server 或 RPA 适配
```

## 判断标准

- Agent就绪度评分阈值：≥8 原生适配 / 5-7 桥接适配 / <5 不可适配（四维度各 0-3 分：API可达率、数据格式、MCP支持、实时性）
- 扫描覆盖客户 ≥ 80% 的日常业务流程使用的软件 → 覆盖率达标
- Agent就绪度"不可适配"的软件如果承载核心流程 → 标注"数字化改造候选"
- 存在手工数据搬运的环节 → 每个搬运点标注"桥接机会"
- 扫描后未发现任何桥接适配标记 → 可能漏了，检查是否涵盖了所有业务软件
- 同一类软件（如 CRM）存在多套系统 → 标注"功能重叠可能"并建议归一

## 常见陷阱

- 只数了软件数量没画数据流依赖——工具数量不是问题，数据断裂点才是
- 忽略影子 IT——员工自费购买的 SaaS 也可能承载核心流程，需要从岗位推测而不是只问 IT 部门
- 对行业专用软件评分偏低——行业软件（如医院 HIS）可能 API 不开放但通过 HL7/FHIR 标准可集成
