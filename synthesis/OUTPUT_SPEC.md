# Synova 专家输出规范 v1.0

> 所有 8 位专家的诊断输出必须遵循此规范。这不是建议——是交付标准。

---

## 一、输出结构：金字塔三层

每位专家的诊断输出必须包含三层，不可跳过任一层：

```
Layer 1: GOVERNING THOUGHT（一句话核心判断）
  └─ CEO 读完这一句就知道你的结论。不超过 50 字。
  └─ 格式: "[企业名]的[维度]核心问题是[根因]，表现为[关键信号]。"

Layer 2: KEY JUDGMENTS（3 个支持判断）
  └─ 每个 Key Judgment 回答一个"为什么"。
  └─ 格式: 判断 + 证据链 + 影响量化 + 排除项

Layer 3: EVIDENCE CHAIN（证据链）
  └─ 每个 Key Judgment 下的证据必须标注认识论状态。
  └─ 格式: 数据事实 / 专家推断 / 预测假设
```

### 示例（strategy 专家）

```
GOVERNING THOUGHT:
XX科技的战略方向（品质优先+区域头部）本身正确，但战略要求的组织能力与当前
组织实际拥有的能力之间存在 3 倍差距——战略质量 0.8，组织能力 0.25。

KEY JUDGMENT 1: 赛道选择正确但时间窗口在缩小
  📊 西南企业培训市场年增速 18%（行业数据）
  🧠 头部竞争者尚未出现——但 2-3 年内会有。窗口期约 18-24 个月（推断）
  🔮 如果 24 个月内未达到区域头部位置，大厂/资本可能进入（预测）
  → IMPACT: 错失窗口 = 增长目标从 5000 万降为 3000 万
  → RULED OUT: 考虑过"先做规模再提品质"——与创始人价值观冲突，排除

KEY JUDGMENT 2: 核心人依赖是战略的阿喀琉斯之踵
  📊 张老师承担 60% 课程量，无备份（企业访谈数据）
  📊 busFactor = 1，恢复期预估 18 个月（key-person-risk measurer）
  → IMPACT: 张老师离职 → 营收直接损失 60%（1200 万/年）
  → RULED OUT: 考虑过"涨薪留人"——解决不了 busFactor=1 的结构性问题

KEY JUDGMENT 3: 品质溢价尚未转化为定价权
  📊 毛利率 45%，处于行业中上水平（财务数据）
  🧠 客户续约率 70%——说明认可品质但不依赖（推断）
  → IMPACT: 定价权未建立 → 增长只能靠获新客 → CAC 持续上升
```

## 二、Finding 必含字段

每个 Key Judgment 下的每个 finding 必须包含：

| 字段 | 说明 | 必填 |
|------|------|------|
| `statement` | 发现陈述（一句话，企业负责人能听懂） | ✅ |
| `severity` | critical / warning / info | ✅ |
| `evidence` | 证据列表，每条标注 📊🧠🔮 | ✅ |
| `impact_if_ignored` | 如果不解决，12 个月内的量化影响 | ✅ |
| `ruled_out` | 考虑过但排除的替代解释（至少 1 条） | ✅ |
| `one_thing_tomorrow` | 明天就能做的第一件事 | Stage 0-1 ✅ / Stage 2+ 可选 |
| `confidence` | 该 finding 的置信度 (0-1) | ✅ |

## 三、诚实边界：三层标注

每条证据必须标注认识论状态。这是强制规则——不标注 = 不合格。

| 标注 | 含义 | 示例 |
|------|------|------|
| 📊 **数据事实** | 来自企业数据/系统日志/财务报表——可验证 | "张老师承担60%课程量（企业访谈数据）" |
| 🧠 **专家推断** | 基于理论框架的推理/行业规律外推——合理但未经本企业验证 | "基于项目制+75天账期，推断现金流是增长自限器" |
| 🔮 **预测/假设** | 基于当前信号的趋势预判——置信度较低 | "如果张老师离职，恢复期预估18个月（模型估算）" |

**数据不足 ≠ 沉默**。永远给出你的最佳判断。但让客户清楚知道每条结论的认识论状态。

## 四、阶段自适应颗粒度

不同规模的企业，输出颗粒度不同。不是简化——是适配。

### Stage 0 (1-19人): 对话式洞察
- 输出载体: 对话中的一句话 + 可选轻量总结
- 不输出: 完整的三层结构报告
- 建议对象: 创始人个人（"你应该..."）
- Governing Thought: 必须有
- Key Judgments: 1-2 个（不是 3 个）
- Impact: 定性描述（不需要量化到具体数字）

### Stage 1-2 (20-149人): 标准诊断
- 输出载体: 结构化 Markdown 报告
- 三层结构: 全量
- 建议对象: 创始人 + 管理团队
- Impact: 量化估计（"约损失 X 收入/Y 客户"）

### Stage 3-4 (150-500人): 董事会级报告
- 输出载体: 完整诊断报告（Markdown → HTML/PDF）
- 三层结构: 全量 + 附录（数据来源清单、方法论说明）
- 建议对象: 管理层 + 董事会
- Impact: 精确量化（附计算依据）

## 五、跨专家一致性要求

### 去重规则
如果两位专家的 Key Judgment 高度重叠（>80% 语义相似），合成层必须去重。
- strategy 和 biz_model 都在说"核心人依赖"→ 合并为一个联合 Key Judgment
- 标注 `crossExpert: strategy + business_model`

### 矛盾上报规则
如果两位专家的判断方向相反（如 strategy 说"赛道好"，finance 说"利润率恶化"）：
- 不静默覆盖
- 标记为"需人工复核的矛盾信号"
- action 专家介入：诊断置信度降级

### 置信度投票
Key Judgment 的置信度受其他专家影响：
- 3+ 位专家的独立证据指向同一结论 → 置信度升级
- 只有 1 位专家的推断 → 置信度标注为 low
- 全票通过 + 零反对 → knowledge 触发反共识检索

## 六、禁止项

以下内容在诊断输出中禁止出现：

| 禁止 | 原因 |
|------|------|
| 内部术语（D1-D7、测量器、GapDimension、本体层、EvidenceRef） | 企业负责人看不懂 |
| 超过 50 字的 Governing Thought | 不是"一句话" |
| 没有 evidence 的 critical finding | 铁律——证据链不能断 |
| 超过 3 个 Key Judgment | 不是"核心判断" |
| "建议提高效率""建议优化流程"等空话 | 不可执行 |
| 给 Stage 0-1 公司建议"建立事业部制" | 规模不匹配 |
| 没有标注认识论状态的 claim | 诚实边界 |
| 报告正文引用超过 1 个外部理论框架 | 客户不需要听你说 Porter，需要听你判断他的赛道 |

## 七、质量标准（对标 L2 法官六维评分）

此输出标准直接对应 `tests/expert-quality/judge-prompt.ts` 的六个评分维度：

| 维度 | 输出规范要求 |
|------|------------|
| D1 事实准确性 | 每个 claim 标注 📊/🧠/🔮，禁止幻觉 |
| D2 证据质量 | evidence 列表 ≥ 1 条，critical finding 需 ≥ 2 条独立证据 |
| D3 推理深度 | Key Judgment 必须包含 ruled_out（排除项） |
| D4 可执行性 | impact_if_ignored + one_thing_tomorrow |
| D5 领域边界 | 跨域判断标注"需与 XX 专家交叉验证" |
| D6 表达质量 | 零内部术语、零空话建议、Governing Thought ≤ 50 字 |
