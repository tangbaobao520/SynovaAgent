# 规模自适应模型

## 六阶段定义

| Stage | 规模 | 组织特征 | 核心矛盾 |
|-------|------|---------|---------|
| 0 | 1-19人 | 创始人 = 公司。可能是人+Agent混合体。 | 创始人的决策质量 = 公司命运 |
| 1 | 20-49人 | 第一个管理层出现。创始人开始管"管人的人"。 | 从"自己做"到"让别人做" |
| 2 | 50-149人 | 职能分化。部门墙开始出现。信息开始衰减。 | 管理层的成熟度 × 信息传递的衰减 |
| 3 | 150-299人 | 超过邓巴数。信息靠系统不靠人。人治失灵。 | 系统能不能替代人治？ |
| 4 | 300-500人 | 多业务/多层级。战略和执行分离。 | 各单元自主权 vs 总部协调 |
| 5 | 500+ | 多业务、多地区、多文化。（未来扩展） | 总部加什么价值？ |

## 规模只影响三件事

- **测量工具**: Stage 0 用对话式提问，Stage 4 用结构化数据采集
- **输出形式**: Stage 0 是对话中的洞察，Stage 4 是董事会报告
- **建议颗粒度**: "你应该..." vs "公司需要在以下领域建立机制..."

规模不影响的是：
- 开哪些维度（D1-D6 全开）
- 用哪些专家（按需求信号唤醒，不按规模裁剪）
- 诊断深度（只看数据够不够，不看公司大不大）

|-------|----------|-----------|-----|---------|-----------|------|--------|

## 创始人决策带宽饱和度（Stage 0-1 硬性指标）

```
FounderBandwidth_sat = 实际决策负荷 / 理性决策容量
```

测量数据源（如已接入）：
- 日历分析：每周会议数、"只需知道不需参加"的比例
- 审批负载：每日审批量、可授权比例
- 消息响应时间：被 @ 频率、响应延迟
- 任务列表：并行任务数、仅创始人能做的比例

判据:
- FounderBandwidth_sat > 0.8 → 创始人是公司最大的瓶颈
- → action 的 1-3 条建议全部围绕给创始人做减法

## 建议的规模边界

1. 建议必须 ≤ 当前阶段 + 1（只能建议跳一级）
2. Stage 0-1 的关键建议对象是创始人个人，不是"组织"
3. 任何建议如果包含"设立/建立/构建"且需要 ≥3 人全职，必须标注所需人数
